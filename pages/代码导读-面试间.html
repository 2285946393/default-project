1Provider 抽象层 lib/ai.ts · 15 行

15 行，但它是整个项目的地基。

export const provider = createOpenAICompatible({
  name:    process.env.AI_PROVIDER_NAME || "deepseek",
  baseURL: process.env.AI_BASE_URL    || "https://api.deepseek.com/v1",
  apiKey:  process.env.AI_API_KEY     || process.env.DEEPSEEK_API_KEY || "",
});

export const chatModel = provider.chatModel(MODEL);

export const hasApiKey = Boolean(
  process.env.AI_API_KEY || process.env.DEEPSEEK_API_KEY
);

在干什么

  • createOpenAICompatible 的意思：只要对方兼容 OpenAI 的接口格式，我就能接。DeepSeek、硅基流动、智谱都兼容，所以换模型 = 改 .env.local 三行，业务代码一行不动。
  • chatModel 是导出的统一模型对象，其他文件都只 import 它，不关心背后是哪家。
  • hasApiKey 是个布尔标志，每个 API route 第一件事就是检查它——没配 Key 就走本地兜底，而不是崩掉。
面试会问
Q：为什么要做这层抽象？
A：AI 模型迭代快、价格变动频繁，业务代码不该绑定某一家。我统一走 OpenAI 兼容协议，换供应商只改环境变量。
Q：hasApiKey 这个标志是干嘛的？
A：让「没配 Key」变成一种正常状态而不是崩溃。这是我的设计目标——不配 Key 也能把整场面试走完。

2检索：BM25 lib/rag.ts · 183 行

这个文件只干一件事：你打一句话，它从你的资料里挑出最相关的几段。五个步骤。

① 切词 —— 中文没空格怎么切（15–38 行）

for (let i = 0; i < segment.length - 1; i += 1) {
  tokens.push(segment.slice(i, i + 2));
}

「模拟面试」切成 模拟 / 拟面 / 面试。英文数字按空格原样切。

  • 为什么不切单字？会丢顺序——「面试」和「试面」就分不出来了。
  • 为什么不切词？要引词典，麻烦。
  • 两个字是折中：不用词典，又保住了局部语序。

② 切块 —— 长文怎么切（40–70 行）

const cut = Math.max(
  window.lastIndexOf("\n"),
  window.lastIndexOf("。"),
  window.lastIndexOf("；"),
  window.lastIndexOf(". ")
);
if (cut > size * 0.5) end = start + cut + 1;   // 别把一句话劈成两半

每块 420 字，相邻块重叠 80 字。重叠是因为怕答案正好卡在两块的交界处被切断。cut > size * 0.5 是防止切得太靠前、块变得太短。

③ 算 IDF —— 提前知道哪个词值钱（98–120 行）

for (const token of new Set(chunk.tokens)) {
  df.set(token, (df.get(token) ?? 0) + 1);     // 用 Set 去重：同一块里出现 10 次也只算 1
}
this.idf.set(token, Math.log(1 + (N - freq + 0.5) / (freq + 0.5)));

一个词出现在越少的块里，它越值钱。「的」「了」到处都是 → IDF 接近 0 → 不影响打分。

④ 打分 —— 心脏在这里（122–151 行）

score += (idf * (f * (this.k1 + 1))) /
         (f + this.k1 * (1 - this.b + (this.b * dl) / this.avgdl));

这三行就是 BM25 的全部。拆开看：

  • f = 这个词在这块里出现了几次 → 越多分越高
  • 但分母里也有 f，所以分数会饱和——出现 10 次不等于重要 10 倍。k1 = 1.5 控制饱和的快慢
  • dl = 这块多长。越长分母越大、分越低——因为长块天然容易命中，不公平。b = 0.75 控制惩罚力度（0 = 不罚，1 = 全罚）

⑤ 拼上下文（160–182 行）

const text = hits.map(({ chunk }, i) =>
  `【片段 ${i + 1}｜来源：${chunk.docTitle}】\n${chunk.text}`
).join("\n\n");

把选中的块拼成一段文字，带上来源标注，最后塞进出题的 prompt。

主动说这个：第 167 行 new BM25Index(buildChunks(docs)) —— 每次检索都重建索引。文档少没事，文档上千就是瓶颈。
面试时主动讲出这一点，比被问出来强得多——它证明你知道自己实现的边界在哪。
面试会问
Q：为什么用 BM25 不用向量检索？
A：三条理由——场景（中文短文档、词汇重合度高，关键词匹配够用）、成本（BM25 纯 JS 毫秒级零成本，向量要么调 API 要么下几十 MB 模型）、可解释（能显示命中了哪段、为什么命中，向量很难 debug）。如果知识库涨到几百篇长文档，我会换混合检索。
Q：k1 和 b 是干什么的？
A：k1 控制词频饱和，b 控制长度归一化。我用的是文献默认值，没针对语料调参——这是可以改进的点。
Q：这个实现的瓶颈在哪？
A：每次检索重建索引。文档多了要建倒排索引并缓存、挪到 Web Worker。

3流式追问 app/api/interview/chat/route.ts · 60 行

「流式输出」这个词，在你项目里就是两行代码。

const result = streamText({
  model: chatModel,
  system: `...`,
  prompt: `...`,
});

return result.toTextStreamResponse();   // ← 流式就这一行

streamText 让模型一个字一个字往外吐；toTextStreamResponse() 把它转成 HTTP 流返回给前端。

prompt 里那 6 条硬性规则（45–51 行）

硬性规则：
1. 每次回复不超过 130 个字
2. 先用一句话点出回答里真实存在的亮点（要具体，不要"很好很棒"这种空话）
3. 如果回答含糊、缺少细节或存在明显漏洞，追问一个具体问题
4. 你是面试官不是讲师，不要长篇讲解知识点
5. 纯口语中文，像真人说话
6. 绝对不要使用 markdown 符号、星号、井号、列表符号（这段文字会被语音朗读出来）

第 6 条是整个 prompt 里最值钱的一句。为什么？因为这段文字会被语音朗读——*、#、反引号读出来全是噪音。

这就是「AI 的输出要服务于下游消费者」——你的下游不是眼睛，是 TTS。

面试会问
Q：为什么用流式？
A：首字延迟。用户不用等整段生成完，体验上像真人在说话。
Q：prompt 里为什么禁用 markdown？
A：因为要被朗读。这是我踩过才知道的——提示词要服务于下游消费者。

4出题 + 解析兜底 app/api/interview/generate/route.ts · 114 行

两件事：让模型出题，然后保证无论它吐什么，我都能解析出来。

四级兜底 parseQuestions（8–42 行）

// 第 1 级：先去掉可能的 ``` 包裹，直接 parse
const parsed = JSON.parse(cleaned);

// 第 2 级：正则抠出 [...] 再 parse
const bracketMatch = cleaned.match(/\[[\s\S]*\]/);

// 第 3 级：提取所有长度 > 6 的引号串
const quoted = [...cleaned.matchAll(/"([^"]{6,})"/g)];

// 第 4 级：按行切，剥掉 1. - * 这类列表符号
cleaned.split("\n").map(line => line.replace(/^[\s\-*\d.、）)]+/, "").trim())

为什么需要四级？因为模型不保证只吐 JSON。它经常在外面包一层「好的，以下是题目：」，或者包个 ```json 代码块。所以第 9–12 行先把 ``` 清掉，然后一层层往下退。

降级：AI 挂了怎么办（96–113 行）

return Response.json({
  success: true,
  source: "fallback",            // ← 关键：告诉前端这是兜底结果
  questions: fallback,
  message: "AI 生成失败，已回退到内置题库",
});

fallback 是内置题库（ROLE_MAP 里每个岗位预制的题）。注意 source 字段——它让前端能显示「当前用的是内置题库」，降级是透明的，不是偷偷糊弄。

面试会问
Q：模型返回的不是合法 JSON 怎么办？
A：这四级兜底就是答案。层层降级：直接解析 → 抠中括号数组 → 提取引号串 → 按行切并剥列表符号。真实跑下来模型偶尔会在 JSON 外面包一层解释文字，前两级就能救回来。
Q：为什么返回体要带 source 字段？
A：降级是为了用户体验，不是为了藏问题。带 source 前端才能如实告诉用户当前用的是兜底数据。

5评分：schema 约束 app/api/interview/feedback/route.ts · 98 行

「结构化输出」这个词，在你项目里就是 generateObject + 一个 schema。

const { object } = await generateObject({
  model: chatModel,
  schema: feedbackSchema,     // ← 用 Zod 定义的 schema
  mode: "json",
  system: "...",
  prompt: `...`,
});

不用「让模型吐 JSON 然后我自己解析」，而是用 schema 直接约束它——返回的 object 已经是类型安全的对象，不用手写校验。

prompt 里两个关键约束（75–83 行）

  • 5 个维度名称必须完全一致（FEEDBACK_CATEGORIES.join("、")）——否则前端按名字渲染会崩
  • 「60 分代表能达到面试及格线」——防止模型一律给高分。不给这个锚点，模型倾向于讨好用户

降级：本地估算 localFallback（8–33 行）

const completion = Math.round((answered / total) * 100);      // 作答覆盖率
const depthScore = Math.min(95, Math.round(avgLength / 3) + 40); // 按回答长度粗估深度
const totalScore = Math.round((completion + depthScore) / 2);

粗糙，但保证 AI 挂掉时界面不白屏——用户至少能拿到一份「本地估算报告」。

面试会问
Q：为什么用 generateObject 而不是让模型自己吐 JSON？
A：评分报告结构固定，用 Zod schema 约束后返回值直接是类型安全的对象，不用手写校验；不合格时 SDK 会重试或抛错，我再兜底到本地估算。
Q：降级会不会掩盖真实错误？
A：会，所以每次降级都带 source 字段，服务端也 console.error 了原始错误。降级是为了体验，不是为了藏问题。
