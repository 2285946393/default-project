# 凛冬尖塔 · 生成提示词（GPT 图片版）

> 这是 `素材清单.md` 里各项素材的出图提示词。
>
> **写法沿用斗地主那套（`projects/dou-spire/assets/生成提示词.md`）—— 那套是实测过的**：
> 一整段像跟画师交代需求的英文简报，**可以整段复制粘贴**，别拆成关键词。
> 三条公共段落（`<STYLE>` / `<KEY>` / `<AVOID>`）每条末尾都拼上，**只换中间那句主语**。
>
> ⚠️ **色板跟斗地主不一样**：斗地主是「赌坊暗红铜」，凛冬是「冰雪冷蓝铁」。
> 工艺标准（描边/上光/饱和/质感）**完全一样**，这样两个 mod 摆一起不像两个游戏。

## 0. 六条铁律（每条都踩过坑）

### ① 一整套图在**同一条对话串**里连着出，而且**每次都附同一张参考图**

GPT 图片会在同一个对话窗口里延续前面的风格。**开一个新对话，第一条跑冰垒，然后别关，
接着跑箭塔、民兵、遗物图标……** 风格会自己收敛。每张图新开一个对话 = 几个不同的游戏。

每条都附上同一张参考图 —— **`projects/sts2-asset-library/风格基准/00_风格基准图.png`**
（色板 + 五个样件的板子）。**有参考图比改十句文字都有效**：描边粗细、上光方向、饱和度上限它会直接抄。

> ⚠️ 那张基准图本身是**赌坊画风**（暗红/旧铜）。当**工艺参考**用（描边多粗、光从哪来、平涂到什么程度），
> **不要抄它的颜色** —— 颜色以下面 `<STYLE>` 里的 hex 为准。

### ② 比例写在**最前面**

所以每条第一句都是 `A wide 16:9 game asset: …` / `A square 1:1 game asset: …`。
生成时在界面里选对应尺寸（每项都写了选哪个）。

### ③ 颜色写 **hex 色号**，别写颜色名

「深霜蓝」它每次都理解得不一样，`#2B4A6B` 每次都一样。下面已经把整套配色 hex 化，
**不要改成 "dark blue" 这种**。

### ④ 别要透明底 —— **要"纯色抠图底"，自己抠**（实测结论）

实测这个通道**不产出真 alpha**，生成出来是 **RGB（`color_type=2`）**：

| 你怎么要 | 实际拿到 |
|---|---|
| 提示词里写 `transparent background` | **烤进像素的棋盘格** —— 是真像素，不是透明 |
| 用生成接口的透明底开关 | 依然是 **RGB 无 alpha** |

**所以正确做法：让它画在纯色底上，然后本地抠掉。** 每条的 `<KEY>` 位置拼上 §1 的 `<KEY>` 段。

**为什么用品红 `#FF00FF`**：它不在我们的调色板里（霜蓝/冷铁/骨白/霜金），
抠的时候**不会误伤主体**。

⚠️ **凛冬这里特别要注意** —— 冰雪工事**大量用骨白/霜白**（冰垒、雪堆、霜面）。
**主体是白的绝对不能拿白当底**，**必须用品红**。

抠图（零依赖，不需要 PS / PIL）：

```bash
cd projects/sts2-asset-library
python tools/keyout.py 生成图.png --trim
#   生成图.png -> 生成图_keyed.png   底色=(175,31,99)   不透明像素 51%
```

- 底色**自动从四角估计**：生成图的品红不是纯 `255,0,255`，实测约 `181,29,102`，**必须给容差**
- `--tol` / `--soft` 控制容差和软边过渡带（默认 55 / 105），边缘不干净就调
- `--trim` 裁掉四周透明边；水印压到主体上的先 `--wipe` 或 `--crop`
- 抠完**在深色底上叠一下**再放进游戏 —— 白边在深色背景上最显眼

### ⑤ 别在提示词里描述场景、别写分辨率

- 写「在雪原上」→ 它就会给你画一片雪原，纯色底直接废掉。
- 写「512×512」→ 它会给你画"假的低分辨率像素感"。**全尺寸出图，事后再缩。**

### ⑥ 九宫格那几项：**中间必须全平**

按钮 / 面板 / 标题条是**拉伸用**的。出图时把**四角画成固定大小、中间可拉伸**，
提示词里明确写 `the entire centre flat and plain and empty`。
代码按边距 **12px（1920 基准）** 切，四角别小于 40px（2 倍图上）以免拉糊。

## 4. 出图后怎么落地

1. **抠底**（本地脚本，零依赖，不需要 PS / PIL）：
   ```bash
   cd projects/sts2-asset-library
   python tools/keyout.py "生成图.png" --trim                 # 单张
   python tools/keyout.py "生成图目录/" -o "抠好/"             # 整批
   ```
   底色自动从四角估；边缘不干净就调 `--tol` / `--soft`；**水印压到主体上**的先 `--crop` 再抠。
2. **修毛刺** —— 白边在深色背景上特别明显（**冰雪素材尤其明显**）。抠完**一定要在深色底上叠一下**看边。
3. **验一下有没有真 alpha**（别信预览）：
   ```bash
   python tools/check_alpha.py "抠好的图.png"
   #   bpp=4 (有 alpha)   alpha 取值数=157  最小=0  最大=255     ← 这才对
   ```
4. **缩放到清单里的尺寸**；九宫格那几项**再确认一次中间是平的**。
5. **按清单里的文件名改名**（代码写死名字取图，**改错名等于没放**）。
6. **看是哪一族，走哪条落地路径**：

   | 族 | 放哪 | 怎么生效 |
   |---|---|---|
   | **UI 槽位**（面板/按钮/提示条/标题条/遗物图标/节点图标） | `projects/frost-spire/assets/<子目录>/` | **丢进 `mods\FrostSpire\assets\` → 按 F8**，一行命令都不用敲 |
   | **工事牌卡面** | `projects/frost-spire/FrostSpire/images/card_art/` | 跑 `tools\build_pck.ps1` → `dotnet build`（**必须打 pck**，见 §5） |

7. 开局日志会打「**凛冬素材：用自己的 N 个…**」—— 数一数 N 有没有涨。

> **注**：编译最后一步要把 dll 拷进 `mods\FrostSpire\`，**游戏运行时 dll 被锁住会失败**。
> UI 换图不用管这个（不用重编译）；卡面要重编译，所以**改卡面前先关游戏**。

## 5. 卡面怎么接进游戏（已实现，说明现状）

**问题**：游戏取卡图走 `CardModel.Portrait` =
`ResourceLoader.Load("res://images/atlases/card_atlas.sprites/<pool>/<entry>.tres")` ——
**从游戏自己的 pck 里按 entry 读**。我们的图不在那儿，所以要**换路径**。

**怎么解决的**（反编译 STS2-RitsuLib 0.6.5 取证）：
RitsuLib 提供了官方接口 `IModCardAssetOverrides` ——
卡牌实现它、给出 `CustomPortraitPath`，RitsuLib 就在 `PortraitPath` 的 getter 上
用 Harmony 补丁**换成我们的路径**。

凛冬已经接好了（`FrostSpireCode/Cards/FrostCardArt.cs`）：

```csharp
// 三族卡牌基类各加一个接口，卡面路径自动推导，不用一张张写
public abstract class FrostDeployCardBase : CardModel, IFrostCardArt { … }
public abstract class FrostBuildingCard    : CardModel, IFrostCardArt { … }
public sealed class SummonMilitiaCard      : CardModel, IFrostCardArt { … }
```

**路径规则**（`FrostCardArt`）：
`res://FrostSpire/images/card_art/` + `类名去掉 Card、转 snake_case` + `.png`

**配套改动**（都已做完）：
- `FrostSpire.json` → `has_pck: true`
- `export_presets.cfg`（导出配置）+ `tools/build_pck.ps1`（打包脚本）
- 图目录 `FrostSpire/images/card_art/`
- csproj 的 `CopyMod` 本来就会拷 pck（`Condition="Exists(...pck)"`）

**你要做的**：图丢进 `FrostSpire/images/card_art/`（**文件名必须对**）→
跑 `tools\build_pck.ps1` → `dotnet build` → 重启游戏。

> ★ **安全兜底**：RitsuLib 会先 `AssetPathDiagnostics.Exists(path)` 检查，
> **路径不存在就静默回退**到游戏默认卡面。所以**图没画全也不会崩**，
> 画一张就换一张。

> ⚠️ 卡面**不能用 F8 热更新**（F8 只管 `assets/` 那套文件系统素材）。
> 卡面走 pck，改一次要重打包 + 重编译。这是 pck 路线的固有代价。

> ★ **8 张占位图已就位**（`tools/gen_card_placeholders.py` 生成：霜蓝底 + 骨白框 +
> 每张一个可分辨的图标 + 英文卡名），已打进 pck 并部署。
> 用途是**先把链路验证掉**——重启后 8 张卡的卡面若全变成占位图，
> 说明「类名 → 文件名 → pck 路径」整条链是通的；之后换真美术**只要覆盖同名文件**。

> ★ **改完图跑 `python tools/verify_card_art.py`**：自动核对
> 卡牌类名 / 磁盘 png / pck 路径三处是否对齐。
> 这条链是**静默失败**的（文件名拼错不报错，只是那张卡默默用回默认卡面），
> 人眼几乎发现不了，所以必须交给脚本查。

## 6. 别指望 AI 的事

| 别指望 | 换成什么办法 |
|---|---|
| 真正的 alpha 渐变（暗角/风雪） | PS / Krita 拉个径向渐变，3 秒 |
| 九宫格中间绝对平 | 多跑几张挑，或事后 PS 涂平中间 |
| 8 张卡面风格统一 | **同一条对话串 + 同一张参考图**，这是唯一可靠的办法 |
| 卡面构图跟本体卡的卡图区对齐 | 出图偏方，事后再裁；或先出一张对一下比例 |
| 干净的描边（放大后不糊） | AI 出图偏软，放大前先锐化，或描一遍线 |
| 「冰雪感」不脏 | 提示词里 `kept COLD overall` 那句别删；脏就重跑 |
