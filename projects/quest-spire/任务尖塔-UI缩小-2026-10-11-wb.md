# 任务尖塔 · UI 再缩小（2026-10-11）

> 玩家反馈「UI 还是太大」。查完之后发现**不是**「默认值不够小」这么简单 —— 有两个真问题：
>
> 1. **改设置页的默认值，对老玩家一点用都没有。** BaseLib 在第一次运行时就把当时的默认值
>    写进了 `user://mod_configs/QuestSpire.cfg`，之后永远以文件里的值为准。
>    老玩家（包括本机那份）cfg 里躺着的 `"UiScale": "0.85"` 会**盖住**任何新默认值。
> 2. **「接取任务」浮层根本不响应「界面缩放」。** 面板固定 680px、描述列固定 560px，
>    玩家把滑块拉到底它也纹丝不动 —— 「还是太大」多半就是在说它。
>
> 本次：给整套 UI 加了一个**全局基准缩放 0.8**（绕过 cfg 把所有人都变小），
> 把浮层接进缩放体系，滑块下限放宽到 0.6。编译 0 错 0 警告，dll 已部署，版本升 **0.2.29**。

## 一、为什么「只改默认值」是无效操作（关键）

### 1.1 证据：cfg 文件是**首次运行就落盘**的

`BaseLib/Config/ModConfig.cs:196-204`：

```csharp
private void Init()
{
    foreach (var property in ConfigProperties)
        _defaultValues.TryAdd(property.Name, property.GetValue(null));

    if (File.Exists(_path)) Load();
    else Save(); // Save default values     ← ★ 第一次运行就把默认值写进文件
}
```

实机验证 —— 本机那份 cfg 确实存在，而且存的是**老默认值**：

```
C:\Users\有花无实\AppData\Roaming\SlayTheSpire2\mod_configs\QuestSpire.cfg
{
  "ShowQuestPanel": "True",
  "ShowRewardLines": "False",
  "UiScale": "0.85",     ← 改代码里的默认值，会被这一行盖住
  ...
}
```

**结论**：把 `UiScale` 默认值从 0.85 改成 0.7，只对**从没运行过 mod 的新玩家**有效。
已经装过、已经生成过 cfg 的玩家（正是那些在反馈「还是太大」的人）**一点都不会变**。

### 1.2 所以这次动的是「基准」，不是「默认值」

`UiKit.cs` 新增：

```csharp
/// 全局基准缩放 —— 「让所有人一起变小」的那个系数。
public const float BaseShrink = 0.8f;

/// 面板 / 浮层实际用的缩放 = 玩家设置 × 全局基准。
public static float Scale => QuestSpireConfig.UiScale * BaseShrink;

public static int Scaled(int baseSize) => Mathf.Max(8, Mathf.RoundToInt(baseSize * Scale));
public static int Px(float basePx)      => Mathf.Max(1, Mathf.RoundToInt(basePx * Scale));
```

- 基准 **0.8** 是乘在**所有人**头上的，跟 cfg 里存了什么无关 → 老玩家一起变小。
- 玩家自己的滑块**仍然叠加**在它上面（`0.85 × 0.8 = 0.68`），想更大更小都还能调。
- 默认值**故意留在 0.85 不动**：改成别的只会让新玩家被缩两次，老玩家还是不变，纯属添乱。

## 五、还没做 / 你决定

1. **一次都没进游戏看过。** 这次改的是纯布局（尺寸/字号/边距），逻辑一行没动，
   编译也过了，但**「缩完到底好不好看、有没有挤在一起」必须你进游戏看一眼**。
   重点看三处：① 右上角面板的文字有没有被截断；② 面板拖动后贴边位置对不对；
   ③ 点「接取任务」浮层有没有出屏。
2. **滑块拉到最小时会撞到 8px 下限。** `Scaled()` 保底 8px 是防「缩到看不见」。
   滑块 0.6 × 基准 0.8 = 0.48，此时描述(14)/奖励(13) 都会被抬到 8px —— 也就是
   **拉到 0.6 和拉到 0.7 看起来差不多**。要么把下限收回 0.7，要么把保底降到 7。**等你实测再定。**
3. **面板的「高度」没单独治。** 面板高矮取决于接了多长的任务描述；
   多人局 4 人 × 20 条本来就该用「点名字收起」（已有）。
   如果还嫌高，比调缩放更有效的是加一个「**简要模式**」开关 ——
   只留「标题 + 进度条」，把描述和奖励整行隐掉。**这是新功能，没做。**
4. **浮层没有滚动容器。** 联机开局给 10 个候选，缩到 462px 宽后描述换行更多，
   总高有可能顶出屏幕（1080p 一般没事，小屏笔记本悬）。
   真要做就是给候选列表套一层 `ScrollContainer` 并给它一个最大高度。**没做。**

- **`UiScale` 这个配置项以后不要再动「默认值」了。** 它只在第一次运行时有意义，

## 八、追加：下限放到 0.1（0.2.30）

> 0.2.29 上传后（23:51）玩家说「最小可以拖到 0.1」。查完发现**滑块下限不是瓶颈**，
> 真正卡住的是 `Scaled()` 的「保底 8px」。

### 8.1 为什么光改下限没用

按 `实际缩放 = 滑块 × 0.8`、`Scaled(base) = max(8, round(base × 缩放))` 算：

| 滑块 | 实际缩放 | 描述(14) | 奖励(13) | 行标题(17) | 面板标题(18) |
| --- | --- | --- | --- | --- | --- |
| 0.85（默认） | 0.68 | 10px | 9px | 12px | 12px |
| 0.70 | 0.56 | **8px** | **8px** | 10px | 11px |
| **0.52** | 0.42 | 8px | 8px | 8px | 8px |
| 0.10 | 0.08 | 8px | 8px | 8px | 8px |

**缩放低于约 0.52 时所有字号都撞到 8px 保底** → 滑块后半段是「拖了没反应」的空档。
（这也解释了之前那个现象：0.6 和 0.7 看起来一样。）

### 8.2 改了三处

| # | 位置 | 改动 |
| - | --- | --- |
| 1 | `QuestSpireConfig.cs` | `[ConfigSlider(0.6, 1.4, ...)]` → **`[ConfigSlider(0.1, 1.4, 0.05, ...)]`** |
| 2 | `UiKit.Scaled` | 字号保底 **8px → 6px**（让 0.1~1.4 整段都有变化） |
| 3 | 宽度兜底 | `QuestPanel.Width` 加 **≥150px**；浮层面板 **≥380px**、描述列 **≥260px** |

**为什么宽度要单独兜底**：0.1 时 `330 × 0.08 = 26px`、`680 × 0.08 = 54px` ——
字号可以继续变小，但面板/浮层会缩成一条细缝，看着像渲染 bug。宽度到此为止。

### 8.3 改完的对照（极端端）

| 滑块 | 实际缩放 | 字号 | 面板宽 | 浮层宽 |
| --- | --- | --- | --- | --- |
| 0.85 | 0.68 | 12 / 10 / 9 | 224px | 462px |
| 0.60 | 0.48 | 8 / 7 / 6 | 158px | 380px（兜底） |
| 0.10 | 0.08 | 6 / 6 / 6 | 150px（兜底） | 380px（兜底） |

> ⚠️ 0.1 时所有字号都是 6px（层级没了），基本属于「能看见但看不清」。
> 这是文本 UI 的物理极限 —— 再小就不是字了。
