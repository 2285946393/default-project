# 面对尖塔 · 第一人称原型

独立工程，不改斗地主、凛冬尖塔。当前版本 **0.1.6**：补三幕各自的墙面、地面和顶部纹理，外壳延伸至相机两侧；保留原背景远近层和五角色武器。**实际画面和操作效果仍待用户测试**。

## 现在能做什么

- 操作：进入普通战斗后，点击右上方 **“开启第一人称 [F8]”**，或按 **F8** 开关；鼠标在上方区域小幅转头，进入手牌区域回中，保留鼠标指针。
- 按钮下显示开启状态或失败原因；地图、奖励、设置等界面不显示按钮，也不切换视角。
- 原敌人和召唤物动画实时显示在 3D 空间中，原版身体保留原站位播放；点击框、选中圈、血条和意图单独投影。
- 背景完整图层分成远景与近景，转头产生不同位移；外壳使用朋友免费魔搭生成的专用材质，颜色随当前原背景变化。蔓生古堡使用石墙、石地、藤叶顶部；虫巢使用蜂巢、根系；荣耀之城使用蓝灰石墙、铺石、石材顶部。替代第一幕码头暂用石材，顶部不使用藤叶。
- 自己身体和血条隐藏，格挡、状态与自身点击区域保留左侧；动态友方摆到两侧。
- 本地玩家触发本体 Attack 动画时播放持武动作；不是鼠标点击就出刀。
- 五角色使用用户提供的图：铁甲剑、静默双短刃、摄政王星辉、故障机器人电球、亡灵镰刀。剑与镰刀缩小并靠下，各近战武器挥动；星辉和电球从原图拆成独立图层，向鼠标附近飞出、缩小淡出，再回手。发射是视觉演出，不改变卡牌目标与伤害。
- 武器与怪物或召唤物投影框重叠的部分淡出，保留鼠标操作。
- 保留原手牌、血条、意图和敌人点击框；不修改伤害、牌堆与存档。
- 手动关闭或离开战斗时恢复原显示；更新异常保留展示并显示提示，不自动关。
- 生物进入死亡退场队列后继续捕获，等待本体结束退场再释放；召唤、队列变化动态更新，零敌人也保持展示。下一场战斗记住开启偏好（本次游戏运行内），开启失败仍会清理并报错。

敌人和背景景物仍是动画纸片，房间外壳有立体平面；不能自由走动或大角度环顾。手部是用户图片，未触发本体 Attack 动画的卡牌不会播放武器动作。

## 本机构建

需要已安装的 .NET 9 和 Godot 4.5.1 的缓存依赖，本机已有。项目引用本体 DLL，没有框架依赖。

在本工程目录执行：

```powershell
dotnet restore FirstPersonSpire.csproj --source 'C:/Users/有花无实/.nuget/packages' -p:NuGetAudit=false
dotnet build FirstPersonSpire.csproj --no-restore
dotnet run --project tests/LayoutChecks.csproj --no-restore -- '.godot/mono/temp/bin/Debug/FirstPersonSpire.dll'
dotnet restore tests/presentation-probe/PresentationProbe.csproj --source 'C:/Users/有花无实/.nuget/packages' -p:NuGetAudit=false
dotnet build tests/presentation-probe/PresentationProbe.csproj --no-restore
& 'D:/software/godot/Godot_v4.5.1-stable_mono_win64/Godot_v4.5.1-stable_mono_win64_console.exe' --headless --path 'tests/presentation-probe'
& 'D:/software/godot/Godot_v4.5.1-stable_mono_win64/Godot_v4.5.1-stable_mono_win64_console.exe' --headless --path 'tests/godot-probe' --script check.gd
```

默认游戏目录为 `D:\software\steam\steamapps\common\Slay the Spire 2`。换位置时给构建命令追加 `-p:Sts2Dir="你的游戏目录"`。

产物在 `.godot/mono/temp/bin/Debug/`：`FirstPersonSpire.dll`、`FirstPersonSpire.json`。
工程**没有自动部署步骤**，构建不会改变游戏的模组目录。这些文件不是双击启动程序。

## 实机验收前不要宣称可用

由用户操作游戏测试；我不自动启动游戏或操作存档。优先只加载本模组，用新测试局验证：

1. 单敌人：F8 开启后不黑屏、动画播放，点击身体能正确选中。
2. 多敌人：各动画独立、血条与意图跟随，目标牌不会选错。
3. 切回：连续开关十次，原背景、身体、位置恢复。
4. 窗口尺寸：调整窗口、全屏和宽屏后，画面/点击框保持对齐。
5. 界面：地图、设置、卡牌查看时 F8 不抢操作。
6. 边界：召唤、死亡、逃跑、变身、进入下一战斗不会遗留展示节点。
7. 玩家和宠物目标牌：身体隐藏后是否仍能正常选中。
8. 演出和性能：攻击路径、受击、屏幕震动、帧率、透明混合与原渲染方式。
9. 本轮重点：两侧、地面和顶部是否可见；三幕是否切换对应材质；纹理大小、接缝与怪物遮挡是否自然。继续观察召唤物是否漂移、死亡是否保持第一人称、五角色武器与点击是否正常。

## 已知限制

- 最多 9 个非本人生物（敌人、友方和仍在退场的生物合计）；借用 20–31 位空闲显示层，其中三层用于远景、近景和隐藏。初始不足时开启失败；后续超过容量时额外生物保留原显示，不退出视角。
- 暂不支持独立 `CanvasLayer` 中的敌人。
- 捕获范围按点击框加边距计算，巨大/伸展动画可能被裁切。
- 宽敌人可能相互重叠；点击框拟合透视四角的包围矩形，边缘命中仍需实测。
- 背景远近按本体直接图层分组，不是逐个景物建模；房间外壳是贴图平面，纹理可能有镜像重复，不能绕到景物背面。码头暂没有专用纹理。
- 星辉与电球从单张图按轮廓拆分，可能有边缘残留；发射朝鼠标附近，不保证逐张卡牌对应真实受击点。
- 本体/其他模组若同时改写同一个界面坐标或显示层，可能存在恢复冲突，不建议第一轮混用。
- 每个敌人增加一张实时纹理；实际帧率、共享世界是否正确渲染、宿主是否启用 3D，均待实机确认。
- `affects_gameplay=false` 只表达不改规则的设计意图，不是兼容性认证。

## 参考与许可

参考本机 Pickleplayer 的 **Pickle's First Person Mod**（饥荒工坊 `1367276577`）的相机、隐藏身体、纸片展示思路；未复制其 Lua 代码或素材，未发现可复用许可证。

工程结构参考本机 `Alchyr/ModTemplate-StS2`；未整套复制模板。本体 API 依据本机 0.111.0 源码和 Godot 4.5.1 官方 XML 文档。
没有打包游戏 DLL、Spine 动画或美术资源。此原型尚未决定对外发布许可证。

0.2.0 内嵌 `assets/武器五种/处理后/` 的九张 PNG，由用户五张原图处理和拆层得到；另内嵌 `assets/杀戮尖塔测试/房间纹理/v2/` 的**十二张**材质（丛林／暗潭码头／蜂巢／荣光各墙地顶）。材质通过用户指定的 `lf3000y/image-studio`、`qwen-image-2.1` 免费生成，提示词保存在同目录 `prompts-v2.json`，复现工具为 `tools/generate_room_textures_v2.py`，画风基准记录在 `v2/画风基准-必读.md`。

⚠️ v1 材质（`房间纹理/*-v1.png`）已废弃：第一幕丛林被画成了米黄石板地，平均色 (146,136,106)，而原版是 (32,42,13) 的苔藓草地。v2 改为**先从本体解包图取样再生成**，并在 `tests/Program.cs` 加了 12 项平均色校验，防止重犯。没有复制原版背景到发布包；用户武器图与生成材质的对外发布授权仍需另行核实。
