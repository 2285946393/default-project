## 三、已确认的技术事实（有证据，别再重测）

### 1. Godot 可见层的规则（探针实测）

- 一个 CanvasItem 能否被某视口拍到 = **自己与所有祖先的 VisibilityLayer 按位与**。
- 只给子节点设层、祖先不管 → 按位与为 0 → **拍不到**。
- 正确做法：**祖先链一路 `|=` 本层，一直到 Viewport**。这是 0.5.5 探针实验证实的。
- 给 `room` 加层**不会**把手牌拍进捕获：手牌自身不含该层，按位与仍是 0。
  之前「遇到 room 就停」「不碰祖先链」两种改法都是错的（人物/背景全黑）。

### 2. 捕获方案：**只设层，不挪节点**（0.7.3 已回退到这个）

- 补层方案捕获正常：不透明像素约 **3256/11440**（诊断 23:34），捕获图是完整怪物。
- 「挪进干净容器」方案已废弃：位置偏移（0.87% 不透明）、打断 Spine 动画、
  特效停住不消失、背景整体偏移。
- 当前 `PresentationSession.cs` 里还留着 `IsolateAdopt` 和 `_captureRoot` 的尸体代码，
  **做方案 2 时可以删掉**，统一只走 `IsolateLayerOnly`。

### 3. 展示层层级：ZIndex = **-8**

原版结构：

```
原版场景/背景  ZIndex = -10
原版特效       ZIndex = -9
展示层         ZIndex = -8   ← 唯一正确区间
手牌/UI        ZIndex = 0
```

- `-12` → 跑到背景下面，怪物被背景盖住（用户实测「怪被挡住了」）。
- `0` → 和手牌同级且后画，盖住手牌。
- 0.7.9 又把 `room.Ui.ZIndex` 提到 200。**用户实测手牌还是看不见**，
  说明「被展示层盖住」不是手牌的真凶，真凶未定。

### 4. 手牌问题的现状（未解决，别宣称修好）

诊断数据（23:34）：

```
手牌：Visible=True VisibleInTree=True Layer=1 位置=(0,0) 尺寸=(1920,1080)
手牌Z链：Hand(z=0) → CombatUi(z=200) → CombatRoom(z=0) → ...
展示层：overlay z=-8 screen z=-8 尺寸=(1920,1080)
主画布遮罩=1048575 预留=4293918720
```

- 层级机制上已排除「被展示层盖住」。
- 可能方向：主画面遮罩被改后影响了某层绘制；`TextureRect` 的 StretchMode/尺寸；
  或手牌实际在别的容器里被别的节点挡住。**不要猜，先做能自动截图的探针**。
- 0.8.0 的主画面截图诊断代码在 `DiagnoseOnce()` 里，可以直接搬去探针用。

### 5. 性能红线

- `Image.GetPixel()` 逐像素调用极慢，跨引擎边界。曾因一帧扫 5 遍导致**游戏闪退**。
- 现在已改成**一次读进 byte[] 数组**。改回纸片后连这一步都不需要了，别再引入逐像素扫描。

### 6. 捕获范围

- 只用 Hitbox 会切掉换皮大帽子；要取 `Hitbox ∪ %Bounds`，再留 `CapturePadding=160`。
- 但 padding 太大时相邻怪的捕获区会重叠（层过滤一般能挡住）。

### 7. 素材

- 房间材质是 v2（用户最后拍板：**第一版绿的墙那套 + 别太空的地板**）。
  用户明确说喜欢 `assets/杀戮尖塔测试/房间纹理/v2/_v2绿旧版存档/` 那三张的感觉。
- 0.4.4 曾出现「拷贝同源同名文件失败，以为换了其实没换」的事故。
  **换材质必须核对哈希**。

## 十一、0.9.2：画面不显示 + 闪屏的根因（2026-10-13 午后）

用户实测 0.9.1 后反馈：「不止是没手牌，现在画面不显示，还会闪屏。」

诊断文件给出决定性一行：

```
纸片 Creature：纹理=(590,466) PixelSize=187.06432
```

`Sprite3D.PixelSize` 的含义是「贴图 1 像素 = 多少世界单位」。
0.9.0 换回纸片时把它写成了 `1 / unitPerPixel`，也就是把 0.00535 写成了 **187**。

结果：590 像素宽的怪被放大到 **约 11 万个世界单位**，直接糊满/超出整个画面；
每一帧捕获尺寸变化时它的巨体又在近处穿过相机，视觉上就是闪屏。
手牌也大概率被这张巨幅贴图盖住，而不只是原来的手牌问题。

**修复**：`PixelSize = unitPerPixel`，并抽成 `FrontLayout.SpritePixelSize()`，
加 3 条离线检查钉住「不能再写倒数」。构建 0 警告 0 错误；
布局检查 285 项、生产探针 144 项通过。已部署 0.9.2，哈希核对一致。

⚠️ 0.9.2 只修「巨幅贴图导致画面糊满/闪屏」。手牌原问题是否仍存在，
要等这一版画面正常后再看——之前手牌可能是被这个巨体贴图盖住的。
