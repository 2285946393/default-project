## 七、23:05 追加：**本地开发版改名 DouSpireDev**（让工坊版能同时装）

**为什么**：用户要「下载创意工坊版和别人联机」，但本地开发版和工坊版的 mod id **都是 `DouSpire`** ——
游戏不允许两条同 id 的 mod，订阅工坊版就撞车。

**怎么改的**（一次改到底，身份链全部跟着走）：

| 位置 | 原来 | 现在（开发版） |
|---|---|---|
| manifest 文件名 | `DouSpire.json` | `DouSpireDev.json`（新增，`DouSpire.json` 保留给工坊） |
| manifest `id`/`pck_name` | `DouSpire` | `DouSpireDev` |
| dll | `DouSpire.dll` | `DouSpireDev.dll` |
| 部署目录 | `mods\DouSpire\` | `mods\DouSpireDev\` |
| `Entry.ModId` | `"DouSpire"` | `"DouSpireDev"`（`#elif DOUSPIRE_DEV` 分支） |
| 网络 opcode 命名空间 | `DouSpire` | 跟 `Entry.ModId` 走 → 两套频道互不串 |
| 诊断日志 | `DouSpire-diagnostics.log` | `<ModId>-diagnostics.log` |

**关键机制**：csproj 里加了 `ModName` 属性（默认 `DouSpireDev`），
`AssemblyName` / `ModOutputDir` / `CopyMod` 全读它；`ModName=DouSpireDev` 时才定义
`DOUSPIRE_DEV` 宏。**这是唯一的事实来源**，改一个地方全跟着变。

**★ 上架命令变了**（默认编译现在编的是开发版！）：
```bash

  bash dou-spire-rules/tools/build-mod.sh dou-spire -p:ModName=DouSpire
```

`prepare_workshop.py` 里加了**身份闸**：`mods\DouSpire\DouSpire.json` 不存在、

（不然会把 `id=DouSpireDev` 的 dll 传上去，把工坊条目改成开发版身份。）

## §九 追加（2026-10-09 23:25）：联机两个致命 bug 已修 + 0.2.35 上架

用户实测反馈：**「看日志测试出现很多问题」＋「AI 代打不出牌，联机」**。
日志 `%AppData%\SlayTheSpire2\logs\godot.log` 里 23:10 那局：

```
272 次  System.NullReferenceException
   at DouSpire.Table.DouSpireTable._Process(Double delta)
```

**272 次、间隔几乎完全均匀（16 行/次）⇒ 每帧一炸、从 3085 行一直炸到 7315 行。**

### 9.1 根因 A（放大器）：`_Process` 里 `_game` 是 null 却硬解引用

`斗地主桌` 的 `RestoreOrPick()` 在联机分支里**直接 return**（注释："BeginNetSession 会摆牌"），
并把 `_picking = false`：

```csharp
if (_netOn) { _picking = false; ShowPicking(false); return; }   // ← _game 还没建！
```

⇒ 上面两道 `return` 拦不住，一路走到 `_Process` 的

```csharp
if (_game.Winner is not null) return;      // 💥 `_game` 是 null（字段声明就是 `GameState _game = null!`）
```

**而 `_Process` 一抛异常，它后面的代码全都不执行** —— `StepAi()` / `StepDiscard()` / `StepRps()`
整段被跳过 ⇒ **电脑一张牌都出不来**；而 `_broken` 没被置位，界面看着还"活着"，
玩家看到的就是"AI 不出牌、整桌假活"。

> **德州桌 (`DouSpirePokerTable._Process:530`) 从一开始就有这条守卫**：
> `if (_game is null) return;  // 联机桌：主机还没说"开这手"，什么都不推进`
> —— **斗地主桌漏了**。这就是"为什么德州没事、斗地主炸"的答案。

**修**：在 `TickAutoPilot()` 之后、`if (_askingShow || _askingDouble)` 之前补
`if (_game is null) return;`。**位置有讲究**：必须放在
`OpenPending` 超时 / `NetRoomGuard` / `NetTickAskTimeout` / 代打 **之后** ——
那几件事**不需要 `_game` 也要跑**（客机等主机超时收桌全靠它们）。

### 9.2 根因 B（触发器）：被顶替的旧桌子还在广播"收桌"

`ReopenForNewTableSize()`（选人界面切人数）是**同一个延迟回调里"先 Close 再 Open"**：

```csharp
Callable.From(() => { Close(Entry.Logger); ...; Open(Entry.Logger); ... }).CallDeferred();
```

而 Godot 的 `QueueFree()` 要等**帧末**才回收 ⇒ 实际执行顺序变成：

1. 新桌子 `_Ready` → `_netOn = true`、**`DouSpireNet.Live = 新桌子`** → 「桌面已打开」(日志 3064)
2. **旧桌子 `_ExitTree`** → `_netOn` 还是它自己的 true、`DouSpireNet.Active` 还是 true
   → 于是它**朝对面广播一次"主机收桌"**（日志 3065，紧跟一条
   `Outbound host->broadcast opcode=7516850543131588634` 就是那个 CastClose）
   → 然后 `DouSpireNet.Live = null` + `DouSpireNet.CloseTable(false)` **把新桌子的联机状态一起清掉**

后果两条，全中：
- **队友的桌面被这个假广播关掉**；
- 新桌子 `_netOn` 仍是 true 却没有联机 backing ⇒ **永远等不到主机的摆牌广播**
  ⇒ `_game` 永远 null ⇒ 根因 A 每帧炸 ⇒ **AI 停摆**（3251 行 vs 3085 行，时序完全吻合）。

**修**（`_ExitTree`）：
```csharp
var stillCurrent = !_silentExit && ReferenceEquals(DouSpireNet.Live, this);
if (_netOn && DouSpireNet.Active && stillCurrent) { ...广播...; CloseTable(false); }
if (ReferenceEquals(DouSpireNet.Live, this)) DouSpireNet.Live = null;   // 别抹掉新桌子的 Live
```
配套：`Close(logger, silent)` 新增 **`silent` 参数**（`ReopenForNewTableSize` 传 `true`）
—— 明确表达"我是被顶替的残骸，闭嘴"。普通收桌（`silent=false`）行为不变。
并新增实例字段 `_silentExit` 记录该语义。

## §十 追加（2026-10-09 23:40）：**残留静态贴图**等三个显示/流程 bug 已修 + **0.2.36 上架**

### 10.1 玩家报的三个现象（同一张截图）

1. 三人局里**多出一个座位** —— 用户原话：「四个人不是四个人是三个人」
2. **旧的静态贴图**残留在屏幕上（左下 / 右下各一张**不属于任何在场玩家**的立绘）
3. 选人界面**点「三人桌 / 四人桌」，队友那边直接闪退**

### 10.2 真因（一句话）

**搭牌桌那一刻 `_game` 还没建好，席位数只能"猜"。**

`BuildScene()` 跑在 `_game` 建好**之前**（联机尤其明显：`_game` 要等主机广播摆牌才建）。
旧代码里 `SeatCount` 在没有 `_game` 时退回"设置里的人数"（本机被留成过 4），于是：

- `BuildScene` 按 4 建了 4 份**回合光环 / 立绘**；
- 之后**所有**每帧循环用的都是真值 3 ⇒ **第 4 席永远没人回收**（`RefreshSeatArt`、`TickWhaleFaces`、
  `TickIdleAnimation`、`_ExitTree`、`RefreshCore` 一律循环到 `SeatCount`）；
- 旧 `MakeSeatArt()` 建出来就 `Visible = true` ⇒ 那张图**永久挂在屏幕上** —— 现象 ② 的由来；
- `RefreshSeatArt()` 开头有 `if (key == _seatArtKey) return;` —— **第一次算错了就永远错下去**，
  玩家只能收桌重开，这才是"旧的"两个字怎么来的。
- 现象 ③：`SetPickerTableSize()` → `ReopenForNewTableSize()` 走的还是 §9 那条"先 Close 再 Open"的路。
  即便 §9 已用 `_silentExit` 静音，**联机下玩家本来就不该能切人数**（桌上有几个人 = 在场几个人说了算）。

### 10.3 改了什么（全在 `DouSpireTable.cs`，7 处）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `SeatCount` / 新增 `PickerSeats` | `_game` 没建好时**不再**退回设置里的人数：联机走常量 `DouSpireNet.Seats`(=3)；选人界面一律用 `PickerSeats` |
| 2 | `_Ready` | 定完 `_netOn` 之后**再读一次摆位表** `DouSpireLayout.Load(SeatCount)` —— 原来那句在"还不知道是不是联机"时就跑了，3 人局读的是 4 人局坐标 |
| 3 | `BuildScene` 第 6/7 段 | 立绘/光环循环从 `s < SeatCount` 改成 **`s < 数组长度`**（恒 4）—— **数组多长就建多长，一坑不多一坑不少**，彻底消灭"没人管的节点" |
| 4 | `BuildScene` 第 7.5 段 | `SpawnActors()` → **`RefreshSeatArt()`** —— 建完立绘立刻按真值同步一次显隐 |
| 5 | `RefreshSeatArt()` | 去掉"key 没变就整个 return"；**显隐遍历整个数组**（`s >= SeatCount` 或空席一律收掉），只有**贴图**还按"换人才换" |
| 6 | `TickWhaleFaces()` ⓪ | 每帧兜底同样**扫整个数组** —— 这是残留贴图的最后一道闸 |
| 7 | 选人界面 / `ApplyPickerSize` / `SeatTag` / `CycleSeat` | **联机时不建「三人桌 / 四人桌」按钮**（换成一行说明字）；`SetPickerTableSize()` 里再留一道 `_netOn` 兜底拦截；人数读数统一走 `PickerSeats` |
