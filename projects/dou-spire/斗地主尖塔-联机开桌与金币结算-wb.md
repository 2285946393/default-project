## 二、本次改了什么

### ① "都点了才开始"（收集开桌意愿）
- 主机点了自己那张，或收到第一个客机请求时 → **进入收集阶段**，屏幕弹
  「等大家一起点「斗地主」…（n/总人数）」。每来一个新请求计数 +1。
- **人齐 → 立刻开桌**；**25 秒没齐 → 照样开**（没点的座位由电脑补）—— 永远不会因为一个人
  没装 mod / 掉线 / 挂机就开不了桌（这是本 mod "永不卡死"的老原则）。
- "总人数" = run 里的玩家数，封顶一桌 3 席（2 人房等 2 个人、4 人房等 3 个人）。
- 配套：客机"等主机应答"的超时从 12 秒放宽到 **40 秒**（原来 12 秒会把桌子提前收掉，
  主机 25 秒后开桌时又重开一遍，看起来像闪一下、还容易漏开桌消息）。

### ② 联机金币：主机结算所有人
- 主机开桌时把"席位 → 玩家对象"留了下来（`DouSpireNet.PlayerOfSeat`）。
- 结算时：**主机**把每个真人席的输赢都写进他自己的 `Player.Gold`（钳 0、写日志），
  游戏自己的玩家状态同步会把结果带到各端；客机仍只写自己那席（主机也在写同一笔，两边算出来一致）。
- 单人路径一个字没动。

## 三、验证方法（需要两个人联机测）
1. 两端都进同一局、走到同一个篝火，**只有一个人**点「斗地主」→ 桌上显示
   "等大家都点了「斗地主」才发牌…"，主机弹（1/2）。**25 秒后自动开**（另一席由电脑顶）。
2. 两端**都点** → 人齐立刻发牌，不再等 25 秒。
3. 打完一局看两端日志：应各有两条 `篝火金币结算 …`（主机侧包含对手那笔），两端的金币一致。
4. 角色照旧：两端坐在桌边的都是自己 run 里选的角色。

## 四、四人斗地主 —— 没做，做之前要你拍板
不是改个数字的事，牵一发动全身：
1. **规则内核** `GameState.NewGame` 要支持 `playerCount`（4 人：13/13/13/13 + 2 底，地主 15），
   而且 `ComboJudge` / `RuleAi` 里所有"三个人"的假设都要翻一遍。
   ⚠️ 这套规则**和开源参考实现 rlcard 做过双向对车（穷举 970 万子集 0 差异）**——改完这个保证就没了，得重新验。
2. **桌面 UI**：几十处 `[3]` 数组 + 三人布局要改成四人（桌子要重新排版，座位摆四个方向）。
3. **网络协议**：`Seats` 从常量变动态、开桌消息格式变（老版本对不上）。
4. **语音/表情**：席位数组、`WhaleReact` 的 `seat > 2` 判断等。

建议：先把上面 ①② 联机部分实测稳了，确认三人同桌没问题，再决定要不要上四人。
要上的话我按上面 1→4 的顺序做，每步单独构建验收。
