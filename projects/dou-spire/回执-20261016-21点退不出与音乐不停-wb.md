# 回执：21 点「退不出去」+ 「关了音乐还在放」（2026-10-16）

> 用户 2026-10-13 报的两个问题，附一句硬要求：
> **「接受斗地主mod。用户反馈21点有可能推出不了。且关闭后音乐一直放」**
> **「一定要保证能退出房间」**

两个问题的根因**都在"收桌"这条链上**，而且是**同一个结构性缺陷**的两张脸：
**收桌代码做完自己的事就走了，而游戏本体有两个东西会"自己把状态恢复回来"。**

---

## 一、问题 2：关了音乐还在放 —— 真因是"只关了喇叭，没关指挥"

### 病灶

游戏里跑局的背景音乐**不是一个通道，是两层**：

| 层 | 类 | 干什么 |
|---|---|---|
| 播放层 | `NAudioManager` | 真正出声的喇叭。`PlayMusic` / `StopMusic` |
| **调度层** | **`NRunMusicController`** | **攥着 `_currentTrack`、每帧 `_Process` 跑 `UpdateMusic()`，自己决定"现在该放哪首"** |

我们原来的 `DouSpireMusic.Stop()` **只调了 `NAudioManager.StopMusic()`** ——
等于**只关了喇叭、没关指挥**。`NRunMusicController` 下一帧一看"我这首还没放完呢"，
**立刻又推回来了**。听感就是用户说的**「关闭后音乐一直放」**。

### 还有第二个断点：停完根本没人盯着

就算调用了停音乐，**收桌之后没有任何东西在管音乐了**：

- `DouSpireMusic.Tick()` 只挂在**牌桌自己的 `_Process`** 上（`DouSpireTable` / `DouSpirePokerTable`）；
- 桌子一收，那个 `_Process` **跟着一起消失**；
- 于是"停一次"之后，**再也没有第二个人去按它**。

### 怎么修的

1. **连调度层一起停**：`Stop()` 里除 `NAudioManager.StopMusic()` 外，
   再反射调 `NRunMusicController.StopMusic()`。
   - 走**反射**而不是直接引用类型：万一某个游戏版本改了/删了这个类，
     直接引用会让**整个 mod 在加载时炸**；反射找不到就退化成"只停 NAudioManager"，
     最多音乐没压住，**绝不会连累开桌**。
2. **加一个 2.5 秒的"压制窗口"**：收桌后的一小段时间里，
   每帧把想自己放回来的跑局音乐再按回去（`NRunMusicController` 是在**场景/房间变化**时
   重新推导该放哪首的，收桌那一瞬间往往正赶上它重建，停一次会被覆盖）。
3. **把巡检钉在常驻节点上**：压制改由 **`DouSpireHotkey._Process`** 每帧驱动
   —— 那个节点是**三张桌子全收掉之后唯一还在跑的东西**。
   ⚠️ 而且**必须排在那段 `_retries` 提前 return 之前**：那段 return 是给按钮重试用的，
   排在后面就变成"开局 30 秒之后不再巡检"。

### 顺带修的一个真 bug

**21 点的 `Open()` 原来一次 `ClearCache()` 都不调**（斗地主和德州一开桌就调）。
后果两条：
- 收桌时登记的压制期**一直留着** → 再开桌头两秒没音乐，看着像"音乐坏了"；
- 往 `music\` 里新丢的歌，**不重启游戏永远认不出来**。

已给 21 点补上 `DouSpireAssets/Voice/Music.ClearCache()`。

## 二、问题 1：21 点退不出去 —— 三层保险

用户口头确认过：**是"点了收桌退不出去、卡在 21 点里"**（不是"出不了牌"）。

复现过：规则内核**没问题**。跑了 4000 局 UI 真实序列 + 40 万局边界压测，
「卡住 0 局 / 牌靴越界 0 / 偷看不结算 0 / 分牌指向死手 0」，`--bj` 那 57 条自检也全过。
**所以问题不在规则，在"退出这条路只有一条，断了就没了"。**

### 找到的实锤

**F9 会在已有牌桌上面再叠一张斗地主桌。**
`DouSpireHotkey._Input` 原来**无条件** `DouSpireTable.Toggle()`：

> 21 点开着的时候按 F9 → **21 点上面又叠一张斗地主桌** →
> 21 点那颗收桌钮被盖住 → 越按越乱 → **人出不来了**。

这基本就是用户"退不出去"的来源。

### 三层保险（全部落地）

| 层 | 做了什么 |
|---|---|
| **① 键盘（最硬）** | **ESC = 退出当前牌桌**。走 `_Input`，**早于 GUI 的 `_GuiInput`** —— **钮点不到也照样收得到**。三张桌子都支持。 |
| **② F9 改正** | **有牌桌开着时，F9 先"收桌"而不是"再开一张"**；都收干净了才走原来的开关逻辑。 |
| **③ 界面可见退路** | 21 点右上角加一颗**带字的「收桌 (ESC)」钮**，钉在 `this` 上（**不在 `_scene` 里**）⇒ **层级上永远压在最上面**，不可能被台面/立绘/横幅盖住。 |

### `Close()` 全部改成幂等（三张桌子）

原来是 `if (!IsOpen) return;` —— **单例状态一旦错乱，这一句就把收桌整个挡掉**。
现在统一成：

1. **先摘单例**（`_instance = null`）—— 立刻生效，防同一帧重复走流程；
2. **音乐/音效/联机状态无条件收干净**（幂等，重复调没副作用）；
3. 再尽力 `QueueFree()` 实例；
4. 实例确实不在了也**照样把音乐停掉**，只是记一条日志。

德州那张尤其重要：`DouSpirePokerNet.Live = null` 和 `CloseTable(broadcast: true)`
现在**无条件跑** —— 不然会留下"桌面没了、联机还挂着"的僵局，**对面会一直等一个已经收掉的桌**。

## 五、你要做的：怎么看它

1. 确认游戏里**只启用 `DouSpireDev`**（工坊那个 `DouSpire` 请保持停用，
   两个同时开会各加一份入口 + **抢 F9**）；
2. **重启游戏**（dll 是启动时加载的）；
3. 开 21 点，试这四条：
   - 点右上角那颗**圆钮**收桌；
   - 点右上角那颗**带字的「收桌 (ESC)」**；
   - 按 **ESC**；
   - 按 **F9**；
   四条**每一条都应该能退出去**。
4. 收桌之后**贴耳听 3 秒** —— 音乐应该彻底停住，不再自己响回来。
5. **反复开关 5 次**，每次都要能收能开、音乐正常。

有任何一条不灵，把日志里 `斗地主：` 开头那几行发我。

## 六、这次学到的（值得写进坑清单）

> **「关闭时把状态恢复回去」这件事，光做一次是不够的 —— 得先搞清楚
> "有没有别的东西会把它恢复回来"，以及"做完之后还有没有人在盯着"。**

1. **停服务要停到"调度层"，不只是"播放层"。**
   `NAudioManager` 是喇叭，`NRunMusicController` 是指挥 —— 只关喇叭，指挥下一帧就把它放回来。
2. **清理逻辑不能挂在"要被清理的那个对象"身上。**
   `Tick()` 挂在牌桌上，桌子一收它自己就没了 —— **清理必须由常驻节点驱动**。
3. **提前 return 是清理逻辑的天敌。**
   `SuppressTick()` 如果排在 `_retries` 那个 return 后面，就变成"开局 30 秒后失效"。
4. **"退出"这类保命操作，永远要有第二条路。**
   界面钮是单点故障（会被盖住 / 会认不出来）；键盘走 `_Input`，
   比 GUI 更早拿到事件，是最可靠的一道。
5. **`if (!IsOpen) return;` 用在"收尾"函数上是危险的。**
   状态机一旦错乱，这句会把**救命的那条路**一起挡掉。收尾要幂等，不要早退。
