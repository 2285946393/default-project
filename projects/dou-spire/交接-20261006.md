## 一、本次（第二版）新做的两件事

### 1. ★ 修好「画好的角色立绘不显示」

**症状**：`assets/seats/char_*.png` 五张立绘（铁甲战士 / 沉默猎手 / 故障机器人 / 摄政王 / 亡灵束缚者）都在、
素材报告也说"解析成功"，**但桌上一个都不显示**。

**根因（`DouSpireTable._Ready()` 的调用顺序）**：

```
BuildScene();      ← 第 7 步在这里调 MakeSeatArt(s) → 读 _chars[s]
...
RestoreOrPick();   ← _chars 到这里才被赋值
```

`_chars` 是 `new CharacterModel?[3]`（**三个 null**）。所以搭场景那一刻
`SeatArt(null)` → `EntryOf(null)` → `""` → **返回 null** → `if (tex == null) return null`
→ 立绘节点**压根没被创建**。素材报告绿是因为它只查"文件能不能读到"，跟有没有挂上节点无关。

**修法**：
- 新增 `InitCharacters()`，**挪到 `BuildScene()` 之前**调（把原来散在 `RestoreOrPick` 里
  的 `_chars = _savedChars ?? Assign(...)` 收进这里）。
- `MakeSeatArt` 改成**不管有没有图都建节点**（否则后面想换也换不了）。
- 新增 `RefreshSeatArt()`：按 `_chars` 当前是谁重贴立绘，**同一套角色重复调不重贴**
  （用 `_seatArtKey = "ironclad|silent|defect"` 比对）。在 `RefreshCore()` 开头调 ——
  换局、改选人之后都会自动跟上，即 **「抽到哪几个角色就放哪几个 UI」**。
- 日志会打两行：`斗地主：三家 = …` / `斗地主：座位立绘 = …`。

### 2. ★ 单人 / 多人 入口菜单（`DouSpireEntry.cs` + `DouSpireNet.cs`）

主菜单「斗地主尖塔」按钮**不再直接开桌**，改成先弹：

```
单人（打两个电脑）  → 直接开桌（现有玩法）
多人联机            → 三人房 / 四人房 → 走官方联机渠道
```

- `DouSpireEntry`：一个挂在 Window 根下的覆盖层（压暗主菜单 + 居中面板），
  ⚠️ 它和牌桌一样**不能靠锚点定位**，所以自带 `FitToViewport()`（同一套修法，见下）。
- `DouSpireNet.HostOfficial(seats, log)`：**走游戏官方那条路**，不自己造房间。
  反编译 `sts2.dll` 拿到的事实：
  - `NMainMenu.SubmenuStack`（公开属性，`NMainMenuSubmenuStack`）就是游戏切换 单人/多人/图鉴 用的那套栈；
  - 游戏自己的「多人」按钮做的事就是 `SubmenuStack.PushSubmenuType<NMultiplayerSubmenu>()`，我们照抄同一句；
  - 官方开房的**人数上限是写死的 4**：`NetHostGameService.StartSteamHost(4)` /
    `InitializeMultiplayerAsHost(netService, 4)`。所以「三人房/四人房」在官方这层**没有开关** ——
    我们把人数记在 `DouSpireNet.RequestedSeats`，等斗地主的网络层接上去时再按它决定发 3 家还是 4 家。

## 三、引擎的事实（存档，别再猜）

| 项              | 值                                                  |
| -------------- | -------------------------------------------------- |
| 窗口             | **2560 × 1600**                                    |
| 内容缩放           | CanvasItems / Keep，基准 **1920 × 1080**              |
| UI 坐标空间        | **1920 × 1080**（设备像素 = UI 单位 × 1.3333）             |
| 黑边             | 16:10 窗口配 16:9 基准 → 上下各 ~80 设备像素黑边                 |
| 你的截图 1920×1200 | = 0.75 缩图 × 1.3333 → **截图 1 像素 ≈ UI 1 单位**（y 要减黑边） |

> **UI 一律按 1920×1080 设计。**

**根 Control 布局塌陷**（上一版查出来的，两条路都用到）：`Control` 直接挂在 **Window 根**下时，
它算位置用的"父级矩形"和真正的可见区域对不上 → 所有 `锚点比例 × 父尺寸` 都算成 0，只剩 offset 生效。
**修法 = 等锚点（四个都设 0，让 Size 成权威）+ 显式 Position/Size**（`DouSpireTable.FitToViewport`，
`DouSpireEntry.FitToViewport` 是同一份）。

## 七、补丁（23:06）：主菜单按钮"挂上了却看不见"

**症状**：用户进游戏，主菜单里没有「斗地主尖塔」。
日志却写着 `斗地主：主菜单按钮已挂上（复制了游戏原生菜单按钮…）` —— 节点在了，就是看不见。

**根因**：复制模板时**把模板的隐藏状态一起复制过来了**。
`NMainMenuTextButton : NButton : NClickableControl : Control`，`Duplicate()` 会连
`Visible` / 启用态 / 透明度 一起复制。而主菜单里「继续游戏」「放弃本局」「时间线」在条件不满足时
是 `Visible=false`，**且排在容器最前面** ——
旧代码 `container.GetChildren().OfType<NMainMenuTextButton>().FirstOrDefault()`
极可能挑中的正是它们 → 我们的按钮也是隐藏的。
（用户截图里恰好既没有「继续游戏」也没有「放弃本局」，和这个推断一致。）

**修法**（`DouSpireMenuButton.cs`）：
1. 模板优先点名 `SingleplayerButton`（一定可见、一定可点），其次任何可见的，最后才随便挑；
2. 复制后**强制掰回**：`Visible = true`、`Modulate = White`、`if (!IsEnabled) Enable()`、
   `labelControl.Modulate = White`（禁用态模板的 label 是 1/4 透明）；
3. `CallDeferred` 等容器布完局再确认一次；
4. **加了自检日志**（下次直接看日志定位，不用猜）：
   - `斗地主：主菜单按钮的复制模板 = <名字>（容器 MainMenuTextButtons 实际类型 = …，原生按钮 N 个，可见的 M 个）`
   - `斗地主：按钮自检 可见=… 树上可见=… rect=… 父=…`

> ⚠️ `NClickableControl` **不是** `BaseButton`，所以没有 `Disabled` 属性 ——
> 启用/禁用是 `public void Enable()` / `Disable()` + `public bool IsEnabled`。

**顺带记下的风险**：日志里有
`Asset not cached: res://scenes/screens/multiplayer_submenu.tscn`。
`NMultiplayerSubmenu.Create()` 走的是 `PreloadManager.Cache.GetScene(...)`，
如果它返回 null，`PushSubmenuType<NMultiplayerSubmenu>()` 会抛 —— `DouSpireNet` 已经 try/catch + Toast 兜住，
真失败时用户仍可点游戏自己的「多人模式」。**这条需要实测确认。**

### 音效是从哪来的（这招以后还能用）

游戏音频走 **FMOD**，音频文件在**加密的 pck 里**（`flags=2`、`file_count=0`）抠不出来。
但**音效的事件名是硬编码在 `sts2.dll` 里的字符串**，而且按 **UTF-16** 存的 ——
用 UTF-8 的正则扫不到，得扫 `(?:[\x20-\x7e]\x00){3,80}` 再 `.decode("utf-16-le")`，
一次扫出 **363 条真实路径**。

播放走游戏自己的 `MegaCrit.Sts2.Core.Commands.SfxCmd.Play(string sfx, float volume)`，
内部是 `NAudioManager.Instance.PlayOneShot(...)` —— 所以**跟游戏「设置 → 音频 → 音效」是同一条通道**。
⚠️ 它里面会摸 `CombatManager.Instance`，主菜单下可能是 null → 每次调用都 try/catch；
连错 3 次就永久闭嘴（没声音只是安静，不该刷日志）。

## 十二、三家换成**活角色**（带 Spine 骨骼）

用户 2026-10-07 01:00：「搞了这么久的ui。为什么我们不把角色直接放在三对应的地方呢。

### 思路
不再自己画立绘。**直接用游戏本体那个角色**（不是图片，是 Spine 骨骼 + 官方动画 + 官方音效）。
我们只做两件事：**摆位置**、**在出牌那一瞬间喊一声"做这个动作"**。

### API（全部反编译核对过）
| 用途 | 怎么拿 |
|---|---|
| 站着那套（首选） | `CharacterModel.CreateVisuals()` → `NCreatureVisuals`（public 方法） |
| 坐着那套（兜底） | `PreloadManager.Cache.GetScene(model.RestSiteAnimPath)` → `NRestSiteCharacter` |
| 骨骼 | `NCreatureVisuals.SpineBody`（public getter，`_Ready` 后才有值） |
| 原始高度 | `NCreatureVisuals.Bounds.Size.Y` |
| 缩放 | `SetScaleAndHue(scale, 0f)`（官方方法） |
| 等骨骼加载 | `SpineNodeExtensions.RunWhenSpineReady(host, sprite, state => …)` |
| 播动画 | `MegaAnimationState.SetAnimation(name, loop, trackId)` |
| 角色音效 | `model.AttackSfx` / `CastSfx` / `DeathSfx`（public 属性） |

> `NCreatureVisuals` 没有 `_Process`、不摸 `CombatManager` → **主菜单里能独立实例化**（已实测确认）。

### ★ 最大的坑：触发器名 ≠ 骨骼动画名
`CreatureAnimator` 的 `Idle/Attack/PowerUp/Cast/Hit/Dead/Revive` **只是状态机钥匙**。
扫 `sts2.dll` 字符串堆：`power_up`、`hit`、`dead` 这三个**在游戏里根本不存在**，
照抄会静默退化（本该倒下的角色却站着发呆）。真名：

| 想做的事 | 真名 |
|---|---|
| 待机 | `idle_loop` |
| 攻击 | `attack`（派生 `attack_single/double/triple/multi/big1/big2`） |
| 蓄力 / 称王 | **`cast`** |
| 挨一下 | **`hurt`** |
| 倒下 | **`die`** |
| 起势 | `revive` |

### 牌型 → 动作
单张 `attack_single` · 对子 `attack_double` · 三张 `attack_triple` ·
顺子/连对/飞机 `attack_multi` · 带牌 `attack` · 炸弹 `attack_big1` · 王炸 `attack_big2`。
（每个动作都有兜底链：这具骨骼没这个动作就一级一级往下退，最后退回待机。）
