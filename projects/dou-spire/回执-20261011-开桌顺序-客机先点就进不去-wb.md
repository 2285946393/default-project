# 回执：开桌顺序 ——「客机先点，主机就进不去」（2026-10-11 00:5x）

> 用户原话：「**还有就是必须主机点斗地主。客机再点。如果客机火堆先点我就进不去**」

---

## 一、现象

**开桌有顺序依赖**：

| 顺序 | 结果 |
|---|---|
| 主机先点 → 客机再点 | ✅ 立刻开桌 |
| **客机先点 → 主机再点** | ❌ 主机点了**没反应**，只能干等 25 秒超时 |

用户想要的规矩（2026-10-08 定）：「**几个玩家都点了斗地主那个图标才能开始斗地主**」
—— 顺序不该影响能不能开。

---

## 二、根因：三条记票路径，两条是漏的

「收集开桌意愿」这套状态机在 `DouSpireNet`：`_gathering` / `_gatherSeen` / `_gatherExpected`
/ `GatherTimeoutSeconds`（25 秒兜底）。

**记票一共有三条路，但「记完票就检查人齐、齐了就开」只写在其中一条里：**

### ① 主机先点时，客机来票 —— ✅ 原本就对

```csharp
if (_gathering)
{
    if (_gatherSeen.Add(senderNetId))
    {
        ...
        if (_gatherSeen.Count >= _gatherExpected) { FinishGather(); }   // ✅ 人齐就开
    }
    return;
}
```

### ② 客机先点时（主机还没点，被客机"起头"）—— ❌ 只记票、不检查

```csharp
StartGather(me, Entry.Logger);                       // ← 旧版：无 mineClicked 参数
if (_gatherSeen.Add(senderNetId))
{
    Entry.Toast(...);                                 // ← 只弹提示，没有"人齐就开"
}
```

### ③ 主机自己**后**点 —— ❌ 直接 return，等于没点

```csharp
private static void StartGather(Player me, Logger logger)
{
    if (_gathering) return;                           // ← ★★★ 撞在这里，什么都不做
    ...
}
```

**② + ③ 叠加的后果**：客机先点 → 主机被"起头"进入收集（**还白送了主机一票**，
见下面第三节）→ 主机自己再点 → 撞 `if (_gathering) return;` → **没有任何反馈**
（没 Toast、没开桌）→ 用户看到的就是「**我点了没反应、进不去**」，只能等 25 秒的超时兜底。

---

## 三、顺带修掉：客机先点时会"白送主机一票"

旧 `StartGather` 里：

```csharp
_gatherSeen.Clear();
_gatherSeen.Add(LocalNetId());            // 主机自己这次点击算一份
```

**不管是谁触发的，都把主机那一票记上。** 于是客机先点时，
2 人房里 `_gatherSeen` 直接就 2/2 了 —— 主机**根本没点**却算"人齐"。
这违反用户「都点了才能开」的规矩（虽然因为②漏了检查而没真的立刻开桌，
但语义是错的，而且一旦补上②的检查就会变成"客机一人点就开桌"）。

---

## 四、修法

### ① 抽出 `GatherNote(ulong netId)` —— 记票 + 人齐立刻开桌

三处记票统一走它，谁点都是「记票 → 人齐就开」。重复点不重复计数（`HashSet.Add` 返回 false 就跳过）。

### ② `StartGather` 加 `mineClicked` 参数

```csharp
private static void StartGather(Player me, Logger logger, bool mineClicked)
{
    if (_gathering)
    {
        // ★ 已经在收集了 —— 主机这一票补上（原来这里直接 return = "点了没反应"）
        if (mineClicked) GatherNote(MyNetIdForSeat());
        return;
    }
    _gatherSeen.Clear();
    if (mineClicked) _gatherSeen.Add(MyNetIdForSeat());   // 只有主机真点了才记票
    ...
}
```

### ③ 三个调用点

| 位置 | 调用 | 说明 |
|---|---|---|
| `OpenAtRestSite`（主机自己点） | `StartGather(player, logger, mineClicked: true)` | 主机真点了 → 记票 |
| `HostOnOpenReq`（客机来票、主机已收集） | `GatherNote(senderNetId)` | 记客机的票 |
| `HostOnOpenReq`（客机先点、主机被起头） | `StartGather(me, logger, mineClicked: false)` + `GatherNote(senderNetId)` | **不白送主机票** + 记客机票 |

### ④ 记票的 id 来源统一成 `MyNetIdForSeat()`

原来用 `LocalNetId()`（第一优先 `LocalContext.NetId`，另一套口径），
现在和座位表、和 `ctx.SenderNetId` 统一到**联机层**（详见
`回执-20261011-出不来牌-客机认错座位-wb.md` 第三节）。

---

## 五、修完后的两种顺序

**主机先点**：
```
主机点 → StartGather(true) → _gatherSeen={主机} 1/2 → Toast(1/2)
客机点 → GatherNote(客机)  → 2/2 → FinishGather() → 立刻开桌 ✅
```

**客机先点**（修复前是"干等 25 秒"）：
```
客机点 → StartGather(false) → _gatherSeen={} → GatherNote(客机) → 1/2 → Toast(1/2)
主机点 → StartGather(true)  → _gathering 已为真 → GatherNote(主机) → 2/2 → 立刻开桌 ✅
```

25 秒超时兜底**原样保留**（有人掉线 / 没装 mod 时照样能开）。
