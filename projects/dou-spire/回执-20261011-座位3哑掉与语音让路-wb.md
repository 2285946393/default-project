# 回执：座位 3「永远听不到声音」的根因 + 语音触发优化（2026-10-11）

> 用户原话：
> **「我打斗地主，我头上那席永远听不到声音。为什么其他的电脑我能听到。语音触发方面是不是可以优化。」**

---

## 一、结论先说

**不是"没素材"，也不是"音量太小"——是一行 3 人时代的硬编码把第 4 席整个挡在门外。**

`DouSpireTable.cs` 的 `WhaleReact()` 第一行：

```csharp
if (seat < 0 || seat > 2) return;     // ← 主犯
```

这行是**3 人斗地主时代**写的。2026-10-09 加了 4 人 2v2 模式之后**忘了放开** ——
于是 **座位 3（上家·左，屏幕左中那一席）从此完全哑掉**：语音、表情、立绘反应全没有。

> ⚠️ 顺带说明：`WhaleReact` 里的座位号是**视角位**，和 `_chars` / `_seatArt` 同一套下标。
> 3 人局：`座位2 = 左`；**4 人局：`座位3 = 左`**（`座位2 = 右下`）。
> 用户截图红圈圈的是屏幕**左中**，4 人局里正是座位 3。

## 三、改了什么

### 修复 1（主）：放开座位上限 —— `DouSpireTable.cs`
```csharp
- if (seat < 0 || seat > 2) return;
+ if (seat < 0 || seat >= _chars.Length) return;
```
`_chars` 固定 4 格，所以 4 人局四席全通。
（德州那边一直写的就是 `seat >= _chars.Length`，是斗地主这边没跟上。）
旁边留了长注释写清"为什么日志看着正常"。

> 已核对：`WhaleReact` 用到的 `_whaleFace` / `_faceAnim` / `_seatArt` / `_lastAction` 等
> **全是 4 格数组**，放开到座位 3 不会越界。

### 修复 2：语音"自己别把自己顶掉" —— `DouSpireVoice.Admit()`

这是回答用户第二问「语音触发方面是不是可以优化」时查出来的第二个毛病。

**现象（日志实锤）**：
```
19:21:48  座位0 [Normal]  4_hint_1.ogg
19:21:48  座位0 [Chatter] 10_pass_1.ogg      ← 同一秒
```
每席只有一个播放器，`p.Stream = x; p.Play();` 会**从 0 重新开始** ——
同一秒里连着的两句，**前一句刚开口就被后一句掐掉**，听起来就是"这席没声音"。

**现在的规则**（三条，按 `VoicePriority` 判）：

| 情况 | 行为 |
|---|---|
| 本席没在说话 | 直接放 |
| 本席正在说，新的一句**更要紧** | **打断**，放新的（炸弹 / 胜负照样能插进来） |
| 本席正在说，新的一句**同级或更次要** | **这次不说了**，让位给正在说的那句 |

⇒ 「点提示」正在说的时候，紧接着的「要不起」不会把它顶掉；
反过来「炸弹」永远能打断正在说的碎嘴。

⚠️ **这不是把 2026-10-08 撤掉的"按秒数节流"加回来**（那个玩家体感是"出牌没声音"）——
只在**真的正在说话**的那一瞬间让路，丢的是零星几句，不会变成"一整局没声音"。
