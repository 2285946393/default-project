## 二、牌桌为什么能"无缝"接上（这步是关键）

德州那 7 档台面的**叠牌坐标是写死的**（`DouSpirePokerTable.ApplyMarks()`：
经典绿绒那组 = 牌位中心 y 450/1080、格宽 96、缝 20）。所以新画的桌子**刻线必须对得上**，
否则牌会叠歪。

**做法：不重画，用「参考图模式」改造已有的 `table_poker.png`。**

- 走的是 `/v1/images/edits`，字段 `image` = `data:image/png;base64,…`，
  模型 `qwen-vl-image-2.1-rmbg`（带真透明通道）。
- 提示词只说"**换材质换配色、刻线位置形状保持完全不变**"，并逐条点名要保留的元素
  （5 个长方形公共牌位 / 底池圆环 / 上下左右三个下注弧线区 / 左右两枚铆钉）。
- 出图回来后**裁到 alpha 边界再缩到 1654×886**（原图四周有 14px 透明边，
  不裁的话刻线整体内缩，同样对不上）。

**验证**（`process_for_mod.py` 里量出来的，不是眼估）：

| 刻线 | `table_poker.png` | 新图（归一化后） |
|------|-------------------|------------------|
| 5 格上轨 ny | 0.3758 | 0.3782 |
| 5 格下轨 ny | 0.5384 | 0.5369 |
| 底池圆上沿 | 0.8488 | 0.8506 |
| 竖线 1 / 2 / 3 | 0.316 / 0.385 / 0.459 | 0.315 / 0.386 / 0.459 |

**误差 < 0.003**（≈ 3‰ 屏宽），可以直接用。

另外：这张图**自带凹槽**，所以 `PlacePotAndBoard()` 里那块 `poker/board_plate.png`
牌匾不会铺（那句 `plateOn` 只在 `table_poker` 这一档为真）—— 是对的，没动它。

## 四、顺手记下来的魔搭接口真相

| 事实 | 说明 |
|------|------|
| `size` 参数**被忽略** | 普通模型恒出 **1024×576**，`-4k` 模型恒出 **4096×4096 方图**。想要别的尺寸只能自己裁。 |
| 返回是 **`url` 不是 `b64_json`** | `data[0].url`；`data[0].meta` 里有 `reference_count` / `seed` / `timings_ms` / `request_size`。 |
| `-rmbg` 后缀**自带真透明通道** | 四角 alpha = 0，不用再跑抠图。 |
| **有参考图通道** | `/v1/images/edits` + `image: "data:image/png;base64,…"` 或 `images: [...]`，两种都收。`meta.reference_count` 可以确认真的吃进去了。 |
| 地址别写错 | 是 `studio-lf3000y-<创空间名>.api-inference.modelscope.net`；<br>`api-inference.modelscope.cn/api/v1/studio/…` 那个路径 **404**。 |
| 耗时 | 普通 ~10-20s，4k ~20s，带参考图 ~15s。 |

脚本全在 **`D:\work\AI产出\魔搭自由创作\`**：
`msimg.py`（客户端）/ `gen_scene.py`（两张背景）/ `gen_table_edit.py`（参考图改桌）/
`process_for_mod.py`（加工入库）/ `make_mock.py`（合成"进游戏摆位"预览）/ `probe_edit.py`（探口）。
