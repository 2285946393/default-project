### ★ 两条 Godot 界面铁律（2026-10-11 各踩一次，都是"用户看得见的丑/坏"）

**① 九宫格（`StyleBoxTexture` / `TextureBox`）的边角是 1:1 画的，不跟着控件缩放。**

源码：`scene/resources/style_box_texture.cpp` 把 `texture_margin_*` 原样交给渲染器，
而 `servers/rendering/renderer_rd/shaders/canvas.glsl` 的 `map_ninepatch_axis()` 第一段是
`if (pixel < margin_begin) return pixel * tex_pixel_size;` —— **目标像素 : 贴图像素 = 1 : 1**。

⇒ **控件比原图小多少倍，边角就大多少倍。** 我们的牌匾普遍比原图小 3~6 倍
（`handrank_plate.png` 1024×193 画进 900×58 的框）⇒ 两端装饰帽硕大、中间被压成一条缝。

**正确做法 = `DouSpireUi.Plate(tex, capL, capR, w, h)`**（2026-10-11 新增）：
自己切三块 —— 左右装饰帽按**高度**等比缩（`s = h / 原图高`，形状不变），中间那段单独横向拉伸。
用 `AtlasTexture` 取原图竖条（**Godot 4 的 `TextureRect` 已经没有 `region` 属性**）。
装饰帽宽度**从原图轮廓的平直段量出来**，别按 1/5 拍脑袋：

| 素材 | 原图 | 左帽 | 右帽 |
|---|---|---|---|
| `poker/pot_plate.png` | 971×256 | 48 | 48 |
| `poker/handrank_plate.png` | 1024×193 | **104** | 66 |
| `poker/plate_wood.png` | 1024×198 | 114 | 114 |

⚠️ `handrank_plate` 左端有枚**圆形徽章**（直径≈100 px），左帽切少了会把徽章劈成两半。

**② 图层顺序别写死绝对索引 —— 用"相对叠放"。**

`MoveChild(x, 0/1/2)` 只在"这一层永远不会被删掉重建"时才成立。
换背景 / 换桌面这类操作都是**删了重加**（新节点落末尾），删一个后面索引全往前挪一格 ⇒ 写死的索引当场指错。

德州就是这么黑屏的：连点「换牌桌 → 换室内 → 换牌桌」之后，那块**整屏不透明的兜底色**
被一步步顶到最上面，把背景和桌子全盖掉（用户报的"切桌子切室内会黑屏"）。
**修法 = `RestackBase()`**：把底座那几层 `[_felt, _bgLayer, _tableLayer, _boardPlate, _winnerHalo]`
按顺序依次 `MoveChild` 到 `0、1、2…`，中间删过谁加过谁都不影响。

### ★ 内核（`dou-spire-rules`）的硬约束要当面抄一遍，别猜（2026-10-11 立的）

`HoldemGame.NewGame` 开头三条硬校验，**不合法就抛**：

```csharp
if (n is < 2 or > 6) throw new ArgumentException($"德州支持 2~6 人，给了 {n} 人");
if (smallBlind <= 0 || bigBlind <= smallBlind) throw new ArgumentException("盲注不合法");
if (startStack <= 0) throw new ArgumentException("开局筹码必须大于 0");
```

抛出来会被 `_Ready` 的 catch 接住 → **整桌收掉 + 一句 Toast**。

**踩的坑**：篝火赌注模式的本金 = 金币 × `BetMaxSwingPercent`(25%)。
99 金币 ⇒ 本金 **24** ⇒ 大盲 `Mathf.Max(1, 24/50)` = **1**，小盲 `Mathf.Max(1, 1/2)` 也 = **1**
⇒ 撞上 `bigBlind <= smallBlind` ⇒ 整桌起不来。
用户看到的就一句：**「德州牌桌起不来：盲注不合法」**（「火堆我进不去德州扑克」）。

**修法 = 本金和大盲都设下限**（`DouSpirePokerTable.ComputeStakes`）：

```csharp
stack      = Mathf.Max(20, gold * pct / 100);   // 至少 10 个大盲的深度，牌局铺得开
bigBlind   = Mathf.Max(2, stack / 50);          // ★ 必须严格大于小盲（小盲下限是 1）
smallBlind = Mathf.Max(1, bigBlind / 2);
```

外加 `StartHand` 里一道**纯函数式兜底 clamp**（本地算 / 主机广播两条路径都过，
各端输入相同则输出相同 ⇒ **联机不会分叉**）：

```csharp
if (smallBlind < 1) smallBlind = 1;
if (bigBlind <= smallBlind) bigBlind = smallBlind + 1;
if (startStack < bigBlind * 2) startStack = bigBlind * 2;
```

**⇒ 铁律：调内核参数前，先去 `projects/dou-spire-rules/` 把它的 `throw` 抄一遍。**
内核只认规则不认画面，参数不合法就是**当场整桌崩**，而 Toast 只打一句
干巴巴的 `{e.Message}`（「盲注不合法」）—— 不看源码根本猜不到是哪个数越界。
（同一类：`BlackjackGame` 那边也有自己的硬校验，动 21 点的注码前同样先抄。）

## 六、魔搭出图进 mod 的套路

朋友三千的 Image Studio 出图**已经真正接进 mod 过一轮**（3 张）：

**① 换材质类素材 → 一律走「参考图模式」，别重画。**
德州 7 档台面的叠牌坐标是**写死的**（`ApplyMarks()` 里经典绿绒那组：
牌位中心 y 450/1080、格宽 96、缝 20）。新画的桌子刻线对不上 → 牌叠歪。
做法：把已有的 `table_poker.png` 当参考图喂 `/v1/images/edits`
（`image` = `"data:image/png;base64,…"`），模型 `qwen-vl-image-2.1-rmbg`，
提示词只说"换材质配色、**刻线位置形状保持完全不变**"，并**逐条点名要保留的元素**。

## 八、魔搭 TTS（`lf3000y/ai-studio`）—— 音色克隆（2026-10-11 立的）

**症状**：用户听 36 句 AI 旁白，说「**为什么你这些语音风格都不一样。。我要求风格一样**」。

**病根（两层，第一层是我先判错的）**：

1. **`voice=nova` 这类预设不是"固定的嗓子"**，服务端叫 `prompt_preset` ——
   本质是一段**音色描述**。**每换一段文本，嗓音和语气都会重新采样** ⇒ 36 句像 36 个人。
2. **★ 我早先测的"输出是确定的"是假象，那是缓存。**
   `GET /api/audio/status` 里写着：
   ```json
   "cache": {"s3":"ready","local":"available","writes":{"s3":50,"local":0},
             "hits":{"s3":9},"misses":50,"skipped_busy":0,
             "policy":"first_sample_non_clone_non_streaming"}
   ```
   ⇒ **只有非克隆请求命中缓存**。我拿同一段文本连测三次得到 md5 相同、时长零波动，
   拿到的其实是**同一份缓存副本**。**换文本 = 全新生成 = 音色会飘。**

**正解 = 音色克隆**（`voice: "clone"`）。字段名是探出来的，一次试 8 个候选：

| 传的字段 | 服务端回什么 |
|---|---|
| 只给 `voice=clone` | 400 `voice clone requires reference_audio and consent: true` |
| `ref_audio` / `prompt_audio` / `audio` | 400 `unknown request fields: …` |
| **`reference_audio`** | 400 `voice cloning requires consent: true from the authorized speaker` ← **名字对了，只差 consent** |
| **`reference_audio` + `consent: true`** | ✅ `audio/mpeg` |

⇒ 正确 body：
```json
{"model":"voxcpm2","input":"…","response_format":"mp3",
 "voice":"clone","reference_audio":"data:audio/mpeg;base64,…",
 "reference_text":"参考音频对应的文字","consent":true}
```

**效果（判据 = LTAS 长期平均谱两两相关系数 —— 反映"声道形状"即真正的音色）**：

| 版本 | 组内均值 | 组内最差 | 对基准最差 |
|---|---|---|---|
| 预设 `voice=nova` | 0.959 | **0.779** | **0.844** |
| 克隆 `voice=clone` | **0.990** | **0.956** | **0.974** |

- **别用基频当唯一判据** —— 基频会随句子语调天然起伏（陈述句 vs 长句差 20% 很正常）。
  **LTAS 才是音色判据**。脚本：`D:\work\AI产出\B站视频配音\_clone_ab.py` / `_audit.py`。
- **参考音频用"用户点名喜欢的那一句"**（4 秒左右足够），并且**那句本身直接沿用原文件、不重新生成** ——
  零风险保住"他喜欢的那句"。
- 克隆请求**不走缓存**，所以每次都是真生成（同一句两次 md5 会不同，但音色被参考锁住）。

**接口其它真相**（沿用之前记的，仍然有效）：

- 口：`POST https://studio-lf3000y-ai-studio.api-inference.modelscope.net/v1/audio/speech`，
  返回**裸 mp3 字节**（不是 JSON、不是 url）。
- 模型 `voxcpm2`。音色预设表 `GET /v1/audio/voices`（23 个，`kind=prompt_preset`），
  **`voice` 必须传这些 id**；传中文名或 OpenAI 风格名 → 400。
- 有 `speed` 参数（测过 1.05 生效）。
- **★ 拼 mp3 别用 `-c copy`** —— 各文件编码器延迟对不齐，报 `non monotonically increasing dts`，听着会顿。
  必须重编码（`libmp3lame -ar 44100 -ac 1 -q:a 4`）。
- **★ CBR mp3 同长度时字节数会一样** —— 别拿文件大小当"是不是同一段音频"的判据，要用 md5。
