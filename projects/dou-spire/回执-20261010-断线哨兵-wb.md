## 二、根因（三个洞，缺一不可）

### 洞 1：没有断线检测

`DouSpireNet` 全程没有一处去看 `NetService` 还在不在、对端还收不收得到。
`DouSpireNet.Active` 只在**主动收桌**时被清（`CloseTable`），
Steam 那边 `ClosedByPeer` 了它照样是 `true` —— 于是 `_netOn` 一直是 `true`，
牌桌"假活"着。

### 洞 2：失败没有计数，只有一行行刷日志

原 `SendIn`（`DouSpireNet.cs`）：

```csharp
var ok = RitsuLibSidecarHighLevelSend.TrySendAsClient(...);
if (!ok) Entry.Logger.Warn("斗地主：发给主机的消息没送出去（连接或握手还没就绪）。");
return ok;
```

**发一次、刷一行，永不放弃**。调用方拿到 `false` 也不做任何事。

### 洞 3：重试是"无限"的

`DouSpireTable.TickAutoPilotOnline`：

```csharp
if (_netAutoSeat == MeSeat && _netAutoWait < 12.0) return;   // 12 秒补报一次
```

12 秒的节流是有的（所以不是每帧刷屏），但**没有任何次数上限** ——
只要主机的广播不来，它就每 12 秒重报一次，报到天荒地老。

### 附带洞：客机"干等"时一个包都不发

客机的 `_game` 只能靠主机广播推进，所以**等主机出牌**的那段时间它
**一个包都不发**。就算加了失败计数，这段最常见的场景也永远数不到 1。

## 三、怎么修的

### 1) `DouSpireNet` 加"连接健康度"（新）

```csharp
public static int    SendFailStreak        // 连着几次发不出去（成功 / 收到任何消息就清零）
public static double SendFailSince         // 这一串失败从什么时候开始
public const  int    LinkFailLimit      = 3;
public const  double LinkFailSpanSeconds = 8.0;

public static bool LinkLost
    => Active && !IsHost
       && SendFailStreak >= LinkFailLimit
       && NowSeconds() - SendFailSince >= LinkFailSpanSeconds;
```

- `NoteSendOk()` / `NoteSendFail()` / `NoteInbound()` 三个记账口。
- **`NoteSendFail` 只在 `Active == true` 时才算** —— 开桌那一下的 `InOpenReq`
  本来就允许发不出去（RitsuLib 握手可能还没做完，见 `Register()` 的注释），
  拿它当断线会误判。
- `LinkLost` 要求 **次数 + 时长双满足**：玩家在 0.2 秒里手抖连点三下「出牌」
  不会被判成断线（那是冤案）。

### 2) `SendIn` 不再每次刷屏

改成：**只有"这一串的第一次失败"和"判定断线"时说话**，中间静默累计。

```csharp
if (ok) NoteSendOk();
else {
    NoteSendFail();
    if (SendFailStreak <= 1) Entry.Logger.Warn("…没送出去…—— 开始累计失败次数。");
    else if (LinkLost)       Entry.Logger.Warn($"…连着 {SendFailStreak} 次发不出去，持续 {…:0.0} 秒 —— 判定和主机断线。");
}
```

`HandleIn` / `HandleOpen` / `HandleAct` 三个收信口开头都加了 `NoteInbound()` ——
**收到对面任何一条消息 = 线活着**，计数清零。`CloseTable` 里清零。

### 3) 加心跳 `InPing = 15`（补洞 4）

客机每 **10 秒**往主机丢一个空包；主机收到**什么都不做**
（`case InPing: break;` —— 它的价值在"发"不在"收"，
`TrySendAsClient` 返回 `false` 本身就是"送不到"的判据）。

有了它，断线最多 **30 秒**（3 个心跳 × 10 秒）内一定被发现，
而且**"客机干等主机"那段也终于有探针了**。

### 4) `DouSpireTable` 加断线哨兵 `NetLinkGuard`

放在 `_Process` 的**最前面**（`DouSpireMusic.Tick()` 之后、`if (_picking)` 之前）——
放下面的话选人阶段永远轮不到它。

```csharp
private bool NetLinkGuard(double delta)   // true = 这一帧刚收桌，调用方立刻 return
{
    if (!_netOn || _netHost || !DouSpireNet.Active) { _netDeadWait = 0; return false; }

    // ③ 心跳：每 10 秒一个
    // ① 硬信号：!InMultiplayerRun() 连续 2.5 秒 且（失败过 ≥1 次 或 已持续 10 秒）
    // ② 软信号：DouSpireNet.LinkLost
}
```

- **主机不参与**：主机发不出去只意味着某个客机掉线，牌局照常 ——
  而且"远程真人不动"早有两道兜底（`_remoteWait` 超时替他出 / `NetTickAskTimeout`）。
- ① 的"或持续 10 秒"那一半是**防冤案**：换房间 / 重连的一瞬间
  `NetService` 也会假 false，单帧不算、2.5 秒 + 双重佐证才算。

### 5) `NetLinkLost(reason)` —— 收桌 + 告诉玩家

```csharp
_broken = true;
Entry.Logger.Warn($"斗地主：{reason} —— 这局收桌（断线救不回来）。");
DouSpireNet.CloseTable(false);      // ← 必须先清联机状态
Close(Entry.Logger);                // ← 再收桌
Entry.Toast($"{reason}。这局救不回来了 —— 回篝火重新点「斗地主」再开一桌。", "斗地主");
```

**顺序讲究**：先 `CloseTable` 再 `Close`。反过来的话 `Close` 会触发 `_ExitTree`
里那段"客机离桌通知主机"（`SendLeave`），而那一下必然又发不出去 —— 白刷一行。

### 6) `TickAutoPilotOnline` 加第二道保险

```csharp
if (DouSpireNet.LinkLost) { _netAutoSeat = -1; _netAutoWait = 0; return; }
```

正常路径上 `NetLinkGuard` 已经先一步收桌（`_broken` 会让本函数在开头 return），
这是"万一它没来得及"的兜底 —— 代打也绝不无限重报。

## 七、待实测核对（需要重启游戏 + 两台机器）

1. **正常对局不误伤**：打完整一局，日志里**不该**出现 `判定和主机断线`
   / `主机已经离开联机了`；`没送出去` 一次都不该有。
2. **主机主动退房**：主机直接退到主菜单 → 客机应在 **2~3 秒**内收桌，
   toast 是「主机已经离开联机了（他退了 / 掉线了）…」。
3. **拔网线 / 关 WiFi（模拟这次的真实场景）**：客机应在 **~30 秒**内收桌，
   toast 是「和主机的连接断了（连着 3 次发不出去）…」。
4. **日志量**：整个断线过程日志**不该超过 5 行** DouSpire 相关（改之前是 132 行）。
5. **选人阶段断线**：在选人界面时主机退房 → 客机也应自动收桌（不是卡死）。
6. **代打开着断线**：`鸡煲代打` 开着 → 主机退房 → 客机自动收桌，不再刷屏。

> ⚠️ 判定阈值（3 次 / 8 秒 / 10 秒心跳 / 2.5 秒硬信号）都是**保守取值**。
> 如果实测发现"网抖一下就收桌"，把 `LinkFailLimit` 调到 4、
> `LinkFailSpanSeconds` 调到 15 即可（都在 `DouSpireNet` 顶部，一处改完）。
