## 一、结论先说（两件事，两个完全不同的根因）

| 症状 | 根因 | 一句话 |
|---|---|---|
| **切桌子 / 切室内黑屏** | 图层顺序写死了**绝对索引** | 换一次就错位一格，那块**整屏不透明的兜底色**被一路顶到最上面，把背景和桌子全盖掉 |
| **牌匾被拉伸 / 挤压** | Godot 的九宫格**边角不缩放** | 原图 1024×193 塞进 900×58 的框，边角按 1:1 画 → 金边粗得离谱、中间被压成一条缝 |

**两件事都不是"素材不好"，都是代码用错了引擎的机制。** 素材一张都不用重画。

## 二、黑屏：写死的图层索引（截图实锤）

### 症状

截图 `20261011192357_1.jpg` 里：**整片背景是黑的，桌子也没了**，
只剩底池牌匾 / 卡牌 / 立绘 / 按钮浮在黑底上。

### 根因链

`DouSpirePokerTable` 的 `_scene` 是一层层叠出来的，原来的约定是：

```
索引 0 = 兜底纯色 ColorRect（DouSpireUi.Deep，**完全不透明**、铺满整屏）
索引 1 = 背景（bg/poker_*.png）
索引 2 = 桌面
索引 3+ = 座位 / 卡牌 / 按钮 …
```

代码里有 **4 处**直接按绝对索引挪节点：

```csharp
_scene.MoveChild(bp, 0);            // PlacePotAndBoard()：公共牌牌匾垫到最底
_scene.MoveChild(_bgLayer, 1);      // ApplyScene()：背景
_scene.MoveChild(_tableLayer, 2);   // ApplyTable()：桌面
_scene.MoveChild(halo, 0);          // ShowWinnerHalo()：赢家金环
```

问题在于「换牌桌 / 换室内」都是 **先 `RemoveChild` 旧的、再 `AddChild` 新的** ——
新节点永远加在**末尾**，而删掉一个节点之后它后面所有兄弟的索引都会**往前挪一格**。
写死的索引当场指错。

**逐步推演**（连点「换牌桌 → 换室内 → 换牌桌」）：

| 步 | 结果 | 屏幕上看到 |
|---|---|---|
| 开局 | `[兜底, 背景, 桌面, 牌匾, …]` | 正常 |
| 换牌桌 | `[兜底, 牌匾, **新桌面**, 背景, …]` | 背景盖住桌子 → 只剩背景 |
| 换室内 | `[牌匾, **新背景**, 兜底, 桌面, …]` | 兜底盖住背景 → **背景变纯色**，桌子还在 |
| 换牌桌 | `[牌匾, 背景, **新桌面**, 兜底, …]` | 兜底盖住前面三个 → **黑屏，桌子也没了** ✅ 与截图一致 |

### 修法：改成**相对叠放**

新增 `RestackBase()`，按固定顺序依次 `MoveChild` 到 `0、1、2…`：

```csharp
var layers = new Node?[] { _felt, _bgLayer, _tableLayer, _boardPlate, _winnerHalo };
var at = 0;
foreach (var n in layers)
{
    if (n is null || !GodotObject.IsInstanceValid(n)) continue;
    if (n.GetParent() != _scene) continue;
    _scene.MoveChild(n, at);
    at++;
}
```

四处写死的 `MoveChild(x, 0/1/2)` **全部换掉**。这样中间删过谁、加过谁都不影响顺序，
底座永远在下面、UI 永远在上面。

> 顺带修好了一个**一直存在但没人发现**的问题：公共牌牌匾 `board_plate.png` 原来被
> `MoveChild(bp, 0)` 塞到了**兜底色背后** → 在经典绿绒台面上**根本看不见**。
> 现在它落在「桌面之上、所有 UI 之下」，第一次真正显示出来。

### 另外两张桌查过了

`DouSpireTable.cs`（斗地主）也写了 `MoveChild(_bgLayer, 1)` / `MoveChild(_tableLayer, 0)`，
但**结构不同、不会踩这个坑**：斗地主的背景 `_bgLayer` 是挂在**桌子根节点 `this`** 上的
（`_scene` 的兄弟），不是 `_scene` 的第 0 层；`_scene` 里索引 0 就是桌面本身，
删了重加也永远回到 0。所以斗地主不用改。

`DouSpireBlackjackTable.cs` 用的是相对索引（`GetChildCount() - 2`），也不受影响。

## 三、牌匾变形：Godot 的九宫格**边角不缩放**

### 先去翻引擎源码（不是猜的）

`scene/resources/style_box_texture.cpp` 把 `texture_margin_*` 原样交给渲染器：

```cpp
Vector2 start_offset = Vector2(texture_margin[SIDE_LEFT], texture_margin[SIDE_TOP]);
Vector2 end_offset   = Vector2(texture_margin[SIDE_RIGHT], texture_margin[SIDE_BOTTOM]);
RenderingServer::canvas_item_add_nine_patch(..., start_offset, end_offset, ...);
```

而着色器 `servers/rendering/renderer_rd/shaders/canvas.glsl` 的 `map_ninepatch_axis()`：

```glsl
float map_ninepatch_axis(float pixel, float draw_size, float tex_pixel_size,
                         float margin_begin, float margin_end, ...) {
    if (pixel < margin_begin) {
        return pixel * tex_pixel_size;      // ★ 目标像素 : 贴图像素 = 1 : 1
    }
    ...
}
```

**`texture_margin_*` 写 59，那 59 个贴图像素就原样画在 59 个屏幕像素上，跟控件大小无关。**
也就是说：**控件比原图小多少倍，边角就大多少倍。**

### 逐块对账（都是实测数字）

| 素材 | 原图 | 比例 | 控件（设计 px） | 比例 | 后果 |
|---|---|---|---|---|---|
| `poker/handrank_plate.png` | 1024×193 | 5.31 | 900×58 | 15.5 | 左右各保护 204 px，上下各保护 38 px 而框只有 58 高 → **中间被压成一条缝** |
| `poker/pot_plate.png` | 971×256 | 3.79 | 240×63 | 3.81 | 比例是对的，但四个角的金铆钉按 1:1 画 → **铆钉又粗又大** |
| `poker/plate_wood.png` | 1024×198 | 5.17 | 430×180 | 2.39 | 两端卷草纹（各 114 px）按 1:1 画 → **占掉半块牌子，中间木纹竖着拉** |

截图实测（`20261011192357_1.jpg`，2560×1600）：
- 提示板实际画成 **1200×77**（比例 15.6），原图比例 5.31 → 横向要拉 **2.94 倍**
- 底池牌匾画成 **320×84**，红底只占高度的 **26%**（原图里占 **72%**）

### 修法：**自己切三块**（`DouSpireUi.Plate`）

新增 `DouSpireUi.Plate(tex, capL, capR, w, h)`：

- 左右**装饰帽按高度等比缩放**（`s = h / 原图高`）→ 形状和原图**一模一样**
- **中间那段单独横向拉伸** → 木纹/皮革被拉，那才是九宫格的本意
- 用 `AtlasTexture` 取原图的一条竖条（Godot 4 的 `TextureRect` 已经没有 `region` 属性了）

装饰帽宽度是**从原图轮廓的平直段量出来的**（`_work` 脚本扫每一列的上下边界）：

| 素材 | 左帽 | 右帽 | 说明 |
|---|---|---|---|
| `pot_plate.png` | 48 | 48 | 四角是圆角 + 金铆钉，圆角半径 48 |
| `handrank_plate.png` | **104** | 66 | ★ 左端有一枚**圆形徽章**（直径约 100 px），切少了会把徽章劈成两半 |
| `plate_wood.png` | 114 | 114 | 两端各一簇卷草纹 |

**渲染前先在 Python 里照抄同一套算法模拟了一遍**（见 `_scratch/sim_plates.png`），
四块牌匾出来都和原图一致 —— 才动的手。

### 顺手调整

1. **日志板 430 → 560 宽**（锚点 `LogAx` 0.878 → 0.845，不然右边缘顶出屏幕）。
   加宽之后装饰帽占的比例小了，中间才有地方放日志文字。
2. **牌力图标往右挪 39 设计 px**（`-430` → `-391`）：牌匾左端那枚徽章现在能看见了，
   图标原来正好压在上面。文字左边距 `Px(56)` → `Px(90)` 给「徽章 + 图标」一起让位。
3. **删掉了 `PlateBox()`**（原来那套 `StyleBoxTexture` 铺横牌匾的做法）—— 它就是这个 bug 本身。
