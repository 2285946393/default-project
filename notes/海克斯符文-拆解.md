# 《海克斯符文》拆解 —— 一个「百花齐放」的效果 mod 是怎么做的

> 对象：Steam 创意工坊 mod **HextechRunes「海克斯符文」**（作者 **Natsuki**，v0.9.5，工坊 id `3747501308`）。
> 官方简介：「在第 1、2、3 幕开始时选择海克斯符文，获得白银、黄金或棱彩阶的构筑改造；
> 同一幕的敌人也会获得对应稀有度的敌方海克斯。包含专属图鉴分类、敌方海克斯顶部提示、
> 中英文文本与联机同步支持。」
>
> 本文是我 2026-09-22 夜拆包看的笔记。中文名和效果是**从它的 pck 里直接读出来的原文**
> （它的本地化是明文 JSON；注意 pck 里多语言混在一起，抽的时候要按「不含假名」筛才是中文）。
> 最后更新：2026-09-22。

## 一、规模与架构

| 项 | 数字 |
|---|---|
| 符文类（`ilspycmd -l c`） | **1689 个类型**，其中 `HextechRunes` 根命名空间下 **880 个** |
| 中文文本条目 | **502 条标题 / 506 条说明** |
| 主 dll 大小 | 加载器 27 KB + 版本实现 **2.2 MB** × 3 个版本 |
| 三档稀有度 | 白银 / 黄金 / 棱彩（同一套代码，靠 `DynamicVars` 给不同数值） |

**架构：Loader + 版本 bundle 模式**（`HextechRunes` / `PengoTarot` / `IntegratedStrategyEvents`
都用这套）。外面那个 27 KB 的 dll 只负责按游戏版本去 `lib/<版本>/HextechRunes.dll` 加载实现，
所以同一个 mod 能同时适配 0.107.1 / 0.110.0 / 0.111.0。我们 quest-spire 现在是硬绑一个版本。

它的模块划分也值得看：`HextechRuneSelectionCoordinator`（三幕开始的选择流程）、
`HextechRuneSelectionScreen`（选择界面）、`HextechRunePoolBuilder`（按稀有度建池）、
`HextechCombatHooks`（44 个战斗钩子类）、`HextechCombatVfx`（24 个特效）、
`HextechMayhemModifier`（48 个，敌方 hex）、`HextechRuneConfigMenuHooks`（配置菜单）、
`HextechTelemetry`（遥测）、`HextechRewardSafetyHooks`（奖励安全兜底）。

## 二、「百花齐放」是怎么做到的 —— 九种手法

### 1. 一个主题铺成一族，玩家总能找到适合自己流派的那个

- **面包四件套**：面包和黄油（首张**攻击**牌重放 1 次）／面包和奶酪（首张**能力**牌）／
  面包和果酱（首张**技能**牌）／面包三明治（**所有**牌重放 N 次）。
- **锻造器一族**：攻击／格挡／缓冲／人工／敏捷／集中／抽牌／能量／礼花／血肉／灾害／宪法锻造器 ——
  同一种「战斗开始时给你点什么」的骨架，换十几个侧重。
- **升级一族**（下面第 4 条详述）：`XXX_UPGRADE_RUNE` 一口气做了几十个。

> 对我们的启示：任务奖励也可以成族。现在我们的「一代遗物」那批其实就是一族，
> 但都是「发一件遗物」，缺少「同一骨架不同侧重」的变化。

### 2. 负面代价换强度（这一族特别有味道）

| 符文 | 代价 | 收益 |
|---|---|---|
| 回归基本功 | 不能打出 3 费及以上的牌 | 治疗、格挡、伤害 **+40%** |
| 二刀流 | 你造成的伤害 **-40%** | 攻击牌会被**再打出一次** |
| 星界躯体 | 伤害降低 | 最大生命大幅提升 |
| 白纸小支票 | 无色牌打出后消耗 | 无色牌变 0 费 |
| 血铠 / 血债血偿 / 歃血 | 要主动掉血 | 掉血换覆甲 / 换攻击力 / 换力量 |
| 狂暴 | 战斗开始自带易伤 | 每回合额外能量 |

> 对我们的启示：**任务奖励不必都是纯赚**。「给你一个强力但有代价的东西」也是一种很棒的奖励，
> 而且能做出取舍感。我们现在所有奖励都是纯赚。

### 3. 资源转换（把一种资源变成另一种）

- 集中 ↔ 力量 / 敏捷（`DEXTERITY_STRENGTH_TO_FOCUS_RUNE` 等三个）
- 格挡/治疗量 → 伤害（死亡之环：获得格挡或治疗时，对随机敌人造成等量伤害）
- 辉星 → 活力；召唤值 → 格挡；掉的血 → 攻击力
- 抽牌 → 立刻触发所有敌人的中毒（催命符）

### 4. 改写单卡（最「有才」的一块）

`XXX_UPGRADE_RUNE` 一大族，每个只给**一张指定的卡**加一条额外效果：

- 升级：痛击 —— 打出痛击或破击时，获得等同于给予易伤层数的力量
- 升级：战斗专注 —— 打出后本回合仍可继续抽牌
- 升级：放血 —— 打出后把它**返回手牌**
- 升级：全身撞击 —— 打出后额外获得等量于所造成伤害的格挡
- 升级：回响形态 / 恶魔形态 —— 每场战斗开始时，自动打出你所有的这张牌
- 升级：爪 —— 每打出一次，**本局游戏永久** +1 伤害
- 升级：防御 —— 你的防御可以**无限升级**

> 对我们的启示：这是「奖励一张定制卡」的思路。我们的任务奖励现在只有整件遗物/整张牌，
> 没有「给你某张牌加一条专属效果」这一档。

### 5. 数值全部走 `{DynamicVar}` 占位

本地化里写 `[blue]{Block}[/blue]`、`{ChancePercent}%`，代码里给 `DynamicVars`。
好处：**同一个符文，白银/黄金/棱彩三档只改数值**，不用写三份文本和三个类。
（我们的任务目标值是硬编码在 C# 里的 —— 对任务够用，但想「同任务多档难度」就该学这套。）

### 6. 敌方也有 hex（双向对称）

`HextechMayhemModifier` 下 48 个类。例如：

- 升级：旧日雕像 —— 玩家每打出 1 张牌，就获得 3/5/8 层**临时缓慢**
- 升级：多尼斯异鸟 —— 战斗开始时所有敌人获得 0/1/2 层领地意识
- 升级：腐化之心 —— 玩家每打出 1 张牌就受到 1/2/3 点伤害
- 升级：仪式兽 —— 敌人意图含攻击时，额外加一条获得力量的意图

这不只是「敌人更强」，而是**把玩家的那套机制反过来用**，让同一幕的博弈有来有回。

### 7. 处决线（新数值维度）

- 收集者：你造成的伤害会处决生命低于最大生命 X% 的敌人，每次处决给金币
- 飞身踢：处决线是「目标最大生命的 X%」，并回复自身 10% 最大生命

### 8. 把奖励本身变成机制

- 复视：获得卡牌/金币/药水/遗物奖励时，**额外获得一份**
- 色彩发现：战斗开始时从 3 张**其他角色**的随机牌里选 1 张，本场免费；战斗后它还会作为额外卡牌奖励
- 严格挑选 / 验牌：把「战后卡牌奖励」和「回合开始抽牌」这两件事本身改掉

### 9. 玩梗和复刻也做进去了

- **腐化树枝**：给几张带固有的「腐化」，并且每消耗 1 张牌就随机加牌到手牌 ——
  这不就是「枯枝 + 腐化」的经典组合吗，我们做枯枝的时候也是往这个方向想的。
- **偏差认知**：你的所有攻击牌都被视作名称中含有「打击」（配合「打击」相关效果）。
- **小丑学院**／**大号匕首**（把小刀换成君王之剑）之类，名字本身就带梗。

## 三、quest-spire 能借什么（按性价比排序）

| 想借的东西 | 价值 | 工作量 / 风险 |
|---|---|---|
| **① 负面代价型奖励**（「给你个强力但有代价的东西」） | 高：奖励有取舍，比纯发钱/发遗物有意思得多 | 中。代价大多是「不能做某事」，要拦卡牌打出/费用，得先找 `ShouldPlay` 这类钩子，**没验证过** |
| **② 「升级/改写一张牌」型奖励**（任务完成 → 你指定一张牌永久升级） | 高：多一种奖励维度，还能和「打铁」流派联动 | 低-中。要先确认游戏的升级接口（篝火打铁那套怎么调的） |
| **③ 一族化任务**（同一骨架铺成若干侧重，让不同流派都能挑到） | 中：现在 51 个任务里已经有点这个味道，但不够显式 | 低，纯设计 |
| **④ 敌方对称机制**（任务也能「给敌人加点东西」） | 中：很出彩，但会让难度不可控 | 高 |
| **⑤ 数值走多档**（同一任务白银/黄金/棱彩三档目标） | 中：能解决「目标值到底是 150 还是 500」的纠结 —— 让玩家自己挑难度 | 低-中 |
| **⑥ Loader + 版本 bundle**（跨游戏版本兼容） | 低（现在只有一个游戏版本），但游戏更新时会需要 | 中 |

**我的建议**：①②⑤ 挑一个做，别一次全上 ——
这个 mod 有 880 个符文是因为它本来就是个「加内容」的大 mod；
我们的 mod 现在有 **51 个任务一条都还没真人实测过**，再加功能只会更难定位问题。

### 最终做法（用户要求「别照抄，但要学到手法」）

**没抄它的任何一个效果。** 第一版我照着做了「二刀流」（攻击重放一次、伤害 -40%），
被用户指出这 mod 在二代太火、基本人人都玩过，抄效果会露怯 —— 已经删掉重做了。

**真正学到的是它的「本钱」：游戏留了一整套钩子。** 把 `AbstractModel` 全扒了一遍，
一共 **25 个否决钩子（`Should*`，返回 bool 挡住一件事）** 和 **29 个改写钩子（`Modify*`，算出一个新值）**。
知道这套菜单之后，效果就不是「想出来」的，而是「顺着旋钮找」的 —— 这才是它百花齐放的原因。

**于是改成：一个奖励对着一个不同的旋钮，全是自己设计的。**（10 个，见下表）

| 任务 | 条件 | 随身物 | 用的旋钮 |
|---|---|---|---|
| 玩命 | 4 次残血赢下战斗 | **莽夫之道**：伤害 +50%，但再也无法获得格挡 | `ModifyDamageMultiplicative` + `ModifyBlockMultiplicative` |
| 手不释卷 | 本局抽 120 张牌 | 每回合多抽 1 张牌 | `ModifyHandDraw` |
| 砍价高手 | 商店累计花掉 300 金币 | 商店价格 -30% | `ModifyMerchantPrice` |
| 养生 | 篝火休息 4 次 | 篝火回复量 +50% | `ModifyRestSiteHealAmount` |
| 稳如老狗 | 5 场无伤取胜 | 能量上限 +1 | `ModifyMaxEnergy` |
| 厚积薄发 | 打出 15 张能力牌 | 你施加的增益与减益都 +1 层 | `ModifyPowerAmountGivenAdditive` |
| 铁壁 | 本局承受 300 点伤害 | 单次受到的伤害不超过 15 | `ModifyDamageCap` |
| 连环拳 | 打出 40 张攻击牌 | 你的攻击牌多打一段 | `ModifyAttackHitCount` |

**「莽夫之道」是这批里我最满意的**：它不是「给个数」，而是一个**取舍** ——
拿一半的防御换一半的输出，玩家得真的改打法。而且它是「玩命」这个任务的自然延续。

## 三、游戏留的钩子菜单（这才是「怎么做出效果」的答案）

扒自 `MegaCrit.Sts2.Core.Models.AbstractModel`。**做效果先去这张表里找旋钮，别硬写。**

### 否决类：`Should*` → 返回 `bool`，挡住一件事（25 个）

| 钩子 | 能挡什么 |
|---|---|
| `ShouldPlay(card, autoPlayType)` | 不让某张牌被打出（做「不能打 X 费以上的牌」这类代价） |
| `ShouldDraw(player, fromHandDraw)` | 不让抽牌 |
| `ShouldFlush(player)` | **回合结束不弃手牌** |
| `ShouldClearBlock(creature)` | 格挡不清空（外卡钳那类） |
| `ShouldEtherealTrigger(card)` | 虚无牌不自动消耗 |
| `ShouldAddToDeck(card)` | 不让某张牌进卡组 |
| `ShouldProcurePotion(potion, player)` | 不让获得药水 |
| `ShouldGainStars(amount, player)` | 不让获得辉星 |
| `ShouldGenerateTreasure(player)` | 不让生成宝箱 |
| `ShouldAllowMerchantCardRemoval(player)` | 商店删牌 |
| `ShouldRefillMerchantEntry(entry, player)` | 商店补货 |
| `ShouldAllowSelectingMoreCardRewards(player, cardReward)` | 卡牌奖励多选 |
| `ShouldAllowTargeting(target)` / `ShouldAllowHitting(creature)` | 不能选中/打中某个目标 |
| `ShouldDie(creature)` / `ShouldDieLate` / `ShouldPowerBeRemovedOnDeath` | 不让死 / 死时不清 buff |
| `ShouldTakeExtraTurn(player)` | **额外回合** |
| `ShouldStopCombatFromEnding()` | 战斗不结束 |
| `ShouldCreatureBeRemovedFromCombatAfterDeath` | 死了留在场上 |
| `ShouldPlayerResetEnergy(player)` | 回合开始不清能量 |
| `ShouldPayExcessEnergyCostWithStars` | 多余能量用辉星付 |
| `ShouldDisableRemainingRestSiteOptions(player)` | 关掉篝火剩余选项 |
| `ShouldAllowFreeTravel()` / `ShouldProceedToNextMapPoint()` | 地图移动 |
| `ShouldAllowAncient(player, ancient)` / `ShouldForcePotionReward(...)` | 先古之民 / 强制药水奖励 |
| `ShouldAfflict(card, affliction)` | 不让被侵蚀 |

### 改写类：`Modify*` → 算出一个新值（29 个）

| 类别 | 钩子 |
|---|---|
| 伤害 | `ModifyDamageAdditive` / `ModifyDamageMultiplicative` / `ModifyDamageCap` / `ModifyAttackHitCount` |
| 格挡 | `ModifyBlockAdditive` / `ModifyBlockMultiplicative` |
| 能量 | `ModifyMaxEnergy` / `ModifyEnergyGain` |
| 抽牌 | `ModifyHandDraw` / `ModifyHandDrawLate` |
| 出牌 | `ModifyCardPlayCount`（重放）/ `ModifyCardPlayResultLocation`（打完去哪）|
| 资源 | `ModifyGoldGained` / `ModifyMerchantPrice` / `ModifyRestSiteHealAmount` |
| 数值 | `ModifyPowerAmountGivenAdditive` / `ModifyPowerAmountGivenMultiplicative` / `ModifyXValue` / `ModifySummonAmount` |
| 充能球 | `ModifyOrbValue` / `ModifyOrbPassiveTriggerCounts` |
| 受伤 | `ModifyHpLostBeforeOsty*` / `ModifyHpLostAfterOsty*` |
| 奖励 | `ModifyCardRewardUpgradeOdds` |

### 还有一大堆「事件之后」的钩子（`After*` / `Before*`）

`AfterCardDrawn / Discarded / Exhausted / Played / ChangedPiles / GeneratedForCombat / EnteredCombat`、
`AfterDamageGiven / Received`、`AfterBlockGained / Cleared`、`AfterFlush`、`AfterOrbEvoked / Channeled`、
`AfterEnergySpent`、`AfterPotionUsed / Discarded / Procured`、`AfterItemPurchased`、
`AfterRestSiteHeal / Smith`、`AfterRoomEntered`、`AfterCombatVictory / End`、
`AfterGoldGained`、`AfterPlayerTurnStart`、`BeforeCardPlayed`、`BeforeCombatStart`……
（用 `ilspycmd -t MegaCrit.Sts2.Core.Models.AbstractModel` 反编译一份就有全部签名。）

**结论**：做效果的正确顺序是 —— 先想「我要改动游戏的哪一环」→ 去上面两张表找旋钮 →
找不到再考虑 Harmony 补丁。这也解释了为什么那个 mod 能有 880 个符文却不重样。

## 四、实际做进去的（quest-spire，60 个任务）

见上表 8 个旋钮型随身物 + 之前的「熟能生巧」（升级型奖励）。
新验证到的接口还有：
`CardCmd.Upgrade(CardModel, CardPreviewStyle)`、`CardModel.IsUpgradable`、
`AbstractModel.ShouldPlay(CardModel, AutoPlayType)`。
`ModifyDamageCap` 的基类实现返回 `decimal.MaxValue` —— 不用它时要原样返回这个值（别返回 0）。

## 四、顺带记下来的技术细节

- 它的 pck 里**本地化是明文 UTF-8 JSON**，可以直接 `open(pck,'rb').read().decode('utf-8')` 后正则抽
  `"<STEM>.title"` / `"<STEM>.description"`。**但多语言混在一起**，同一 key 会出现 3 次；
  筛「不含平假名/片假名」才能拿到中文。
- 符文 ID 是 `大写下划线` 形式（`ADAMANT_RUNE`、`BLOOD_PACT_RUNE`），
  和遗物的 `[CustomID("DeadBranch")]`（驼峰）不是一套 —— **不同 mod 的 ID 风格不一样，
  运行期按 ID 找别家内容时要用模糊匹配**（我们现在用的 `Contains` 就是这个原因）。
- 它带 pck，所以能加带名字的新内容（符文名字、图鉴分类）；
  我们 quest-spire 是纯 dll，加不了带中文名的新遗物 —— 这是「随身物」方案的根本原因。
