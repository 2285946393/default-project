## ★ fluid-src 嵌套 .git 的坑（2026-09-14 已解决）

- 现象：主仓库 `git add -A` 报 `error: 'fluid-src/' does not have a commit checked out` / `unable to index file 'fluid-src/'`，整个提交被这条中断。
- 原因：`fluid-src/` 里自带一个 `.git`（是它自己 clone/init 出来的**独立子仓库**）。Git 不允许把一个 git 仓库当普通文件加进另一个仓库 → add 直接 fatal。
- 处理（用户拍板：不要独立子仓库）：**删掉 `fluid-src/.git` 让它变成普通代码文件夹**，即可被主仓库统一纳管：
  `Remove-Item -LiteralPath projects\fluid-src\.git -Recurse -Force`（只删版本控制元数据，`index.html`/`script.js` 等代码文件全部保留）。
- 提醒：删 `.git` 会丢弃该子仓库的历史/未推送提交，**确认里面没有只存在于此仓库、没备份的独家提交**再删。日后凡是克隆进来的示例工程（fluid/sand/vibes 这类）都留意有没有夹带 `.git`，要并入主仓就先删子 `.git`。

## ★ Git 推送被墙 → 走本地代理（2026-09-14 实测）

- 症状：`git push`/`ls-remote` 报 `Failed to connect to github.com:443 after 21000ms` 或 `Recv failure: Connection was reset`；但 `api.github.com` 时不时能通（走的是另一套 CDN），会造成"API 显示旧 commit"的假象。国内直连 GitHub 间歇性抽风，不代表代码有问题。
- 本机代理：**自由猫（ziyoumao）**，系统代理 `127.0.0.1:7892`（HTTP）。读端口方法：`Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings"` 看 `ProxyServer`。
- **git 不读系统代理**，必须显式给（临时，不改全局配置）：
  `git -c http.proxy=http://127.0.0.1:7892 -c https.proxy=http://127.0.0.1:7892 push origin main`
  API 校验也加 `-Proxy "http://127.0.0.1:7892"`。加完秒过。
- 大文件历史首次推送很慢（本仓库 pack 223MB，含照片墙历史），会被工具 5 分钟超时误杀 → 用 `Start-Process git push` 脱离终端后台跑，再轮询 `ls-remote` 确认。别按进程名乱杀，命令行含 `push` 再杀。

## ★ Cloudflare Workers 上文章/详情页 500（fs + 无缓存）· 2026-09-14 已修

- 症状：迁移到 Cloudflare Workers 后，首页/说说/照片墙正常，但 `/posts/[slug]`、`/chatter/[slug]` 返回 500；本地 `npm run dev` 和 Vercel 都正常。
- 根因：全站 markdown 用 Node `fs` 在**运行时**读文件。首页等是构建期预渲染成静态 HTML 资源，不吃 fs；而 `[slug]` 动态段页面默认走"dummy"缓存 → Workers 请求时**重新执行组件 → 调 fs → workerd 没有 fs → 500**。
- 关键坑：Next 16.3 默认 **Turbopack**，`next.config.ts` 里的 `webpack` 规则被忽略（构建直接报错提示），所以 `.md` 内联 / `require.context` 那套走不通。
- 正解（零改业务代码/文章/写作控制台）：`open-next.config.ts` 用 **Workers 静态资源当增量缓存**：
  ```ts
  import staticAssetsIncrementalCache from "@opennextjs/cloudflare/overrides/incremental-cache/static-assets-incremental-cache";
  export default defineCloudflareConfig({ incrementalCache: staticAssetsIncrementalCache });
  ```
- 必须配 **populateCache 这一步**，否则预渲染缓存不会进 assets、照样 500：
  `npx opennextjs-cloudflare build && npx opennextjs-cloudflare populateCache local`
  （`populateCache` 要带子命令 `local`；它把 `.open-next/cache` 拷进 `.open-next/assets/cdn-cgi/_next_cache`，随 wrangler deploy 上传，运行时 worker 直接读、不碰 fs）。
- 本地验证：`npx opennextjs-cloudflare preview --port 8799`（wrangler 跑真 workerd），curl `/posts/xxx` 从 500 变 200。`Start-Process cmd /c` 起 preview 会被工具"ChildProcess.kill"清理但进程实际脱管存活，用 `Get-NetTCPConnection -LocalPort` 确认真在监听。

## 七、历史地图册实战（2026-09-11 新增）

- **浏览器缓存会伪装成功能 bug**：本地 http.server 改完页面，无头 Edge"全新 user-data-dir"仍加载旧 HTML（Last-Modified 启发式缓存），报错信息与旧代码一模一样。确诊法：`Invoke-WebRequest` 抓服务器返回比对 → 是服务端新内容就换 URL 加 `?nc=随机数` + `--disk-cache-size=1`，别急着改代码。
- **raw.githubusercontent.com 大文件时好时坏**（同秒 243KB/s 或彻底挂起）；`ourednik.info` 这类原作者官网直连常是快源。curl.exe `--compressed` 对 geojson/文本能省 ~50-80% 流量，卡死的下载用它救。小文件（3KB）能通 ≠ 大文件能通，探测要用真实体积。
- **Python 限时任务三重坑**：`ThreadPoolExecutor` 的 with 退出会 shutdown(wait=True) 拖死预算制；`as_completed` 要传 `timeout=`，否则无人完成时饿死预算检查；被工具超时 SIGKILL 时用 `.part` + `os.replace` 原子写保证断点续传。
- **repo 自带的 d3 是 5.0.0**，`selection.join()` 要 5.5+——用库前先 `typeof`/试跑最小 demo，别信"v5 都有"。
- CDP 无头验证已完全成型（verify_histmap.py 模式）：起 Edge headless → 扫 /json/list → evaluate 断言 DOM/渲染量 → 杀自己起的进程（按 user-data-dir 过滤，绝不碰用户浏览器）。

## 踩的坑

1. **config.py 读写正则不对称**：POST 写入嵌套对象用 `json.dumps`（键带双引号 `"photoWall": true`），GET 解析的键名字符类 `[a-zA-Z0-9_]+` 不含引号 → 写一次后第二次读取全空。修复：GET 正则加可选引号 `"?([a-zA-Z0-9_]+)"?`。教训：**写方和读方的正则要一起改并做写读循环测试**。
2. **用没 import 的变量 prerender 才炸**：`app/about/page.tsx` 原文件从不 import siteConfig，我直接用 `siteConfig.contentVisibility`，build 时 `/about` 页 ReferenceError。dev 下可能晚炸，`npm run build` 的 prerender 是最可靠的第一道验证。

# 踩坑笔记 · 2026-09-13 诗集归档战役

> 89 首 docx 诗搬进小站说说的全过程。这一天加前一晚共翻了 5 轮车，教训全在下面。

## 一、docx → 纯文本提取的铁律

1. **空行是诗的呼吸，绝不是垃圾数据。** 第一版提取把空行全过滤了，所有诗的分段被压成一坨。重写时保留空行（连续空行压成 1 个、去首尾），`whitespace-pre-wrap` 才能还原分节。
2. **行首空格同理**：`l.rstrip()` 而不是 `l.strip()`——诗里有故意缩进的行。
3. **docx 文件名 ≈ 不可信**：90 个文件里文件名与正文题目大面积错位（《奶奶.docx》装着《你来了，五月》）。题目必须从**正文尾部《题目》落款行**取，没有再取开头书号行，都没有才用首句。用户确认过：**题目在结尾**。
4. **docx ≠ docx**：47 号是 OLE2 老格式伪装成 .docx（magic `D0 CF 11 E0`），zipfile 必炸。无 Word 组件可用时跳过，别硬刚。

## 二、用户拍板的编辑规则（诗集专用，别再问）

- 一首诗**只留一个标题**：正文自带题目就删掉尾部重复的《题目》行；落款里的题目尾巴也剥掉（`——2022.1.26有花无实《杂诗》` → `——2022.1.26 有花无实`），只留时间+署名。
- **署名只留末尾一处**；开头"标题《xxx》/作者xxx"模板行删除。
- 真名/笔名全家桶 → 有花无实：`毛烨`、落款`烨`、`一烨`、`142毛烨`、`summer of trees`、`sumner of trees`、`夏树`（注意：38 号诗里"夏树"是树木意象，用上下文白名单保留）、`河希夏树`、`鹤见江`。
- 第三方人名：`胡洁 → 某人`（骂人随笔）；题赠对象（杜荞/旻/心月）保留。
- **学校名也是地址泄漏**：`武陵源一中/武陵一中 → 一中`；电话全打码。
- 参赛登记表（学院/班级/真实姓名/指导老师/征文/院系/作品体裁/作品字数/第十五届/南禮士）整段删除，84 号曾连删 21 行。
- 无写作时间的诗：date 占位 `2022-01-01`，description 标注"写作时间不详"。

## 三、工程坑

1. **同一内容多贴是常态**：《初恋》docx 里同诗贴 3 遍（分行版/合行版/压缩版，用户指定留分行版）；《沙与月》和《水镜》两个文件 100% 相同；《月下散步闲赋记》占两个文件。**上传前必须做：篇内重复检测（题目行×2、长句×2、落款×2）+ 跨文件相似度比对**。
2. **修改 moments md 手工删行时差点把 frontmatter 的 `---` 删掉** → gray-matter 把整篇正文当 YAML 解析、直接抛 YAMLErrException。改完必跑 node 端 matter() 全量解析 + `npm run build`。
3. **`24:03:00` 这种时间会让 `new Date()` 返回 Invalid** → /about 页 prerender 时 `toISOString()` 炸 RangeError。解析时间时 `hh>23 → 23:59:59` 归一。
4. **说说(moments) ≠ 杂谈(chatters)**：chatters 是文章式 md（frontmatter: title/tags/mood），moments 是朋友圈式（frontmatter: id/date/location/images，正文纯文本 whitespace-pre-wrap 渲染）。用户说"发说说"时别往 chatters 塞。
5. moments 的 date 用 `date: "YYYY-MM-DD HH:MM:SS"`（双引号），id 唯一即可；写入前全量验证 `new Date()` 不为 NaN。

## 四、流程教训

- **做事情不要太苛刻，不追求完美：** QQ空间日志逐篇抓正文 → 比对 → 补缺 → 部署，流程太长太复杂，最后因为登录态失效全卡住了。其实诗集已经上传了很多首，不一定要一首不漏，还有很多写下来的东西根本没发在网上。**当务之急是看已有素材的质量和方向，不是追求数量全覆盖。**
- **中途别让用户反复指出同类问题**：换行丢失、题目重复、署名重复、登记表残留——这四类本该在第一版上传前全量自检。以后任何"批量文本搬运"上线前跑一遍固定清单：空行保留？单标题？署名去重？噪声清零？泄漏扫描（真名/笔名/电话/学校/登记表）？frontmatter 可解析？date 合法？
- 用户连发几条同类反馈 = 我在同一类问题上反复出车，此时应该停下来全量排查这一类，而不是修一首是一首。
- AI 看不了图片（用户发图必报错）：封面图可以直接复制文件+引用路径使用，但要明说"没法核对图里内容"。
