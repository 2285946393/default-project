## 一、这一版解决了一个**静默失效的真 bug**

M3.2 的冰垒「替玩家挡伤害」**其实是完全不生效的** —— 不报错、不崩溃，只是什么都不做。

根因（反编译取证）：

```
Creature.Pets      => Player?.PlayerCombatState?.Pets ?? Array.Empty<Creature>()
Creature.IsPet     => PetOwner != null
DieForYouPower.ModifyUnblockedDamageTarget:
    if (target != base.Owner.PetOwner?.Creature) return target;   // ← 这里
```

M3.2 用 `combat.CreateCreature(...) + CreatureCmd.Add(...)` 造的「裸生物」：

- `PetOwner` = null
- 不在 `PlayerCombatState.Pets` 里

→ `PetOwner?.Creature` 恒为 null → 恒 `target != null` 成立 → **永远直接返回原目标，替伤一次都不会触发**。

> 教训：**「造一个我方生物」必须走 `PlayerCmd.AddPet`（或 MinionLib 的 `MinionCmd.AddMinion`）**，
> 不能用 `CreateCreature + CreatureCmd.Add`。前者会挂 `PetOwner` 并进 Pets 列表，后者不会。

## 六、待验证 / 风险

1. **站位能否真的生效** —— MinionLib 的 `NCombatRoom.AddCreature` Patch 依赖 `NCreature` 节点存在；如果用卡打出生物时战斗节点尚未就绪，位置可能不对（需实测）。
2. **我方生物会不会被敌人 AI 优先打** —— 未验证；若敌人仍只打玩家，替伤机制的价值会打折。
3. **`MinionGuardianPower` 的 `BlockToHpPatch`** 会把格挡转成生命上限 —— 若后续给冰垒加格挡，语义会变，需注意。
4. **Pets 列表容量统计**：其它 mod（星见雅）召唤的邦布也是 `Pets` 成员吗？若同队游玩会互相占容量，但那是单人 mod，暂不影响。
5. **`MinionCmd.AddMinion` 是 async 但 `Rearrange()` 未 await**（MinionLib 源码如此）—— 排布动画可能晚一帧。
