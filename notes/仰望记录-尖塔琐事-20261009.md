### 关于「比游戏作者更新的内容都多」这句 —— 说实话是**两半**

**成立的那半（也是更重要的那半）**：
在「**一次更新**」这个尺度上，这句话**完全成立**，而且不是勉强成立。
一次游戏补丁不可能塞进「一个完整的幕 + 31 个遭遇 + 29 个怪物 + 13 个事件 + 46 个能力」。

**不成立的那半**：在「**整个本体**」的尺度上不成立 —— 卡牌 2%、遗物 3%，
那些是本体攒了好几代的东西。

**但「幕」这一档最值得说**：本体一共 4 幕，它加了 1 幕 —— **25%**。
而且**幕不是「加内容」，是「加结构」**。加一张卡，就是一张卡；
加一幕意味着要同时给出：

- 一套**地图生成**（14 个房间、2 组弱遭遇的配额）
- 一整套**背景**（8 种地形变体）
- 一个**篝火**（自己的场景 + 4 张座位图）
- 三张**地图底图** + 一套地图配色
- 一条 **Boss 循环**（6 个精英 + 洞神，还留了兜底）
- 一个**事件池**（拿蜂巢的池、把本体事件剔干净、换自己的）
- 一个**进入方式**（见下）

这是**结构性**的增量。难度和「加 100 张卡」不是一个量级。

## 四、真正让人佩服的，不是体量，是**收尾**

体量大可以靠时间堆。下面这些是「不写也能跑，但写了才专业」的东西 —— 这才是它值得仰望的原因。

### 1. 一个包同时吃两个游戏版本

`STS2_Things.dll` 是个 416 行的壳，里面**内嵌了两份完整实现**（v107.1 的 993 KB、v111 的 1 MB）。
启动时反射探测游戏版本，挑对应那份加载。

**为什么要这么做**：游戏更新会改 API 签名。多数 mod 的解法是「更新日当天炸一片」，
它的解法是**一次发版，两个版本都能进**。玩家不用管自己是不是最新版。

### 2. 同时兼容两个 modding 框架

它自带一个 `STS2_Things.BaseLibBridge.dll` 专门接 **BaseLib** 的设置页，
同时又用反射接 **RitsuLib** 的设置页（`ModSettingsRuntimeReflectionInteropMirror.RegisterProviderTypeAndTryRegister`）。

**两个都找不到？** 照样能跑，只是没有设置页。

而且因为 mod 加载顺序不定，它还补了 `ModManager.State` 的 setter，
**等状态变成 `"Initialized"` 再重试一次注册**。

> 两个互相竞争的框架，它谁也不得罪，还给自己留了「都不用」的退路。这是老手的写法。

### 3. 把「自己的东西」和「本体的东西」严格隔开

这几处是最容易被忽略、但一旦漏了就会出 bug 的地方：

```csharp
// ① 本体「击败所有敌人」成就：遇到 mod 幕直接跳过
//    —— 否则玩家的本体成就会被 mod 内容污染
private static bool Prefix(ActModel act) => !(act is Depths);

// ② 幕生成 / 读档时，把本体事件从 mod 幕的事件池里剔掉
//    —— 否则 mod 幕里会刷出本体的剧情事件，很出戏
DepthsEventPool.RemoveNativeEvents(__instance);
```

**它想到了「我的幕不能污染本体的成就系统」这件事。** 这是很少见的自觉。

### 4. 联机的确定性排序

联机时每个玩家的内容 ID 必须**排得一模一样**，否则两边对不上。它自己写了
`DeterministicContentOrder`，用**游戏自己的 `ContentSorter<ModelId>.Sort`** 排序，
并且所有「追加型」的补丁一律 `[HarmonyPriority(0)]`，保证自己的东西永远排在最后。

### 5. 进「深处」要花钱买路 —— 而且做成了正规的网络动作

不是「自动遇到就进去了」。它做了一套**岔路（Crossroads）**系统：
在地图上花金币买通一条岔路才能进。买路这个动作写成了

```csharp
public sealed class UnlockCrossroadAction : GameAction
{
    public UnlockCrossroadAction(Player, int act, ulong fingerprint,
                                 MapCoord from, MapCoord to, int price);
    public override INetAction ToNetAction();   // ★ 重写了，所以联机也同步
}
```

**它没有用 hack 去改地图，而是走了游戏正规的 GameAction 通道。** 所以联机不出问题。

### 6. 音乐 / 宝箱 / 先古 —— 借，不重打包

新幕的 BGM、环境音、宝箱骨骼、先古事件，**全部转发到蜂巢那一幕**：

```csharp
public override string[] BgMusicOptions => ModelDb.Act<Hive>().BgMusicOptions;
public override string ChestSpineResourcePath => ModelDb.Act<Hive>().ChestSpineResourcePath;
public override IEnumerable<AncientEventModel> AllAncients => ModelDb.Act<Hive>().AllAncients;
```

**包体省下来了，风格也不会跑偏。** 一个 199 MB 的 mod，没有为了「完整性」去塞 500 MB 的音频。

## 五、对我们自己的启发

| 我们手上的事 | 从这个 mod 能学到什么 |
|---|---|
| **斗地主上架** | 我们纠结的「一个包怎么兼容多个游戏版本」—— 它给了现成答案（壳 + 内嵌多实现）。不用现在换，但这条路是通的 |
| **斗地主联机** | 它证明「mod 的东西要能被联机正确排序」，靠的是 `AssociateAssemblyWithMod` + `ContentSorter` |
| **尖塔任务** | 如果哪天想加一整幕，`Depths` 这个类就是最好的模板：继承 `ActModel`、定 `Index`/`IsDefault`、给房间数、借音频、隔离事件池、隔离成就 |
| **通用** | **「收尾」才是分水岭。** 成就隔离、事件池隔离、双框架兼容、失败可降级 —— 这些没人会夸，但玩家不会遇到 bug |

## 七、一句话

它做到的不是「内容多」，是**「内容多、而且没崩」**。

一个 43,000 行、67 处补丁、加了整整一幕的 mod，同时照顾到了：
两个游戏版本、两个 modding 框架、联机确定性、成就隔离、事件池隔离、包体控制、失败降级。

**这些东西全都做好了，玩家是不会察觉的 —— 玩家只会觉得「这 mod 内容真多」。**
这大概就是它值得仰望的地方。
