## 零、★ 方法论修正：代码不一定在 `Assembly-CSharp.dll`

**Stacklands 踩到的坑**：它的 `Assembly-CSharp.dll` 反出来**只有 3 个文件**（几乎空的），
真正的游戏逻辑在 **`GameScripts.dll`**，反出来 542 个文件。

```
Stacklands_Data/Managed/
├── Assembly-CSharp.dll      → 只有 3 个 .cs（空壳）
└── GameScripts.dll          → ★ 542 个 .cs（真身）
```

**以后扫 Unity Mono 游戏时，`Assembly-CSharp.dll` 反出来文件数 < 10 就要警觉** ——
逻辑多半被拆到了自定义命名的 dll 里。快速排查办法：

```bash
ls -S "<game>_Data/Managed/"*.dll | head -10     # 按大小排，找非 UnityEngine/mscorlib 的大 dll
```

（Stacklands 是 Sokpop Collective 的作品，他们习惯用 `GameScripts.dll` 装逻辑。）

## 一、★ 训牌师（真名 **Decktamer**）

**833 个 .cs**，dll 在 `Decktamer_Data/Managed/Assembly-CSharp.dll`。
这是一款"宝可梦 + 卡牌 roguelike"：驯服怪物、编成卡组、3 槽位出战。

### 1.1 完整战斗配置（`BattleConfigScriptableObject.cs`）

**这份配置几乎把整个游戏的数值旋钮都摊开了：**

```csharp
public int numberOfCardsToDraw  = 5;      // 抽牌 5
public int maxCardsInHand       = 5;      // ★ 手牌上限也是 5
public int maxNumberOfSlots     = 3;      // ★ 场上 3 个槽位
public int rewardChoice         = 3;      // 奖励 3 选 1
public int numberOfEncounterChoices = 2;  // 遭遇 2 选 1
public int healAfterRetreat     = 1;      // 撤退回 1 血
public int numberOfRats         = 4;
public int legendaryEncounterInterval = 4; // ★ 每 4 次遭遇出 1 次传说
public int attackMutationDangerLevelDelta = 2;
public int maxMutationsForAbilitiesThatGiveMutations = 15;

// 驯服效率三档（喂对/喂错差距很大）
public float foodDislikeTamingEffectivenessMultiplicator = 0.5f;   // 讨厌的食物 ×0.5
public float foodNeutralTamingEffectivenessMultiplicator = 0.75f;  // 中性     ×0.75
public float mutationTamingEffectivenessMultiplicator    = 0.85f;  // 变异     ×0.85
public float tamingAttemptEffectivenessMultiplication    = 0.15f;  // 每次尝试 ×0.15

// 四种变异，各 10%
public float speedMutationChance     = 0.1f;
public float attackMutationChance    = 0.1f;
public float talentMutationChance    = 0.1f;
public float maxHealthMutationChance = 0.1f;
```

### 1.2 从这份配置能读出什么

**① `maxCardsInHand = numberOfCardsToDraw = 5` —— 手牌不能囤积。**
抽 5 张、上限也是 5 张，意味着你**每回合必须把牌打完**，不存在"攒一手大牌"的打法。
对比 MT2（抽 5、上限 10）就能看出设计取向差别：MT2 允许囤牌做爆发，
Decktamer 逼你每回合做即时决策。

**② `maxNumberOfSlots = 3` —— 宝可梦式的出战槽位。**
场上只能站 3 个，逼玩家做编成取舍。

**③ 驯服效率三档：0.5 / 0.75 / 0.85。**
喂对食物效率 0.85，喂讨厌的只有 0.5 —— **差距接近一倍**，
这让"记住每只怪爱吃什么"变成一个真实的技巧维度，而不是无脑喂。

**④ `legendaryEncounterInterval = 4` —— 每 4 次遭遇固定来一次传说。**
这是**节奏控制器**：不用随机数碰运气，而是保证玩家每隔一段就有一次高光时刻。
这类"保底间隔"比纯概率更能稳定体验曲线。

**⑤ 四种变异各 10%** —— 概率全部相等，不给某一维特权，让变异结果更随机、更耐玩。

## 二、对决（真名 **RuneCollseum**）

**5414 个 .cs** —— 是这批里源码量最大的（MT2 也才 2524）。
dll 在 `对决/RuneCollseum/RuneCollseum_Data/Managed/Assembly-CSharp.dll`。

从目录结构看是**国产卡牌游戏**：

```
Assets.Assets_3.Scripts.FuWenChenLieShi/   ← "符文陈列师"拼音
BattleSystem.BattleProp.道具/              ← 中文目录名
BaseCard.cs / ATKCardTag_240302.cs
```

带了一堆第三方库（BansheeGz.BGDatabase 数据库、COSXML 腾讯云对象存储、

如果要挖，建议从 `BattleSystem.BattleProp.道具/` 和 `BaseCard.cs` 入手。

## 五、三批合起来看：手牌数的设计取向

把扫过的几个卡牌游戏放在一起，光看手牌这一个参数就能看出取向差异：

| 游戏 | 抽牌 / 手牌上限 | 取向 |
|---|---|---|
| **Decktamer** | 5 / **5** | 抽多少用多少，**禁止囤牌**，逼即时决策 |
| **Monster Train 2** | 5 / **10** | 允许囤牌做爆发，配 3 能量做取舍 |
| **Wildfrost** | — / **6** | 无能量系统，靠手牌数本身限制 |

**`抽牌数 == 手牌上限` 是一个很强的设计信号** —— 它直接消灭了"攒资源"这个选项，
把游戏从"规划型"推向"应对型"。想要紧张感就照 Decktamer 这么设，
想要策略深度就照 MT2 留出一倍冗余。
