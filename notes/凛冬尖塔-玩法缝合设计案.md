# 凛冬尖塔（FrostSpire）— 把《凛冬前线》玩法搬进《杀戮尖塔2》设计案

> 立项：2026-10-06。用户需求原话：**「不是新角色，是直接把这个玩法搬进去——把战士等卡牌直接放上去，
> 敌方的怪物也列出来，然后再开始战斗，卡牌还是卡牌。」**
> 对应游戏：《凛冬前线/FrostBound》（Steam appid 3649580，UE 引擎，创意工坊只支持卡面皮肤、无玩法接口，
> 所以缝合方向只能是「搬它的玩法进尖塔2」，不可能反向改它本体）。
> 技术路线：全新 mod 工程 `projects/frost-spire/`，复用 quest-spire 的构建链与经验，不改动 quest-spire 本体。

---

## 一、目标一句话

在杀戮尖塔2 里玩到凛冬前线的核心循环：

**布防（把单位/建筑卡放到场上）→ 敌方波次列表亮出来 → 敌潮一波波进攻 → 撑过全部波次算赢。**

卡牌还是卡牌：玩家照常打尖塔2 的攻击/防御/技能牌；凛冬的部分只多不少地加在「场面」上。

---

## 二、挂载方式（为什么不是新角色）

- 用户明确否掉「新角色」。改成**模式开关**：
  - 主开关在 BaseLib 设置页（复用 quest-spire 的 `QuestSpireConfig` 手艺）：`凛冬模式 开/关`。
  - 打开后，`RunStarted` 时给玩家发一件起始遗物**「凛冬契约」**（模式载体 + 存档桥，走
    `[SavedProperty]` 铁律），本局所有战斗变成敌潮战。
  - 关闭时一切照旧。这样不绑角色、不换地图、对本体零侵入，出问题随时关。
- mod id：`FrostSpire`；中文名：**凛冬尖塔**；依赖 RitsuLib + BaseLib（同 quest-spire）。

## 三、玩法映射表（凛冬前线 → 尖塔2 实现）

| 凛冬前线概念 | 尖塔2 里的实现 | 依据（全部来自 quest-spire 已验证 API） |
|---|---|---|
| 布防阶段 | 战斗开始时额外发一手「工事牌」（建筑/单位），首回合 +N 能量供免费布置 | `ModifyMaxEnergy` / 首回合能量钩子已验证；发牌用 `CardFactory.GetDistinctForCombat` 正规路 |
| 建筑卡（箭塔/冰墙/篝火/工坊…） | 打出后变成**持久能力**（挂在玩家身上的 Power），每回合自动触发：箭塔射击、篝火回血、工坊多抽一张 | 能力模型 268 个已摸清；`ValueProp.Unpowered` 无来源伤害路径已验证 |
| 单位卡（民兵/猎手/冰法师…） | 打出后变成**召唤物**（我方生物，每回合自动攻击敌人） | Necrobinder 的 Osty 召唤物先例 + `AfterSummon` 钩子已验证 |
| 敌潮 | 战斗中按波次表 `CreatureCmd.Add<T>(combatState)` 刷怪（**已验证**，quest-spire「怪潮/盛碗虫」在用） | 放在 `BeforeSideTurnStart`（有 combatState） |
| 波次预告 | 常驻面板显示「第 X/共 Y 波：怪A×2、怪B×1」（复用 QuestPanel 的 UI 手艺：拖动/折叠/借字体） | UI 全套手艺现成 |
| 撑过全部波次=胜利 | 最后一波清完 → 走本体 `AfterCombatVictory` 正常结算（金币/卡牌奖励照旧） | 胜利结算不动，风险最小 |
| 卡牌还是卡牌 | 玩家卡组不变，工事牌混在卡组里照常抽打出；攻防技能手感与本体一致 | — |

## 四、v1 内容清单（第一版可玩切片）

- **工事牌 8 张**（自绘/占位图 + pck 本地化，三张图铁律：小图/轮廓/大图）：
  - 建筑 4：箭塔（每回合射 5）、冰墙（每回合 +6 格挡）、篝火（每回合回 3）、了望台（每回合多抽 1）
  - 单位 4：民兵（自动普攻 6）、猎手（自动打最脆）、冰法师（自动减速/减益）、重装兵（嘲讽+高血量）
- **波次系统**：三幕战斗全部改成 3/4/5 波（对照交接文档 §12.3 本体真实数值平衡）；
  波次表确定性生成（用 ActFloor 当种子，联机各端一致，学 quest-spire 的做法）。
- **波次预告面板**：右上角可拖动/折叠，显示当前波 + 下一波阵容。
- **设置页**：凛冬模式开关、难度（休闲0.6/正常1/硬核1.5，学 quest-spire）。
- 联机：v1 先按单机做；联机闸门学 quest-spire（不安全的效果不开），标注「联机未适配」。

## 七、风险与对策

1. **召唤物复用**：Osty 的 AI/属性是否可编程复用未验证 → M3 第一个验证项，先反编译 `Osty`/`SummonCmd`。
2. **波次胜负判定**：加怪是否影响本体「清场=胜利」逻辑 → M1 就用真战斗验（最后一波清完必须正常弹胜利）。
3. **性能/联机同步**：每回合加怪走确定性种子；联机 v1 直接不支持（开关里注明）。
4. **存档**：模式状态全走 `[SavedProperty]`（quest-spire 踩过的坑不重踩）。
5. **上传纪律**：改完不自动传工坊，等用户发话（2026-09-23 铁律）。

## 八、技术底账

- 一律「先反编译验证再写」：`ilspycmd -t <类型> "<游戏>\data_sts2_windows_x86_64\sts2.dll" -o %TEMP%\sts2dec`。
- 已验证可用、直接抄的：`CreatureCmd.Add`、`AfterSummon`、`BeforeSideTurnStart`、`ModifyMaxEnergy`、
  `[SavedProperty]`、BaseLib 配置页、Toast、面板 UI、`CardFactory.GetDistinctForCombat`。
- 待验证清单（M1/M3 逐个核）：召唤物生成命令、召唤物自定义属性/AI、我方生物每回合行动钩子、
  战斗胜利判定对「回合中加怪」的兼容。
- 工程底子：复刻 `projects/quest-spire/` 的 `Directory.Build.props/local.props` + csproj CopyMod 链，
  mod 目录 `projects/frost-spire/`，产物部署到 `mods\FrostSpire\`。
