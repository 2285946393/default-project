### 2.2 `RemoveDisabledMods()`（`:481-543`）—— 双来源去重

游戏**自己就处理**「同一个 mod id 同时来自创意工坊和本地 `mods/`」这件事。
源码文档注释原话：

> *"If the user has subscribed to a mod via Steam workshop and also has it in their local directory:
> - Prefer the newer mod if it is the same version
> - Otherwise, load the mod that has a greater version.
> **This is to help mod developers in development.**"*

规则（本地版进字典 → 逐个工坊版比对）：

| 情况 | 结果 |
|---|---|
| `settings.IsModDisabled(id, source)` 为真 | 该条 `state = Disabled`（**无条件优先**） |
| 版本号任一解析不出来 | **禁工坊版**（Warn） |
| 两边版本相同 | **禁工坊版**（Warn） |
| 工坊版 > 本地版 | **禁本地版** |
| 本地版 > 工坊版 | **禁工坊版** |

被禁的那个 `state = ModLoadState.DisabledDuplicate`，并 `errors.Clear()`。

**`ModLoadState` 全枚举**（`MegaCrit.Sts2.Core.Modding/ModLoadState.cs`）：

| 值 | 名 | 含义 |
|---|---|---|
| 0 | `None` | 还没尝试 |
| 1 | `Loaded` | 加载成功 |
| 2 | `Failed` | 尝试了但失败 |
| 3 | `Disabled` | 用户没开 mod 加载 / 这条被标为禁用 |
| 4 | `DisabledDuplicate` | **同时有 Steam 版和本地版，这条被去重掉** |
| 5 | `AddedAtRuntime` | 加得太晚，没加载 |

### 2.3 `SortModList()`（`:345-469`）—— 手动顺序**只是平局决胜**

用 **Kahn 算法**做拓扑排序：

- **入度** = `manifest.dependencies` 里能在本次列表中找到的依赖条数（按 `dependency.id == m.manifest.id` 匹配）。
- **就绪队列**是 `PriorityQueue<Mod,int>`，**优先级 = 该 mod 在 `settings.save` 的 `mod_list` 里的下标**；
  不在列表里的给 `999999999`（**排最后**）。
- 已禁用/失败/重复的 mod（`state != 0`）先被挑出去，**最后统一追加到队尾**。
- **环检测**：Kahn 跑完后仍不可达的 mod 记进 `_circularDependencies[id] = "涉及的所有 id"`，然后追加到队尾。
- **变更检测**：把排好的顺序和手动顺序**按 id 逐个比**，不一样就打印
  `"Mods have been re-sorted because we detected a change or dependency order was broken."`
  并把完整新顺序逐行打进日志。
- 最后 `_mods = 排好的顺序` —— **这个内存顺序就是真实加载顺序**。

> ★ **排查加载顺序的日志信号**：在 `%APPDATA%\SlayTheSpire2\logs\` 里搜
> `Mods have been re-sorted` 和 `--- RUNNING MODDED! ---`，
> 后面紧跟的就是当次**真实生效顺序**，不用猜。

### 2.4 ★★ `:289-298` 回写 —— 以及藏在里面的 bug

```csharp
List<SettingsSaveMod> list = new List<SettingsSaveMod>();
foreach (Mod mod in _mods) {
    SettingsSaveMod settingsSaveMod = new SettingsSaveMod(mod);
    bool isEnabled = _settings.ModList
        .FirstOrDefault((SettingsSaveMod m) => m.Id == mod.manifest?.id)   // ★★ 只比 Id！
        ?.IsEnabled ?? true;
    settingsSaveMod.IsEnabled = isEnabled;
    list.Add(settingsSaveMod);
}
flag = _settings.ModList.Count == 0;      // 「第一次玩 mod」
_settings.ModList = list;                  // ★ 覆盖
```

**两个后果：**

1. **`settings.save` 的 `mod_list` 每次启动都会被重写成「实际生效顺序」** ——
   所以「手动排序」只在**当次排序时**起作用，存不住。
   有依赖的 mod 一定被拉前面；**唯一能跨启动存住的是 `IsEnabled`**。
2. **★★ 第 293 行的匹配键只有 `m.Id`，没有 `m.Source`** ——
   当同一个 id 存在两条（本地 + 工坊），`FirstOrDefault` 会对**两个 Mod 实例返回同一条**，
   于是**两条拿到同一个 `IsEnabled`**。用户「按来源分别开关」的意图被静默抹平。
   → 这正是 §4 那个补丁要绕的 bug。

（顺带：`SortModList` 里的 `dictionary2` 也是**只按 `Id` 建键**，同样在双来源时冲突。）

### 2.5 修正后的规则（替换旧笔记里的模糊说法）

- **停用 mod 用游戏设置里的开关**，不要挪 `mods/` 目录（`ReadModsInDirRecursive` 是**递归**的，
  在 `mods/` 下建 `_disabled/` **等于没关**；而且会被重新部署复活）。
- **唯一键是 `(Id, Source)`，不是 `Id`**。
- **手动加载顺序 = 拓扑排序的平局决胜**，游戏启动后会覆盖回写；
  **只有 `IsEnabled` 是可靠的持久状态**。
- **游戏自带 API**：`ModSettings.IsModDisabled(string id, ModSource source)`
  → `ModList.Any(m => m.Id == id && m.Source == source && !m.IsEnabled)`。**别再自己遍历判断。**
- `ModManagerState { None=0, Initialized=1, Skipped=2 }`；`ModManager.State == Initialized`
  是「所有 mod 都处理完了」的锚点（本 mod 就靠它做延迟恢复）。

## §3 ★★★ `affects_gameplay` 的官方口径

`ModPresetService.FindMultiplayerDependencyClosure()`（`ModPresetService.cs:408-435`）——
「联机必要」的定义**完全照抄了游戏的设计意图**：

```csharp
HashSet<string> hashSet = (from entry in enabled
    where entry.AffectsGameplay          // ① 起点 = 所有 affects_gameplay:true 的 mod
    select entry.Id).ToHashSet(StringComparer.Ordinal);
if (dictionary.ContainsKey("ModPresetManager")) hashSet.Add("ModPresetManager");  // 工具自己

Queue<string> queue = new Queue<string>(hashSet);   // ② BFS 沿 manifest.dependencies 扩散
while (queue.Count > 0) {
    string key = queue.Dequeue();
    if (!dictionary.TryGetValue(key, out var value)) continue;
    foreach (ModDependency item in value.Mod.manifest?.dependencies ?? new List<ModDependency>())
        if (!string.IsNullOrWhiteSpace(item.id) && dictionary.ContainsKey(item.id) && hashSet.Add(item.id))
            queue.Enqueue(item.id);
}
```

→ **联机必要 = `affects_gameplay:true` 的 mod ＋ 它们的传递依赖闭包。**
导出「仅联机必要」时**只导这一份**；UI 文案也写死了：
「仅导出联机必要模组及其依赖。始终包含模组预设本身。」

这与我们之前从 `ContentSorter` 挖出来的结论**互相印证**：
`affects_gameplay` 是联机 id 稳定性的开关，**必须诚实标注** ——
标成 `false` 但实际改了玩法，别人不装就跟你对不上；标成 `true` 但只是 UI 美化，会白拉一堆人装。

> ★ **对我们的直接用途**：以后写「联机推荐配置」或做「开房前自检」，

## §4 ★★★ `DuplicateSourceSettingsGuard` —— 一个真实游戏 bug 的绕法

文件：`Scripts/Patches/DuplicateSourceSettingsGuard.cs`（133 行）。

**症状**（从代码倒推）：mod 开发者常用「本地 `mods/` 放开发版 + 创意工坊放正式版」的用法，
用户也可能手动关掉其中一个。但 §2.4 的第 293 行只按 `Id` 匹配，
所以启动后 `settings.save` 里**两条同 id 记录的 `IsEnabled` 会被写成同一个值** ——
用户「只关工坊版」的选择丢失。

**绕法**（时序很讲究）：

```csharp
public static void CaptureAndScheduleRestore()   // 在 Entry.Init() 里、PatchAll 之后立刻调
{
    var duplicateIds = ModManager.Mods
        .Where(m => !string.IsNullOrWhiteSpace(m.manifest?.id))
        .GroupBy(m => m.manifest.id, StringComparer.Ordinal)
        .Where(g => g.Select(m => m.modSource).Distinct().Count() > 1)   // ★ 同一 id 出现在多个来源
        .Select(g => g.Key).ToHashSet(StringComparer.Ordinal);
    if (duplicateIds.Count == 0) return;

    // ① 趁 settings 还没被覆盖，把「按 (id, source) 的开关状态」抄下来
    _enabledBySource = ModManager.Mods
        .Where(m => m.manifest?.id != null && duplicateIds.Contains(m.manifest.id))
        .Select(m => new ModSourceKey(m.manifest.id, m.modSource)).Distinct()
        .ToDictionary(k => k, k => !modSettings.IsModDisabled(k.Id, k.Source));

    _remainingAttempts = 120;                        // ② 最多等 120 帧
    Callable.From(RestoreAfterInitialization).CallDeferred();   // ③ 下一帧再跑，别在 Init 里做
}

private static void RestoreAfterInitialization()
{
    if (ModManager.State != ModManagerState.Initialized) {      // ④ 等初始化完成
        if (--_remainingAttempts > 0) Callable.From(RestoreAfterInitialization).CallDeferred();
        else Log.Warn("... did not finish.", 2);
        return;
    }
    foreach (SettingsSaveMod item in SaveManager.Instance.SettingsSave.ModSettings.ModList) {
        var key = new ModSourceKey(item.Id, item.Source);
        if (_enabledBySource.TryGetValue(key, out var value) && item.IsEnabled != value) {
            item.IsEnabled = value;                              // ⑤ 把被吞掉的开关写回去
            num++;
        }
    }
    if (num > 0) Log.Info($"... restored source-specific enabled states for {num} duplicate mod entries ...");
    Clear();
}
```

**要点：**

- **时机**：`Entry.Init()` 里（mod 初始化阶段）**先抄快照**，`CallDeferred` 到 `ModManager.State == Initialized` **之后**再恢复。
  太早抄不到，太晚已经被覆盖。
- **上限**：`MaxDeferredAttempts = 120`，超了就 Warn + `Clear()` —— **不会无限挂**。
- **只动受影响的条目**：`TryGetValue` 命中才改，不碰别的。
- 用 **`ModSettings.IsModDisabled(id, source)`** 这个官方 API 读，而不是自己遍历。

> ★ **对我们的直接用途**：DouSpire 将来如果要给玩家一个「本地开发版 / 工坊版」切换，
> **必须知道这个坑**；或者干脆照抄这套「抄快照 → 等 Initialized → 写回」。

## §5 ★★ 写 `settings.save` 的完整配方（含失败回滚）

`ModPresetService` 把「改 mod 配置」拆成了**五段**，每段职责单一 —— 这是可以直接照抄的结构：

| 阶段 | 方法 | 产出 |
|---|---|---|
| ① 读现状 | `CaptureLoaded()` / `CaptureSaved()` | 两份 `CurrentModEntry` 列表 |
| ② 比对 | `CompareLoadedAndSaved()` | `{ Loaded, Saved, Matches }`，`Matches` 用 `SequenceEqual` 严格比 `(Id, Source, Version)` |
| ③ 导出 | `Export(scope)` | JSON 文本（先做三种拒绝：`UnavailableModId` / `DuplicateModId` / `InvalidModId`） |
| ④ 解析+分析 | `TryParse` → `Analyze` | `ModPresetDocument` → 逐条 `PresetImportItem`（含匹配状态） |
| ⑤ 应用 | `CreateApplyPlan` → `Apply` | 算好 `FinalOrder`，**写盘失败则回滚** |

**应用与回滚**（`Apply()`）：

```csharp
var plan = CreateApplyPlan(analysis, importMode);
try {
    plan.ModSettings.ModList = plan.FinalOrder;
    settingsSave.ModSettings  = plan.ModSettings;
    SaveManager.Instance.SaveSettings();
} catch (Exception value) {
    plan.ModSettings.ModList = plan.PreviousOrder;         // ★ 回滚内存状态
    settingsSave.ModSettings = plan.PreviousModSettings;
    Log.Error($"Failed to apply imported mod preset: {value}", 2);
    return new PresetApplyResult { Error = "save_failed" };
}
```

**预设文件格式**（`ModPresetDocument`，`format` 兼容旧名 `mdv-preset`）：

```json
{
  "format": "mpm-preset",
  "schema": 1,
  "game": "0.111.0",
  "mods": [
    { "id": "DouSpire", "version": "1.2.0", "source": "local",
      "workshopId": null, "affectsGameplay": true }
  ]
}
```

**健壮性设计（都值得抄）：**

- `MaxPresetMods = 2048` —— 导入时**硬上限**，防超大文本。
- 逐字段校验：`id`/`version` 非空、`source` 只能是 `local`/`workshop`、
  **不允许重复 id**（`DuplicateMod`）。
- `PresetParseError` 是**原因码枚举**（`Empty`/`InvalidJson`/`UnsupportedFormat`/`UnsupportedSchema`/`InvalidEntry`/`DuplicateMod`），
  不是 bool —— 跟弹幕尖塔的做法一致。
- **导入永远先预览**（`Analyze` → UI 表格），用户点「应用」才写盘。
- `PresetImportStatus` 六态：`Exact` / `LocalFallback` / `DownloadRequired` / `Missing` / `VersionMismatch` / `Ambiguous`。
  **`Ambiguous`（同 id 同版本多个候选）也算「未解决」，不许应用** —— 不确定就明说。

**工坊 id 解析**（0.107.1 的写法，0.111.0 已弃用）：

```csharp

int i = path.Replace('\\','/').IndexOf("/workshop/content/2868840/", StringComparison.OrdinalIgnoreCase);
//                                    ↑ STS2 的 appid = 2868840

## §6 ★ Steamworks 集成（批量订阅 + 下载）

文件：`Scripts/Presets/WorkshopSubscriptionBatch.cs`（226 行）。
**这是第一份我们手上「mod 主动操作创意工坊」的完整样本**。

用到的 Steamworks API：

| API | 用途 |
|---|---|
| `SteamAPI.IsSteamRunning()` | 可用性探测（**外面包 try/catch，异常即 false**） |
| `SteamUGC.GetItemState(id)` | 查状态位 |
| `SteamUGC.SubscribeItem(id)` | 订阅 |
| `SteamUGC.DownloadItem(id, true)` | 强制下载 |
| `SteamUGC.GetItemDownloadInfo(id, ref dl, ref total)` | 进度 |
| `Callback<ItemInstalled_t>.Create(...)` | 安装完成回调 |
| `Callback<DownloadItemResult_t>.Create(...)` | 下载结果回调 |

**状态位**（`GetItemState` 的位）：

| 位 | 含义 |
|---|---|
| `4` | Installed |
| `8` | NeedsUpdate |
| `0x10` | Downloading |
| `0x20` | DownloadPending |

判定「装好了」= `(state & 4) != 0 && (state & 8) == 0`（**装好且不需要更新**）。

**工程细节（值得抄）：**

- **超时 300000 ms（5 分钟）** → `TimedOut`。
- **5 秒还没开始下就 `DownloadItem` 踢一脚**（`DownloadKicked` 标记，只踢一次）。
- 回调里先校验 `installed.m_unAppID.m_AppId == 2868840`，**避免被别的游戏的事件污染**。
- `DownloadItemResult_t.m_eResult == 1`（`k_EResultOK`）→ `WaitingForInstall`，否则 `Failed`。
- 全程 `try/catch`，任何异常 → 该 job `Failed`，**不影响其它 job**。
- `Active` 单例 + 构造时**已有活跃批次就抛异常**（防止两批下载打架）。
- `IDisposable` 释放回调；`Environment.TickCount64` 做计时（不用 DateTime）。
- 状态机 `WorkshopDownloadState`：`Pending / Downloading / WaitingForInstall / Installed / Failed / TimedOut`，
  `IsTerminal` = 后三态。

> ★ **对我们的直接用途**：想做「一键装齐斗地主尖塔推荐模组」的话，
> 这套订阅 + 下载 + 进度 + 超时就是现成模板。
> 注意 `Steamworks` 程序集是游戏本体带的，**引用时按 0.107 的版本编译**即可。

private const string Table  = "main_menu_ui";
private const string Prefix = "MOD_PRESET_MANAGER.";

public static string Text(string key, params (string Name, string Value)[] variables) {
    LocString val = new LocString("main_menu_ui", "MOD_PRESET_MANAGER." + key);
    for (int i = 0; i < variables.Length; i++) val.Add(variables[i].Name, variables[i].Value);
    return val.GetFormattedText();
}
```

**关键结论：**

- **约定路径** `res://<ModName>/localization/<lang>/<表名>.json`，语言码 `eng` / `zhs`。
- **表名就是游戏原有的表名**（这里蹭了 `main_menu_ui`），所以 mod 的文案和原版文案**共用一套查找**，
  只是键带了自己的前缀。
- 文本里可以写 **`{占位符}`**，运行时用 `LocString.Add(name, value)` 填 —— 和梗化尖塔处理的占位符是同一套机制。
- ★ **对 MemeSpire 的意义**：如果以后要给 mod **自己新增的** UI 加中英文案，
  这就是标准做法，**不用去改本体本地化文件**。

## §8 ★★★ 逐版本适配成本实证：0.107.1 → 0.111.0 **只差 3 处**

`runtimes/0.107.1/` 和 `runtimes/0.111.0/` 两个 Runtime，**6,569 行里只有 4 个文件不同，
真正的逻辑差异只有 3 处**：

| # | 文件 | 0.107.1 | 0.111.0 | 性质 |
|---|---|---|---|---|
| 1 | `ModPresetService.cs` | `return ParseWorkshopIdFromPath(mod.path);` | `return mod.workshopId ?? ParseWorkshopIdFromPath(mod.path);` | **游戏新增 `Mod.workshopId` 属性**（旧版只能解析路径） |
| 2 | `ModPresetModal.cs` | `((NClickableControl)node).ForceClick();` | `node.ForceToggleTick();` | **`NTickbox.ForceToggleTick()` 是新方法**，旧的 `ForceClick` 走不通了 |
| 3 | `Entry.cs` | 无 | 新增 `WarnWhenUsingNewerVersionFallback()` | 不是 API 变更，是给「0.112+ 用 0.111 Runtime」加一句警告 |

其余两个文件的差异全是 `AssemblyInfo.cs` 的版本号 + 反编译器生成的 `//IL_xxxx` 注释。

> ★ **结论（对我们很有用）**：跨 4 个小版本，一个 3,000 行的 mod 的实际适配成本 = **2 处 API + 1 处警告**。
> 这实证了 RandomForeseer 那套方法论的说法 ——
> **数值 / 文案 / 稀有度之类的变化会自动继承，只有「真的被删掉/改了签名的方法」才要动手。**
> 也说明**「一个 compat 包装 + 逐版本实现目录」的投入是划算的**：
> 平时零维护，版本一变只改那一两行。

## §11 一句话总结

**这个 mod 本体是个「配置搬运工」，但它是一份免费的、极其精确的「游戏 mod 系统说明书」** ——

**「游戏更新到底要花多少适配成本」——答案是：比想象中少得多。**
