# AI 协作人格 · 玩法与实现说明

> 对应页面：`pages/AI协作人格.html`
> 2026-10-13 做。题材由用户拍板（在「游戏 / 求职状态 / 摸鱼」三个候选里选了 **AI 协作人格**）。
> **2026-10-13 第二版**：用户反馈「答题会不会太多了 / UI 太少了」，于是加了**双入口**并整体翻新视觉。

---

## 一、这东西是什么

情境题，测**你跟 AI 搭伙干活时是哪种人**。**两个入口**：

| 入口 | 题量 | 耗时 |
|---|---|---|
| ⚡ **快速版** | **15 题**（每维度 1 题） | 约 2 分钟 |
| 🔍 **完整版** | **30 题**（每维度 2 题） | 约 4 分钟 |

- 打开就能测，**不用注册、不联网、不收集任何数据**
- 结果 = **12 种人格**里的一种 + **15 个维度的剖面图**
- 答完可以复制结果链接（结果编在网址里，别人打开能看到同一份结果）

> ⚠️ **快速版为什么是 15 题而不是 12 题**：结果靠 15 维向量匹配，**少一个维度结果就会歪**。
> 实测只答 12 维（缺 3 维）时，「唠嗑搭子」一个人吃掉 **43.8%**，
> 「处处存疑 / 反复打磨 / 记笔记的人」几乎测不出来（0.x%）。
> 改成每维各 1 题后，分布与完整版几乎一致（最热 19.0% vs 19.8%）。
> **所以快速版砍的是"重复题"，不是"维度"。**

**题材为什么选它**：用户排除了游戏题材，理由是「真的已经出过很多这种了，有些人也不玩游戏」。
AI 协作人格的受众是**凡是碰过 AI 的人**——学生、上班族、老师、家里长辈都能测，而且**只有真在用 AI 干活的人做得出来**，别人是装的。

## 三、15 个维度（5 组 × 3 维）

| 组 | 维度 | 含义 |
|---|---|---|
| **A 怎么把活交出去** | 放权程度 | 丢个方向就走，还是盯着 |
| | 指令密度 | 说一句话，还是列一份需求 |
| | 中途干预 | 跑一半会不会插手 |
| **B 怎么验收** | 动手验真 | 会不会真的打开跑一遍 |
| | 留存习惯 | 好用的东西存不存、转不转 |
| | 挑刺习惯 | 找不找它的逻辑漏洞 |
| **C 怎么跟它相处** | 客套程度 | 说谢谢吗、骂它吗 |
| | 拟人倾向 | 当它是人还是工具 |
| | 依赖程度 | 没它能不能干活 |
| **D 怎么推进节奏** | 并行程度 | 同时开几个 |
| | 迭代方式 | 一轮改一点还是一把梭 |
| | 收尾习惯 | 做完还回头收拾吗 |
| **E 怎么看它** | 信任程度 | 说啥信啥还是处处存疑 |
| | 归功习惯 | 做成了算谁的 |
| | 边界感 | 哪些事必须自己来 |

**每维度 2 题**，得分求和后归一化 → 判定 **L（偏低）/ M（中等）/ H（偏高）**。

## 四、12 种人格

| 代号 | 名字 | 一句话 |
|---|---|---|
| `DIRECTOR` | 甩手掌柜 | 说个方向就走，回来直接验收 |
| `ENGINEER` | 甲方提需求 | 需求写得比文档还细 |
| `BUDDY` | 唠嗑搭子 | 边干活边聊，还会跟它吐槽 |
| `SKEPTIC` | 处处存疑 | 它说的每句都要自己再验一遍 |
| `SWITCHER` | 同时开五个 | 多线并行，谁快用谁 |
| `POLISHER` | 反复打磨 | 一轮改一点，改到满意为止 |
| `COLLECTOR` | 记笔记的人 | 它说的好用的，一条都不放过 |
| `SPRINTER` | 一把梭 | 要的就是快，先跑起来再说 |
| `CRAFTSMAN` | 自己来 | 有些活宁可自己动手 |
| `NAVIGATOR` | 掌舵的 | 方向必须我说了算 |
| `EXPLORER` | 试水的人 | 一边用一边摸它到底能干嘛 |
| `PARTNER` | 搭伙的人 | 它出力，你出判断，谁也不欠谁 |

> **素材来源**：全部提炼自用户自己的真实协作笔记（`notes/AI协作-项目总结与技术沉淀.md`），
> 不是凭空编的。比如「我是多ai协用」→ 同时开五个；「不要自己造轮子」→ 先找现成的；
> 「可以可以」「一般吧」→ 一把梭 / 反复打磨；写满踩坑记录 → 记笔记的人。

## 五、匹配算法

1. 每维度 2 题得分求和 → 归一化到 0~1 → 判 L / M / H
2. 15 维向量与 12 种人格模式做**加权曼哈顿距离**
   - **A 组（怎么交活）和 C 组（怎么相处）权重 ×1.25** —— 这两组区分度最高
   - 反向错过（用户 H、类型 L）**额外罚 0.35**，让"像"更值钱
3. 最近的为结果，相似度 = `(1 - 加权距离/34) × 100%`，钳制在 **35~96%**

**为什么这么设计**（踩过的坑）：
- 一开始用等权距离，出现 **38% 的并列第一**，结果不稳定
- 又发现纯中间态的人格（15 个 M）会**白捡**答案，四分之一的人都测出「试水的人」
- 改法：**加权 + 反向罚分 + 把中间型人格重塑出棱角**
- 修完：并列降到 **3.7%**，12 种类型分布均匀（最热门 19%、最冷门 1.8%）

### ⚠️ v3 为什么被推翻（值得记住的教训）

v3 用 `ui-ux-pro-max` 查到了 Claymorphism，就照着做了厚阴影软糖风。
**但那个风格表里明确写着 `Avoid: Complex shadows / 3D effects`** ——
**等于用顶级工具做出了它自己明令禁止的东西**，所以看起来"很 AI、一眼假"。

**教训**：用技能时不能只取"风格名字"，必须**把整条记录读全**（含 `Avoid` 反模式、`Do Not Use For`、
`Implementation Checklist`）。v4 起改成**整条记录抄下来再动手**。

### v4 液态玻璃的依据（全部照抄，不自己发挥）

**风格表 `styles.csv` › `liquid-glass`**：

- 关键词：dynamic material / optical glass / translucency / **lensing** / **refraction** / fluid morphing
- 效果：**Lensing and refraction**、adaptive translucency、fluid morph transitions
- 变量：`--material-role: navigation-controls`、`--translucency: adaptive`、
  `--reduced-transparency-fallback: opaque`

**动效表 `motion.csv`**（v3 是自己瞎调的曲线，v4 全部按表）：

| 用途 | 时长 | 缓动 | 表里的原话要求 |
|---|---|---|---|
| Hover 微交互 | **180ms** | power1.out | **位移 <2px**，读作"反馈"不是"运动"；不许动 width/height |
| 列表错开入场 | **380ms** | back.out(1.4) | **每项错开 ≤0.1s**，长列表用 0.02~0.04s |
| 页面切换 | **260ms** | power1.inOut | **退场不超 250ms**，别让应用显得卡 |

**清单 `Implementation Checklist`（逐条落实）**：

- ☑ 用在导航和控件上 —— 玻璃只给卡片/按钮/选项，不给正文
- ☑ **内容单独一层** —— `.glass > *{position:relative;z-index:1}`
- ☑ 颜色克制 —— 只用 1 主色 + 1 次色 + 1 强调色
- ☑ **测 reduced transparency** —— `@media (prefers-reduced-transparency:reduce)` 关玻璃
- ☑ **测 reduced motion** —— `@media (prefers-reduced-motion:reduce)` 停全部动画
- ☑ 验对比度 —— 见下面验收记录

**另加**：`@supports not (backdrop-filter)` 兜底（老浏览器自动变不透明）。
光斑层加了 `aria-hidden="true"`（装饰性内容，不该被读屏念）。

### v4 具体做了什么

- **底**：深色/粉色 → **浅灰白**（`#eef2f9 → #e6ecf7 → #f3f0fa`），让玻璃有东西可透
- **材质**：`backdrop-filter: blur(22px) saturate(180%)` + 顶部反光描边（`mask-composite` 做 1px 渐变棱）
- **光斑**：**4 层彩色光斑**（蓝/紫/粉/薄荷，`blur(70px)`，26 秒漂移循环）——
  这是 `lensing`（透镜折射）的**原料**，没有它玻璃就是块白板
- **文字**：改用高对比深灰蓝（`#141a26`），**实测正文对比度 17.42**
- **动效**：全部换成 `motion.csv` 给的曲线与时长了

### 视觉部分做了什么（v2 起保留）

- **开场遮罩**：`blur(26px)` 玻璃散射，点一下淡出 + 撒花
- **进度条**：三色渐变 + 流光
- **选项**：逐条错开 30ms 入场（**照表里 ≤0.1s 的要求**）
- **结果页**：撒花 + 类型名弹性放大 + 维度条逐条生长
- **首页**：12 类型卡网格

### 撒花特效是自己写的，不是塞库

原计划用 [canvas-confetti](https://github.com/catdad/canvas-confetti)（**12798★、MIT**，源码 24.7 KB），
评估后**没用**——它一个库的体积顶得上整个页面的 2/3，而我们只用到"撒花"一个动作。

**自己写的版本约 2 KB**：`FX.burst()` / `FX.celebrate()` / `FX.clear()`，
带重力、阻力、旋转、透明度衰减，canvas 按 devicePixelRatio 适配高清屏。

> 这是遵守用户「**不要自己造轮子**」规矩时的一个**有理由的例外**：
> 现成的轮子（24.7 KB）比要解决的问题（2 KB）大一个数量级。
> 如果他要用 confetti 的更多花式（`shapeFromText` 撒文字、`fire` 系列），再换回库也不迟。

**用到的既有规矩**（来自用户笔记）：
- 零外部引用、单文件内联
- 开场遮罩 + `setTimeout` 兜底（防节流环境残留）
- 中文系统字体栈
- `overflow-x:hidden` + 全局 `box-sizing`

### 测试时踩过的两个坑（记下来，下次别再犯）

1. **往页面里注入测试代码时，`previewTypes();` 后面紧跟一个 IIFE，中间没有分号** ——
   把测试代码插在它前面会被 JS 当成连续调用**直接吞掉**，表现为"注入的代码根本没跑"
   （页面标题保持原样）。**正确做法：插在最后一个 `</script>` 之前，并且开头补一个 `;`。**
2. **`pick()` 内部有 `setTimeout(...,200)` 会自己推进到下一题** ——
   测试循环里再手动 `cur++` 就会**双重推进冲出数组**，报 `Cannot read properties of undefined (reading 'part')`。
   **这不是页面的 bug**，是测试脚本写错了。
   正确做法：循环里只调 `pick()`，用 `setInterval` 轮询等结果页出现。

### 已知不足（下次可改）

- 相似度普遍偏低（多数在 60~80%），因为加权后距离天然偏大；不影响排序，但看着不够"准"
- 结果链接只编码了类型序号和相似度，没编码完整答案，别人打开只能看到类型、看不到 15 维剖面
- 撒花特效只在结果页和点遮罩时触发，答题过程中没有即时反馈音效/微动效

## 八、怎么用

**看效果**：双击 `pages/AI协作人格.html` 就能开（不用起服务器）。

**改题目**：文件里搜 `const QUESTIONS`，每题的格式是：

```js
{id:'Q01', part:1, dim:'A2', quick:false,   // quick:true = 快速版选中
 scenario:'情境描述', prompt:'问题？', options:[
  {t:'选项文字', s:0},   // s = 分值 0/1/2
  {t:'选项文字', s:1},
  {t:'选项文字', s:2}
]}
```

- `dim` 必须是 `DIMS` 里定义的 15 个键之一
- **快速版必须保持每个维度恰好 1 题 `quick:true`**，否则归一化会歪（原理见第一节的警告）
- 完整版每个维度 2 题

**改人格**：搜 `const TYPES`，每种类型的 `pat` 是 15 个维度的 L/M/H 模式。

**改权重**：搜 `function dimWeight`，调 A / C 组的 `1.25` 系数。
