## ★ 核心技术一：轮廓挤出（星露谷 3DVR 的 `VoxelMesh.Build`）

**这是把平面精灵变成「有厚度的立体」的做法**，位于反编译源码约 9238 行：

```
对每个像素 (k, l)：
    if (不透明(k,l) && !不透明(k+1,l))  → 在右侧竖一面墙
    if (不透明(k,l) && !不透明(k-1,l))  → 在左侧竖一面墙
    ... 上下同理
```

再加上前后两个完整面（`FullFace(0f, back: false)` / `FullFace(1f, back: true)`）。

**效果**：一个平面精灵被挤成一块「饼干模具压出来」的立体，
**任何角度都有真实厚度，不会变成一条线**；背面自动用同一张贴图。

细节：`AlphaThreshold = 48`（判定不透明的阈值）、有缓存（`MaxCache = 16384`）、
每帧限制构建数量（`BuildsPerFrame = 16`）以控制开销。

## ★ 核心技术二：交叉广告牌（starwdew3d 的 `MeshBuilder.AddCrossedBillboards`）

**两片互相垂直的平面**代替单片平面：

- 单片平面：转到 90° 侧看 → 变成一条线 → 消失
- 交叉双片：无论转到哪个角度，**总有一片接近正对相机**

用于树、灌木这类「从任何角度看都该是同一个样子」的东西。
（星露谷作者也提到农作物/树木用交叉平面渲染。）

**注意副作用**：如果给所有东西都加「永远正对相机」（billboard），
玩家移动时**全世界的东西都会转头盯着你** —— 星露谷那个 mod 报道里专门吐槽过这个怪异感。
所以该用交叉平面的地方用交叉平面，该用挤出的地方用挤出。

## ★ 核心原则三：只补「本来就有的那一面」

PZFPS 的 `BoxSideCompletion.java` 注释原话：

> **"This completes only the unseen opposite side; it does not invent a back/bottom."**
> （只补看不见的另一面，**不凭空发明背面/底面**）

**这条直接否掉了我们之前「给尖塔补一整面后墙」的做法** ——
尖塔原版根本没有背面素材，凭空补出来的墙就是「臆造」，所以怎么补都别扭。

## ★ 关键情报：原作者自己承认这条路的固有代价

星露谷 3DVR 的说明页（[新手盒子](https://www.wclbox.com/games/25/modSearchItem/127675)）里，
作者 GingasVR 自己列的「已知问题」原文：

> 「**漂浮物体、奇怪的墙壁隐形区域、物体不应直立时却直立** ——
> 由于我渲染的方式（**使用精灵数据而不是从头制作模型**），事情有时看起来会很奇怪……
> **我对此能做的并不多。**」

**结论：我们遇到的「墙壁空洞、物体飘浮、转头出界」不是实现水平问题，
而是「2D 游戏硬改 3D」这条路的固有代价，连专业作者也只能接受。**
→ 所以不要试图把每个洞都补掉，**要选一个代价可接受的范围**。

## ★★★ 0.6.0 前方全黑的真正根因：可见层祖先链

**连续五轮「前方全黑」，最后用一个独立探针（`tests/capture-probe/`）实测出结论。**

### Godot 的可见层规则（实测确认，不是查文档猜的）

> **一个节点的实际可见层 = 自己 `VisibilityLayer` 与「所有祖先」的 `VisibilityLayer` 的按位与。**
> 所以祖先链中间**任何一层**没带上本层，按位与就变成 **0**，**任何视口都拍不到它**。

### 实测对照（同一环境、同一帧）

| 做法 | 结果 |
|---|---|
| 只给子节点设层，祖先不动 | **60 帧全是 0** ❌ |
| 祖先 `\|=` 上同一层 | **第 2 帧 625 个不透明像素** ✅ |
| 祖先设成 `1`（第 1 层），子节点设 `1<<20` | 按位与 = **0** → 拍不到 |

### 我们踩的坑

`Isolate` 里的祖先补层循环写成：

```csharp
for (Node? parent = root.GetParent();
     parent != null && parent is not Viewport && parent != room;   // ← 这里
     parent = parent.GetParent())
```

`parent != room` 让循环**永远不给 `room` 补层**。而 `room` 是 `%EnemyContainer` 的父节点，
**链子在这里断了** —— 于是怪物、宠物全被按位与成 0，整个前方全黑。

**修法**：一路 `|=` 补到 `Viewport` 为止，中间任何一层都不漏。
祖先要用 `|=` 而不是 `=`，否则会破坏它们原本挂在别层上的用途。

### 顺带确认的另外两条（都不是根因，但都是真问题）

1. **SubViewport 要等渲染完成再取样**：探针显示第 2 帧才有内容，`CallDeferred` 只等一帧会拿到空图。
2. **空图不能当有效帧缓存**：开局头几帧捕获是空的，若那时就建网格并记进缓存，
   之后每帧都会因「内容没变」直接返回，网格永远是空的。
   （已修：空图不消耗重建预算、不更新缓存。）

### 教训

**不要在没有最小复现的环境里反复试错。**
前面五轮都在 mod 里直接改、靠截图判断，每轮只能拿到"还是黑的"这一个信息。
最后建了一个 20 行的独立探针，**五轮没搞定的事，探针十分钟就定位了**。

```

```

**一存就看清了**：捕获完全正常（拍到了完整的怪物和小骨头），
问题根本不在捕获、也不在网格 —— 让排查范围立刻缩小到"显示"这一步。

> 教训：**能导出中间产物就不要靠描述猜。**「感觉有两只」查了三轮，
> 存一张图就定位了。

### 各问题的真实根因

| 现象 | 根因 | 修法 |
|---|---|---|
| 前方全黑 | 可见层是「自己 & **所有祖先**」按位与；祖先链中间断一层就全废 | 祖先一路 `\|=` 补到 Viewport |
| 手牌看不见 | 展示层 ZIndex=0 与手牌同级、后画盖住手牌 | 展示层放 **-8**（背景 -10 与手牌 0 之间） |
| 怪被挡住 | 改到 ZIndex=-12，**跑到原版背景 -10 下面**，被背景盖住 | 同上，取中间值 |
| 怪物重叠成两只 | 曾用「把节点挪进捕获容器」，挪动打断动画且位置偏移 | 回退为**只设层、不挪动节点** |
| 背景偏移 / 特效停留 | 同上：背景和特效也被挪动，触发 `_ExitTree` 打断自身生命周期 | 分开成 `IsolateAdopt`（挪动）与 `IsolateLayerOnly`（只设层） |
| **怪物显示成白色碎块** | 材质用了**半透明混合**；半透明不写深度缓冲，几百个三角形渲染顺序随机、互相穿透 | 改 **AlphaScissor**（alpha 测试），不透明像素正常写深度 |
| 闪退 | 同一帧把图像逐像素扫了 5 遍（判空/计数/比内容/挤出/统计），96×96×3 只怪 ≈ 每帧十几万次 `GetPixel` | **只读一次** alpha 数组，之后全在数组上判断 |

### 关于「挪动节点」的结论

把节点挪进干净容器听起来优雅（祖先链短、不会误抓别的分支），
**但对有动画/生命周期的节点是灾难**：换父节点会触发 `_ExitTree`/`_EnterTree`，
打断 Spine 动画、停掉特效的销毁计时器。
**实测对比：补层方案捕获到 6.1% 不透明像素（正常），挪动方案只有 0.87%。**
→ 结论：**优先用「只设层」，除非确认该节点挪动无副作用。**
