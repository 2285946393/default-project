## 一、⚠️ 先看打包形态：这个 mod 是完全导出过的 Godot 工程

拆 pck 会看到和万象辉星**完全不同的结构**：

| 后缀 | 数量 | 说明 |
|---|---:|---|
| `.ctex` / `.import` | 245 / 251 | 贴图（同万象辉星） |
| **`.remap`** | 18 | **重映射文本**：`path="res://.godot/exported/<n>/export-<md5>-X.scn"` |
| **`.scn`** | 14 | **二进制场景**（不是 `.tscn` 明文！） |
| **`.spatlas` / `.spskel`** | 3 / 3 | **Spine 骨骼动画**（atlas 是文本，skel 是二进制） |
| **`.gdc`** | 1 | **GDScript 编译后的字节码**（`.gd` → `.gdc`） |
| `.gdextension` | 1 | **原生扩展声明**（Spine 的运行库） |
| `project.binary` | 1 | Godot 工程设置 |

### 三个必须知道的差异

**① 场景被转成了二进制 `.scn`**
Necrobinder 的 14 个动作场景（`血斩` / `一闪` / `上勾拳` / `旋风斩` / `谋杀01/02` / `华丽收场` / `精准瞄准` / `放血` / `死神待机` / `BLUDGEON` …）
在 pck 里是 `.godot/exported/133200997/export-<md5>-<名字>.scn`，
而 `res://scenes/血斩.tscn` 只留了一个 `.remap` 文本指过去：

```ini
[remap]
path="res://.godot/exported/133200997/export-397b875d8d214bc66e5dd126eef1a163-血斩.scn"
```

原因：Godot 导出设置里的 **"Convert Text Resources To Binary"**。
- **ON** → 场景变 `.scn`（体积小、加载快，但**你读不了**）
- **OFF** → 保留 `.tscn` 明文（万象辉星就是这样）

→ **我们自己打包时，一定要把这项关掉**（至少调试期），不然改一次要看一次二进制。
`.scn` 还是能捞到字符串表（节点名/类名），但节点树读不出来。

**② 它顺带定义了 `.remap` 这套"资源重定向"**
和贴图的 `.png.import` 是同一个思路：**逻辑路径不变，实体文件挪到 `.godot/` 下面**。
所以判断一个 pck 是不是"完全导出过的"，看有没有 `.godot/exported/` 就知道了。

**③ 它带了一个原生扩展（GDExtension）**
`bin/spine_godot_extension.gdextension` —— 官方 spine-godot 运行库：

```ini
[configuration]
entry_symbol = "spine_godot_library_init"
compatibility_minimum = "4.1"
[libraries]
windows.release.x86_64 = "windows/libspine_godot.windows.template_release.x86_64.dll"
...
```

⚠️ **但 pck 里只有 `.gdextension` 声明文件，没有 `windows/*.dll`** —— 原生库没打进包。
（大概是因为游戏本体自带 Spine 运行库，作者直接复用了。**这条存疑，未验证。**）

→ **对我们**：Spine 骨骼动画这条路**成本高**（要原生扩展 + 骨骼工具链）。
本体的角色本来就用 Spine，我们做"新角色/新皮肤"才需要；
做**卡牌特效**完全不需要 —— 万象辉星那条帧动画路线就够。

## 二、★ 打击感六件套

这个 mod 的 76 个类，本质是六种手法的排列组合。**每一种都能单独拿来用。**

### 1. 打击停顿（HitStop）—— 性价比最高的一招

`HitStop.cs`：命中瞬间把**整个游戏的时间冻住 0.1~0.2 秒**，然后恢复。

```csharp
public static async Task Apply(float duration = 0.2f)
{
    if (SettingsUI.IsFastModeEnabled() || Engine.TimeScale < 0.01f) return;

    float originalTimeScale = (float)Engine.TimeScale;
    var sceneTree = (SceneTree)Engine.GetMainLoop();

    // ★ 用 wall-clock 计时，不能用 Timer
    var guardNode = new Node();
    sceneTree.Root.AddChild(guardNode);
    bool finished = false;
    long startMs   = (long)Time.GetTicksMsec();
    long durationMs = (long)(duration * 1000f);

    Action onFrame = () => {
        if (finished) return;
        if (Math.Abs(Engine.TimeScale) > 0.001f) Engine.TimeScale = 0.0;   // 保持冻住
        if ((long)Time.GetTicksMsec() - startMs >= durationMs) finished = true;
    };
    sceneTree.ProcessFrame += onFrame;

    try
    {
        Engine.TimeScale = 0.0;
        while (!finished)
            await sceneTree.ToSignal(sceneTree, SceneTree.SignalName.ProcessFrame);  // ★
    }
    finally
    {
        sceneTree.ProcessFrame -= onFrame;
        Engine.TimeScale = originalTimeScale;          // ★ 一定要还原
        await sceneTree.ToSignal(sceneTree, SceneTree.SignalName.ProcessFrame);
        if (Math.Abs(Engine.TimeScale - originalTimeScale) > 0.001) Engine.TimeScale = originalTimeScale;
    }
}
```

**三个非显而易见的点，全是坑：**

1. **`Engine.TimeScale = 0` 之后，普通 `Timer` 也会停** —— 因为 Timer 用的是缩放后的时间。
   所以计时必须用 **`Time.GetTicksMsec()`（挂钟毫秒）**，并且要靠 **`ProcessFrame` 信号**
   一帧一帧地轮询（`ProcessFrame` 不受 TimeScale 影响，TimeScale=0 时照样发）。
2. 它还是塞了个 `Timer`（`WaitTime = duration + 0.1f`）当**兜底保险**，
   防止 `ProcessFrame` 那个循环因为什么原因卡住不退出。
3. **还原写在 `finally`，而且还原后还复查一次** —— 因为别的地方（比如本体的暂停菜单）
   可能在这期间动过 `TimeScale`。

**什么时候触发**（`HitStopController.cs`）：

```csharp
[HarmonyPatch(typeof(AttackCommand), "Execute")] [HarmonyPrefix]
static void Prefix() => _highDamageHitStopTriggered = false;   // 每次攻击重置

// 造成伤害后（Postfix）：
if (dealer.Side == Player && target.Side == Enemy
    && cardSource != null && cardSource.IsUpgraded          // ← 只对升级过的卡
    && !ExcludedHitStopCards.Contains(cardSource.Id.Entry)  // ← 排除 BODY_SLAM
    && !_highDamageHitStopTriggered)                        // ← 一次攻击只顿一下
{
    HitStop.Apply(0.1f);
}
```

→ **注意 `_highDamageHitStopTriggered` 这个"一次攻击只顿一下"的闸**。
多段攻击（比如连击 3 下）如果不加这个闸，会连冻三下，观感很糟。

### 3. ★ 冲刺 + 拉伸形变（squash & stretch）—— 最值钱的一招

`SimpleTeleportPatch.GetEasedProgress` / `GetStretchFactor` —— 两个纯数学函数，**可以直接抄**：

```csharp
/// 分段缓动：前 62.5% 的时间只走 20% 的路程（慢慢"蓄力"起步），
/// 后 37.5% 的时间冲完剩下 80%（猛地窜出去）
internal static float GetEasedProgress(float t, float splitTime = 0.625f, float splitProgress = 0.2f)
{
    t = Mathf.Clamp(t, 0f, 1f);
    if (t <= splitTime) return t / splitTime * splitProgress;
    return splitProgress + (t - splitTime) / (1f - splitTime) * (1f - splitProgress);
}

/// 拉伸倍率：0 → 峰值(默认 4.5 倍，在第 70% 处) → 回落
internal static float GetStretchFactor(float progress, float peakStrength = 4.5f,
                                       float exponent = 4f, float peakProgress = 0.7f)
{
    progress = Mathf.Clamp(progress, 0f, 1f);
    if (progress <= peakProgress)
    {
        float n = progress / peakProgress;
        return 1f + (peakStrength - 0.8f) * Mathf.Pow(n, exponent);   // 加速拉起
    }
    float m = 1f - (progress - peakProgress) / (1f - peakProgress);
    return 1f + (peakStrength - 1f) * m;                              // 线性回落
}
```

用法（`PerformDashWithStretch`）：

```csharp
public static async Task PerformDashWithStretch(NCreature node, Vector2 targetPos,
    float duration = 0.2f, float peakStrength = 2f, float exponent = 6f,
    float peakProgress = 0.7f, bool applyFacing = true, Vector2? facingReferencePoint = null)
{
    var visual = node.Body;
    var origScale = visual.Scale;
    var absScale  = new Vector2(Math.Abs(origScale.X), Math.Abs(origScale.Y));
    float sign    = applyFacing ? Math.Sign(dir.X) : Math.Sign(origScale.X);

    var startPos = node.GlobalPosition;
    var tween = node.CreateTween();
    tween.TweenMethod(Callable.From<float>(t =>
    {
        float p = t / duration;
        node.GlobalPosition = startPos.Lerp(targetPos, GetEasedProgress(p));   // 位移
        float s = GetStretchFactor(p, peakStrength, exponent, peakProgress);   // 形变
        visual.Scale = new Vector2(absScale.X * s * sign, absScale.Y);         // ★ 只拉 X，不拉 Y
    }), 0f, duration, duration);

    await WaitTweenOrTimeout(tween, node, duration + 0.5f);
    // ★ 收尾：还原缩放、吸死到目标点（防止浮点误差留一点点偏移）
    if (completed && IsInstanceValid(node))
    {
        visual.Scale = new Vector2(absScale.X * sign, absScale.Y);
        node.GlobalPosition = targetPos;
    }
}
```

**关键**：只拉伸 **X 轴**（水平方向 = 运动方向），Y 轴不变。
这就是动画十二法则里的 **squash & stretch** —— 角色像橡皮筋一样被"拽长"再弹回来，
是"快"这个感觉的主要来源。**光有位移没有形变，看起来就是"瞬移"，不是"冲上去"。**

各角色的参数（作者调过的）：

| 角色 | duration | peakStrength | exponent | peakProgress |
|---|---|---|---|---|
| Defect（故障机器人） | 0.25s | 3.0 | 6 | 0.75 |
| Ironclad（铁甲战士） | 0.2s | 2.0 | 6 | 0.35 |

→ **同一套代码，靠参数区分手感。** 铁甲的峰值来得早（0.35）所以更"顿"。

### 4. 弧形位移（ArcMove）—— 直线冲刺的升级版

直线冲刺看起来像"贴地滑行"，走弧线才有"跳过去"的重量感：

```csharp
float maxHeight = distance * 0.3f;      // ★ 弧高按距离的 30% 算，不是固定值
...
float arch = (num <= 0.5f)
    ? maxHeight * (1f - Mathf.Pow((num - 0.5f) / 0.5f, 2f))    // 前半段：起跳
    : maxHeight * (1f - Mathf.Pow((num - 0.5f) / 0.5f, 2f));   // （反编译两分支相同，是 (1-t²) 型抛物线）
arch = Mathf.Max(arch, 0f);
node.GlobalPosition = new Vector2(lerpPos.X, lerpPos.Y - arch);   // ★ Y 轴向上减
```

> ⚠️ 反编译出来的两个分支表达式**一模一样** —— 原作者的源码里大概率是
> `(num-0.5)/0.5` 和 `(num-0.5)/0.5` 相同，或者其中一个本意是别的。
> 抄的时候按 `arch = maxHeight * (1 - ((num-0.5)/0.5)^2)` 理解即可（开口向下的抛物线，顶点在 t=0.5）。

### 6. 朝向翻转（`VfxFacingFix`）—— 一个真坑

特效/残影要跟着攻击者的朝向翻转。但**直接翻 `Scale.X` 会让粒子飞反**：

```csharp
private static void ApplyFacingFix(Node2D outerNode)
{
    var attacker = ResolveAttacker();
    var visual = SimpleTeleportPatch.GetVisualNode(attacker);
    float sign = Math.Sign(visual.Scale.X);
    if (sign < 0f)
    {
        PrepareParticlesForFlipping(outerNode);       // ★ 先处理粒子
        outerNode.Scale = new Vector2(-outerNode.Scale.X, outerNode.Scale.Y);
        RestartAllParticles(outerNode);               // ★ 再重播粒子
    }
}

// 关键：把 GPUParticles2D / CpuParticles2D 的 LocalCoords 设成 true
foreach (var child in parent.GetChildren(false))
{
    if (child is GpuParticles2D g && !g.LocalCoords) g.LocalCoords = true;
    else if (child is CpuParticles2D c && !c.LocalCoords) c.LocalCoords = true;
    PrepareParticlesForFlipping(child);
}
// 然后 Restart() 每个粒子节点，让它们按新的坐标系重新发射
```

**为什么**：`LocalCoords = false` 的粒子，速度是**世界坐标**的 ——
你把父节点 `Scale.X` 翻成负的，粒子照样往原来的世界方向飞，看起来就是"反了"。
必须先切成局部坐标，再翻转，再重播。

> **这条在我们自己的模板里也有对应**（`VfxUtil.ScaleAllParticles` 会设 `LocalCoords = true`、
> `ReplayAllParticles` 会 `Restart()`）—— **两个 mod 独立踩到同一个坑，说明这是真坑。**

它的触发方式也很巧：**不用改本体的代码，监听 `SceneTree.NodeAdded`**：

```csharp
tree.NodeAdded += OnNodeAdded;   // 任何节点加进场景树都会通知

void OnNodeAdded(Node node)
{
    if (node is Node2D n2d && IsWhitelisted(n2d) && IsDirectChildOfVfxContainer(n2d))
        Callable.From(() => ApplyFacingFix(n2d)).CallDeferred();   // ★ 必须 deferred
}
```

`IsWhitelisted` 靠**场景文件名匹配**（`fx_dagger_spray_flurry` / `vfx_sweeping_beam`），
`IsDirectChildOfVfxContainer` 靠**父节点名字包含 "VfxContainer"** 或父节点是 `NCombatRoom`。

→ 好处：**不用 hook 本体任何一个函数**，纯靠"节点被加进来了"这个事件。
→ `CallDeferred` 是必须的：`NodeAdded` 是在别的节点树的添加过程中触发的，
在那时候改 `Scale` 会触发 Godot 的安全检查报错。

## 三、位移状态机：怎么"冲出去"还知道"怎么回来"

这是"近身攻击然后返回"的核心机制。`SimpleTeleportPatch` 里有个状态对象：

```csharp
internal static readonly ConcurrentDictionary<NCreature, AttackSequenceState> _attackStates = new();

class AttackSequenceState
{
    public Vector2 LockedHomePos;        // ★ 出去前锁定的"家"位置
    public Vector2 LockedHomeLocal;
    public bool    IsReturning;
    public CancellationTokenSource ReturnCts;
    public TaskCompletionSource<bool> ReturnCompletion;
    public float   BaseDelay, ExtraDelayAccumulated, ElapsedDelay, MaxTotalDelay = 3f;
    public Vector2 BodySlamFacingDir;
    public bool    SkipFadeAndStretchOnReturn;
    public Vector2 LastAttackTargetCenter;
    public bool    HasLastAttackTarget;
}
```

流程（一次打牌里可能有多段攻击）：

```
1. 每次攻击前：If 没有 state → 记下 LockedHomePos = 当前 GlobalPosition
2. 上一轮的返回还没完 → await ReturnCompletion.Task  ← ★ 等干净再开始
3. 取消旧的 _returnCtsTable / _bodySlamDashCts（Cancel + Dispose）
4. 备份 _initialScales[attackerNode] = node.Scale      ← ★ 还原用
5. 血条透明化 + 抬高图层（RaiseLayer）
6. ExecuteMovement(...)      → 冲过去（各角色不同手法）
7. PlayEffectsAndAnimation() → 播特效/动画
8. 等 extraBuffer（按角色配置的额外延时）
9. RunReturnDetached(...)    → ★ 分离出去跑"返回"，不 await（不阻塞后续逻辑）
10. StartTurnEndMonitoring()  → 监控玩家回合结束，万一没回去就强制收尾
```

**几个关键设计：**

- **`LockedHomePos` 一旦锁定就不改**：多段攻击时，每次都回到**同一个原点**，
  而不是回到"上一次的位置"，否则会越走越偏。
- **`RunReturnDetached`（分离出去跑）**：返回是异步的，但**不能 await** ——
  因为要等所有攻击段都打完才返回。用一个 `CancellationTokenSource` 存表里，
  下次攻击来了先 `Cancel()` 掉旧的。
- **`MaxTotalDelay = 3f`**：延时累计上限。防止多段攻击时 `extraBuffer` 无限累加导致卡住。
- **`ReturnCompletion`**：用 `TaskCompletionSource` 让别人能 `await` 到"返回完成"。
- **回合结束兜底**：`AttackTimeTerminator.StartTurnEndMonitoring()` 起一个每 `0.05s` 的循环，
  发现玩家回合结束了就强制 `ClearAllSnapshots()` —— **防止角色卡在敌人那边回不来**。

> ⚠️ **这条对我们的启发最大**：
> 任何"改了角色位置/缩放/图层"的操作，都必须有一个 **"还原"** 的对偶操作，
> 而且要有一个**兜底的强制还原**（战斗结束 / 回合结束 / 换房间）。
> 不然一次异常就会让角色永久歪在场景里。

## 四、★ "改了就要还"—— 一组原值备份表

这是这个 mod 最"工程化"的地方。所有被动过的属性，都留了备份：

```csharp
internal static readonly ConcurrentDictionary<NCreature, Vector2Wrapper> _initialScales          = new();  // 节点缩放
internal static readonly ConcurrentDictionary<NCreature, Vector2Wrapper> _visualInitialScales    = new();  // 视觉子节点缩放
private  static readonly ConcurrentDictionary<NCreature, ColorWrapper>   _originalColors          = new();  // 颜色
internal static readonly ConcurrentDictionary<NCreature, IntWrapper>     _originalZIndices        = new();  // 层级
internal static readonly ConcurrentDictionary<NCreature, Vector2Wrapper> _blockIconInitialPositions = new(); // 格挡图标位置
```

外加一堆 **`CancellationTokenSource` 表**，每个"可能还在跑的异步流程"都有一张表：

```csharp
_returnCtsTable          // 返回动画
_bodySlamDashCts         // 撞墙冲刺
_positionLockCtsTable    // 位置锁定（阻止本体 AI 同时改位置）
_whirlwindFlipCts        // 旋风斩翻转循环
```

**为什么需要 `_positionLockCtsTable`**：本体自己在出牌时也会摆角色的位置。
我们的冲刺和本体的摆位**同时进行**就会打架（角色抖动）。
所以拿一个"位置锁"把控制权抢过来，用完（`finally`）再放掉。

> 💡 **`Vector2Wrapper` / `ColorWrapper` / `IntWrapper` 这种包装类**是因为
> 反编译的工具类需要（值类型不能直接 `null`），源码里其实是 `Vector2?` 之类的。
> 抄的时候直接写 `ConcurrentDictionary<NCreature, Vector2>` 就行。

## 五、目标中心：用 `Hitbox`，不是用节点位置

`TargetCenter.cs`（**9 行，直接抄**）：

```csharp
public static Vector2 GetCenter(NCreature targetNode, float offsetY = 0f)
{
    if (targetNode == null || !GodotObject.IsInstanceValid(targetNode)) return Vector2.Zero;

    if (targetNode.Hitbox != null)                                   // ★ 优先用碰撞盒
    {
        Vector2 p = targetNode.Hitbox.GlobalPosition + targetNode.Hitbox.Size * 0.5f;
        return p + new Vector2(0f, offsetY);
    }
    return targetNode.GlobalPosition + new Vector2(0f, offsetY);     // 兜底
}
```

**为什么比 `VfxSpawnPosition` 好**：`GlobalPosition` 是角色的**脚底/原点**，
`VfxSpawnPosition` 是本体给特效预留的一个点；而 `Hitbox` 是**实际判定框**，
它的中心才是"打在身上"的那个位置。冲击波/命中标记画在这儿最准。

## 八、⚡ 一个我们不该学的地方

`RuntimeCompat.cs` —— 它的做法是：

```csharp
// 找到另一个 mod（LibraryOfRuina = 工坊上的「Ruina 2」）的类
var t = assembly.GetType("LibraryOfRuina.compat.IncompatibleModGuard");
// 然后 Harmony 掉它的检测方法，强行返回 false
_h.Patch(t.GetMethod("DetectBlockingMods", ...), new HarmonyMethod(typeof(RuntimeCompat).GetMethod("Pre")), ...);
public static bool Pre(ref bool __result) { __result = false; return false; }   // ← 骗它说"没有冲突"
```

**这等于绕过另一个 mod 的兼容性防护。** 技术上很聪明
（`AppDomain.AssemblyLoad` 事件 + 候选方法名枚举 + 反射，优雅地处理"对方不存在时也不报错"），
但**这是 hostile interop**：如果那两个 mod 真的不兼容，用户会遇到比"被拦住"严重得多的问题。

→ **记下来当反面教材**：我们要做跨 mod 兼容，正确做法是**暴露一个官方接口 / 写进文档**，
不是去 patch 别人的防护。
（顺带：`AppDomain.CurrentDomain.AssemblyLoad += ...` 这个"等对方 dll 加载完再动手"的
反射探测写法本身是好东西，可以用在**合法的**场景。）
