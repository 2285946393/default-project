- `dotnet build FirstPersonSpire.csproj --no-restore`：0 警告，0 错误。

探针发现并修正：

1. `BasisXformInv` 不能当作缩放矩阵的通用逆，改用 `AffineInverse().BasisXform()`。
2. `GetGlobalTransformWithCanvas()` 在本机 Godot 4.5.1 不包含视口 `GlobalCanvasTransform`；截取坐标沿用该空间，最终展示再由宿主视口统一变换。
3. 展示层用独立 Node2D 的全局变换抵消宿主画布缩放，避免仅改 Size/Position 导致错位。
4. 关闭时不再无条件打开借用的显示层；清理单个节点失败不阻断后续恢复。

## 0.2.1 血条收敛与死亡特效归位（2026-10-12）

用户实测反馈两条：**开局会出现血条移动**；**怪死了会在原地出现尸体特效**。用户追问「血量条移动应该是无法避免的？如果无法避免可以把这个移动效果搞得快点嘛」。

### 一、血条移动：能避免「被看见」

**移动本身躲不掉**：血条必须跟随怪物，否则会跟怪物脱节、点选错位。
但**玩家不该看见跟随过程**。

病因在 `PresentationSession.Update`：

- `target` 是固定的舞台站位，算好不变；
- 真正在变的是 `CanvasAnchor(creature)` —— **原版怪物入场时的摆位过程**；
- 血条忠实跟随，于是玩家看见血条从原版位置一路滑到 3D 站位。

**做法：等锚点自己稳下来再露出界面。**
判定抽成纯逻辑类 `Core/OpeningSettle.cs`（无 Godot 依赖，可离线检查）：

- 连续 2 帧位移小于 1.5 画布像素 ⇒ 认为原版已摆好；
- 怪物还没同步进来（数量 0）时**不计帧**，否则会白掉几帧提前露出；
- 怪物数量变化（召唤物加入）不算稳定；
- 兜底 60 帧，防止动画一直抖导致血条永不出现。

收敛期间用 `_settleHidden` 临时隐藏血条/意图/选中圈。
⚠️ **必须跟 `_visibility` 分开记** —— `_visibility` 是关闭 Mod 时用来还原原版状态的，混用会让血条永久消失。

### 二、尸体特效留在原地：根因是挂载点

看反编译源码 `NCreature.AnimDie`（0.111.0）：

```csharp
NMonsterDeathVfx nMonsterDeathVfx = NMonsterDeathVfx.Create(this, cancelToken);
Node parent = GetParent();                 // ← 房间层，不是 NCreature
parent.AddChildSafely(nMonsterDeathVfx);
```

死亡特效 `NMonsterDeathVfx` **挂在怪物的父节点（房间层）上**，不在 `NCreature.Visuals` 底下。

## 0.4.4 手牌根因、右键视角、材质真正替换（2026-10-12）

### ★ ① 手牌不见了：根因是 Isolate 污染了房间根节点

用户那句「**切回原始视角会有一堆牌卡在左上角**」是决定性线索 —— 说明手牌**确实被搬过**。

看回 `Isolate`：

```csharp
for (Node? parent = root!.GetParent(); parent != null && parent is not Viewport; parent = parent.GetParent())
{
    if (parent is not CanvasItem canvas) continue;
    canvas.VisibilityLayer |= layer;      // ← 一路往上加层
}
```

这段本来是为了「Godot 逐级检查祖先可见层，遗漏祖先会得到空白纹理」。
但 **`room.Background` 的直接父节点就是 `room`**，而 `room` 是所有东西的爸爸 ——
**手牌、顶栏全在 `room` 底下**。给 `room` 加了捕获层，手牌就被一起拉进展示层坐标系，
于是在屏幕上表现为「看不见」或「卡在左上角」。

**修法**：向上遍历时遇到 `room` 就停，只补中间那些纯展示容器。

⚠️ 教训：**给祖先节点「打标记」之前，先确认这个祖先到底管着哪些东西。**
`room` 不是背景的一部分，它是整场的根。
