## 八、踩坑记录

1. **不要直接运行 `SlayTheSpire2.exe`**：报 `Steamworks initialization failed` 后退出，必须从 Steam 启动。
2. **构建前必须关游戏**，否则 dll 被占用，构建失败。
3. **模板有 API 不兼容**：模板里的 `AttackCommand.FromCard(this)` 在最新 RitsuLib（0.6.2）上
   必须写成 `FromCard(this, cardPlay)`。
4. **`CanonicalKeywords` 必须是 `public override`**，`CanonicalTags` 才是 `protected override`。
5. **`CardModel` 在 `MegaCrit.Sts2.Core.Models`**，不在 `MegaCrit.Sts2.Core.Entities.Cards`。
6. **自定义动态变量进不了本地化**：`ModCardVars.Int("Claw", 2)` 配 `{Claw}` 或 `{Claw:diff()}`
   都会报 `No source extension could handle the selector named "Claw"`（游戏加载卡牌资产时）。
   原版变量 `{Damage:diff()}` / `{Block:diff()}` 正常。**原型阶段描述里直接写固定数值**。
   以后要支持自定义变量显示，需要研究 RitsuLib 的格式化 source 注册。
7. **模板多写的 `smartDescription` 字段要删掉**：官方文档只要求 `.title` + `.description`。
   多写的 `smartDescription` 会让游戏把 `{Damage:diff()}` 原样显示出来（玩家看到 "diff"）。
8. **战斗内生成卡必须用 `CombatState.CreateCard(ModelDb.Card<T>(), owner)`**；
   用 `RunState.CreateCard<T>()` 生成的卡，打出时报
   `must be added to a CombatState before playing it`，卡会卡在屏幕中间不能动。
9. **验证时要确认读的是本次会话日志**：Godot 会把上次的 `godot.log` 归档成带时间戳的文件，
   容易读到上一次会话的内容而误判 dll 没更新。用 `findstr` 直接查 dll 更可靠。

## 十三、本轮新踩的坑（比上一节更细，照抄能省半天）

1. **改卡牌基础费用没有 `SetBaseValue`** → 用 `CardEnergyCost.UpgradeBy(int)`（升级时降费的官方钩子）。
2. **判断敌人攻击意图没有 `Monster.Intent`** → 正确写法：
   ```csharp
   using MegaCrit.Sts2.Core.MonsterMoves.Intents; // IntentType / AbstractIntent 在这
   var hasAttack = monster != null
       && monster.NextMove.Intents.Any(i => i.IntentType == IntentType.Attack);
   ```
   `AttackIntent` 还有 `DamageCalc / Repeats / GetTotalDamage(targets, owner)` 可取伤害。
3. **升级卡没有 `card.Upgrade()` Instance 方法** → 用 `CardCmd.Upgrade(card)`；卡内判断自己是否已升级读属性 `IsUpgraded`。
   LesserHex 造 GreaterHex：`var hex = CombatState.CreateCard(ModelDb.Card<GreaterHex>(), Owner); if (IsUpgraded) CardCmd.Upgrade(hex);`
4. **`ModelDb` 要 `using MegaCrit.Sts2.Core.Models;`**，否则 `CS0103`。原生状态牌 `Dazed` 确在 `MegaCrit.Sts2.Core.Models.Cards`。
5. **本地化 key 必须等于「框架自动生成的 id」，不能照类名硬拼**。
   类 `StrikeABargain` 被框架拆成 id `BLOOMLESS_SPIRE_CARD_STRIKE_A_BARGAIN`（`A` 与 `BARGAIN` 之间补了下划线）。
   ⚠ **本轮已知遗留（暂停前未修）**：zhs/eng 里把 key 写成了 `..._STRIKE_ABARGAIN`（少一个下划线），
   对不上会导致这张卡标题/描述显示异常。**通用规矩**：以运行日志 `Registered card: X (id=...)` 里的 id 原样复制，别手推。
6. **`GameReadyEvent` 不可靠，别拿它当开局时机**。它由 RitsuLib 的 `game_node_lifecycle` Harmony patch
   （`IsCritical=false`）在 `NGame._Ready` 里发布；patch 没生效就永不触发（本轮日志里就没出现）。
   **改法**：在**一定会触发**的 `RunStartedEvent` 回调里，直接拿场景树根挂 UI，绕开事件时序：
   ```csharp
   var tree = Engine.GetMainLoop() as SceneTree;
   tree.Root.AddChild(PackSelectionOverlay.CreatePanel());
   ```
   ⚠ 此 SceneTree 方案 `dotnet build` 通过，但暂停前**没跑游戏实测**浮层是否真的弹出。
7. **校验本地化 JSON 别信 PowerShell 控制台**（GBK 中文必乱码）。写 Python 脚本到临时目录跑 `json.load` 数条数即可。
