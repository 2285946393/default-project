## 一、问题：我们所有随从的攻击都用 `Unpowered`，而力量只加成「Powered Attack」

### 起因
M3.10 补了力量来源（霜锻 / 极寒核心）之后，回头检查「力量到底加在谁身上」时发现：
**寒冰王座（4 费 Rare）的「部署时全体友军 +3 力量」可能根本没效果。**

### 反编译取证（决定性）

`MegaCrit.Sts2.Core.Models.Powers.StrengthPower`：

```csharp
public override decimal ModifyDamageAdditive(Creature? target, decimal amount, ValueProp props,
                                             Creature? dealer, CardModel? cardSource, CardPlay? cardPlay)
{
    if (base.Owner != dealer) return 0m;          // 只加成"我自己造成的伤害"
    if (!props.IsPoweredAttack()) return 0m;      // ★ 卡在这里
    return base.Amount;
}
```

`MegaCrit.Sts2.Core.ValueProps.ValuePropExtensions`：

```csharp
public static bool IsPoweredAttack(this ValueProp props)
{
    if (props.HasFlag(ValueProp.Move))
        return !props.HasFlag(ValueProp.Unpowered);   // 有 Move 且没有 Unpowered
    return false;
}
```

`ValueProp` 枚举的官方注释：
```
///   - Unblockable = HP loss like Poison
///   - Unpowered   = Damage from relics, potions, and powers    ← 我们全用的这个
///   - Move        = Attack damage from Attack cards and Enemy creatures attacking
```

### 结论
**力量只加成「Move 且非 Unpowered」的伤害**（= 攻击牌、怪的普通攻击）。
而我们**所有**随从/建筑的伤害都用 `ValueProp.Unpowered`：

| 位置 | 伤害 | 原来吃力量吗 |
|---|---|---|
| `ArrowTowerPower`（箭塔每回合 AOE 4） | Unpowered | ❌ |
| `MilitiaAttackPower`（民兵每回合 5） | Unpowered | ❌ |
| `ArrowTowerVolleyAction`（齐射 6） | Unpowered | ❌ |
| `MilitiaChargeAction`（突击 8） | Unpowered | ❌ |
| `FrostBurstDetonateAction`（引爆蓄力） | Unpowered | ❌ |

⇒ **寒冰王座的「全体友军 +3 力量」是一张空头支票** —— 4 费 Rare，一半效果不存在。
⇒ 「养大哥」这条核心玩法线**在随从上根本走不通**。

## 二、为什么选「显式加力量」而不是改成 `ValueProp.Move`

`ValueProp.Move` 确实能让力量自动生效，但会顺带带来一整串连带行为：

- 伤害会被**格挡挡住**（箭塔从"稳定输出"变成"会被挡"）
- 会触发敌人的**荆棘反伤**（Thorns）
- 会被 `RuneWallPower` 之类的"减普通攻击伤害"减半
- 会被各种「受到攻击时」钩子反复触发，可能和我们的触发式能力形成怪异连锁

⇒ 改动面太大、不可控。

**采用的方案：伤害保持 `Unpowered`，但显式把力量加进去。**

优点：精确、可控、零连带风险，且语义上说得通（力量本来就该让攻击变强）。

实现：
```csharp
// FrostBuildingPowerBase（建筑/单位光环用）
protected static decimal AddStrength(PowerModel power, decimal amount)
    => amount + power.Owner.GetPowerAmount<StrengthPower>();

// FrostActionBase（随从主动技用，ActionModel 不走上面那个基类）
protected static decimal WithStrength(Creature creature, decimal amount)
    => amount + creature.GetPowerAmount<StrengthPower>();
```

### ★ 刻意**不做**的部分
M3.9 那批**反应式**能力（遗霜 / 雪崩 / 寒风 / 霜之回响 / 碎冰 / 凛冬之怒 / 冰壳）
**保持不吃力量** —— 它们是"能力造成的伤害"，官方惯例就是 Unpowered 不吃力量，
而且这些触发频率高，加力量会失控。

⇒ 只有**「单位/建筑的攻击行为」**吃力量（本质是攻击，不是反应）。这个区分很清晰：
- 箭塔射击 / 民兵攻击 / 齐射 / 突击 / 引爆 = **攻击行为** → 吃力量 ✓
- 遗霜（随从死 → AOE）= **反应能力** → 不吃力量（官方惯例）

## 四、这条教训（值得记住）

**加了一个 buff（力量），一定要验证它到底作用于哪些伤害。**

`ValueProp` 不是"开关"，是**伤害来源标签**：
- `Move` = 攻击牌 / 怪的普通攻击 → **吃力量、吃虚弱、被格挡挡**
- `Unpowered` = 遗物 / 药水 / **能力**造成的伤害 → **不吃力量、不被格挡挡**

用 mod 的方式做"随从自动攻击"时，官方惯例值是 `Unpowered`，
于是**所有基于力量的强化（养大哥）都会静默失效** —— 不报错、不崩溃，就是没效果。
这类 bug 只有去反编译 `StrengthPower` 才能发现。

⇒ 写进 skill 了：见 `sts2-mod-debug/SKILL.md` 第 8 节。
