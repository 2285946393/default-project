## 一、★ 海龟潜海（Shelldiver）—— 为什么它的数值最完美

### 1.1 先说结论：它解决了增量游戏最大的病

纯增量游戏的通病是**后期无事可做**：数字一直变大，但玩家的动作从头到尾不变，
最后变成看着数字涨。海龟用**一个机制**治好了这个病 ——

> **氧气 = 有限的时间预算，而时间可以直接换成收益。**

一次下潜（ expedition ）就是一局：氧气开始倒计时 → 你争分夺秒收集资源 →
氧气耗尽强制上浮 → 用资源升级 → 下次潜得更深、待得更久。

**增长没有改变玩法，但增长不断抬高"这一局能拿多少"的上限。**
玩家每一局都在做同样的动作，但每一局的收获都在变大 —— 这才是增量该有的样子。

### 1.2 氧气：把「限制」做成「可交易资源」★

这是整个设计里最漂亮的一笔。氧气不只是倒计时，它有 **4 个独立升级维度**：

| 维度 | 技能 | 作用 |
|---|---|---|
| 上限 | `oxygen_tank_01…_08`、`_10` + `oxygen_tank_extra_01/02` | 氧气总量（拆到 10 级 + 2 级突破） |
| 回复量 | `oxygen_regen_amount_01/02/03` | 每次回多少 |
| 回复速度 | `oxygen_regen_speed_01/02/03` | 多久回一次 |
| 拾取 | `oxygen_catch_01/02` | 捡氧气泡的效率 |

然后是关键 —— **氧气能直接花掉**：

```
o_skill_bubble_damage_oxygen    用氧气换气泡伤害
o_skill_plasma_damage_oxygen    用氧气换等离子伤害
o_skill_resource_oxygen         用氧气换资源产出
o_skill_jellyfish_oxygen        用氧气换水母收益
```

**这一步把"被动倒计时"变成了"主动决策"**：你是省着氧气多待一会儿，
还是烧掉氧气换取这一趟的高收益？每一局都在做这个取舍。

终局奖励是 `Unlimited Oxygen`（无限氧气）—— 到这一步，核心约束被解除，
游戏也就进入尾声了，收得很干净。

> **可复用手法：给你最硬的那个限制，开一个"花掉它换收益"的出口。**
> 限制一旦可交易，就不再是枷锁，而是资源。

### 1.3 五种资源 × 四条价值链

资源：`crystal`（水晶）、`scrap`（废料）、`mushroom`（蘑菇）、
`obsidian`（黑曜石）、`flask`（瓶子）。

**每一种资源都有完全对称的 4 个技能：**

```
o_skill_{资源}_value          单价
o_skill_{资源}_value_rare     稀有变体的单价
o_skill_{资源}_increase       每次给的数量
o_skill_{资源}_final          终级突破（该类资源的毕业升级）
```

再叠加玩家身上的两个属性：`bonus_player_{资源}_amount`（数量）
和 `bonus_player_{资源}_frequency`（频率）。

于是产出是个**三层独立乘算**：

```
产出 = amount（每次多少） × frequency（多久一次） × value（每个值多少）
```

**每个维度单独升级、互相乘算。** 玩家永远能找到"当前最便宜的那一档"去点，
而不是干等一个巨大的数字慢慢涨。

> **可复用手法：产出不要用一个数，拆成「数量 × 频率 × 单价」三层。**
> 三层各有各的升级线，选择空间立刻放大三倍。

### 1.4 双武器系统（各约 100 个技能）

| 武器 | 技能数 | 升级维度 |
|---|---|---|
| `bubble`（气泡） | 96 | damage、fire_rate、ammo、reload_speed、critical_chance / critical_damage、penetration、projectile_size / speed、life_time、execute_threshold、extra_shot_chance、first_strike、smite… |
| `plasma`（等离子） | 106 | 上面那套 + chain_damage / chain_number、explosion_chance / damage、lightning_chance / damage / range、overheat_damage / speed、start_speed… |

两套武器**各自独立成长、风格不同**（等离子多了连锁/爆炸/闪电这类 AOE 维度）。
玩家在两套之间切换，成长感翻倍。

### 1.5 深度分区 —— 纵向进度换场景

5 个生物群系：`ds_shallows`（浅滩）、`ds_swamp`（沼泽）、`ds_magma`（岩浆）、
`ds_glacial`（冰川）、`ds_island`（岛）。

- 每区有独立技能：`o_skill_biodiversity_{shallows,swamp,magma,glacial}`
- 深度用**米**计（`meters_abbreviation`），成就按深度分档 `ACH_DEPTH_01~04`
- 调试变量直接叫 `dbg_biome_depth` / `dbg_biome_index`

**数字变大是抽象的，往下潜到第 4 个生态区是具体的。**

### 1.6 经济与自动化的第二层循环

- **商店（40 个技能）**：`sell_speed`（卖出速度）、`extra_sell_chance`（额外卖出几率）、
  `transmutate_chance`（转化几率）、`inventory_slot_number / capacity`（库存槽位数量与容量）、
  `expedition_sell_speed_times`
  → 收集来的东西要"卖出去"才变成钱，多了一整层循环
- **转化器（18 个）**：`o_skill_transmutator_*`，把低级资源转成高级
- **友方单位**：`friendly`（14）、`starfish`（12）、`robot`（12）、`chain`、`doppel`
  → 自动战斗，把主动操作逐步变成挂机

### 1.7 技能总数与各系统规模（实测 535 个技能对象）

```
plasma 106   bubble 96   store 40   oxygen 38   jellyfish 26
player 20    transmutator 18   friendly 14   starfish 12   slot 12
robot 12     biovalue 12   alchemy 12   submarine 8
scrap 8      pickup 8      obsidian 8   mushroom 8   crystal 8
biodiversity 8   storage 6   shock 6   movement 6
faster 4     entity 4      chest 4     chain 4      agile 4
```

### 1.8 两个侧面证据

- 制作名单里有 **`credit_balancing`（数值平衡师）** 的独立署名 —— 数值是专门一个岗位
- 有 **demo 版限制**：`demo_level_max`、`demo_lock`、`inst_demo_lock`
  → 用等级上限做试玩版阉割，而不是砍内容
- `Update Skill Prices` 这个函数名说明**技能价格是动态重算的**
- `Price - Level {0}` 是价格显示格式（价格与等级绑定显示）

## 二、另外四款的数值提升，各学一点

### 2.1 点击宝箱（Click the Button）

**提升形式**：`price_values` / `add_values` 两个手填数组（详见配套笔记）。

值得学的一点 —— **用一个数组长度表达两种升级形态**：

```gdscript
func _is_repeating() -> bool: return add_values.size() == 1
```

`add_values` 只有 1 项 = 重复型（固定价、无限买）；多项 = 有限型（有满级）。

**稀有度阶梯**：common(1e1) → uncommon(1e3) → rare(1e5) → epic(1e8) →
legendary(1e11) → mitic(8e13)，每档差约 1000 倍。

### 2.2 财富磨坊（Fortune Mill）

**加算池 / 乘算池分开**（增量游戏数值的命门）：

```csharp
if (comboTypeArray[num] == 1)
    attributeMuls[idx] *= 1.0 + knowledgePower;   // 乘算
else
    attributeVals[idx] += knowledgePower;         // 加算
```

**转生（Knowledge）公式**：

```csharp
double num = level * (Math.Floor((type + 1) / 10.0) + 1.0) / 100.0;
```

每 10 个 type 一个台阶 —— 越靠后的条目，每级收益越高。
成本减免那一类（type 3）走另一套：显示时 `1 - 1/(1 + num/100)`，永远减不到 0 以下。

### 2.3 咖啡星球工匠（Astro Prospector）

**局内与永久严格分离**：

```
Domain.Rogue      ShipStats / RogueState / ShipRecord   ← 局内
Application       DoPrestige                            ← 跨局转生
```

这是"一局一局的增量"的架构范本，直接对应海龟那种 expedition 结构。

### 2.4 丁东王（Hole Is Mine）

拆不动（metadata v39），无数值资料。

## 三、横向提炼：数值提升可以抄的 8 个手法

按"学谁"归类：

| # | 手法 | 学谁 | 具体做法 |
|---|---|---|---|
| 1 | **把最硬的限制做成可交易资源** | 海龟 | 氧气既是倒计时，又能换伤害/资源 |
| 2 | **产出拆三层：数量 × 频率 × 单价** | 海龟 | 三个维度各有升级线，互相乘算 |
| 3 | **约束拆多维** | 海龟 | 氧气拆成 上限/回复量/回复速度/拾取 |
| 4 | **加算池与乘算池分开，先加完再乘** | 财富磨坊 | `attributeVals[]` + `attributeMuls[]` |
| 5 | **数值进表不进公式** | 点击宝箱 / 财富磨坊 | 手填数组 或 `generated/` 表格生成 |
| 6 | **一个数组长度表达有限/无限** | 点击宝箱 | `add_values.size() == 1` |
| 7 | **纵向前进度换场景** | 海龟 | 5 个生态区，每区独立技能 |
| 8 | **局内与永久状态分开存** | 咖啡星球工匠 | `Domain.Rogue` vs `DoPrestige` |

### 两条最值钱的

**① 限制要能花掉。** 海龟的氧气是唯一的硬约束，但它同时是资源 ——
玩家可以主动烧掉它换这一趟的收益。这一步让"被动等待"变成"主动决策"，
是整个设计的胜负手。别的增量游戏没有这层，所以后期只能干看着数字涨。

**② 产出要能拆开升。** 一个"每秒 +10"的升级，玩家感知是模糊的；
拆成"每次 +2 / 每 3 秒一次 / 每个值 1.5"三条独立的线，
玩家每次都能挑最便宜的那条点 —— 点击欲望和节奏感都出来了。

## 四、如果要动手做，最小验证路径

1. 先做**一个硬约束 + 一个出口**（比如氧气 + 氧气换伤害），这是海龟的骨架
2. 再做一个资源的**三层产出线**（数量 × 频率 × 单价）
3. 加算/乘算双池从第一行代码就分开，别等后面重构
4. 数值全部走表（哪怕先用一个 CSV），不要写死在代码里
5. 只放 5 个升级 + 1 次转生，自己玩两小时看手感

**手感对了再堆内容，不对就趁早改。** 535 个技能是结果，不是起点。

## 五、附录：具体数值（能挖到的都在这）

### 5.1 财富磨坊 —— 232 个升级，完整数值表

数据来源：`src/generated/UpgradeDatabase.cs`（表格生成，232 条 `UpgradeContainer`）。
每条含 **基础价 / 价格倍率 / 最大级数 / 前置 id** —— 价格走公式：`基础价 × 倍率^等级`。

**基础价分布（跨度 15 个数量级，从 3 到 5e15）**

| 数量级 | 个数 | | 数量级 | 个数 |
|---|---|---|---|---|
| 1e0–1e1 | 21 | | 1e6 | 47 |
| 1e2 | 25 | | 1e7 | 14 |
| 1e3 | 35 | | 1e8 | 9 |
| **1e4** | **49**（最多） | | 1e9–1e15 | 8 |

中位基础价 **50,000**。

**最大级数分布**

| 上限 | 个数 | 说明 |
|---|---|---|
| **1 级** | **79** | 一次性解锁类，价格固定 |
| 10 级 | 15 | |
| 20 级 | 20 | |
| 25 级 | 11 | |
| 50 级 | 10 | |
| 100 级 | 5 | |
| **无限** | **53** | 后期无限成长 |

**价格倍率分布（几个高频值）**

```
×1.0   44 个（固定价，多为一次性解锁）
×1.3    9 个      ×1.35   7 个      ×1.5    5 个
×2.0   16 个      ×3.5   10 个      ×5.0    7 个
×10.0  27 个      ×15.0   5 个
极端值：×400 / ×500 / ×1000 / ×5000 / ×10000 各 1–2 个
```

**典型条目（前几条，看出链条结构）**

| id | 名称 | 基础价 | 倍率 | 上限 | 前置 |
|---|---|---|---|---|---|
| 0 | Million Nugget Bribe | 1,000,000 | ×1.0 | 1 | — |
| 1 | Better Nuggets | 8 | ×1.2 | 25 | — |
| 2 | Valuable Nuggets | 100 | ×1.3 | 25 | ← 1 |
| 3 | Expensive Nuggets | 7,000 | ×1.75 | 20 | ← 2 |
| 4 | Priceless Nuggets | 10,000,000 | ×3.5 | 无限 | ← 3 |
| 5 | Shiny Nuggets | 4,000,000 | ×1.45 | 40 | ← 2 |
| 14 | Bigger Bullseye | 30 | ×1.6817928305 | 无限 | ← 1 |

**两条从数据里读出来的规律：**

1. **倍率与级数大致成反比。** 级数多的用低倍率（25 级 → ×1.2~1.3），
   级数少的用高倍率（10 级 → ×2.0~3.5，1 级 → ×1.0 固定价）。
   不然要么几级就买不起，要么涨得像没涨。
2. **高倍率 + 无限级 = 软上限。** 比如 ×3.5 的无限级，到第 25 级价格已经 8e20，
   玩家自然停在那里。**不用写死 max level，靠倍率就能做出事实上的封顶。**
   （反过来，79 个 1 级项说明"解锁型"内容也占很大比重 —— 增量游戏不只是堆数字。）

### 5.3 海龟 —— 数值拿不到，原因记录

尝试过两条路，都堵了：

1. **data.win 里没有 `CODE` 段。** 实际能定位到的段只有
   `GEN8`(8) / `OPTN`(304) / `OBJT`(393136) / `ROOM`(562048) / `SPRT`(20640) /
   `TXTR`(1361536) / `AUDO`(2262544) / `STRG`(998384)。
   → 这是 **YYC（YoYo Compiler）编译**：GML 被编成原生机器码放进 exe，data.win 只剩数据。
2. **扫 Shelldiver.exe 的 double 常量**：18,707 个候选，
   但去重后全是 ±9.9e14 这类编译器/资源噪声，**无法与变量名建立对应关系**。

另外 FORM 头被破解版改过（声明 344MB / 实际 2.2MB），按长度跳转会越界，
只能靠搜 magic 定位 —— 好在这招对数据段有效。

**结论：海龟的数值要拿到得反汇编 exe（IDA/Ghidra）去定位 GML 常量表，
属于硬核逆向，投入产出比很低。** 目前记下的 535 个技能与完整变量体系
（`bonus_*` / `o_skill_*`）已经足够复刻它的**结构**，缺的只是每级的具体数字。

### 5.4 三个游戏的数值量级横向对比

| 游戏 | 升级条目 | 数值跨度 | 定价方式 |
|---|---|---|---|
| 点击宝箱 | 62 | 10 → 1e+17（17 个数量级） | 手填数组 |
| 财富磨坊 | 232 | 3 → 5e+15（15 个数量级） | 公式 `基础价 × 倍率^级` |
| 海龟 | 535（技能对象） | 未取得 | 未知（有 `Update Skill Prices`） |

**共同点：都跨 15 个以上数量级。** 这是增量游戏的硬指标 ——
如果数值跨度只有 5~6 个数量级，后期数字就"不够看"了，玩家会失去增长感。
