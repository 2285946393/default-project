**四个必须知道的技术点**：

1. **接口形态先看 `/gradio_api/info`** —— 用 API 域名 + 令牌敲它，会返回全部 21 个端点
   和每个参数的**名字、类型、默认值**。比瞎猜参数快一百倍。
2. **参考音频要先上传**：`POST /gradio_api/upload`（表单字段名就叫 `files`）→
   返回一个服务端路径 `/tmp/gradio/<一长串>/<文件名>`，再把这个路径当 `prompt` 参数传进去。
   ⚠️ **直接塞一个网上 URL（比如 GitHub 上的示例 wav）会失败** ——
   服务端会真去下载它，404 就报 `404: Not Found`，**0.6 秒就返回**，别以为是参数写错了。
3. **结果的音频也必须从 API 域名下载**：`<API域名>/gradio_api/file=<服务端路径>`。
   换成 `.ms.show` 域名、或者不带令牌，都是 **403**。
4. **一次生成 = 两步**：先 `POST /gradio_api/call/gen_single` 拿一个 `event_id`
   （0.7 秒就返回，**这不代表生成完了**），再
   `GET /gradio_api/call/gen_single/<event_id>` 读 SSE 流，
   期间每 15 秒一个 `heartbeat`，最后 `event: complete` 才带结果。

**实测数字**：

| 项目 | 实测值 |
|---|---|
| 冷启动第一次 | **47.8 秒** |
| 之后每一句 | **2.4 ~ 3.0 秒**（6.5 秒的句子） |
| 输出格式 | 22050 Hz / 单声道 / 16 bit WAV，约 286 KB（6.5 秒） |
| 语言参数 | `ZH` / `JA` / `EN` |
| 时长系数 `duration_factor` | 1.0 正常，1.2 = 慢 20%（治"语速不对"） |

**音色稳不稳（用户最关心的）—— 2026-10-14 补测完成**

> ✅ **结论先说：音色本身很稳，飘的是"时长"。**

同一段参考音频 + **同一句话**，串行连跑 4 次
（第 1~3 次 `do_sample=True`，第 4 次 `do_sample=False`）：

| 第几次 | 时长 | F0 中位数 | 响度 RMS | 与别次的频谱相似度 |
|---|---|---|---|---|
| 第 1 次 | 6.34 s | 279.1 Hz | 0.1563 | 0.9599 ~ 0.9853 |
| 第 2 次 | 6.14 s | 279.1 Hz | 0.1606 | 0.9599 ~ 0.9912 |
| 第 3 次 | 6.42 s | 282.7 Hz | 0.1585 | 0.9752 ~ 0.9912 |
| **第 4 次（确定性）** | 6.50 s | 279.1 Hz | 0.1589 | 0.9794 ~ 0.9872 |

- **基频中位数四次的差 ≤ 1.3%**，频谱相似度 **0.96 ~ 0.99**
  ⇒ **听起来就是同一个人，音色不飘。**
- **飘的是时长**：6.14 ~ 6.50 秒，波动 **5.6%**（≈ 0.36 秒）—— 同一句话每次的停顿略有不同。
- **`do_sample=False` 并不会更稳**（这一遍 6.50 秒反而最长）：它只关掉采样，别的随机项还在。
- 跨句子的旧数据（3 段不同文本）：F0 中位数 282.7 / 279.1 / 272.2 Hz，相似度 0.935 ~ 0.958 ⇒ **也不飘**。

**那用户说的"飘"到底是什么？** 数据只支持两种解释：

1. **不是 IndexTTS 的锅** —— 是他之前用的那套（nova / voxcpm2 那条线）；
2. 或者指的是**停顿/语速每次不一样**（听感上"跟上次不太像"），而不是音色变了。

👉 **最终裁判是耳朵**：`D:\work\AI产出\魔搭跑通\IndexTTS-2.5\音色稳定性-同一句话4次.wav`
（27.2 秒，同一句话念 4 遍，每遍之间隔 0.6 秒静音）—— **听一遍就知道飘不飘**。

⚠️ 另外量过：拿同一把尺子量用户那 4 段 voxcpm2 老样本，相似度 0.954 ~ 0.978，
**比 IndexTTS 还略高**。所以这个指标**不能用来吹 IndexTTS 更好**，只是证明它及格。

**⚠️ 本次踩的坑：别猛刷，队列会堵**。为了测"同一句话重复生成稳不稳"，
一口气提交了 12 个任务，结果服务端排队直接堵死，后面的请求等了 **150 秒还在 heartbeat**。
教训有三：

- 创空间是**作者出算力**，一次最多排 **2~3 个**，等结果出来再提下一批。
- 并发（同时开几个进程一起等）反而更容易失败，**串行最稳**。
- **排队时间完全不可控**：这次串行 4 个，第 1 个排了 **401 秒**（前面有别人在用），
  后 3 个只用了 57 / 9 / 5 秒。**耐心等，别重提**（重提只会让自己排得更后）。

## 二之六、✅ 2026-10-14 已跑通：HeartMuLa（给词 + 标签 → 一首歌）

做视频要 BGM，这个能**直接唱出来**（中文歌词也唱）。

- **调用地址**：`https://studio-gswyhq-heartmula.api-inference.modelscope.net`
- **端点**：`POST /gradio_api/call/generate_song_with_cli`

**6 个入参**：

| 参数 | 含义 | 怎么写 |
|---|---|---|
| `lyrics_text` | **歌词** | ★ **必须带结构标记**：`[前奏] / [主歌] / [副歌] / [尾奏]`（服务端会自动转成 `[Intro]/[Verse]/[Chorus]/[Outro]`） |
| `tags_text` | 风格标签 | 英文逗号分隔，如 `pop,happy,piano` |
| `max_duration` | 最长时长（**毫秒**） | 60000 ~ 600000 |
| `topk` | 采样范围 | 默认 50 |

## 二之七、✅ 2026-10-14 已跑通：MinerU（PDF → Markdown，5 秒一篇）

`OpenDataLab/MinerU`（30.4 万热度，官方）。**能把 PDF / 扫描件直接转成干净的 Markdown**。

- **调用地址**：`https://studio-opendatalab-mineru.api-inference.modelscope.net`
- **端点**：`POST /gradio_api/call/convert_handler`
- **4 个入参**：`[PDF文件, 档位(默认2), 页码范围(''=全部), 强制OCR(False)]`

### ⚠️ 它返回 **16 项**，而且大部分是给网页用的垃圾 —— 只有 `[15]` 有用

| 第几项 | 是什么 |
|---|---|
| `[0]` | 状态面板 HTML（**没用**） |
| `[1]` | 渲染好的 HTML 预览（塞在 iframe 的 `srcdoc` 里，约 20 KB） |
| `[2]` | **`layout.pdf` —— 版面分析可视化**（框出每一块在哪，想核对解析对不对就看它） |
| `[7]` | 任务 id |
| `[8]`~`[14]` | 一排格式按钮（Markdown / JSON / HTML / DOCX / LaTeX / EPUB / PDF） |
| **`[15]`** | ★ **结构化 JSON，这才是要的东西** |

`[15]` 长这样：`{"pages":[{"page_idx":0,"blocks":[{"type","bbox","content"},…]}]}`

**关键**：`content` 里**已经是 Markdown 语法了**（`**加粗**`、表格都带），
所以只要按 `type` 加标题符号就行：

| `type` | 拼成 |
|---|---|
| `header` | `# 内容` |
| `paragraph_title` | `## 内容`（`level` 字段决定几个 `#`） |
| `text` / `table` / `equation` | 原样贴 |
| `image` | 注释掉（图片内容在 `content` 里） |

## 二之八、视频生成：三个屋的接口已探明（2026-10-14）

**同一家（`gswyhq`）开了三个视频屋，分工不同**：

| 屋 | 有什么口 | 备注 |
|---|---|---|
| `gswyhq/LTX-2` | 文字→视频、图→视频、**图+音频→视频**、音频→视频 | ⚠️ **它的上传口挂了**（见下面坑） |
| `gswyhq/MiniMax-H3` | 文字→视频、图→视频、**首帧+尾帧→视频** | 首尾帧 = 给两张图，中间自动补动画 |
| `gswyhq/LongCat-Video` | **图+音频→视频**（一个口），带**人声分离**、480p/720p | 专门做"让立绘跟着声音动" |

**参数套路三家一模一样**（记住这五个就够）：

| 参数 | 含义 | 常见值 |
|---|---|---|
| `prompt` | 画面描述 | 中文也能写 |
| `aspect_ratio` | 画面比例 | `16:9` / `9:16`（竖屏）/ `1:1` / `3:4` … |
| `short_side` | **短边像素**（越小越快越省） | `256` / `480` |
| `duration` | 秒数 | 默认 `5` |
| `fps` | 帧率 | 默认 `24` |

**返回 2 项**：视频文件 + 一段状态日志。

### ⚠️ 坑：某个屋的"上传口"会单独挂（2026-10-14 实撞）

`LTX-2` 的 `/gradio_api/info` 返回 **200**（屋是活的），但 `/gradio_api/upload` 返回
**502 Bad Gateway**（nginx）。同一张图传另外三个屋**全是 200**。

⇒ **不是令牌问题、不是代理问题、不是图片问题，是那个屋的上传服务坏了。**

**通用排查法（很省时间）**：图片/音频传不上去时，
**拿同一个文件再传另一个屋** —— 立刻能分清是"我的问题"还是"它的问题"。
（别对着一个 502 反复重试，502 是 nginx 说的，重试没用。）

### ⚠️ 坑 2：`info` 会**少列参数**，而少的那一个往往是"登录态"

`MiniMax-H3` 的 `/process_i2v`，`/gradio_api/info` 明明只列了 **6 个**参数，
提交 6 个却报：

```
An event handler (process_i2v) didn't receive enough input values (needed: 7, got: 6).
```

补一个占位当第 7 个，服务端就换了句话：

```
🚫 请先使用 ModelScope 账号登录！
```

⇒ **那个第 7 个是隐藏的"登录用户状态"组件**（Gradio 的 `gr.State`），
它**不出现在 `info` 里，但算一个输入**。纯令牌调用喂不进去，**这条路只能网页手点**。

**判断口诀**：

- 报 `needed: N, got: N-1` ⇒ **先补一个占位试**（随便 `None` 或空串）；
- 补完变成 **"请登录"** ⇒ **这个口是给网页用的**，API 走不通，**别硬啃**，换屋。

（Gradio 的 `/gradio_api/info` 只给 `named_endpoints`，**不含 `dependencies`**；
想看完整依赖表要 `/gradio_api/config`，但魔搭这边 `/config` 返回 `{"detail":…}` 拿不到。
所以"少列参数"只能靠**报错信息反推**。）

|---|---|---|
| ✅ **`lf3000y/ai-studio`**（**朋友三千**，最高优先级） | **OpenAI 兼容口** `POST /v1/chat/completions`，`model=TaichuAI/ZDTaichu5.0-9B`，图用 base64 塞 `image_url` | **29 秒**，问"反推提示词"就给一段完整英文 prompt，**还看出图里藏的细节**（粉围巾小人、松树剪影） |

```python
body = {"model": "TaichuAI/ZDTaichu5.0-9B", "messages": [{
    "role": "user",
    "content": [
        {"type": "image_url", "image_url": {"url": "data:image/png;base64,<图>"}},
        {"type": "text", "text": "反推一段能复现这张图的英文提示词，只输出提示词"}

# POST https://studio-lf3000y-ai-studio.api-inference.modelscope.net/v1/chat/completions
```

**反推实测样本**（输入：蚂蚁出的鲸鱼极光图）：
> A 2x3 grid of cartoon illustrations featuring a large blue whale flying through a starry night sky with an aurora borealis in the background. In some panels, a small, cute, round character with a pink scarf is riding on the whale's back...

**问法影响输出**：要"提示词"就说**「只输出提示词，用一段话」**，不然它会写成作文。
