## 一、今日产出

### 1. 小站评论系统正式上线（Gitalk）
- 现象：/tree、/music、/friends、/about 和两篇文章的评论区全在裸奔报错——`api.github.com/repos///issues`，owner/repo 是空的
- 修复：GitHub 建公开仓库 `blog-comments` + 创建 OAuth App（Ov23li 开头），填入 `siteConfig.gitalkConfig` 五项
- 防御：5 处消费端（Comments / LabComments / MomentComments / AlchemyLab / DijiangModel）全部加了空配置守卫，以后配置再空也不会对游客报错
- 复测：6 个页面 console 清零、评论区正常渲染「来做第一个留言的人吧」
- 遗留：每个页面的评论 Issue 需要站长 GitHub 账号首登初始化一次

### 2. 糖果果冻罐（被毙）
- 基于 saharan/works/jelly（Haxe+WebGL2 计算着色器的果冻物理）做包裹改造
- 编译产物从 oimo.io 官方 demo 扒（182KB main.js），粉彩奶油底+樱色粒子+毛玻璃面板
- 用户判决：**「这几个颜色看着别扭，而且除了捏东西以外没有任何乐趣」**——毙
- 教训：jelly 原生只有一个果冻只能揉捏撕裂，混淆 JS 加不了玩法深度；视觉 demo 撑不起"好玩"两个字

### 3. 合成猫猫（上线）
- 玩法来源：moonfloof/suika-game（**Unlicense 公共领域**，400 行逻辑全可读），matter.js 物理
- 主题：11 级粉色进化链 🐾爪印→😺→🐱→😸→😹→😻→😼→🙀→😿→🐯→🦁猫猫大王
- 素材第一轮：canvas 手绘 11 级粉猫（径向渐变脸+三角耳+王冠）——用户判决**「UI 丑的没话说」**——毙
- 素材第二轮：换成 **Twemoji 官方彩猫 SVG**（CC-BY 4.0，base64 内嵌仅 38KB，矢量随便放大不糊），坐粉色渐变圆底徽章
- UI 糖果玻璃风重做：下一只大预览卡 + 分数卡 + 常驻进化图鉴条（养到哪级亮哪级）+ 瞄准虚线
- 音效零文件：WebAudio 合成「喵~」「啵」（音调随等级升）、「大王号角」
- 玩法增强：合成 toast 播报「心心眼猫 × 2 ➜ 嘚瑟猫！」、猫猫大王金色庆祝、最高分 localStorage
- 产物：单文件 136KB，零网络依赖

## 二、今天最值钱的发现：headless 浏览器「真输入」验证

合成猫猫是**游戏**，视觉截图证明不了可玩性。验证链路一路踩过来：

| 方法 | 结果 |
|---|---|
| Playwright 工具 | 会话中期不可用，绕 |
| Chrome headless + `--screenshot` | profile 和用户 Chrome 冲突，挂起；**只能证明渲染，证明不了交互** |
| 页面内 `dispatchEvent(new MouseEvent(...))` | **过不去 matter.js 0.19 的输入层**（探针 down:0 up:0），合成计分全 0 |
| **Edge headless + CDP `Input.dispatchMouseEvent`** | ✅ 内核真事件路径，模拟真人连投 24 猫，合成 33 分，物理/合并/胜负全验通 |

配套配方（已可复用）：
- Edge 用**独立 `--user-data-dir`** + `--remote-debugging-port`，绝不动用户开着的 Chrome
- `GET /json/list` 拿 webSocketDebuggerUrl → `websockets` 连 → `Input.dispatchMouseEvent`(mousePressed/mouseReleased) + `Runtime.evaluate` 读 DOM 状态
- 我看不了截图 → **Pillow 像素分析代替肉眼**：黄色像素占比证明 emoji 贴图渲染、平均色证明配色方向
