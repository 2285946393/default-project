## 一、为什么做这一批 —— 补两个**结构性缺口**，不是凑数

M3.9 把卡池从 16 张提到 27 张，但**质量上还有两个会让卡组中期崩掉的洞**：

### ① 易伤（Vulnerable）：整池 **0 张**

易伤是尖塔的**伤害放大器**（受到的攻击伤害 +50%）。
本体基准：Bash = **2 费 8 伤 + 2 层易伤**，它的真实价值远高于 8 点。

这是 **M3.8 时就记下的隐患**，原话：
> 「⚠️ 凛冬牌没有任何易伤来源，本体 Bash 的 2 层易伤是伤害放大器。
>   实测若『打不动』，**优先补一张带易伤的凛冬牌，而不是再削波次**。」

### ② 力量（Strength）：只有寒冰王座一张 **4 费 Rare**

力量是"养大哥"的通用货币。全池只有一张高价牌 = 成长线不存在。

⇒ 所以 M3.10 = **易伤来源 + 力量来源**，并且继续沿用 M3.9 的触发式范式。

### 数值对标（反编译本体取数，不凭感觉）
- 本体 Bash = **2 费 8 伤 + 2 易伤**
- 我们的裂霜 = **1 费 5 伤 + 2 易伤** —— 便宜一半、直伤更低，但**放大器的价值完整保留**

### 三条设计闭环
1. **易伤线**：裂霜（上 debuff）+ 霜蚀蔓延（debuff 不随目标死亡蒸发，而是**传下去**）
   ⇒ 打法因此改变：给**快死的那个**挂易伤，让它死时传染 —— 战场变成一个整体
2. **力量线**：霜锻（每回合复利）+ 极寒核心（阵亡换永久力量）
3. **殉爆线收束**（M3.9 的三选一决策树补全）：
   随从阵亡时——遗霜（要眼前输出）/ 霜之遗赠（要这回合活命）/ **极寒核心（要长期变强）**

## 三、★ 本批挖到的官方样板：`JuggernautPower`

想做「获得格挡时造成伤害」，先去反编译了本体的 **JuggernautPower**（正是这个效果），
原文：

```csharp
public override async Task AfterBlockGained(Creature creature, decimal amount, ValueProp props, CardModel? cardSource)
{
    if (!(amount <= 0m) && creature == base.Owner) {
        var enemies = base.CombatState.HittableEnemies;
        if (enemies.Count != 0) {
            var target = base.Owner.Player.RunState.Rng.CombatTargets.NextItem(enemies);
            await CreatureCmd.Damage(new ThrowingPlayerChoiceContext(), target, base.Amount, ValueProp.Unpowered, base.Owner);
        }
    }
}
```

### ★★ 两件自己想一定会想错的事

1. **`AfterBlockGained` 没有 `PlayerChoiceContext` 参数**，但 `CreatureCmd.Damage` 仍需要一个。
   官方用的是 **`new ThrowingPlayerChoiceContext()`**，**不是传 `null`**。
   （"Throwing" = 一旦真的需要玩家做选择就抛异常，因为这里本就不该有选择。）
   → 命名空间：`MegaCrit.Sts2.Core.GameActions.Multiplayer`
2. 官方联机安全的随机取目标：`Owner.Player.RunState.Rng.CombatTargets.NextItem(list)`

### 其它核实到的 API
- `Creature.GetPowerAmount<T>()` / `GetPower<T>()` —— 读死者身上的层数用这个
  （`AfterDeath` 里 creature 对象还在、Powers 还在，读得到）
- 状态能力全在 `MegaCrit.Sts2.Core.Models.Powers`：
  `VulnerablePower` / `WeakPower` / `StrengthPower` / `DexterityPower` / `FrailPower` / `PoisonPower` / `DoomPower`

### 编译踩坑
- `FrostStatePowers.cs` 缺 `using MegaCrit.Sts2.Core.Combat;`（`CombatSide` / `ICombatState` 在那）
- `IsMyTurnStart` 只在 `FrostBuildingPowerBase` 里有，触发式基类没有
  → 在 `FrostTriggerPowerBase` 里**补一份同实现的 helper**（两条线刻意不互相继承，避免耦合）

## 四、★ 顺手修了一个真 bug：「每局波次不同」从未生效

### 现象
`WaveTable.For(ulong runSeed)` 从一开始就有种子参数，但 **grep 所有调用点**：

```
FrostPactRelic.cs:99   var wave = WaveTable.All[SubWavesSpawned];   ← 真正生成波次的地方
FrostUi.cs:363/396/400/429  WaveTable.All[...]                      ← 面板预览
FrostPactRelic.cs:60   WaveTable.All.Length
```

**没有一个用 `For(seed)`**，而 `All` 写死 `For(0)`
⇒ **每一局的 16 波完全相同**，那个种子参数是个**死旋钮**。

（和 M3.7 修的 `Difficulty` / `WaveMultiplier` 是**同一类毛病**：写了没人读。）

### 修法
1. `WaveTable` 加静态绑定：`BindRunSeed(ulong)` / `RunSeed` / `IsSeedBound`，`All` 改 `For(_runSeed)`
   ⇒ **所有调用点一个都不用改**，且面板预览与实战自动一致
   （如果只改遗物不改 UI，预览会显示另一套波次 —— 那更糟）
2. `FrostPactRelic` 加 `EnsureRunSeed()` 懒绑定，两个地方调：
   - `BeforeCombatStart()` —— 正常开战
   - `BeforeSideTurnStart()` 取波次前 —— **兜底**
     ★ 为什么必须兜底：`BeforeCombatStart` **只在 `CombatManager.StartCombatInternal()` 里被调用**，
     **读档恢复战斗不走这条路**（M2 就踩过）⇒ 只在那里绑，读档局会退回种子 0。

### 种子来源
`RunState.Rng.Seed` —— 反编译确认 `RunRngSet` 有 `public ulong Seed { get; }`
（另有 `StringSeed`；`RunState` 本身没有直接暴露 Seed，要经 `Rng`）
