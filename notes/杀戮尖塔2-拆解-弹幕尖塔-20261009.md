## 0. 先纠正我自己的一个错判

我在菜单里把它写成「**玩法改造，和"类幸存者"那个可对照**」。**这是错的。**

「弹幕」在这个 mod 里指 **B 站那种横向滚动的弹幕评论**，不是弹幕射击。
它**不碰任何玩法**：不加角色、不加卡牌、不改战斗、不改数值，
清单里明写 `"affects_gameplay": false`。

真正的对照对象是 **HUD / 设置页集成类**模组（`DamageMeter`、`ModConfig` 这一线），
不是 `ref-actiongame`（假如塔2是类幸存者，那个才是真·玩法改造）。

> 教训：**中文词有歧义时先打开包看 README，别按字面猜。**
> 「弹幕」在中文游戏语境里至少有两个意思（弹幕射击 / 弹幕评论），
> 而这个作者的第一句就写清楚了。

## 1. 它到底做了什么

一句话：**监听你爬塔的每个动作 → 在合适时机从社区词条库里抽一条 → 以滚动弹幕放出来。**

- 监听面：打牌、受伤、购买、奖励、事件、火堆、SL（存读档）、Run 开始/结束
- 触发时机：**58 条规则**（编号 A1–H1 单人 + I1–I3 多人专用 + E14/F3 后补）
- 词条来源：**社区抓取 + 玩家投稿（作者人工审核）**，作者声明「模组不自行创作弹幕文本」
- 多人：队友的行为弹幕互通（**只传信号不传文本**，见 §5）
- 共创闭环：游戏内投稿 → 作者审核 → **版本化快照下发** → 全玩家本地离线播放

### 词条库盘点（`content/danmaku/rules.json`）

| 项 | 数量 |
|---|---|
| 规则组 | **58** |
| 单人词条 | **336** |
| 多人词条 | **58** |
| `narration` 旁白体 / `character` 角色体 | **259 / 77** |
| 带 `variant`（同规则变体） | 17 |
| 已填 `author` / `color` / `top` | **0**（基线快照里全空，这三字段留给 UGC 投稿） |

规则 id：`a1–a6, b1–b8, c1–c9, d1–d7, e1–e14, f1–f3, g1–g7, h1, i1–i3`
（`i*` 是多人专用，基线里 0 条词条 —— 靠 UGC 填。）

`DanmakuRuleIds.Get()` 是唯一的「触发器 → 规则 id」映射表（`:15044`），
`DanmakuTrigger` 枚举 1–58 + 100(`CombatStart` 元规则 `META-COMBAT-START`)。

## 2. ★ 机制一：逐补丁安装 + 优雅降级（**最值得抄**）

`HarmonyPatchInstaller`（`:12524`）。**核心：一个补丁装不上，绝不让整个 mod 挂掉。**

```csharp
public static IReadOnlyList<HarmonyPatchInstallResult> Install(Harmony harmony, Assembly assembly)
{
    foreach (Type item in Discover(assembly))
    {
        ...
        try { ResolveTargets(item); harmony.CreateClassProcessor(item).Patch();
              list.Add(Result(item, true, ...)); }
        catch (Exception ex2)
        {
            list.Add(Result(item, false, ex2.Message, readOnlyList, harmonyPatchImpact));
            MainFile.Log($"[Harmony] 补丁安装失败，其他补丁继续：{value} | 受影响规则 {…} | {ex2}");
        }
    }
}
```

`Discover()` 连**类型加载失败**都兜住了：

```csharp
public static IReadOnlyList<Type> Discover(Assembly assembly)
{
    try { source = assembly.GetTypes(); }
    catch (ReflectionTypeLoadException ex)   // ← 关键
    {
        source = ex.Types.OfType<Type>();    // 能加载的继续，加载不到的丢掉
        MainFile.Log("[Harmony] 当前游戏版本无法加载部分监听类型，已跳过并继续发现其余补丁：" + …);
    }
    return source.Where(t => t.GetCustomAttributes(typeof(HarmonyPatch), false).Length != 0)
                 .OrderBy(t => t.FullName, StringComparer.Ordinal).ToArray();   // ← 确定性顺序
}
```

配套：`HarmonyPatchImpact { ProducedFacts, AffectedRuleIds }` → `HarmonyCompatibilityReport`
（`:2792`）→ 写一份兼容报告落盘（`HarmonyCompatibilityReporter.Write`，`:2811`）。

> **为什么这条重要**：这正好是我们 DouSpire 启动崩溃的**反例**。
> DouSpire 的静态字段类型来自 ONNX，BaseLib 一扫描就抛，**没有 try/catch**，
> 整个游戏起不来。DanmakuSpire 用的是**同一个扫描思路（反射找补丁类型），但每步都 try**，
> 所以它经历了好几轮游戏 API 变更还活着（CHANGELOG：「修复模组在部分版本加载闪退，黑屏问题」
> 「修复模组与部分角色模组一同使用闪退，黑屏问题」）。

## 3. ★ 机制二：能力探测门（Capability Gating）

游戏 API 变了怎么办？**先探测类型在不在，不在就 return null，让 Harmony 自己 no-op。**

```csharp
[HarmonyPatch]
public static class DanmakuFrontendUiActivationPatch
{
    public static MethodBase? TargetMethod()
    {
        Type type = AccessTools.TypeByName("MegaCrit.Sts2.Core.Nodes.Screens.MainMenu.NMainMenu");
        if (!(type == null))
            return AccessTools.DeclaredMethod(type, "_Ready", (Type[])null, (Type[])null);
        return null;      // ← 类型不存在 → Harmony 直接跳过这个补丁，不抛
    }
    public static void Postfix() { DanmakuFrontendUiGate.Activate(); }
}
```

- **全部用字符串类型名**（`"MegaCrit.Sts2.Core.Nodes.Screens.MainMenu.NMainMenu"`），
  不写 `typeof(...)` —— 这样编译期就不依赖那个类型，游戏删了它也不会编译/加载失败。
- `NSettingsScreen` 用同一套（`:33719`）。
- 另外还有一套**运行期 BFS 兜底**：`DanmakuFrontendUiGate.ActivateIfMainMenuPresent()`（`:29676`）
  遍历 SceneTree，按 `GetType().FullName` 字符串比对找 `NMainMenu` —— 万一 `_Ready` 没挂上也能激活。

> **规则：跨版本 mod 的补丁目标一律走「字符串类型名 + `TargetMethod()` 返回 null 降级」，
> 不要 `typeof()`。** 这比版本号判断干净得多。

## 4. ★ 机制三：内容与程序解耦（3 层覆盖 + 远程快照）

CHANGELOG v1.2.0 原话：「**内容与功能解耦**：规则弹幕词条、角色/别名目录、可增删集合与
共创词条从程序集抽离为可下载、可替换、可校验的 JSON 内容包；硬编码仅作回退。」

三层内容（`enum ContentLayer { Baseline, Ugc, Overlay }`，`:22168`）：

| 层 | 位置 | 作用 |
|---|---|---|
| `Baseline` | `mods/DanmakuSpire/content/danmaku/ugc/` | 随包内置快照 |
| `Ugc` | `user://DanmakuSpire/content/…`（远程下载缓存） | 作者审核后的版本化快照 |
| `Overlay` | `user://DanmakuSpire/content/danmaku/ugc/` | 本地覆盖层 |

- 加载顺序 Baseline → Ugc → Overlay（后者覆盖前者），`ContentStore.Load(entries, layer)`
  返回 `ContentLoadResult(Added, Replaced, Skipped)`（`:22174`）。
- 远程源（硬编码常量，`:25988` / `:20096`）：
  - `https://dl.danmakuspire.top/version.json` ← 清单
  - `https://dl.danmakuspire.top/<shard>` ← 7 个分片：
    `characters / cards / relics / monsters / events / acts / turns`（`.json`）
  - `https://danmaku.danmakuspire.top` ← 投稿/反馈/点赞 API
- 同步是**后台 Task + 主线程回投**（`TryStartUgcSync`，`:1618`）：5 秒超时，
  失败只打日志，**不阻塞启动**；成功才 `ClearContent()` → 重载。
- 投稿走 `SubmissionClient`（`:24676`）+ `CloudApiContract`（`:20064`），
  `DeviceIdentity.GetDeviceId()` 做匿名标识。

> **可抄的**：想让玩家不用重下 mod 就能更新内容，就照这个做
> —— 内容全 JSON、分片下载、3 层覆盖、失败静默降级。

## 5. ★ 机制四：多人「只传信号不传文本」

README 原话：「**只传信号不传文本（防注入）**，队友弹幕本地渲染；握手确认模组版本」。

4 个网络消息类型（`namespace .Core.Multiplayer`，`:19094`）：

| 类型 | 传什么 |
|---|---|
| `ZzzDanmakuHandshakeMessage` | 只有 `ModVersion` 字符串（握手，`ShouldBroadcast=true`） |
| `ZzzDanmakuNetMessage` | `Trigger(int) / EntryIndex / Variant / SourceCharacterId / SourcePlayerNetId / CorrelationId / Scope / ContextRefs` |
| `ZzzDanmakuChatMessage` | 玩家手打聊天文本 |
| `ZzzDanmakuUgcMessage` | `EntryId`（UGC 词条 id，不是文本） |

**关键设计**：
1. **规则弹幕传的是 `EntryIndex`（词条下标），不是文本** —— 接收方拿本地词条库渲染。
   → 恶意/异常客户端**无法往别人屏幕里塞任意文本**。
2. **握手按版本过滤**：`DanmakuMultiplayerState.RecordPeer(netId, modVersion)` 只在
   `modVersion == ModVersion` 时记入 `_compatiblePeers`（`:14959`）；
   不兼容的 peer 收到消息时**只回握手**，不处理内容。
3. **反序列化全程防炸**（`:19185`）：每个字段 try/catch、超长字符串丢弃、
   `Corrupt` 标记、`ContextRefs` 上限 16 且 key 去重。
4. **限流 + 去重**（`DanmakuNetworkForwarder`，`:19236`）：
   - 全局 **40 条/秒/发送者**，分类限流 `Rule 30 / Ugc 20 / Chat 5`
   - `CorrelationId` 去重窗口 **4096**
   - 收到就校验：`Enum.IsDefined(Trigger)` / `Enum.IsDefined(Scope)` /
     `ContentValidator.CountTextCharacters(text) <= 40` / `IsValidAvatar(...)`

> **可抄的**：我们要做联机 mod（斗地主 netcode），这套「**传 id 不传文本 + 握手卡版本 +
> 限流 + 相关性去重 + 逐字段防炸反序列化**」是现成的安全模板。
> 配合记忆里那条 `PlayerChoiceSynchronizer`（游戏自带的「选一个 int 并全网同步」原语）
> 一起用。

## 6. 机制五：弹幕调度（表现层工程学）

- **`RollingDanmakuPlanner`**（`:5209`）：一次触发要放 N 条时，**时间间隔不是均匀分布**，
  而是分段采样：
  - 第 1 条：0.1–0.4s（快）
  - 中间条：截断正态 `μ=1.6 σ=0.5`，夹在 [0.55, 2.75]
  - 最后一条：3.3–4.5s（N≥6 时 4.0–5.6s）
  - 然后**整体 shuffle** —— 让「有快有慢」自然，不像机器定时器。
  - 正态用 **Box-Muller + 12 次重采样拒绝法**，不是简单 clamp。
- **顶部弹幕概率**：`Light 0.0 / Medium 0.15 / Strong 0.3`（`BaseTopProbability`，`:5332`）。
- **`RollingLaneAllocator`**（`:7880`）：4–12 条可调轨道，分配不重叠。
- **`ShuffleBag`**（`:24616`）：**不重复抽样**——抽过的进 `_drawn`，
  抽空后 `allowReshuffle` 才清空重来；`Restore()` 支持从存档恢复已抽集合。
  → 玩家不会连着看到同一条弹幕。
- 表现用**原版资源**：原版静态烟雾九宫格、官方字体、角色头像
  （`DanmakuEmojiFont` `:3574`、`DanmakuEmojiPicker` `:3674`）。

## 7. 机制六：规则引擎分层（事实 → 规则 → 生命周期门 → 信号 → Hub）

```
游戏事件
  └─ [33 个 HarmonyPatch]  ← .Monitor.Rules
       └─ 发布 GameFact（带 Lifecycle / Scope / Boundary / Phase）
            └─ GameFactBus
                 └─ RuleConsumer（Combat / Reward / NonCombat / Multiplayer 四组，:13565）
                      └─ RuleLifecycleGate.Evaluate(header, current, phase, …)  ← :18949
                           └─ ConditionResult.Match/Miss(reasonCode)   ← 每个都带原因码
                                └─ DanmakuHub.Dispatch(signal, evidence)  ← :14754
                                     ├─ 本地 Emit
                                     └─ 网络 Forward（多人）
```

值得注意的细节：

- **`Dispatch(DanmakuSignal)` 单参版本被 `[Obsolete(..., true)]` 标成编译错误**
  （`:14748`）：`throw new InvalidOperationException("缺少 RuleEvidence 的本地 Dispatch 已禁用。")`
  → **强制每条弹幕都必须带证据**，否则不给放。这是「审计优先」的硬约束。
- 每个判定都返回 **`ConditionResult.Match(reason)` / `.Miss(reason)`**，
  而不是 bool —— 所以日志/遥测能回答「这条规则为什么没触发」。
- `EmissionScopePolicy.FromPhase(phase)`：由阶段推导可见范围。
- 遥测：`RuntimeTraceRecorder`（`:2994`）记录 Fact / Rule / Dispatch / Emission 四级，
  落盘到 `user://DanmakuSpire/coverage`，配套 `CoverageProof` / `RuleObservationSummary`
  —— **作者在用实机数据反推「哪条规则从没触发过」**。
- 诊断命令：`danmaku_audit [read|reset|mark|status|harmony]`、`danmaku_diagnostics`、
  `danmaku_fixture`、`danmaku_settings`（都是游戏 `AbstractConsoleCmd` 子类，`:43771`）。

## 8. 设置页集成（HUD 类模组该抄的）

`DanmakuSettingsScreenPatch`（`:33719`）：挂 `NSettingsScreen._Ready` Postfix，
往 `%GeneralSettings/VBoxContainer` 里**在「发送反馈」行上方插入自己两行**
（「模组配置」+「投稿弹幕」），并复用原生行/按钮组件、手动接好
`FocusNeighborTop/Bottom`（手柄导航）、加分割线。

降级链条（每一层失败都只打日志、不崩）：
1. 找不到 `NSettingsScreen` 类型 → 补丁自动 no-op
2. 找不到 `%GeneralSettings` / `SendFeedback` → `Log("[ConfigUI] 当前游戏版本未找到设置页发送反馈行，跳过设置页入口。")` → `return false`
3. 面板建不出来 → **控制台命令 `danmaku_settings open` 兜底**（README 原话：
   「若某个游戏版本的设置页结构发生变化，还可在游戏控制台输入 `danmaku_settings open` 打开同一面板」）
4. 设置面板**自研**（不用游戏/框架的设置系统），配置存
   `user://DanmakuSpire/settings.json`，旧配置首次启动自动迁移、旧文件保留可回退

> **可抄的**：往原生设置页插入口时，**永远准备一个控制台命令兜底**。
> 顺便发现：**游戏有 `AbstractConsoleCmd` 这个基类**（`MegaCrit.Sts2.Core.DevConsole.ConsoleCommands`），
> mod 可以注册自己的控制台命令。

## 9. 横向对照：和已拆的谁像、谁不像

| 维度 | 弹幕尖塔 | 假如塔2是类幸存者（ref-actiongame） | 我们的 DouSpire |
|---|---|---|---|
| 是否改玩法 | **否**（`affects_gameplay:false`） | **是**（整体改造） | 是（斗地主玩法） |
| 依赖框架 | **无** | — | 无（自研） |
| 补丁安装 | **逐个 try，坏了丢那一个** | — | **一次性，静态字段炸就全崩** |
| API 兼容策略 | **字符串类型名 + TargetMethod→null** | — | 直接调，撞 API 变更 |
| 内容存放 | **外置 JSON + 3 层覆盖 + 远程快照** | — | 内嵌 |
| 联机 | **只传信号不传文本** | — | 自研 netcode |
| 诊断 | 四级遥测 + 4 个控制台命令 + 兼容报告 | — | 日志 |

**结论：它不是玩法改造样本，是「兼容性工程 + 内容工程」的样本。**
真正该对照的是它和 DouSpire 的**反面**关系 —— 它把 DouSpire 踩的坑全避开了。

## 10. 对我们 4 个 mod 的可复用结论（给国内 WB）

1. **补丁安装器**：把 `HarmonyPatchInstaller` 的 `Discover()` + 逐条 try 抄过来。
   能顺带解决「一个补丁目标在新版本没了 → 整个 mod 不加载」。
   （注意：这条**只治 Harmony 补丁**，治不了 DouSpire 那个**静态字段**触发的崩溃 ——
   那个得靠 `[ModuleInitializer]` 提前 `Assembly.LoadFrom` 或改字段类型，见
   `notes/斗地主尖塔-启动崩溃诊断-ONNX依赖-20261009.md`。）
2. **能力探测门**：所有跨版本补丁目标改「字符串类型名 + `TargetMethod()` 可返回 null」。
3. **内容外置**：词条/配置类数据别内嵌，走 JSON + 分片 + 3 层覆盖。
4. **联机安全模板**：传 id 不传文本 + 握手卡版本 + 限流 + 相关性去重 + 逐字段防炸。
5. **设置入口兜底**：插原生设置页时配一个控制台命令。
6. **诊断优先**：判定返回带原因码的结果，而不是 bool。

## 12. 一句话给用户

这个 mod 不是「弹幕射击」，是**把 B 站的弹幕评论搬进了尖塔**：
你打牌、受伤、买错东西，屏幕上有"人"在吐槽你。作者一个人做完了
内容库、设置界面、联机、投稿审核、远程更新全套，
**而且是用"每个零件坏了都能单独扔"的方式拼起来的** —— 这就是它能熬过好几轮
游戏 API 变更还活着的原因，也是我们 DouSpire 最该学的地方。
