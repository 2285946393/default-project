## 零、为什么拆这个

我们自己的 mod 特效「乏力」，本质上不是不会写 shader，而是**没有一套骨架**：

- 特效场景怎么摆？坐标从哪算？
- 打牌的时候，特效应该挂在哪个时机？
- 怎么让它从"出牌的人"射向"被打的人"？
- 打包成 pck 之后为什么加载不出来？

万象辉星是**给储君（Regent）职业的 20 多张卡逐个还原卡面特效**的 mod，玩家口碑好，
而且它是**纯 C# + 纯 Godot 资源**的干净样本（没有乱七八糟的引擎插件）。
把它拆开，上面四个问题全都有现成答案。

拆解方法（照项目规矩，不靠"我记得"）：

```
1. 抽 pck   → tools/extract-pck-files.py
2. 反编译   → ~/.dotnet/tools/ilspycmd.exe   （关键！见第 2 节）
3. 对答案   → 拿它的着色器/场景跟本体 sts2 的比，看它抄了什么、改了什么
```

## 一、装机清单：一个特效 mod 由什么组成

```
3747497501/
├── RegentFX.dll    245,760 B   ← 代码（编译好的 IL，没有源码）
├── RegentFX.json       404 B   ← 清单
└── RegentFX.pck 60,716,376 B   ← Godot 资源（场景/材质/着色器/贴图）
```

`RegentFX.json` 全文（**这就是模组清单的标准格式，直接抄**）：

```json
{
  "id": "RegentFX",
  "name": "万象辉星[RegentFX]",
  "author": "Vitech,SSSuika,Margaritana",
  "description": "为储君的部分卡牌按照卡面还原了特效。Q群1042906424。\n...",
  "version": "0.5.1",
  "has_pck": true,
  "has_dll": true,
  "dependencies": [],
  "min_game_version": "0.103.0",
  "affects_gameplay": false
}
```

要点：
- `has_pck: true` + `has_dll: true` —— **代码和资源可以分家**，dll 管逻辑，pck 管美术。
- `affects_gameplay: false` —— 纯特效 mod 要显式声明。**这条很关键**：
  联机时它告诉对方"这个 mod 不改玩法"，所以联机双方对不上 mod 也不会判定为不同步。
- `min_game_version` —— 游戏版本比这低就不加载。

## 二、⚠️ 第一个大坑：pck 里的 `.cs` 全是 1 字节

一开始我按老办法把 pck 全抽出来，结果 **61 个 `Scripts/*.cs` 全变成 1 字节**，
读出来是空的。看着像解包器写错了，其实**解包器没毛病**。

回到 pck 原始目录里核对每条的 `size` 字段：

```
.cs 条目共 61 条
  size=1  @59293680  'Scripts/Entry.cs'                  raw=b'\n'
  size=1  @59293696  'Scripts/MyNLargeMissile.cs'        raw=b'\n'
  size=1  @59292832  'Scripts/Patches/CardAnimPatch.cs'  raw=b'\n'
  ...
```

**pck 里存的就是 1 字节（一个换行符）。** 这是 Godot 导出 C# 项目的标准行为：

- C# 源码**不导出**进 pck（编译进 dll 了）；
- 但 `res://Scripts/Vfx/Star.cs` 这个**路径必须还在**，因为：
  - `.tscn` 场景里有 `[ext_resource type="Script" path="res://Scripts/Vfx/Star.cs"]`；
  - `.godot/global_script_class_cache.cfg` 里按路径索引类名。
- 所以 Godot 塞一个 1 字节占位文件，保证路径解析不崩。

### 结论 / 我们该怎么做

| 想知道什么 | 该去哪 |
|---|---|
| 它的**资源**怎么搭的 | 抽 pck（tscn/tres/gdshader 都是明文） |
| 它的**代码**怎么写的 | **反编译 `RegentFX.dll`**，抽 pck 抽不出来 |

```bash
~/.dotnet/tools/ilspycmd.exe -o decompiled -p "…/RegentFX.dll"
```

产出 **79 个 `.cs`**（另有 1 个 `.csproj`），其中包含 `Properties/AssemblyInfo.cs`、
`GodotPlugins.Game/Main.cs` 等工具生成物，真正的业务代码约 58 个。

## 三、pck 里到底装了什么（实测统计）

对 2569 个条目按后缀统计：

| 后缀 | 数量 | 说明 |
|---|---:|---|
| `.ctex` | 1211 | **真正的贴图数据**（Godot 压缩纹理） |
| `.import` | 1211 | 每个贴图配一个的**重映射元数据**（ASCII 文本） |
| `.cs` | 61 | 1 字节占位（见上节） |
| `.tscn` | 45 | 场景 |
| `.tres` | 16 | 材质 |
| `.gdshader` | 16 | 着色器 |
| `.json`/`.cfg`/`.txt`/`.bank`/`.svg`/`.binary` | 各 1~3 | 清单、脚本类缓存、FMOD 音源库等 |

### 坑 2：贴图是「两份」，不是一份

抽出来看一个 `.import`（194 字节，明文）：

```ini
[remap]

importer="texture"
type="CompressedTexture2D"
uid="uid://w0k4aikxyiov"
path="res://.godot/imported/fn0001.png-4cc0068c38fbe900680b3a6b4602965b.ctex"
metadata={
"vram_texture": false
}
```

**所以贴图在 pck 里是这样一套：**

```
res://RegentFX/frames/laser_1/fn0001.png.import      ← 194B 文本，指向↓
res://.godot/imported/fn0001.png-4cc006…965b.ctex    ← 真数据
```

而场景里写的是 `path="res://RegentFX/frames/laser_1/fn0001.png"`（**没有后缀变化**）。
运行时的解析链是：`load("res://…/fn0001.png")` → 找到 `fn0001.png.import` → 按 `path=` 去读 `.ctex`。

> ⚠️ 这条直接决定了"我们怎么打包"：
> **不能只把小 png 塞进 pck 就完事。** 要么让 Godot 自己导出（它会把两份都生成），
> 要么手工组包时老老实实造 `.import` + `.ctex` 两份，且 `uid` 要对上。

### 坑 3：本体着色器不能整份照抄 —— `_util` 依赖

我拿万象星辉的 4 个 `common` 着色器跟**本体 sts2 的**做 diff：

| 着色器 | 本体 | 万象星辉 | 结论 |
|---|---:|---:|---|
| `vfx_grayscale_particle_shader` | 452B | 473B | **内容逐字相同**，只差换行符（CRLF/LF）→ 原样抄的 |
| `vfx_flipbook_shader` | 2087B | 2921B | **改过**：本体有 3 行 `#include`，万象全内联了 |
| `vfx_poof_shader` | 1016B | 984B | 有改动 |
| `vfx_ring_polar_shader` | 799B | 1023B | 有改动 |

本体 flipbook 的开头：

```glsl
#include "res://shaders/vfx/_util/flipbook.gdshaderinc"
#include "res://shaders/vfx/_util/hue_shift.gdshaderinc"
#include "res://shaders/vfx/_util/erosion_from_factors.gdshaderinc"
```

而万象星辉的 pck 里 **`gdshaderinc` 条目数 = 0**。

**结论**：本体的着色器很多依赖 `res://shaders/vfx/_util/*.gdshaderinc`（本体共 7 个：
`bloat` / `erosion_from_factors` / `flipbook` / `hue_shift` / `polar_coordinates` / `rotate` / `tiling_and_offset`）。
你要抄进自己的 mod，只有两条路：

1. **内联**（万象星辉的做法，稳妥）—— 把 `#include` 的函数体粘进来；
2. 把自己的 `.gdshaderinc` 也打进 pck，**但 `#include` 路径会跟本体撞名**，风险高，不建议。

## 四、代码骨架：四个层次

反编译出来的 58 个业务文件，其实是很规整的一套。核心只有 6 个文件：

```
RegentFX.Scripts/
├── Entry.cs                 ← 入口：[ModInitializer("Init")] + 私有场景缓存
├── VFXUtil.cs               ← 工具箱：缓存读取 / 生成节点 / 拉伸对准 / 等待
├── Setting.cs               ← 开关（读第三方配置库 RitsuLibModConfig）
└── Vfx/
    ├── FX.cs                ← 抽象基类：只有一个 VfxScenePath + AssetPaths
    ├── IWithFxLoad.cs       ← "我要预加载哪些资源"
    ├── WorldEnvironmentUtil.cs ← 全屏后处理（曝光/发光/亮度/对比/饱和）
    ├── Cards/
    │   ├── CardFX.cs        ← 卡牌特效基类（所有可覆写的参数都在这）
    │   ├── CardFxAttribute.cs  ← [CardFx(typeof(某张卡))] 注册标记
    │   └── CardVfxUtil.cs   ← 通用播放流程（生成→对准→挂载→音效→清理）
    └── Powers/
        ├── PowerFX.cs       ← 能力特效基类（同样一套）
        └── PowerFxAttribute.cs
```

外加 `Patches/` 11 个 Harmony 补丁负责**时机**（见第 7 节）。

### 4.1 入口：一行注册，顺手做缓存

```csharp
[ModInitializer("Init")]                 // ← 框架按这个名字找静态方法
public class Entry
{
    public const string ModId = "RegentFX";

    // ★ 关键：mod 私有场景缓存
    public static readonly ConcurrentDictionary<string, PackedScene> ModSceneCache = new();

    public static void Init()
    {
        new Harmony("sts2.vitech.regentFx").PatchAll();          // 装补丁
        ScriptManagerBridge.LookupScriptsInAssembly(typeof(Entry).Assembly);  // ★ 注册 C# 脚本
        if (Setting.PreloadEffects) LoadScenes();                // 预加载，避免第一次卡顿
    }
}
```

`ScriptManagerBridge.LookupScriptsInAssembly` —— **必须调**。
不调的话，`.tscn` 里 `path="res://Scripts/Vfx/Star.cs"` 找不到对应的 C# 类，场景加载出来是个空壳。

### 4.2 缓存为什么必须自己做

```csharp
private static void LoadScenes()
{
    foreach (var path in CollectAssetPathsSafely())
    {
        if (!ModSceneCache.ContainsKey(path))
        {
            var scene = ResourceLoader.Load<PackedScene>(path, null, CacheMode.Reuse);
            if (scene != null) ModSceneCache[path] = scene;
        }
    }
}
```

原因和手册第五章一致：`PreloadManager.Cache` 在换房间时会 `UnloadAssets()`，
**mod 自己的资源会被一起清掉**，第二次进战斗就"特效没了"。所以必须自己存一份。

`CollectAssetPathsSafely()` 的写法也很省事 —— **反射扫全程序集**，把每个 `CardFX` /
`PowerFX` 实例化一遍，收集它声明的 `AssetPaths`：

```csharp
foreach (var t in assembly.GetTypes().Where(t => t.IsSubclassOf(typeof(CardFX)) && !t.IsAbstract))
{
    if (Activator.CreateInstance(t) is CardFX fx)
        foreach (var p in fx.AssetPaths) set.Add(p);
}
```

→ **加一张新卡的特效，不用改预加载列表**，只要新类继承 `CardFX` 就自动被收进来。

### 4.3 注册表：用特性（Attribute）代替 if-else

```csharp
[AttributeUsage(AttributeTargets.Class, Inherited = false)]
public class CardFxAttribute : Attribute
{
    public Type CardType { get; }
    public CardFxAttribute(Type cardType) => CardType = cardType;
}
```

```csharp
public abstract class CardFX : FX
{
    public static readonly Dictionary<Type, Type> Registry = new();   // 卡类型 → 特效类

    public static void EnsureRegistry()
    {
        if (_registryInitialized) return;
        _registryInitialized = true;
        foreach (var t in GetTypes)                       // 扫全程序集
            if (t.GetCustomAttribute<CardFxAttribute>() is { } a)
                Registry[a.CardType] = t;
    }

    public static CardFX? FromCard(CardModel card)
    {
        EnsureRegistry();
        return Registry.TryGetValue(card.GetType(), out var t) && Activator.CreateInstance(t) is CardFX fx && fx.Enabled
            ? (fx.card = card, fx).Item2
            : null;
    }
}
```

## 五、★ 最值钱的一条：`StartPos` 约定 + 拉伸对准

这是整个 mod **最核心的技巧**，也是我们自己写特效最缺的那块。

### 5.1 场景怎么摆

看 `RegentFX/scenes/vfx/laser_1.tscn`（激光）的节点树：

```
[node name="Laser1" type="Node2D"]                       ← 根
[node name="StartPos" type="Node2D" parent="."]          ← position = (-362, -1)   ★ 起点标记
[node name="AnimatedSprite2D" type="AnimatedSprite2D" parent="."]
  position = (-164, -14)
  sprite_frames = SpriteFrames（23 帧，fn0001.png ~ fn0023.png）
  autoplay = "default"
```

**约定：场景按「目标在原点 (0,0)、起点在 `StartPos`」来画。**
`StartPos` 是个空 `Node2D`，纯定位用，不渲染任何东西。

→ 好处：**一个激光场景，能打任意距离、任意方向。** 不用给每张卡单独做朝向版本。

### 5.2 运行时怎么对准

```csharp
public static void FitVFX(this Node2D node,
    Vector2 nodeStartPos, Vector2 nodeEndPos,      // 场景内：StartPos、原点
    Vector2 sceneStartPos, Vector2 sceneEndPos)    // 世界上：出招者、目标
{
    Vector2 a = nodeStartPos - nodeEndPos;         // 场景内向量（长度 = 特效"原长"）
    Vector2 b = sceneStartPos - sceneEndPos;       // 世界向量（长度 = 实际距离）
    node.Rotation = b.Angle() - a.Angle();         // 差角
    node.Scale    = Vector2.One * (b.Length() / a.Length());  // 缩放 = 世界长 / 场景长
}
```

调用方：

```csharp
var node = VFXUtil.GenVFXNode(vfxScenePath);
var startMarker = node.FindChild("StartPos", recursive: true, owned: true) as Node2D;
node.FitVFX(startMarker.GlobalPosition, Vector2.Zero, starPos, targetPos);
node.GlobalPosition = targetPos;                  // ★ 整体挪到"目标"上
NCombatRoom.Instance.CombatVfxContainer.AddChildSafely(node);
```

> 📐 **验算**（我在纸上推过，是对的）：
> `StartPos` 在局部是 `(-362,-1)`，缩放 `s = D/362`、旋转 `Δ = θ_世界 - θ_场景` 之后，
> 它的局部长度变成 `362 × D/362 = D`，角度变成 `θ_场景 + (θ_世界 - θ_场景) = θ_世界`。
> 再整体平移到 `targetPos`，于是 `StartPos` 落在 `targetPos + (source - target) = source`。
> **首尾正好吻合** —— 起点对出招者、终点对目标。✔

> ⚠️ 反编译出来的**形参名是误导的**（`nodeStartPos` 其实是"场景内的起点"，`sceneStartPos` 才是"世界的起点"）。
> 上面已经改成正确语义的名字。

### 5.3 不是所有特效都要 `StartPos`

`p_burst.tscn`（爆点）就是极简的一个一次性帧动画：

```
[node name="PBurst" type="Node2D"]
[node name="AnimatedSprite2D" type="AnimatedSprite2D" parent="."]
  sprite_frames = SpriteFrames
  autoplay = "default"
```

→ **定点的（爆点、光环、星光）不需要 `StartPos`，直接摆位置就行。
指向性的（激光、导弹、冲击波）才需要。**

播放逻辑里也留了后门：

```csharp

if (startMarker == null)
{

```

## 六、完整播放流程（`CardVfxUtil.PlayVfxInternal` 逐行）

这就是「打一张牌，从出牌者射向目标」的完整一次：

```csharp
private static async Task PlayVfxInternal(CardFX config, Vector2 startPos, Vector2 targetPos, string logTag)
{
    if (TestMode.IsOn) return;                          // 1. 测试模式别放特效

    var node = VFXUtil.GenVFXNode(config.VfxScenePath); // 2. 从私有缓存取（没有就报错）
    if (node == null) return;

    var startMarker = (Node2D)node.FindChild("StartPos", true, true);
    node.FitVFX(startMarker.GlobalPosition, Vector2.Zero, startPos, targetPos);  // 3. 拉伸对准
    node.GlobalPosition = targetPos;                    // 4. 整体移到目标

    NCombatRoom.Instance?.CombatVfxContainer.AddChildSafely(node);  // 5. 挂到战斗特效层

    FmodLite.Play(config.HitSfxPath);                   // 6. 命中音效

    TaskHelper.RunSafely(CardVfxUtil.ClearAfter(node, config.VfxClearDelay));   // 7. N 秒后销毁

    if (config.HasExposureEffect)                       // 8. 可选：闪屏
    {
        WorldEnvironmentUtil.TweenExposure(config.ExposurePeak, config.ExposureInDuration);
        await VFXUtil.Wait(config.ExposureInDuration + 0.05f);
        WorldEnvironmentUtil.TweenExposure(1f, config.ExposureOutDuration);   // 一定要弹回来
    }
    FmodLite.Play(config.SecondarySfxPath);             // 9. 可选：第二段音效
}

public static async Task ClearAfter(Node2D? node, float delay)
{
    await VFXUtil.Wait(delay);
    if (node != null && GodotObject.IsInstanceValid(node))
        node.QueueFreeSafely();                         // ★ 必须用 Safe 版，别直接 QueueFree
}
```

**注意三个"安全版"调用**：`AddChildSafely` / `QueueFreeSafely` / `Wait`。
它们都在处理同一件事：**可能在特效播到一半的时候，战斗结束了 / 换场景了**。
直接用 Godot 原生 API 会在那种时机炸掉。

`VFXUtil.Wait` 里还有一层保护：

```csharp
public static async Task Wait(float seconds, CancellationToken token, bool ignoreCombatEnd = false)
{
    if (NonInteractiveMode.IsActive) return;
    if (seconds <= 0) return;
    if (NGame.Instance != null
        && SaveManager.Instance.PrefsSave.FastMode != 3     // 3 = 瞬间模式
        && (ignoreCombatEnd || !CombatManager.Instance.IsEnding))   // 战斗结束就别等了
    {
        await WaitInternal(Engine.GetMainLoop().CreateTimer(seconds), token);
    }
}
```

→ **顺手支持了游戏的"快进模式"和"非交互模式"**。这是细节，但决定了 mod 会不会被玩家骂。

想让两张特效同时播：

```csharp
await Task.WhenAll(PlayLunarVfx(targetPos, starPos), PlayLaserVfx(targetPos, starPos));
```

## 七、时机：11 个 Harmony 补丁挂在哪

特效"打得准不准"全靠这个。反编译出的补丁清单（按重要度排）：

| 补丁 | 挂的原函数 | 干什么 |
|---|---|---|
| `CardPlayTimingPatch` | `NPlayerHand.StartCardPlay` (Postfix) | **开始拖牌** → 播"拿在手上"的表现 |
| 同上 | `NCardPlay.CancelPlayCard` (Postfix) | **取消出牌** → 收掉手上的特效 |
| `CardAnimPatch` | `AttackCommand.Execute` (Prefix) | **攻击指令执行前** → 换掉本体命中特效、播自己的 |
| 同上 | `CardModel.OnPlayWrapper` (Postfix) | **一张牌彻底打完** → 清理临时状态 |
| 同上 | `NRegentVfx.Attack` (Prefix → 返回 false) | **掐掉本体攻击动画**（被自己的特效替代） |
| 同上 | `SfxCmd.Play` (Prefix → 返回 false) | **掐掉本体攻击音效** |
| `PowerTimingPatch` | 能力相关 | 能力挂上/移除时的表现 |
| `DamageTargetPatch` | 伤害目标 | 按目标播 |
| `ZIndexPatch` | `NCreature._Ready` / `NCombatRoom._Ready` | **改层级**（见下） |
| `RegentStarRingPatch` | 储君星环 | 职业专属 |
| `SupermassivePatch` / `StarryImpactPatch` | 特定卡 | 特定卡 |

### 关键设计：用"上下文单例"跨补丁传状态

```csharp
public static class AttackVfxContext
{
    public static bool ShouldDisableRegentWeaponAttack = false;
    public static bool ShouldDisableRegentWeaponSFX = false;
    public static CardModel? CurrentModelSource { get; set; }
    public static AsyncLocal<AttackCommand?> CurrentAttackCommand { get; } = new();
}
```

**为什么需要它**：`AttackCommand.Execute` 的 Prefix 里判断"这张牌有自定义特效"，
然后设置 `ShouldDisableRegentWeaponAttack = true`；
到了 `NRegentVfx.Attack` 的 Prefix 里读这个标志，`return false` 掐掉本体动画。
**两次调用之间没有参数可传，只能靠静态字段搭桥。**

⚠️ 而且它是 **`AsyncLocal`**（`CurrentAttackCommand`）—— 因为多人联机时
不同玩家的出牌流程是**并发的**，普通静态字段会被别的玩家串掉。

### ⚠️ 联机红线：一定要判 `IsMe`

```csharp
[HarmonyPrefix]
[HarmonyPatch(typeof(AttackCommand), "Execute")]
public static bool ExecutePatch(AttackCommand __instance, ...)
{
    ...
    if (!LocalContext.IsMe(val2.Owner))    // ★ 只处理"我自己的"出牌
        return true;                        //   别人的出牌走原逻辑
    ...
}
```

**原因**：本体的同步机制会把出牌动作**广播给所有机器**，每台机器都会跑一遍 `Execute`。
不判 `IsMe` 的话，队友出牌也会在**你的屏幕上**播你的自定义特效，
更糟的是会去改你本地的 `ShouldDisableXXX` 状态。

> 🔗 这条跟我们另一条线（斗地主尖塔联机）里的 `RestSiteSynchronizer.ChooseLocalOption`
> 是**同一个坑**：任何"本地表现层"的钩子，都必须先确认"这个动作是不是本机发起的"。

### 层级：`ZIndexPatch`

```csharp
[HarmonyPatch(typeof(NCreature), "_Ready")] [HarmonyPostfix]
static void Postfix(NCreature __instance)
{
    __instance.ZIndex = 10;              // 角色 → 10
    __instance.ZAsRelative = true;
}

[HarmonyPatch(typeof(NCombatRoom), "_Ready")] [HarmonyPostfix]
static void NCombatRoomReadyPatch(NCombatRoom __instance)
{
    if (__instance.BgContainer != null)        __instance.BgContainer.ZIndex = -20;   // 背景 → -20
    if (__instance.CombatVfxContainer != null) __instance.CombatVfxContainer.ZIndex = 0;  // 战斗特效层 → 0
}
```

对齐手册第四章：**特效挂 `CombatVfxContainer`（0），角色在 10（压住特效），背景在 -20**。
想让特效压住角色就调大一点，想垫在角色后面就调小。

## 八、全屏后处理（`WorldEnvironmentUtil`）

直接抄这套就够用了，**核心就是拿 `NGame.Instance.ActivateWorldEnvironment()` 然后 tween 属性**：

```csharp
private static WorldEnvironment? _cachedEnv;

public static WorldEnvironment? GetOrActivateEnvironment()
{
    if (_cachedEnv != null && GodotObject.IsInstanceValid(_cachedEnv)) return _cachedEnv;
    if (NGame.Instance == null) return null;
    return _cachedEnv = NGame.Instance.ActivateWorldEnvironment();   // ★ 开机就能用
}

public static Tween? TweenExposure(float exposure, float dur, EaseType ease = 2, TransitionType trans = 7)
{
    var env = GetOrActivateEnvironment(); if (env == null) return null;
    float threshold = Setting.ExposureThreshold;    // 玩家自己能调强度，0 = 关掉
    if (threshold <= 0.001f) return null;
    float target = (exposure - 1f) * threshold + exposure;   // 按玩家阈值打折
    return env.CreateTween().TweenProperty(env, "environment:tonemap_exposure", target, dur)
              .SetEase(ease).SetTrans(trans);
}
```

可调的 5 个属性（对应 Godot `Environment`）：

| 方法 | 属性 | 效果 |
|---|---|---|
| `TweenExposure` | `tonemap_exposure` | **闪白/过曝** —— 大招必备 |
| `TweenGlowIntensity` | `glow_intensity` | 泛光强度 |
| `TweenBrightness` | `adjustment_brightness` | 整体亮度 |
| `TweenContrast` | `adjustment_contrast` | 对比度 |
| `TweenSaturation` | `adjustment_saturation` | 饱和度（打黑白用） |

**两条经验**：
1. **一定要加"玩家可关"的开关**（这里的 `ExposureThreshold`）。闪屏对光敏感的人是伤害。
2. **用完必须弹回默认**（`ResetToDefaults()` / `TweenResetToDefaults()`），
   否则会永久污染后面的战斗画面。万象辉星用 `try/finally` 兜底。

拿它的资源和本体 sts2 的比，结论很干脆：

| 类别 | 情况 |

## 十、装到我们自己的 mod 里，要动哪些地方

```
① 复制骨架（projects/sts2-vfx-template/）
   VFXUtil.cs / FX.cs / CardFX.cs / CardFxAttribute.cs / WorldEnvironmentUtil.cs
   → 改命名空间、ModId、Logger 名

② 入口加两行
   new Harmony("sts2.<你的mod>").PatchAll();
   ScriptManagerBridge.LookupScriptsInAssembly(typeof(Entry).Assembly);

③ 自己的特效场景放 mod 目录，遵守两条约定
   · 指向性的：画在"目标在原点"，加一个空 Node2D 叫 StartPos
   · 定点的：随便摆，不要 StartPos

④ 打卡特效 = 一个类 + 一个特性
   [CardFx(typeof(你的卡类))]
   class 你的卡FX : CardFX { override VfxScenePath / TargetOffset / HitSfxPath ... }

⑤ 预加载：反射自动收，不用手写列表
   但记得在 Init 里调一次 LoadScenes()

⑥ 打包
   · 贴图：让 Godot 导出（自动生成 .import + .ctex 两份）
   · 着色器：有 #include 的**必须内联**，别指望本体的 _util
   · 清单 json：affects_gameplay 按实际填
```

## 十二、一页速查

