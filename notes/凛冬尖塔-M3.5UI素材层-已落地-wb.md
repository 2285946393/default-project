### 4. ★★ 踩坑：脚本编码（两个都中招）
| 文件 | 症状 | 根因 | 修法 |
|---|---|---|---|
| `build_pck.ps1` | 跑起来 exit 1、无输出 | 存成 **UTF-8 无 BOM**，PS 5.1 按 GBK 解码 → 中文乱码 → `"完成：$pck（$size KB）"` 引号解析失败 | 存成 **UTF-8 with BOM** |
| `自检-凛冬.bat` | 中文全乱码 | cmd 按**系统 ANSI(GBK)** 读 .bat | 存成 **GBK + CRLF** |

- `chcp 65001` 救不了 .bat —— cmd 是**按当前代码页解析文件字节**的，
  chcp 在文件开头执行前，前面的行已按旧代码页解析了
- `.bat` 里**不能用 `⚠`（U+26A0）** —— GBK 编不了，`open(...,'w')` 会先截断文件再失败
  → **文件直接变 0 字节**（我踩了，重写了一遍）
- ⚠️ 教训：**写脚本前先确认目标解释器的编码要求**；改编码别用「先 open('w') 再写」，
  要么先读进内存再写，要么写临时文件再替换

### 4. ★ 虚惊一场：pck 里出现 `.cs` 路径
用字符串扫 pck 时看到 `res://FrostSpireCode/.../*.cs`，一度以为 **exclude_filter 没生效、源码被打包**。

查下来是**误报**：
- `grep -a -c "namespace FrostSpire" FrostSpire.pck` → **0**（没有 C# 源码本体）
- pck 里那个文件是 **`global_script_class_cache.cfg`**（Godot 自动生成的脚本类缓存，
  记录所有脚本路径 → 类名映射）。**所有 Godot 项目的 pck 都有它**，quest-spire 同样如此
- 交叉验证：pck 才 41 KB，光 8 张 ctex 就占满了，**物理上装不下 19 个 .cs 源码**
- quest-spire 的 `exclude_filter` 写法与本项目**逐字相同**，已稳定跑数天

> 教训：**pck 是二进制，别用字符串扫描下结论**。要判断「文件是否真被打包」，
> 看**特征内容**（如 `namespace X`）+ **体积是否对得上**，两者一起看。
