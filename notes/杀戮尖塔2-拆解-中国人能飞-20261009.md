## 1. 它做什么

- 战斗中按**双击空格**起飞，WASD 移动、QE 旋转，Shift+R 复位。
- 起飞时播放自己的歌，并把原 BGM 音量压到 0。
- **多人联机同步**每个玩家的位置 / 朝向 / 是否在飞。
- 全部按键和"是否双击"通过 **ModConfig** 在设置页里配。
- 战斗结束 / 离开房间自动复位。

**6 个 Harmony 补丁，全部挂在 `NRun` / `NGame` / `NAudioManager` 上**：

| 补丁 | 目标 | 干什么 |
|---|---|---|
| `NGameInputPatch` | `NGame._Input` **Prefix** | 调 `FlightController.HandleInput(inputEvent)`；返回 false 时 `GetViewport().SetInputAsHandled()` **吃掉事件** |
| `NRunReadyPatch` | `NRun._Ready` **Postfix** | `FlightController.Bind(RunManager.Instance.NetService)` —— **绑定网络服务** |
| `NRunProcessPatch` | `NRun._Process` **Postfix** | `FlightController.Update(delta)` —— **每帧推进 + 定时发包** |
| `NRunNotificationPatch` | `NRun._Notification` **Prefix** | `what == 1006`（`NotificationPredelete`）→ `Unbind()` |
| `NAudioManagerSetBgmVolPatch` | `NAudioManager.SetBgmVol` **Prefix** | `SuppressBgmWhileFlightSongIsPlaying(ref volume)` → 飞行时 `volume = 0` |
| `CombatFlightMod` | — | `[ModInitializer]` 入口：`FlightSettings.Register()` + `PatchAll` |

## 2. ★★★ 游戏网络层全解（本次最大收获）

### 2.1 定义一条自己的网络消息（mod 口子）

```csharp
public struct MyMessage : INetMessage, IPacketSerializable
{
    public RunLocation Location;      // 游戏自带的可序列化"局内位置"
    public Vector2 Offset;
    public float RotationOffset;
    public uint Sequence;
    public bool IsFlying;

    public bool ShouldBroadcast => true;                 // 发给 host 时会被转发给所有客户端
    public NetTransferMode Mode => (NetTransferMode)1;   // 1 = Unreliable，2 = Reliable
    public LogLevel LogLevel => (LogLevel)0;             // 0 = VeryDebug（几乎都该用它）
    public bool ShouldBuffer => true;                    // SetBufferMessages(true) 时是否缓冲

    public void Serialize(PacketWriter writer)
    {
        writer.Write<RunLocation>(Location);
        writer.WriteVector2(Offset, null, null);
        writer.WriteFloat(RotationOffset, null);
        writer.WriteUInt(Sequence, 32);
        writer.WriteBool(IsFlying);
    }
    public void Deserialize(PacketReader reader) { /* 对称 */ }
}
```

**`INetMessage : IPacketSerializable`** 的四个属性（全部来自游戏源码注释）：

| 成员 | 含义 |
|---|---|
| `bool ShouldBroadcast` | **发给 host 时，host 会把它转发给所有客户端** |
| `NetTransferMode Mode` | `{None=0, Unreliable=1, Reliable=2}` —— **位置同步用 Unreliable**（丢一帧无所谓） |
| `LogLevel LogLevel` | 几乎都该 `VeryDebug`；**只在极少打日志时才用 Info** |
| `bool ShouldBuffer` | `SetBufferMessages(true)` 期间是否进缓冲队列。**几乎总是 true** |

### 2.2 ★★★ mod 消息怎么被发现的（官方口子）

`MegaCrit.Sts2.Core.Multiplayer.Serialization.MessageTypes`：

```csharp
public static void Initialize()
{
    List<Type> list = new List<Type>();
    list.AddRange(INetMessageSubtypes.All);                          // 本体内置 52 条
    list.AddRange(ReflectionHelper.GetSubtypesInMods<INetMessage>()); // ★★★ MOD 的消息，自动发现
    _cache = new NetTypeCache<INetMessage>(list);
}
```

**→ mod 只要定义一个实现 `INetMessage` 的类型，启动时自动被扫进去，不用注册、不用写配置。**

`ReflectionHelper.GetSubtypesInMods<T>()` 的实现很简单：
```csharp
GetSubtypesFromList(ModTypes, parentType)
  → ModTypes.Where(t => t != null && !t.IsAbstract && !t.IsInterface && InheritsOrImplements(t, parentType))
```
（`InheritsOrImplements` = 是子类 **或** 实现了该接口。）

**★ 触发时机**：`OneTimeInitialization.ExecuteEssential()` 里，顺序是
```
LocManager.Initialize();
AssemblyInfo.Init();
ModelDb.Init();
ModelIdSerializationCache.Init();
ModelDb.InitIds();
MessageTypes.Initialize();     // ★ 网络消息表
ActionTypes.Initialize();      // ★ 网络动作表（INetAction 同理可被 mod 扩展）
```
→ **这是「所有 mod 都加载完了」的第三个锚点**（前两个：`ModelDb.InitIds`、`LocManager.Initialize`）。
**且必须在它之前把自己的类型定义好**（编译期就存在，所以没问题）。

### 2.3 ★★★ `ContentSorter` —— 联机 id 分配的统一排序器（**最重要的一条**）

`MessageTypes` 用 `NetTypeCache<INetMessage>` 把类型映射成 **id（就是数组下标）**。
而 `NetTypeCache` 构造时**不是按注册顺序**，而是：

```csharp
IEnumerable<Item> source = ContentSorter<string>.Sort(types, (Type t) => t.Name);
_idToType = source.Select(i => i.type).ToList();
for (int j = 0; j < _idToType.Count; j++) _typeToId[_idToType[j]] = j;
```

`ContentSorter<TIdType>.Sort` 的**多级排序规则**（顺序即优先级）：

1. **`affectsGameplay` 降序**（`true` 在前，`false` 在后）
2. `id`（这里传的是**类型名**）升序
3. **有 mod 的排在后**（`mod != null` → 1；`mod == null` → -1）
4. **mod id 的序数比较**（`string.CompareOrdinal`）
5. 类型 `FullName` 的序数比较
6. 程序集 `FullName` 的序数比较

**★★★ 第 1 条的注释原文（一定要看）**：

> `affectsGameplayAtEnd`: If true, types from mods that do not affect gameplay will be placed at the
> **end** of the resulting list. **This is important so that players without those mods will still have a
> stable and deterministic sorting of IDs that will be sent over the network.**

→ **`affects_gameplay: false` 的 mod 的内容被排到列表末尾**，
→ **这样"没装这个 mod 的玩家"，前面那段的 id 编号仍然对齐**（末尾多出来的不会顶掉前面的）。

> **→ 这就是「不改玩法的 mod 联机安全」的底层机制。**
> **`affects_gameplay` 不是给人看的描述，它是联机 id 稳定性的开关 —— 必须诚实标注。**

### 2.4 ★★★ 那条警告的完整真相（接上了我们之前记的一条）

`ContentSorter.Sort` 里：

```csharp
Mod mod = AssemblyInfo.ModForType(type, out isBaseGame);
if (mod == null && !isBaseGame) {
    Log.Error($"Attempting to register type {type} in assembly {type.Assembly}, but it is not associated " +
              $"with any mod! You may need to call ModManager.AssociateAssemblyWithMod to manually register " +
              $"the assembly. Type sorting may break because of this, causing errors in multiplayer.");
}
```

**机制**：类型既不是本体的、也不属于任何 mod → 排序时被当成「没有 mod」（排**前面**）；
而**别人那边可能认为它属于某个 mod**（排**后面**）→ **两端排序不一致 → 同一个 id 指向不同类型**。

**★★★ 所以 `ModManager.AssociateAssemblyWithMod` 不调，坏的不只是"内容排序"，而是
网络消息 id + 网络动作 id + 模型 id 三样一起错位 → 联机串数据。**
（`ContentSorter` 被 `ModelIdSerializationCache` / `MessageTypes` / `ActionTypes` 共用。）

### 2.5 `NetMessageBus` 的行为（收发路径）

```csharp
// 发：包 = [1 字节类型 id][8 字节 senderId][消息体]
SerializeMessage<T>(ulong senderId, T message, out int length) {
    _writer.WriteByte((byte)message.ToId());
    _writer.WriteULong(senderId);
    message.Serialize(_writer);
}

// 收
TryDeserializeMessage(byte[] bytes, out INetMessage? message, out ulong? overrideSenderId) {
    byte b = _reader.ReadByte();
    if (!MessageTypes.TryGetMessageType(b, out Type type)) {
        if (ModManager.IsRunningModded() && b >= MessageTypes.Count && !_warnedMessageTypes.Contains(b)) {
            Log.Warn($"... first byte {b} that is outside the bounds of our known messages. " +
                     $"Since we are modded, we are assuming this is a message that does not affect gameplay " +
                     $"and will not warn about this again.");
            _warnedMessageTypes.Add(b);
        } else Log.Error("... is not a valid message ID!");
        return false;
    }
    overrideSenderId = _reader.ReadULong();
    message = (INetMessage)Activator.CreateInstance(type);   // ★ 必须有无参构造
    message.Deserialize(_reader);
    return true;
}
```

**★ 三条要点**：
1. **消息类型必须有 public 无参构造**（用 `Activator.CreateInstance` 造）。
2. **收到不认识的 id**：只要 `IsRunningModded()`，就**只警告一次然后静默丢弃**（"假定是不影响玩法的消息"）
   —— **这是联机安全设计**：装 mod 多的一方发的消息，装得少的一方不会崩，只是收不到。
   ⚠️ **反过来说：两端 mod 集合不同 → 消息静默丢失，不会报错**（排查联机"没反应"时要想起来）。
3. **`_messageHandlers` 按 `Type` 分发**，同一个类型可以有**多个** handler（`List<CallbackPair>`），
   每个 handler 单独 try/catch（一个抛异常不影响其他）。
4. **缓冲**：`SetBufferMessages(true)` 期间，`ShouldBuffer == true` 的消息进队列，
   `false` 时按顺序重放。**用于状态切换期**（游戏注释：状态切换时会 unregister/register handler，
   这个窗口期到达的消息可能"游戏还不知道怎么处理"）。

### 2.6 `INetGameService` —— 完整接口（`RunManager.Instance.NetService`）

```csharp
ulong NetId { get; }                    // 本地玩家 ID
bool IsConnected { get; }               // 能发包吗
bool IsGameLoading { get; }
NetGameType Type { get; }               // host / client / singleplayer

void SendMessage<T>(T message, ulong playerId);   // ★ 只发给某个 peer（host 专用）
void SendMessage<T>(T message);                   // 发给所有（客户端发 → host，带 broadcast 则转发）
void RegisterMessageHandler<T>(MessageHandlerDelegate<T> handler);

```

`public delegate void MessageHandlerDelegate<in T>(T message, ulong senderId) where T : INetMessage;`

**★ 现成的按位置定位接口**：`IRunLocationTargetedMessage { RunLocation Location { get; } }`
（在 `Multiplayer.Messages.Game`）—— 配套 `RunLocationTargetedMessageBuffer`。
CombatFlight 是手写了一个 `Location` 字段，正规做法是实现这个接口。

### 2.7 `PacketWriter` / `PacketReader` —— 带位宽和量化的序列化

```csharp
WriteBool(bool)                    WriteBytes(byte[], int byteCount)
WriteByte(byte, int bits = 8)      WriteShort(short, int bits = 16)      WriteUShort(ushort, int bits = 16)
WriteInt(int, int bits = 32)       WriteUInt(uint, int bits = 32)        WriteEnum<T>(T)
WriteLong(long, int bits = 64)     WriteULong(ulong, int bits = 64)      WriteDouble(double)
WriteFloat(float, QuantizeParams? quantizeParams = null)
WriteVector2(Vector2, QuantizeParams? x = null, QuantizeParams? y = null)   // ★ 可量化压缩
WriteList<T>(IReadOnlyList<T>, int lengthBits = 32) where T : IPacketSerializable, new()
WriteString(string)                Write<T>(T val) where T : IPacketSerializable
```

**★ `bits` 参数 = 位宽压缩**（如 `WriteUInt(sequence, 32)`，其实序号只要 8 位就够）；
**★ `QuantizeParams` = 浮点量化**（位置同步可以用它把 float 压成 2 字节）。

## 3. ★★ 联机同步模式（可直接抄的"位置同步"配方）

CombatFlight 用了一套很标准的做法，**斗地主的任何"实时状态同步"都能照抄**：

| 手法 | 实现 |
|---|---|
| **★ 只发"相对偏移"不发绝对坐标** | `Offset = Position - Origin`，接收端 `Origin + Offset` 还原。**避免两端基准不同** |
| **★ 序号 + 去重** | `uint Sequence`（本地自增），接收端 `LastRemoteSequences[senderId]` 比对，**旧的丢弃** |
| **★ 环形序号比较** | `IsNewerSequence(seq, prev) => seq != prev && (seq - prev) < 0x80000000u`（**无符号回绕安全**） |
| **★ 限流（按需变速）** | 移动中 `0.05s`（20/s）；静止 `0.75s`（1.3/s）；`_sendAccumulator += delta` 累加 |
| **★ 脏标记** | `_positionDirty` —— 没变就不发 |
| **★ 数值防御** | `IsFinite(msg.Offset)`（拒 NaN/Inf）+ `ClampNetworkOffset(±10000)` + `NormalizeRotation(-π..π)` |
| **★ 位置一致性校验** | `message.Location == _runLocation` —— **不是同一场战斗就整包丢弃**（防跨房间串数据） |
| **★ 自己发的包自己忽略** | `senderId == _netService.NetId` → return |
| **★ 玩家集合按需清理** | `PruneDisconnectedFlyingPlayers()`（`GetCreatureNode(id) == null` 就移除） |
| **★ 绑定/解绑成对** | `NRun._Ready` → `Bind`；`NRun._Notification(1006 Predelete)` → `Unbind`；`Bind` 里先 `Unbind()` 防重复注册 |
| **★ 解绑时 try/catch** | `UnregisterMessageHandler` 包在 try 里，失败只 Warn |

## 4. ★★★ dll 内嵌音频并播放（2MB 的真相）

包只有一个 2MB 的 dll，**没有 pck** —— 音频是**嵌在 dll 里的**：

```csharp
// 1. 从程序集资源流读出 mp3
using Stream stream = typeof(FlightController).Assembly.GetManifestResourceStream("CombatFlight.CombatFlightSong.mp3");
using MemoryStream ms = new MemoryStream();
stream.CopyTo(ms);

// 2. 包成 Godot 音频流
AudioStreamMP3 mp3 = new AudioStreamMP3 { Data = ms.ToArray(), Loop = true };

// 3. 造播放器并挂到 NGame 上
_songPlayer = new AudioStreamPlayer {
    Name = "CombatFlightSong",
    Stream = mp3,
    ProcessMode = ProcessModeEnum.3      // Always（不受 pause 影响）
};
GodotTreeExtensions.AddChildSafely(NGame.Instance, _songPlayer);
```

**★ 配套的 BGM 压制/恢复**：
- 起飞：`NAudioManager.Instance.SetBgmVol(0f)` + 自己播。
- 停止：`NAudioManager.Instance.SetBgmVol(SaveManager.Instance.SettingsSave.VolumeBgm)`（**读回玩家的原设置**）。
- 另加一个 `SetBgmVol` **Prefix** 兜底：飞行期间任何试图设置 BGM 音量的调用都被改成 0。
- 音量：`VolumeDb = value <= 0 ? -80f : Mathf.LinearToDb(value)`。

> **→ 对 DouSpire 的 BGM 有直接参考价值：**
> **不想带 pck 的话，把 mp3 塞进 dll 的资源里就行**（csproj `<EmbeddedResource>`）。
> 而且**"压制原 BGM 再恢复"的姿势要照抄**（读回 `SettingsSave.VolumeBgm`，别硬编码）。

**★ 屏幕提示条（纯代码搭 UI）**：
`CanvasLayer{Layer=100}` → `Label`（锚点上中 `LayoutPreset.5`，`OffsetTop=82`，字号 22，描边 5，黑色 85% 描边）
→ `AddChildSafely(NGame.Instance, layer)`；用 `CreateTween()` 做"停留 1.1s → 0.25s 淡出 → 回调隐藏"。

## 6. ★★ 对我们 4 个 mod 的可用结论

| # | 结论 | 用在哪 |
|---|---|---|
| 1 | **`INetMessage` + `IPacketSerializable` 就是 mod 自定义网络消息的官方接口**；实现即自动注册（`ReflectionHelper.GetSubtypesInMods<INetMessage>()`） | **斗地主 netcode 的核心** —— 出牌 / 准备 / 计时 / 投票 全都可以是自定义消息 |
| 2 | **★★★ `ContentSorter` 按 `affects_gameplay` 排序**：`false` 的排末尾，**保护没装该 mod 的玩家 id 对齐** | **必须诚实标注我们 4 个 mod 的 `affects_gameplay`**；标注错了会破坏别人的联机 |
| 3 | **`ModManager.AssociateAssemblyWithMod` 不调 → 网络消息 id + 动作 id + 模型 id 三样一起错位** | 之前只知道"内容排序失稳"，现在知道**具体坏在哪** |
| 4 | **消息类型必须有 public 无参构造**（`Activator.CreateInstance`） | 写自定义消息时注意（用 `struct` + 全 public 字段，或 `class` + 无参构造） |
| 5 | **两端 mod 集合不同 → 消息静默丢弃**（`IsRunningModded()` 时只警告一次） | 排查联机"没反应"时先想这条 |
| 6 | **`SetBufferMessages(true/false)` 用于状态切换期** | 斗地主"发牌 → 开局"这种切换窗口 |
| 7 | **`SetGameLoading(bool)` + `ConnectionStats? GetStatsForPeer(id)`** | 加载期抑制误判 / 显示延迟 |
| 8 | **`PacketWriter` 支持位宽压缩 + 浮点量化** | 斗地主的出牌包可以压得很小 |
| 9 | **位置同步配方**：相对偏移 + 序号去重 + 环形比较 + 限流 + 有限性校验 + 位置一致性校验 | 任何实时同步 |
| 10 | **dll 内嵌 mp3 + `AudioStreamMP3` 播放 + 压制/恢复原 BGM** | **DouSpire 的 BGM**（不想带 pck 就这么干） |
| 11 | **`ReleaseInfoManager` / `PeerVersionInfo LocalVersion`** | 联机版本握手（"握手卡版本"那条已有，这里给了数据源） |

| 13 | **ModConfig 是第三个配置框架**（9 种控件，含 KeyBind / ColorPicker） | 如果不想挂 RitsuLib 设置页，可以考虑它 |

## 8. 一句话总结

**这个 mod 本身只是个玩具（1,294 行，让角色飞起来），
但它无意中把游戏的整套联机机制摊开了 —— 而这正是斗地主 mod 最需要的东西。**

三条最值钱的：
1. **`INetMessage` 实现即自动注册** → 我们可以自由定义出牌 / 准备 / 计时消息。
2. **`ContentSorter` 按 `affects_gameplay` 排序** → **`affects_gameplay` 是联机 id 稳定性的开关，必须诚实标注**。
3. **`ModManager.AssociateAssemblyWithMod` 不调 = 三套 id 一起错位** → 之前那条警告的完整机制。

⚠️ 它用了 `RunManager.Instance.DebugOnlyGetState()`（拿 `RunState.RunLocation`）——
和 Intent Graph / RandomForeseer 一样的灰色地带，**用就收口到一个类型里**。
