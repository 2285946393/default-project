## 一、用户原话（本轮的动因）

> 「凛冬前线的玩法应该是各种有意思卡。我们就这么几个基础塔有什么用呢。
> 连人家邦布的效果都比我们多，而他甚至都是角色mod附带的一个小玩意」

拆解：
1. **卡太少** —— 原来只有 4 张，全是「部署一座被动站桩的塔」，没有技能卡、没有成长卡。
2. **对标对象**：a) 《凛冬前线》的卡池设计；b) 星见雅 mod 的「邦布」（11 种，每种都能点、能互动）。
3. 潜台词：**要"有意思"的卡 = 能互动、有取舍、有成长**，不是再来四座塔。

## 二、对标情报（先查清楚才动手）

### 《凛冬前线 / FrostBound》真实设计（Steam appid 3649580，LyraStudio，2025-11-27）
- **卡牌五大类**：**攻击** / **防御**（直接召唤军队）/ **技能**（改变战局）/ **建筑**（**数量最多**，持续场地支援）/ **精锐**（**可成长的战场领袖**）
- **四大派系**：强权 / 金手 / 轮回 / 公理
- **战斗**：7 列棋盘，左 6 列部署，最左是防线；普通防御单位**只活一回合**（暴风雪）；远程单位（投石车）在后方且**不朽**（回合结束不离场）
- **「养大哥」** = 精锐卡养成：通过精锐强化卡/反复召唤，把一张精锐培养成战场主宰；声望到阈值解锁词条（单体→群攻）
- 特色词条：**连击**（前进时攻击 2 次）、**固守**（+1 在场时间）、**不朽**（回合结束不离场）
- 500+ 张卡，10 难度等级，13 天坚守

### 星见雅 mod（Miyabists2，工坊 3747607263）邦布系统
- **11 种邦布**，每种 = `<X>Bangboo : MinionModel` + `<X>Act : MiyabiBangbooActBase`（**可点击行动**）+ `<X>Relic`
- 5 张指令卡（`BangbooSummonOne / ActiveOne / ChargeAll / HelpmeOne / UseOnemore`）
- `LuckybooAct`：花 10 金币 → 打 20（`PlayerCmd.LoseGold`）
- **结论：邦布的"有意思"不在模型，在「点它 → 触发一件事」这个交互。** 我们的 `FrostActionBase` 已经同源。

### 设计取舍说明（写给未来的自己）

1. **「点它触发」= 沿用已验证的 `FrostActionBase`**（MinionLib `ActionModel`），和邦布完全同源，
   不用写任何 UI 代码（图标点击由 MinionLib 的 `ActionClickPatch` 自动装）。
2. **蓄力/成长不做成"永久成长"**（那是《凛冬前线》的精锐，需要跨战斗存档），
   只做**单场内蓄力**：`FrostBurstChargePower` 每回合 +4，引爆清零。
   → 用「攒多久 × 会不会被拆」的赌注替代「跨场养成」，复杂度低、单场就能感受到。
3. **寒霜法师的随机**用 `new Rng((ulong)combatState.RoundNumber, "frost_mage_aura")`，
   种子只由回合数决定 → 各端一致（联机安全），不引 `System.Random`。
4. **符文壁只减「普通攻击」**（`props.IsPoweredAttack()` 过滤），不减免毒/能力伤害 ——
   官方一致惯例（`DieForYouPower` / `ThornsPower` 都这么做）。
5. **两张技能卡是本 mod 第一批"不部署任何东西"的牌** —— 之前所有牌都是部署牌，
   手牌一旦被容量卡住就全是废牌。技能卡**永远打得出去**，这是对「卡自己」的结构性解法之一。

## 四、API 核实（动手前逐条反编译/查 xml 确认，别凭印象写）

| API | 核实结论 | 来源 |
|---|---|---|
| `CreatureCmd.Stun(Creature, string? nextMoveId = null)` | **1 参调用合法**（默认参数）；内部挂 stunMove + 自动播 `NStunnedVfx` | `ilspycmd` 反编译 sts2.dll |
| `PowerCmd.Remove(PowerModel?)` | `async Task`；传 null 安全 | 同上 |
| `CombatState.HittableEnemies` | `IReadOnlyList<Creature>`（每次 getter 都 `.ToList()`） | 同上 |
| `CombatState.RoundNumber` | `int`，起始 1 | 同上 |
| `Rng.NextInt(int)` | 返回可隐式转 `int`（现有 `int j = rng.NextInt(i+1)` 已在编译） | 现有代码 |
| `new Rng((ulong)seed, string tag)` | 2 参构造存在（**xml 里没写**，`WaveTable`/`FrostRiftSession` 已在用） | 现有代码 |
| `CreatureCmd.GainBlock(Creature, decimal, ValueProp, CardPlay?, bool)` | 末参有默认值 → 4 参调用合法 | xml + 现有代码 |
| `CreatureCmd.Heal(Creature, decimal, bool)` | 同 `CampfirePower` | xml |
| `PowerCmd.Apply<T>(ctx, Creature, decimal, Creature?, CardModel?, bool silent)` | 末参有默认值 | xml + 现有代码 |
| `CreatureCmd.Damage(ctx, IEnumerable<Creature>, decimal, ValueProp, Creature)` | 5 参重载存在 | xml |

★ 教训复用：**`sts2.xml` 覆盖不全**（`Rng` 2 参构造、`Stun` 默认参数都没写），
**xml 搜不到 ≠ 不存在**，拿不准就 `ilspycmd` 反编译。
