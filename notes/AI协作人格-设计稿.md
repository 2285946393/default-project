# 「你的 AI 协作人格」— 设计稿

> 2026-10-13 立。题材经用户拍板：**AI 协作人格**（在游戏 / 求职状态 / 摸鱼三个候选中选定）。
> 素材来源：**用户自己的真实协作笔记**（`notes/AI协作-项目总结与技术沉淀.md`），不凭空编。
> 引擎参考：[XBTI](https://github.com/lovstudio/XBTI)（Apache-2.0）的 15 维 + 曼哈顿距离匹配。

---

## 一、为什么是这个题材

用户排除游戏题材的理由：「**真的已经出过很多这种了。有些人也不玩游戏。**」——受众窄、赛道挤。

**AI 协作人格的优势：**

| 对比例子 | 覆盖人群 |
|---|---|
| 游戏人格 | 只有玩家（且已被 SBTI 各游戏版刷过一轮） |
| **AI 协作人格** | **凡是碰过 AI 的人** —— 学生、上班族、老师、家里长辈，全都能测 |
| 恋爱人格 | 想测的人多，但赛道同样挤（Loveage 那种已成熟） |

而且它**只有真在用 AI 干活的人做得出来** —— 用户几个月来跟四五个 AI 协作的实感，
别人是装不出来的。

## 二、素材：从用户笔记里长出来的真实协作模式

来自 `AI协作-项目总结与技术沉淀.md`（用户亲手维护的笔记）：

| 笔记里的原话 | 提炼出的协作模式 |
|---|---|
| 「我是多ai协用」 | **多线并行** —— 同时指挥好几个 AI，还会跨 AI 交接 |
| 「不要自己造轮子」 | **先找现成的** —— 上手先翻 GitHub，不从头手搓 |
| 「自主完成，不追问」「不要问我的意见」 | **放权型** —— 讨厌被反复确认 |
| 「可以可以」「一般吧」「不好玩」 | **极简反馈** —— 三个字定生死 |
| 「有点圆满了」「非常喜欢」 | **感觉优先** —— 用心情判断，不用技术指标 |
| 「感觉这种挺容易火的」 | **传播直觉** —— 先想这东西有没有人看 |
| 「再找点有意思的」 | **不停歇** —— 一个刚圆满了马上要下一个 |
| 写满踩坑记录、参数表、验证清单 | **较真型** —— 踩过的坑必记，下次不重踩 |

## 三、15 个维度（5 模型 × 3 子维度）

| 模型 | 子维度 | 含义 |
|---|---|---|
| **A. 委托度**（你怎么把活交出去） | `A1 放权` | 说个方向就让 AI 自己跑，不盯着 |
| | `A2 指令密度` | 一次给多少信息，写不写详细要求 |
| | `A3 中途干预` | 跑一半会不会插话改方向 |
| **B. 审阅度**（你怎么验收） | `B1 验真` | 会不会真的打开看、跑一遍 |
| | `B2 留存` | 会不会把它说的东西存下来、转给别人 |
| | `B3 挑刺` | 找不找它逻辑漏洞 |
| **C. 情绪度**（你怎么跟它相处） | `C1 客套` | 说谢谢吗、骂它吗 |
| | `C2 拟人` | 当它是人还是工具 |
| | `C3 依赖` | 没它能不能干活 |
| **D. 节奏**（你怎么推进） | `D1 并行` | 同时开几个 |
| | `D2 迭代` | 一轮改一点还是一把梭 |
| | `D3 收尾` | 做完了还回头收拾吗 |
| **E. 认知**（你怎么看它） | `E1 信任` | 说啥信啥还是处处存疑 |
| | `E2 归功` | 做成了算谁的 |
| | `E3 边界` | 哪些事自己干、哪些交给它 |

> 每题对应 1 个维度，同维度 2 题，得分求和 → L(≤3) / M(4) / H(≥5) 三级。
> 15 维向量与人格模式做**曼哈顿距离**匹配，相似度 = `(1 - distance/30) × 100%`。

## 四、人格类型（待细化，8~12 种）

初步构想的类型名（**全部中性或夸人，不贬低**）：

| 代号 | 类型名 | 画像 |
|---|---|---|
| `DIRECTOR` | 甩手掌柜型 | 说个方向就去干别的，回来直接验收 |
| `ENGINEER` | 甲方提需求型 | 需求写得比文档还细，AI 只是执行手 |
| `BUDDY` | 跟 AI 唠嗑型 | 边干活边聊，会跟它吐槽 |
| `SKEPTIC` | 处处存疑型 | 它说的每句都要自己验一遍 |
| `SWITCHER` | 同时开五个型 | 多线并行，谁快用谁 |
| `POLISHER` | 反复打磨型 | 一轮改一点，改到满意为止 |
| `DELEGATOR` | 全权委托型 | 结果直接交，中间不看 |
| `COLLECTOR` | 记笔记型 | 它说的好用的都抄下来 |
| `...` | | 待补全 |

## 五、技术方案

- **单文件 HTML**，落 `pages/`，零外部依赖（遵守用户既有铁律）
- 参考体积：`二次元抽卡机.html` 21 KB / `深渊塔.html` 39 KB → 目标 **100 KB 内**
- 中文系统字体栈，玻璃拟态，手机宽度自适应
- **结果卡可截图**（竖版 1080×1350 比例友好）
- 无账号、无后端，结果编码进网址 hash

## 六、合规（硬性）

- 页脚必须写「**娱乐测验，仅供参考**」
- 类型名**全部中性偏夸**，不出现羞辱向词汇
- **不收集任何个人信息**，不要注册
- 不涉及心理疾病诊断
