## 一、点击宝箱（Click the Button · Godot 4.7.1）

### 恢复命令

```bash
cd /c/Temp/gdre
./gdre_tools.exe --headless --recover=".../Click the Button.pck" --output-dir=/c/Temp/ctb_project
```

25 秒完成，产出 **257 个 .gd 脚本 + 169 个 .tres + project.godot**，是完整可运行工程。

### ★ 核心：`UpgradeRes` —— 数值不是公式，是手填数组

`scr/Common/UI/Scripts/Upgrades/upgrade_res.gd`：

```gdscript
extends Resource
class_name UpgradeRes

@export var upgrade_var: String = ""        # 作用于哪个属性（字符串索引）
@export var current_level: int = 0
@export var used_coin: SaveGame.coins       # ★ 用哪种货币
@export var price_values: Array[float] = [10, 20, 30]   # ★ 每级价格，手写
@export var add_values:   Array[float] = []             # ★ 每级增量，手写
@export var show_chance / show_percentage / show_money / is_boolean
```

几个关键方法：

```gdscript
func is_maxed() -> bool:        return current_level >= price_values.size()
func get_current_price() -> float:  return price_values[current_level]
func _is_repeating() -> bool:   return add_values.size() == 1   # ★ 重复型=可无限买
func _add_at_level(level) -> float:
    if _is_repeating(): return add_values[0]        # 重复型永远取第 0 项
    return add_values[clampi(level, 0, add_values.size()-1)]
```

**三个设计点值得抄：**

1. **`price_values` / `add_values` 是逐项手填的数组，不是 `cost * 1.15^level` 公式。**
   好处是设计师能手工调每一级的曲线（前几级便宜、中间卡一下、后面暴涨），
   公式做不到这种手感。`validate()` 里还校验了两个数组长度必须一致。
2. **`_is_repeating()`：`add_values` 只有 1 项时 = 重复型**，价格固定、可无限买。
   用一个数组长度就能表达"有限升级"和"无限升级"两种形态，很省事。
3. **批量购买**：`get_price_for_levels(n)` 累加、`get_max_affordable_levels()` 算买得起几级
   —— clicker 必备，一次性买 10 级不然点到手酸。

## 二、财富磨坊（Fortune Mill · Godot 4.5.1 Mono）

### 结构：表格驱动 + 代码生成

```
src/generated/          ← ★ 自动生成，说明设计师在表格里填数值
    AttributeDefaults.cs / AttributeIndex.cs
    ItemDatabase.cs / ItemIndex.cs
    MagicDatabase.cs / MagicUpgIndex.cs
    SecretDatabase.cs / SecretIndex.cs
    SushiBonusDatabase.cs
    UpgradeDatabase.cs (664 行) / UpgradeIndex.cs
src/AllCalc.cs          CoreFunc.cs（联网）
    CurrencyManager.cs（货币）  CostReductionManager.cs（成本减免）
    AutoPlay.cs（自动游玩）
src/Sushi/*             src/Darts/*
KnowledgeBonusManager.cs   ← ★ 永久加成（转生系统）
```

**`src/generated/` 这一层是最值钱的工程实践**：
数值不写在逻辑里，而是由表格生成 `Database` + `Index` 两个文件
（一个存数据、一个存枚举索引）。改数值只改表，不动代码。

### ★ Knowledge 永久加成系统（转生）

`KnowledgeBonusManager.cs`：80 个寿司 → 每升一级给一种永久加成，共 5 类：

| 类型 | 效果 |
|---|---|
| `SUSHI_BASE_MUL` | 丝带获取 +% |
| `SUSHI_FUEL_MULTI` | 燃料/分钟 +% |
| `SUSHI_FUEL_MAX_FROM_RATE` | 最大燃料 + |
| `SUSHI_COST_REDUCTION` | 商店升级 **-%**（走另一套公式） |
| `PERFECTO_CHANCE_MUL` | 完美率 × |

核心公式：

```csharp
static double GetKnowledgePower(int type, long level, bool isPerfecto, double perfectoMulti)
{
    double num = level * (Math.Floor((type + 1) / 10.0) + 1.0) / 100.0;
    if (knowledgeAttributeForSushiIndex[type] == 3) num *= 100.0;   // 成本减免档
    if (isPerfecto) num *= perfectoMulti;
    return num;
}
```

- `level × (floor((type+1)/10) + 1) / 100` —— 每 10 个 type 一个台阶，越靠后的寿司每级收益越高
- 成本减免（type 3）单独处理：显示时走 `1 - 1/(1 + num/100)`（永远不会减到 0 以下）

### ★★ 加算与乘算分开存 —— 增量游戏数值的命门

```csharp
if (comboTypeArray[num] == 1)
    attributeMuls[(int)attributeIndex] *= 1.0 + knowledgePower;   // 乘算
else
    attributeVals[(int)attributeIndex] += knowledgePower;         // 加算
```

**`attributeVals`（加算池）和 `attributeMuls`（乘算池）是两个数组，最后再合并。**
这是所有正经增量游戏的标准做法：先加完再乘，避免"加成互相稀释"或"指数爆炸"。
`AllCalc.cs` 里的 `GetUniversalMuli()` 也是同一个套路（多个倍率连乘）。

## 三、海龟（Shelldiver · GameMaker）

`data.win` 只有 2.2MB（美术全在 `ag_musics.dat` / `ag_sounds.dat` / `ag_ui.dat` 里），
逻辑全在这 2.2MB 内。拿到的是 **GML 符号表**（`gml_Object_o_xxx_Create_0` 这种格式）。

### 双货币 + 生态分区

- 货币：**`crystal_coins`**（水晶币）、**`flask_coins`**（瓶币）
- 生态区（深度递进）：**shallows（浅滩）→ swamp（沼泽）→ magma（岩浆）→ glacial（冰川）**
  —— 对应 `o_skill_biodiversity_{shallows,swamp,magma,glacial}`
- 成就：`ACH_DEPTH_01~04`（下潜深度）、`ACH_SHELLS_01~04`（贝壳数）
- 调试变量：`dbg_biome_depth`（生物群系深度）
- 特殊：**`o_jellyfish_transmutator`（水母转化器）**、`o_alchemy_station`（炼金台）

### 技能树规模（节选）

```
o_skill_bubble_damage_01 … _10        o_skill_bubble_critical_chance_01…_10
o_skill_bubble_capacity_01…_04        o_skill_bubble_critical_damage_01…_03
o_skill_bubble_firerate_01…_03        o_skill_bubble_size_01/02/10
o_skill_bubble_doppel_01…_03          o_skill_bubble_tank_01/02/03/10
o_skill_bubble_penetration_01/02      o_skill_bubble_reload_01/02
o_skill_bubble_execute_01/02          o_skill_bubble_smite / _02 / _threshold
o_skill_bubble_duration_01            o_skill_bubble_speed_01/02
o_skill_biovalue_{gold,silver,rainbow,amount_01/02/10}
o_skill_alchemy_station{,_dc_01/02,_speed_01/02/03}
o_skill_agile_hands_01/10
o_skill_cellphone    o_skill_chain_bubble    o_skill_arrow_any / arrow_max
```

**结构规律**：`{系统}_{属性}_{档位}`，档位从 01 到 10。
同一属性拆成 10 个小级而不是一个大级 —— 让每级都有"立刻能买得起"的获得感。

### 可复制的点

- **"深度/生态区"做纵向进度锚**：不是纯数字变大，而是换个场景继续变大，
  每个区有自己的技能（`biodiversity_*`）和怪物（`jellyfish_{区}_{色}`）。
- **成就绑定两个维度**（深度 + 资源数），给长线目标。

## 四、咖啡星球工匠（Astro Prospector · Unity IL2CPP）

IL2CPP 拿不到方法体，但 `global-metadata.dat` 的**类型名和字段名是明文**，
足以还原出整套领域架构：

```
AstroProspector.Runtime
├── Application        DoPrestige          ← ★ 转生
├── Domain             Stat / Element / Operator / Generator / TimeScaler
│                      TextColor / SpriteFontNames
├── Domain.Enemies     Enemy / EnemyIDs / Hittable / Health
├── Domain.Rogue       ShipStats / RogueState / ShipRecord   ← 局内（rogue 层）
├── Domain.Ship        LaserState / LassoState / ParryState / PulseState
│                      TurretState / MoonState
├── Domain.Status      FireState
└── Domain.Storage     Resource
```

还拿到了具体数值参数名：`NumberOfAsteroids`、`ResourcesPerAsteroid`、
`RestoreFuelPerFlow`、`Generator/Asteroid*Generator/BigAsteroid.Generator/SmallAsteroid`。
源码路径也留着：`Assets\AstroProspector\Runtime\Domain\Stat.cs`（说明是手写架构，不是糊的）。
输入用 Rewired。

**架构信号很明确：这是个"rogue + 增量"混合体。**
`Domain.Rogue`（ShipStats / ShipRecord = 单局档案）和 `Application.DoPrestige`（跨局转生）
是两套独立的状态，边界划得很清楚 —— **局内进度和永久进度分开存**，这是混合品类的关键。

## 六、横向提炼：增量游戏的通用骨架

把 5 个（实际成功 4 个）放在一起看，骨架高度一致：

### 1. 数值用「表」不用「公式」

点击宝箱手填 `price_values` 数组，财富磨坊用 `src/generated/` 从表格生成代码。
**没有一个是硬编码 `cost = base * pow(1.15, level)` 的。**
手填/表格的好处：能手工捏出"前期爽、中期卡、后期爆"的手感曲线，且改数值不用动代码。

### 2. 加算池与乘算池必须分开

财富磨坊的 `attributeVals[]` / `attributeMuls[]` 是最标准的示范：
**先加完再乘**。混在一起要么互相稀释、要么指数爆炸。

### 3. 一个数组长度表达「有限 / 无限」两种升级

点击宝箱的 `_is_repeating()`（`add_values.size() == 1`）——
数组只有 1 项 = 重复型（固定价、无限买），多项 = 有限型（有满级）。
省掉了一整套分支。

### 4. 多货币是后期内容的主要手段

点击宝箱 `used_coin`（每个升级指定用哪种币）、海龟 `crystal_coins` / `flask_coins`。
单一货币到后期必然通胀失控，加一种币就多一层节奏。

### 5. 稀有度按数量级跳档

点击宝箱：common(1e1) → uncommon(1e3) → rare(1e5) → epic(1e8) → legendary(1e11) → mitic(8e13)。
**每档 1000 倍**（后面两档放宽到 100 倍）。这是让玩家"数字变大但感知可控"的成熟做法。

### 6. 纵向前进度要换「场景」不只是换数字

海龟的四个生态区（浅滩→沼泽→岩浆→冰川），每区有自己的技能和怪物。
数字变大是抽象的，换个场景是具体的。

### 7. 局内进度与永久进度分开存

咖啡星球工匠的 `Domain.Rogue`（局内）vs `Application.DoPrestige`（跨局）是教科书式边界。
财富磨坊的 Knowledge 加成也是独立一层。

### 8. 批量购买是 clicker 的刚需

点击宝箱有 `get_price_for_levels(n)` / `get_max_affordable_levels()` /
`upgrade_levels(n)` 一整套。不做这个，后期一次买一级会点到手废。

## 八、一句话结论

**Godot 游戏是最好学的** —— 一条命令就能拿到完整工程和源码，两个 Godot 游戏（点击宝箱、
财富磨坊）直接给出了教科书级的数值架构。核心就两条：**数值进表不进公式**、**加算乘算分池**。

海龟给出了"纵向分区"的进度设计，咖啡星球工匠给出了"局内/永久分离"的架构边界。
丁东王因为 Unity 版本太新（metadata v39）拆不动 —— 本机 Il2CppDumper 该升级了。
