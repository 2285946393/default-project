## 一、CrownSiege（王冠围城）—— 隐藏动态难度，本批最有价值

反向塔防：你带兵去打敌人的塔。

### 1.1 核心数值（`DynamicDifficultyManager.cs`）

```csharp
const int   AttemptsBeforeReduction    = 2;    // 允许失败 2 次
const float DifficultyReductionPerAttempt = 0.25f;  // 之后每失败一次 ×0.75
const float DifficultyPerCompletedLevel = 40f;  // 每通关一关，难度地板 +40

initialDifficulty = 80f;
minDifficulty     = 45f;
```

**胜利加难度**（`GetWinIncrease`）：

| 第几次尝试通关 | 加成 |
|---|---|
| 1 次就过 | **+32%** |
| 2 次过 | **+20%** |
| 3 次及以上过 | **+13%** |

公式（原文）：
```csharp
winIncrease = GetWinIncrease(attemptCount);
added       = (attemptCount <= 2) ? LastWinIncrease : 0f;   // 上次也是一次过就再加一遍
newDiff     = max(current, highestCleared) * (1 + winIncrease + added) + 75f;
```

### 1.2 我按源码模拟出来的实际难度曲线

| 关卡 | 难度 | 涨幅 |
|---|---|---|
| 起始 | 80 | — |
| 1 关首通 | 180.6 | +126% |
| 2 关首通 | 371.2 | +106% |
| 3 关首通 | 683.7 | +84% |
| 4 关首通 | 1196.3 | +75% |
| 5 关首通 | 2037.0 | +70% |
| 6 关首通 | 3415.7 | +68% |
| 7 关首通 | 5676.7 | +66% |
| 8 关首通 | 9384.8 | +65% |

> 稳态就是 **×1.64 再 +75**。前期爆炸、后期趋近固定倍率——这是"加法尾巴"在压指数，和财富磨坊那套是一个思路。

### 1.3 三条可以立刻抄的规矩

1. **难度是浮点数、不是档位。** 没有"简单/普通/困难"三选一，是 80 → 180.6 → 371.2 连续爬。玩家永远感觉"刚刚好难一点"。
2. **输了自动降，但不告诉你。** 同一关失败 3 次起，每次 ×0.75，且给这关"锁一个难度"（`SetLockedDifficulty`），下次进这关就用锁定的值。退出不保存 → 回滚到进关前的值（`CancelAttempt`）。
3. **地板随进度抬升**：`MinDifficulty = max(45, 已通关数 × 40)`。防止玩家靠刷低难度关刷爽感。

**对你的 mod 怎么用**：DouSpire 高级难度用 DouZero ONNX（固定强度）。可以加一层这个壳——
玩家连胜 N 局 → ONNX 出手强度/牌力补偿悄悄上调；连败 2 局 → 下调 25%。玩家不会察觉，但不会连跪弃坑。

## 二、RockBottom（点击挖矿）—— 增量数值的三层骨架

Godot 工程，`Scripts/PlayerUpgrades.gd`（101KB）是这一批最大的数值宝藏。

### 2.1 三层升级结构（重点）

| 层 | 机制 | 数值 |
|---|---|---|
| **第一层：Token Buff**（有限 5 级） | 花 token 买离散档位 | 成本 `[5, 10, 20, 35, 50]`，共 120 token |
| **第二层：Mastery 精通**（99 级） | 挖矿积累 XP 自动升 | XP = `10 × 1.082^L`，满级 99 |
| **第三层：XP 倍率升级**（9 级） | 再花 token 买"XP 获取速度" | 成本 `[3,5,8,12,18,25,35,50,70]`，每级 +0.5 倍 |

**关键**：第三层买的是**第二层的速度**，不是直接买数值。这是"元升级套升级"的标准做法——玩家花的钱在加速一个自动过程，而不是直接加数字，心理上更耐玩。

### 2.2 精通 XP 曲线（`MASTERY_XP_BASE=10.0, GROWTH=1.082`）

| 等级 | 升到下一级所需 XP |
|---|---|
| 0 | 10 |
| 1 | 11 |
| 5 | 15 |
| 10 | 22 |
| 25 | 72 |
| 50 | 514 |
| 75 | 3,690 |
| 90 | 12,035 |
| 98 | 22,608 |

**0 → 99 累计 ≈ 298,197 XP。**

> 增长率只有 **8.2%**——比常见的 15%（财富磨坊）温和得多。因为这一层是"挂机自动涨"，不是"花钱买"，所以斜率必须平。

### 2.3 Token Buff 档位表（部分，全部是 5 级）

| Buff | 5 档数值 | 性价比（增益/成本） |
|---|---|---|
| 挖掘速度 | 15% 30% 45% 60% 75% | 0.030 → 0.015（**递减**） |
| 资源获取 | 20% 40% 60% 80% 100% | 0.040 → 0.020（**递减**） |
| 双倍掉落 | 5% 10% 15% **22%** 30% | 0.010 → 0.006 |
| 闪电链 | 1 2 4 6 9 | 0.20 → 0.18（**几乎持平**） |

**规律**：
- 增益线性、成本超线性 → **性价比必然递减**，这是设计师刻意的（防止一路无脑点满）。
- 但 `lightning_chain`（闪电链）刻意**保持性价比不变**——因为它是"机制型"升级（跳几个目标），不是"数值型"。**机制升级不惩罚，数值升级才惩罚。**
- `double_drop` 第 4 档是 **22%** 不是 20% —— 手工微调，说明表是人填的不是公式生成的。

### 2.4 镐子升级 = 门槛制，不是花钱制

```gdscript
const CHUNKS_REQUIRED_FOR_PICKAXE_UPGRADE: int = 5
const CHUNKS_REQUIRED_EARLY_LEVELS: int = 3
const EARLY_LEVEL_MAX_LAYER: int = 3
pickaxe_tier = clampi(level_id + 1, 1, 8)   # 共 8 档
```

**镐子不能买，只能靠"收集 5 块巨型矿石"解锁**，且早期（前 3 层）只要 3 块。
→ 这是"**进度门槛替代价格门槛**"：核心成长线不给钱买断，逼玩家去玩内容。

### 2.5 货币层级（11 种）

`gold / cobalt / iron / crystal / molten / sea / void / cosmic` 八种矿 → 各有 ore（原矿）和 bar（锭）两种形态，
再加 `stone`、`tokens`、8 种 `gems`、3 种高级锭（electrum / tempered steel / prismatic）。

> 和海龟那套"5 种资源 × 4 条技能链"同构：**资源种类 = 场景层级**。每进一个新矿区就解锁一对（ore + bar）。

## 三、Shroom and Gloom（蘑菇与幽暗）—— 深度指数缩放 + 友好数字

手牌 roguelike（杀戮尖塔同类），1112 个 .cs。

### 3.1 `CombatBalancingConfiguration.cs`：难度按"层深"缩放

每条路线（Path）独立配置，三个维度各四条参数：

```csharp
public float BaseHealthPercent;      // 基础加成 %
public float HealthPercentPerDepth;  // 每层深加多少 %
public int   HealthScalingStartDepth;// 从第几层开始算
public float HealthScalingExponent = 1f;  // 指数（1=线性）
```

公式：
```csharp
float t = Pow(Max(0, currentDepth - HealthScalingStartDepth), HealthScalingExponent);
return RoundToFriendlyPercent(Base + PerDepth * t) / 100f;
```

**四个设计点**：
1. **指数可调**：`Exponent=1` 是线性，`>1` 后期陡峭，`<1` 前快后缓。一个参数切换整条曲线的性格。
2. **起始层可偏移**：Boss 层可以从第 3 层才开始加难度。
3. **可跳过指定层**：`IgnoredHealthDepths` 列表，某些层故意不涨（给玩家喘息）。
4. **三个开关独立**：`ApplyHealthBalancing` / `ApplyDamageBalancing` / `ApplyDangerBalancing`——调数值时可以只开一个维度做 A/B。

### 3.2 "友好数字"取整（很妙的小细节）

```csharp
// BlacklistedLastDigits：禁止出现的尾数，命中就往下减
public static int RoundToFriendlyNumber(int value)

// 百分比取整：尾数 9 进 1，尾数 1 退 1
public static float RoundToFriendlyPercent(float p)
{
    int n = RoundToInt(p);
    if (n % 10 == 9) n++;
    if (n % 10 == 1) n--;
    return n;
}
```

> 血量不显示 137，显示 135 或 140。玩家对"整十"数字的判断力远强于精确值。
> **代价**：取整是**向下**的（难度偏低），说明他们宁可偏简单也不让玩家困惑。

### 3.3 其他数值

| 项 | 值 | 备注 |
|---|---|---|
| 默认手牌上限 `_handSize` | **4** | 比 MT2 的 10、Relief 的 5 都小 |
| 敌人默认血量 | 25 | `EnemyHealthData._startingHealth = 25` |
| 商店删牌费用 | 1 | `CardShopForgetCost = 1` |
| 触发链最大深度 | 6 | `MaxAllowedTriggerCycleDepth = 6`——防无限循环 |
| 老兵护甲 | 5 | 精英词缀 |
| 阵营中立区间 | -5 ~ +5 | 阵营好感度 |

### 3.4 奖励桶（`CardRewardBucket`）—— 三层过滤

发牌前要走：
1. **锁状态过滤** `FilterByLockState`：当前路线排除的卡（IsCardExcluded）+ 未解锁的卡（Meta 进度）→ 移除，并记录原因
2. **替换规则** `ApplyAlternates`：`GetAlternateCardIfAvailable` —— 同一张卡在不同隧道有不同变体
3. **兜底** `LastResortChoice`：过滤完不够 3 张就用兜底池

> 关键：**过滤全程带日志**（`filterReasons` / `swapLog`）。调数值时能直接看到"为什么这张卡没出现"。
> 这条对你的 mod 很有用——斗地主发牌如果加了过滤，一定要留原因日志，否则玩家说"我怎么老摸不到炸弹"你查不出来。

## 四、Budgie's Bug Shop（账单需要支付）—— 升级表数据结构

抓虫 + 开店 + 放生，160 个 .cs（小工程，结构清晰）。

### 4.1 `UpgradeData`：成本/增量双数组

```csharp
public float[] stageCosts;      // 每一级的价格
public float[] stageIncrements; // 每一级的效果值
public bool MaxStageIsLimited;  // 是否有上限
public UpgradeData limitingUpgrade;  // 上限由哪个升级决定
```

**三个设计点**：
1. **成本数组、效果数组分开写，不写公式。** 想要什么曲线手填，允许手工微调（呼应 RockBottom 的 22%）。
2. **上限可以挂在别的升级上**（`limitingUpgrade`）：
   ```csharp
   int StageLimit() {
       if (!MaxStageIsLimited) return stageCosts.Length;
       int idx = Array.IndexOf(stageIncrements, limitingUpgrade.CurrentStageValue());
       return idx < 0 ? stageCosts.Length : idx + 1;
   }
   ```
   → "这个升级能升到几级，取决于另一个升级现在是多少"。**升级之间的依赖不只是"解锁"，还能是"封顶"**。
3. **三种升级类型共用一个结构**：`SHOP` / `BUG_CATCHING` / `SKILL_TREE`，只是显示货币不同。

### 4.2 经济数值

| 项 | 值 |
|---|---|
| 圣甲虫兑换起始手续费 | **250** |
| 手续费增长率 | **×1.15 / 次** |
| 手续费上限 | **1e9** |
| 精通目标（4 种虫） | 各 5 只 |

> 手续费指数涨但**有硬上限 1e9**——这是"反通胀"设计：防止后期数字大到没法看。
> 和海龟氧气那种"把硬约束变成资源"是同一种思路：**给任何无限增长的东西加天花板**。

## 六、Flowers and Deities（鲜花与众神）—— 分档表写法

387 个 .cs，自走棋 + 好感度。

```csharp
public static int[] favorGain_Max  = { 550, 600, 600, 520, 480, 460, 450 };  // 7 个角色上限
public static int[] favorGain_Player   = { 16, 19, 21 };
public static int[] favorGain_Easy     = { 14, 16, 19 };
public static int[] favorGain_Mid      = { 15, 18, 20 };
public static int[] favorGain_Elite    = { 17, 20, 22 };
public static int[] favorGain_Boss     = { 20, 22, 23 };
public static int[] favorGain_Nightmare= { 23, 24, 25 };
public static int[] favorGain_FinalTrial = { 34, 34, 34 };

public static int[] forgeSpecialChance = { 1, 5, 20, 40, 60, 80, 90 };  // 7 档锻造特殊概率

public static int favor_Max = 99;
public static int chance_Legend = 3;   // 传说 3%
public static int chance_Hero   = 20;  // 英雄 20%
public static int maxUpgrade    = 3;   // 一张卡最多升 3 次
```

**两个规律**：
1. **难度档位的数值是重叠的**，不是整数倍。Easy 的 14/16/19 和 Mid 的 15/18/20 只差 1~2 点——**微调靠档位内平移，不靠拉大差距**。
2. **FinalTrial 是 34/34/34 三档相同**——最高难度取消随机性，变成保底。
3. `forgeSpecialChance = {1, 5, 20, 40, 60, 80, 90}`：**首档极低（1%）、中段陡升、末档不到 100%**——永远留一点失败可能。

另外 `GetGodItemRate() = 2 × (storeUpgrade - 2)`——商店升级直接换算成道具率，线性。

## 七、Sovereign Tower（君王之塔）与 CubeDungen（点击地牢）

### 7.1 Sovereign Tower —— 结构有价值，数值拿不到

Godot 工程，3127 个 .gd（含 addons）。完整还原了整个工程：

**数值不在 Godot 资源里，在 Ink 脚本里**（Ink 是纯文本叙事语言，变量写在 .ink 里）。
→ 这是个**方法论教训**：Godot 工程还原了 ≠ 数值拿到了，还得看数值是存在 `.tres` 还是存在第三方脚本里。

### 7.2 CubeDungen —— 反例

367 个 .cs，看起来有 `CellProgassData`、`LevelParameterGroup`、`ConstGlobalParameterData`，
但打开全是空壳：

```csharp
public struct CellProgassData { public string key; public string data; }
public struct LevelParameterGroup { public string localParamemterName; public float everyLevelIncrease; }
```

## 九、可直接抄进你自己项目的 7 条

1. **隐藏动态难度**（CrownSiege）：连胜加难度、连败 ×0.75、地板随进度抬升。你的 DouSpire 高级难度外面套一层这个。
2. **"友好数字"取整**（Shroom and Gloom）：血量/伤害取整到整十，且**向下取整**。
3. **难度指数可调 + 可跳层**（Shroom and Gloom）：`exponent` 一个参数切曲线性格，`IgnoredDepths` 给喘息层。
4. **元升级加速自动过程**（RockBottom）：第三层买的是"精通 XP 速度"，不是直接数值。
5. **数值升级惩罚、机制升级不惩罚**（RockBottom）：性价比递减只施加于纯数值 buff。
