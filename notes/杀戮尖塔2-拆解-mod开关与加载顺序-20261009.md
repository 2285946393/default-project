# 拆解 · 游戏**自带** mod 开关与加载顺序（`settings.save`）+ LoadOrderManager

> 2026-10-09 · 国际台（只读侦查）
> 起点：`LoadOrderManager`（3747605109）的说明写着「保存到 settings.save，下次启动生效」。
> 顺着这条线挖下去，发现**游戏本体自己就有一套 mod 开关 + 加载顺序机制**。

---

## 一、结论：游戏自带「按 mod id 停用」的开关（不怕重新部署）

```csharp
// MegaCrit.Sts2.Core.Modding/ModManager.cs:481
/// If it's disabled in settings.save, the mod is unconditionally disabled.
private static void RemoveDisabledMods()
{
    ...
    if (settings.IsModDisabled(mod.manifest.id, mod.modSource))
    {
        Log.Info("Skipping loading mod " + mod.manifest.id + ", it is set to disabled in settings");
        mod.state = ModLoadState.Disabled;
    }
    ...
}

// ModManager.cs:293
bool isEnabled = _settings.ModList.FirstOrDefault(m => m.Id == mod.manifest?.id)?.IsEnabled ?? true;
```

**这解决了一个实际问题**：之前为了绕开 DouSpire 的启动崩溃，只能把 `mods/DouSpire` 挪出去；
但**国内台每次重新编译部署都会让它复活**。改用这个开关就覆盖不掉了 —— 它**按 mod id 记**。

## 二、机制全貌

### 2.1 数据结构（`MegaCrit.Sts2.Core.Saves/SettingsSave.cs`）

```csharp
[JsonPropertyName("mod_settings")]
public ModSettings? ModSettings { get; set; }
```

```csharp
// ModSettings.cs
[JsonPropertyName("mods_enabled")]
public bool PlayerAgreedToModLoading { get; set; }     // 「我同意加载 mod」的确认

[JsonPropertyName("mod_list")]
[JsonSerializeCondition(SerializationCondition.SaveIfNotCollectionEmptyOrNull)]
public List<SettingsSaveMod> ModList { get; set; } = new();

public bool IsModDisabled(string? id, ModSource source)
    => ModList.Any(m => m.Id == id && m.Source == source && !m.IsEnabled);
```

```csharp
// SettingsSaveMod.cs —— 注释原文：用于「手动加载顺序」和「启用/停用」
[JsonPropertyName("id")]         public string Id { get; set; } = "";
[JsonPropertyName("source")]     public ModSource Source { get; set; }      // 枚举
[JsonPropertyName("is_enabled")] public bool IsEnabled { get; set; } = true;
```

`settings.save` 里的形状（本机 `%APPDATA%\SlayTheSpire2\default\1\settings.save`）：

```json
{
  "schema_version": 8,
  "language": "zhs",
  "mod_settings": {
    "mods_enabled": true,
    "mod_list": [
      { "id": "DouSpire",  "source": 0, "is_enabled": false },
      { "id": "BaseLib",   "source": 1, "is_enabled": true  }
    ]
  }
}
```

> ⚠️ **本机现在的 `mod_settings` 是 `null`** —— 也就是这个用户**从来没确认过「加载 mod」那个弹窗**，
> 所以 `mod_list` 一直没被写出来（见 §四 的坑）。

### 2.2 游戏自带的 UI：模组界面每行一个勾选框

```
MegaCrit.Sts2.Core.Nodes.Screens.ModdingScreen/
    NModdingScreen.cs
    NModMenuRow.cs          ← 每行：_tickbox
    NModMenuButton.cs
    NModInfoContainer.cs
    NConfirmModLoadingPopup.cs   ← 「是否加载 mod」确认框
```

```csharp
// NModMenuRow.cs:266
private void OnTickboxToggled(NTickbox tickbox)
{
    SettingsSave settingsSave = SaveManager.Instance.SettingsSave;
    if (settingsSave.ModSettings == null)
        settingsSave.ModSettings = new ModSettings();

    foreach (SettingsSaveMod mod in SaveManager.Instance.SettingsSave.ModSettings.ModList)
        if (mod.Id == Mod?.manifest?.id && mod.Source == Mod.modSource)
            mod.IsEnabled = tickbox.IsTicked;      // ← 落盘

    _screen.OnModEnabledOrDisabled();
}
```

→ **游戏自带界面能开关 mod，但没有任何排序功能**（`NModdingScreen` 里搜 `MoveUp/MoveDown/Reorder/Sort` 全空）。
**这就是 `LoadOrderManager` 补的那块**（它的说明：`Add a load-order editor in Modding screen`）。

### 2.3 加载顺序从哪来

```csharp
// ModManager.cs:274-278
RemoveDisabledMods();
SortModList(_settings?.ModList ?? new List<SettingsSaveMod>());   // ← 手动顺序在这里生效
foreach (Mod mod2 in _mods) TryLoadMod(mod2);
```

`SortModList(manualOrdering)`（`ModManager.cs:345`）：
先把 mod 分成「已就绪」和「其它」两堆，然后**按 manifest 里声明的 `dependencies` 做依赖拓扑排序**
（给每个 mod 数「有多少个依赖也在列表里」，据此排），`manualOrdering` 用来定同层内的先后。

**→ 顺序 = 依赖拓扑排序 + 手动顺序（`mod_list` 的排列）**，不是文件系统顺序。

## 三、LoadOrderManager 做了什么（拆解结果）

产物：`projects/ref-loadordermgr/decompiled/LoadOrderManager.Impl.decompiled.cs`（178,807 B）

结构是**「壳 + 版本化实现」**（和 RitsuLib / 尖塔：琐事同一套路）：

```
3747605109/
    LoadOrderManager.dll              16,896 B   ← 壳（挑版本）
    mod_manifest.json                 488 B      ← ⚠️ 清单文件名不是 <id>.json
    bin/g0.107.1/LoadOrderManager.Impl.dll   94,208 B   ← 实现（按游戏版本分目录）
    i18n/{en,zhs,zht,ja,ko,de,es-ES,es-419,fr,it,pl,pt-BR,ru,tr}.lang   15 种语言
```

它做的事：

1. 在模组界面加一个**加载顺序编辑器**（上移/下移/勾选启停）。
2. 读写 `settings.save`（`SettingsSaveFileName = "settings.save"`），
   `ReadSettings(out orderedKeys, out enabledByKey)` → `List<string> orderedKeys` + `Dictionary<string,bool> enabledByKey`。
3. **「下次启动生效」**：写完之后提示用户重启（因为顺序在 `ModManager.Initialize` 早期就决定了）。
4. 还做了**漂移检测**：把上次 apply 的快照存下来，
   启动时比对当前 `settings.save`，不一致就打
   `detected drift from last apply snapshot. reason=...`
   （用来警告「你的顺序被别的工具改掉了」）。
5. 能识别存档路径里的用户 id（`/steam|gog|epic|xbox|none/<id>/`）—— 多账号/多平台适配。

> **对我们的启发**：想给玩家一个「配置开关」，**先看游戏本体有没有现成的地方可以存**
> （`settings.save` 的 `mod_settings` 就是现成的），不要自己另起一套文件。
> 游戏本体已有 `SettingsSaveMod.IsEnabled` 这种「按 id 记状态」的模式可以照抄。

## 四、★ 坑：`mod_list` 是空的时，勾选框点了没用

```csharp
// ModManager.cs:291-300
if (_settings != null && _settings.PlayerAgreedToModLoading)
{
    var list = new List<SettingsSaveMod>();
    foreach (Mod mod in _mods) { ...; list.Add(settingsSaveMod); }
    _settings.ModList = list;              // ← 只有「已同意加载 mod」时才会把 mod_list 建起来
}
else if (_settings != null)
{
    _settings.ModList = new List<SettingsSaveMod>();   // ← 否则清空
}
```

而 `OnTickboxToggled` 是**遍历 `ModList` 找匹配项才写入**：

```csharp
foreach (SettingsSaveMod mod in ...ModList)
    if (mod.Id == Mod?.manifest?.id && mod.Source == Mod.modSource)
        mod.IsEnabled = tickbox.IsTicked;     // 列表里没有这一项 → 什么都不发生
```

**→ 如果 `mod_list` 还是空的，你在界面上取消勾选会「静默无效」。**

**正确顺序**：
1. 先让游戏弹出并**确认**「是否加载 mod」（`NConfirmModLoadingPopup` → `PlayerAgreedToModLoading = true`），
   **下一次启动**时 `mod_list` 才会被建出来（本机 `mod_settings` 现在是 `null`，所以这一步还没发生）；
2. 之后再去模组界面取消勾选，才会真的落盘成 `is_enabled: false`。

## 五、对我们的直接用处

| 场景 | 以前的做法 | 现在更稳的做法 |
|---|---|---|
| 临时停用某个 mod 做排查 | 把 `mods/<X>` 挪出去（**重新部署会复活**） | 模组界面取消勾选（**按 mod id 记，覆盖不掉**） |
| 让某个 mod 排在前面/后面 | 没辙 | `settings.save` → `mod_list` 的顺序，或装 LoadOrderManager 用界面调 |
| 给玩家一个「功能开关」 | 自己写配置文件 | 参考游戏自带的 `SettingsSaveMod.IsEnabled` 模式 |
