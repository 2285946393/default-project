# 卡 A · 创作中台（creator-studio）

**一句话定位**：把你的个人作品收拢起来管理的运营后台——基于 `art-design-pro`（MIT）二次开发，主题、Logo、菜单、业务数据与接口层全部重构，演示模块移除。

> 代码位置 `projects\creator-studio\`；技术栈 Vue 3.5（`<script setup>`）+ TS 5.6 + Vite 7 + Element Plus 2.11 + Tailwind 4 + Pinia（持久化）+ ECharts 6（按需引入）。

## 背景 / 目标

作品散落在各个单文件 HTML 里，靠一个静态展馆页列出来：改一个标题要手动开文件，加一个作品要手动改数组。这个后台把它们统一管起来——列表能搜能筛能分页、能增删改、能导出，还有一块看板回答「哪些作品真的有人玩」。

## 方案选型与对比

| 决策点 | 选了 | 没选 | 理由 |
|---|---|---|---|
| 底座 | **art-design-pro（MIT）二次开发** | 从零搭后台 | 后台的表格 / 表单 / 权限 / 布局是成熟工程模式，重写一遍不会更好，只会更慢；我把时间花在业务层与数据口径上 |
| 权限粒度 | **菜单级 + 按钮级** | 只做菜单级 | 只藏菜单不够——同页面里不同角色能点的按钮不同，得能到按钮级 |
| 数据来源 | **本地 mock 数据集（34 项）+ 模拟延迟** | 直接接真后端 | 这是个人作品后台，没有服务端；但接口层按真实形态封装，换后端只替换函数体 |
| 图表 | **ECharts 6 按需引入** | 全量引入 | 全量包很大，按需 + 封装成 `Art*Chart` 组件，不拖首屏 |
| 图标 | **构建脚本裁剪成离线子集** | 整包图标 / 在线 CDN | 见下方「图标离线化」 |

## 落地细节（能讲这些就够深了）

1. **路由即菜单**（`src/router/modules/workspace.ts`）：用 `meta` 描述标题、图标、`keepAlive`、`roles`、`authList`，**菜单、面包屑、标签页、权限全部由它推导**。单一数据源，改一处全同步。
2. **两级权限**：
   - 菜单级——按 `meta.roles` 过滤路由；
   - 按钮级——`v-auth="'edit'"` 指令**直接移除无权限 DOM**，而不是 `display:none` 留着。
3. **接口层收口**（`src/api/works.ts`）：统一封装查询 / 增删改 / 各类统计口径，页面只关心 loading 与数据；换真实后端只需替换函数体。
4. **状态收敛**：表格的筛选条件与分页收在一个 `query` 对象里，改条件只改一处。
5. **图标离线化**（`scripts/build-icons.mjs`）：扫描源码里**真正用到的**图标，把 **3.5MB 的整包图标集裁到 14.6KB**——既离线可用，又不拖累首屏。

## 收益 / 数据

- 总览看板（作品总数 / 累计浏览 / 累计点赞 / 本月新增 + 30 天趋势 + 类型分布 + 热度排行 + 技术栈频次）
- 作品管理（关键字 + 分类 + 状态筛选、分页、增删改、批量删、CSV 导出）
- 数据分析（分类环形图、技术栈雷达、体积 Top 8、浏览量-点赞散点、近 12 个月上线节奏）
- 图标集 **3.5MB → 14.6KB**

## 高频追问 & 参考答案

- **这项目基于开源模板，你的贡献边界在哪？**（**必问**）
  > "底座是 `art-design-pro`（MIT）。我做的是：**主题色、Logo、菜单结构、业务数据与接口层全部重构，并把模板自带的演示模块移除**。换句话说，我拿的是它的**工程骨架**，业务层和这一套作品运营逻辑是我自己搭的。我在 README 里也写明了底座来源和协议。"
- **两级权限怎么实现的？**
  > "菜单级按路由 `meta.roles` 过滤；按钮级用 `v-auth` 指令，**直接把无权限的 DOM 移除**。"
- **那前端做权限过滤，安全吗？**（**这是陷阱题，答错就翻车**）
  > "**不安全，前端过滤只是体验层，不是安全边界。** 真正的鉴权必须在服务端——后端每个接口都要独立校验当前用户的角色和资源归属。我这个项目没有服务端，所以只能做到展示层；如果接真实后端，`v-auth` 会保留作为交互优化，但**权限判定会以服务端返回为准**。这一点我很清楚。"
- **图标 3.5MB → 14.6KB 是怎么做的？**
  > "写了个构建脚本 `build-icons.mjs`，扫源码里实际引用的图标名，只把用到的注册进离线图标集。**整包图标里有大量用不到的资源，全带上就是白扛体积。**"
- **「路由即菜单」的好处和代价？**
  > "好处是单一数据源——菜单、面包屑、标签页、权限都从路由 `meta` 推导，不会出现'加了路由忘了加菜单'。代价是 `meta` 的字段约定要维护，字段一多要写文档约束。"
- **为什么用 Pinia 持久化？**
  > "登录态、主题、标签页这些需要在刷新后保持，否则一刷新就退出登录、标签页全没了。"
- **如果接真实后端要改什么？**
  > "替换 `src/api/works.ts` 里的函数体即可，页面层不用动——**接口收口就是为了这一刻**。另外要补服务端鉴权中间件，前端 `v-auth` 降级为体验优化。"

## 如果重来

- 把 `meta` 的字段约定抽成 TypeScript 类型 + 校验，现在靠约定；
- 表格加**列宽记忆**和**导出字段选择**；
- 补一个真实的「作品访问埋点」，现在浏览量 / 点赞是演示数据。

## ⚠️ 如实说明

- **底座是 art-design-pro（MIT），不是我写的。** 说「二次开发」，别说「我独立设计了这套后台框架」。
- **接口是本地 mock，不是真后端。** 被问到直接说：「没有服务端，数据是本地数据集 + 模拟延迟，但接口层按真实后端形态封装。」**主动承认比被拆穿强。**
- **前端权限不等于安全。** 见上面的陷阱题，务必守住。

# 卡 B · 鲸云 API（ai-gateway）

**一句话定位**：一个 AI 大模型统一接入网关的**前端产品**——官网 + 用户控制台 + 管理后台三端，数据服务层收口 15 个接口，首屏 JS 从 841KB 优化到 389KB。

> 代码位置 `projects\ai-gateway\`；技术栈 React 18 + TS 7（strict）+ Vite 8 + Tailwind 3（自建设计 token）+ React Router 7 + Recharts + lucide-react + framer-motion。

## 背景 / 目标

想验证一件事：**能不能独立设计并落地一个多端产品的前端**——不只是页面能打开，而是有完整信息架构、统一的数据服务层、可复用的组件与类型体系，并且**性能经得起看**。

## 方案选型与对比

| 决策点 | 选了 | 没选 | 理由 |
|---|---|---|---|
| 项目定位 | **纯前端演示产品** | 真做模型转发 | 我要展示的是**前端产品能力**（信息架构 / 设计系统 / 工程化），不是后端网关；README 里写得很清楚 |
| 数据 | **mock + 固定种子随机** | 直接硬编码 / 随机 | 见下方「mulberry32」 |
| 状态管理 | **自研 `useAsync` hook** | Redux / Zustand / SWR | 四态收敛一个小 hook 就够，引入状态库是负担 |
| 表格 | **列配置驱动的泛型 `DataTable`** | 每个页面手写表格 | 用 `Column<T>[]` 描述列，泛型保证 `render(row)` 类型安全，多页复用 |
| 样式 | **Tailwind + 自建设计 token** | 直接上 antd | 官网需要独特视觉；后台部分借鉴模板结构 |
| 字体 | **自托管 woff2 + 子集** | Google Fonts `@import` | 国内会直接超时，见下 |

## 落地细节（能讲这些就够深了）

1. **数据服务层收口**（`src/lib/api.ts`）：统一封装模型 / 密钥 / 日志 / 渠道 / 用户 / 统计共 **15 个接口**，签名与返回结构**对齐真实后端**，页面只关心 loading 与数据；`Paged<T>` 统一分页口径。
2. **`useAsync` hook**：把「加载中 / 成功 / 失败 / 手动刷新」**四态收敛成一个 hook**，并处理了**组件卸载后不 setState** 的问题——所以页面里**没有一处手写 `useEffect + useState` 三件套**。
3. **列配置驱动的表格**：`DataTable` 用 `Column<T>[]` 描述列，泛型保证 `render(row)` 类型安全。
4. **路由级代码分割（性能主线）**：官网同步加载，控制台与管理端用 `lazy()`，**把 410KB 的 recharts 从首屏挪走**——首屏 JS **841KB → 389KB（gzip 128KB）**。
5. **自托管字体**：模板原本 `@import` Google Fonts，国内直接超时；改为**本地 woff2 + `unicode-range` 只带 latin 子集**，共 127KB。
6. **固定种子随机数**：mock 数据用 **mulberry32** 生成，**刷新页面图表不会乱跳**。

## 收益 / 数据

- 三端：官网（Hero / 模型广场 / 能力介绍 / 实时状态 / 价格 / 常见问题）+ 控制台 6 页 + 管理后台 4 页
- 数据服务层 **15 个接口**、统一 `Paged<T>` 分页
- 首屏 JS **841KB → 389KB（gzip 128KB）**
- 自托管字体 **127KB**

## 高频追问 & 参考答案

- **这是个纯前端项目？有没有真后端？**（**必问，别含糊**）
  > "没有真后端，数据由 `src/lib/mock` 生成。**但我把接口层 `src/lib/api.ts` 按真实后端的形态封装了异步调用**——签名、返回结构、分页口径都对齐真实服务，换成 `fetch` 就能对接。我想展示的是前端产品能力：信息架构、设计系统、类型体系和性能。"
- **首屏 841KB → 389KB 是怎么降下来的？**
  > "主要是**路由级代码分割**：官网同步加载，控制台和管理端 `lazy()`，把 **410KB 的 recharts 从首屏挪走**。再叠上自托管字体只带 latin 子集（127KB），以及检查打包构成去掉冗余。**这是工程手段，不是算法优化**——我不会把它说成算法。"
- **`useAsync` 到底解决了什么？**
  > "两件事。一是**四态收敛**——loading / 成功 / 失败 / 手动刷新，页面不用各写各的。二是**组件卸载后不 setState**——异步请求回来时组件可能已经卸载，直接 setState 会报警告、也容易埋内存问题。收敛之后页面里一处 `useEffect + useState` 三件套都不用写。"
- **表格为什么用泛型列配置？**
  > "`Column<T>[]` 描述列，`render(row)` 的 `row` 类型跟着走，**列定义错了编译期就报**。而且多页表格复用同一套 `DataTable`，不用每页手搓。"
- **mock 数据为什么用固定种子？**
  > "如果用 `Math.random()`，**每次刷新图表都在跳，看起来像 bug**。mulberry32 让同一个种子永远生成同一份数据，演示时稳定、可复现。"
- **15 个接口怎么组织的？**
  > "全部收口在 `api.ts`，按业务域分组（模型 / 密钥 / 日志 / 渠道 / 用户 / 统计），统一 `Paged<T>` 分页。页面只关心 loading 与数据，**不关心数据从哪来**。"
- **为什么不用 antd 这类成熟组件库？**
  > "官网需要独特视觉，用通用组件库反而要大量覆盖样式。我选择**自建设计 token + Tailwind**，后台部分借鉴模板结构。**代价是基础组件要自己写，收益是视觉和交互完全可控。**"
- **这个项目最能体现你什么能力？**
  > "**信息架构 + 设计系统 + 工程化**。三端十来个页面的信息组织、统一的数据层与组件层、以及首屏性能从 841KB 压到 389KB——这些是一个前端产品该有的东西，不是几个页面能糊出来的。"

## 如果重来

- 补**真实后端**（哪怕是最小可用的转发服务），把 `api.ts` 换成真 `fetch`；
- `useAsync` 加**请求去重**与**竞态处理**（现在并发同名请求会重复发）；
- 加**暗色主题**和移动端适配。

## ⚠️ 如实说明

- **这是纯前端演示，没有真网关服务。** 被问到**第一时间说清**，别等被追问。
- **841KB → 389KB 是工程手段（代码分割 / 字体子集 / 打包裁剪），不是算法优化。** 别说成"我优化了算法"。
- 界面设计语言**参考了开源模板 brainwave（MIT）**，已重构为 TypeScript 并替换为 AI 网关业务内容——如实说。

# 卡 C · 菌丝世界（Mycelia）

**一句话定位**：WebGL2 GPU 黏菌（Physarum）模拟——在 `MattKulka/mycelia` 底座上，加入**「输入一个词就长出一只专属生物」**的原创玩法，中文界面与交互层整体重做，打包成零依赖单文件。

> 这是你**改造类里最强的一个**，也是旗舰三的有力候选。

## 背景 / 目标

原项目是个很棒的模拟，但它是个「参数面板」——普通人打开不知道该干嘛。目标：让它变成一个**能玩、想分享**的东西。

## 落地细节（**这些才是"我做的"**）

1. **「文字 → 基因组」（原创玩法）**：把用户输入的任意文字（中文 / 英文 / 整条链接都行）**哈希成一个种子**，再用这个种子**确定性地推导出全部 14 个参数**（感知角度、感知距离、转向速度、痕迹衰减、配色、萌发形态……）。
   → **同一个词永远长出同一只生物，链接发给别人能一字不差复刻。**
2. **整套中文界面与交互层重做**：8 套氛围配色（深渊 / 余烬 / 孢子 / 星云 / 象牙 / 青腐 / 岩浆 / 霜雪）、7 项参数实时滑块、鼠标「喂养 / 驱散」。
3. **打包成零依赖单文件**，双击即运行。

**技术底座（如实说）**：WebGL2 + `EXT_color_buffer_float` **浮点纹理**，多 Pass 迭代，**粒子状态存在纹理里**——这是原项目的架构，不是我设计的。

## 收益 / 数据

- 近百万粒子在 GPU 上自组织成菌丝网络
- 14 个基因组参数、8 套配色、7 项实时滑块
- 零依赖单文件，双击即运行

## 高频追问 & 参考答案

- **你改了什么？**（**必问**）
  > "内核是 `MattKulka/mycelia` 的 WebGL2 黏菌模拟。我加的是：**'文字 → 基因组'这个玩法**（哈希种子 → 确定性推导 14 个参数，实现'同词同生物'）、**整套中文界面与交互层**、8 套配色、7 项参数滑块、鼠标喂养/驱散，以及打包成零依赖单文件。"
- **为什么要做「同词同生物」？**
  > "为了**可复现**。如果每次都不一样，用户就没法跟别人说'这是属于我的生物'。**确定性哈希让一个词变成一个身份**，链接发出去别人能一字不差复刻。"
- **哈希冲突怎么办？**
  > "会有，但哈希空间很大，日常用词基本不会撞；就算撞了也只是两只生物长得像，不影响体验。"
- **为什么用浮点纹理？`EXT_color_buffer_float` 是干嘛的？**
  > "粒子状态（位置 / 朝向 / 痕迹）要存在纹理里，用 8 位纹理精度不够、会量化出问题，所以要**浮点纹理**做状态存储。而 WebGL2 默认不能渲染到浮点纹理，**必须开 `EXT_color_buffer_float` 扩展**才能把浮点纹理当渲染目标。"
- **为什么要多 Pass 迭代？**
  > "粒子要读其他粒子留下的痕迹来转向，这没法在一个 pass 里完成——所以拆成**多个 pass**：先更新粒子状态、再沉积痕迹、再衰减。每步都是一个 fragment shader。"
- **如果粒子数再涨 10 倍？**
  > "GPU 上主要是显存带宽和纹理读写压力，会先到瓶颈。届时要降精度 / 降分辨率、或把多 Pass 合并、上 WebGPU compute。**我知道瓶颈在哪。**"
- **为什么不自己从零写黏菌模拟？**
  > "因为不值得。人家迭代了好几年，我从零写最好也就是达到它的水平，但要花几周——**这几周我本来可以用来设计玩法**。我更愿意把时间花在有差异化的部分：这个东西怎么玩、怎么让人一眼看懂。"

## 如果重来

- 把基因组参数做成**可视化编辑 + 导出/导入**，让玩家能微调自己的生物；
- 加**作品导出**（截图 / 参数卡）方便分享；
- 上 WebGPU compute 试更高粒子数。

## ⚠️ 如实说明

- **内核是 MattKulka/mycelia 的，不是我写的。** 说「改造 + 加玩法」，别说「我写了黏菌模拟内核」。
- **许可证：原仓库没有 LICENSE 文件。** 所以**只在作品里如实标注来源，没有声称适用任何协议**——这恰恰是最准确、最安全的写法。
  > 被问到时可以主动说："这个底座的作者**没有声明许可证**，所以我只标了来源，没有声称它适用某个协议。用别人的代码，把来路搞清楚是基本的。"

# 通用追问（跨项目 · 面试官最常打的那几张牌）

## ① 「你的作品有多少是你自己做的？」
> "分两类。一类**完全是我自己做的**——AI 面试官、鲸云 API、创作中台，从零到上线都是我自己写的。另一类我更愿意叫**开源改造**——我先在 GitHub 上找成熟底座，自己负责判断、改造、玩法设计和视觉包装。比如菌丝世界，内核是开源的黏菌模拟，但**'输入一个词长出一只专属生物'这个玩法是我加的**。
>
> 我不太倾向于重复造轮子——把时间花在重新实现一个已有的粒子系统上，产出不会比现成的好，但会耗掉我做玩法设计的时间。"

## ② 「你用 AI 写代码吗？」（2026 必问）
> "大量用，当**加速器**。但用在**该用的地方**：检索筛选开源项目、解释看不懂的代码、处理样板逻辑。而**选题、判断项目值不值得做、玩法设计、交互调优、最后验收——这些我自己来**。
>
> 举个例子：元素秘境的软笔刷，一开始用实心圆撒沙，一整块同时出现、整体下坠，很假。是我自己发现'颗粒之间缺少独立性'，改成逐格随机撒点才自然的。**这种问题 AI 给不了答案，得自己看、自己判断。**"

## ③ 「那你到底自己写了多少？」
> "分项目。AI 面试官、鲸云、创作中台**全部是我写的**。改造类的话，**内核可能来自开源，但玩法设计、交互、视觉、中文化和工程适配都是我做的**。"

## ④ 「为什么不自己从零写？」
> "**因为不值得。** 成熟的黏菌模拟、流体求解，人家迭代了好几年。我从零写，最好的结果是达到人家的水平，但要花几周——这几周我本来可以用来设计玩法、调交互、做包装。前提是我得**真的读懂它**：知道入口在哪、依赖怎么接、为什么会卡、改哪里会坏。"

## ⑤ 「你最强的能力是什么？」
> "**判断 + 改造 + 产品化**。我最强的不是从零造底层轮子，而是**理解一个已有项目、判断它值不值得做成产品、然后真的把它改出来**——包括玩法设计、交互、视觉和工程适配。"

## ⑥ 「你的项目有真实用户吗？」
> **诚实答，别吹**：
> "没有大量用户，这些是我的个人作品和求职作品。但我做过可验证的事：比如 AI 面试官的**三级降级**，我用拔掉 API Key 的方式验证了全流程不崩；鲸云的首屏体积是**打包分析后实测**的 841KB→389KB。"

## ⑦ 「讲一个你定位过的最难的 bug」
> 从 `踩坑笔记.md` 里挑一个真实的说，**重点讲定位过程**（怎么缩小范围、怎么验证假设），而不是结果。没有现成的就现场想一个你确实花过时间的。

## ⑧ 「如果给你一个全新项目，你怎么开始？」
> "先想清楚**目标用户和核心体验**是什么，再判断**技术底座是自研还是改造**，然后定义**最小可用的完整流程**（能进能出、有加载/空/错误态），最后才是性能和打磨。"

## ⑨ 「你最近在学什么？」
> 说真的：**WebGPU compute**（想把压力迭代 / 粒子计算搬上去）、**混合检索**（BM25 召回 + 向量重排）。**别编没在学的东西。**

## ⑩ 「你最大的短板是什么？」
> 诚实 + 带改进动作，例如："**我倾向于过度打磨单个作品，容易在一个项目上停不下来**。我现在给自己定了规则：每两周只允许在一个项目上深入，其余时间强制推进新选题。"（换成你真实的短板，但**必须带一个已经在执行的改法**）
