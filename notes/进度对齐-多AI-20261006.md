## 五、⚠️ 环境坑（所有 AI 都要知道）

### 坑 1 · WorkBuddy 的 bash 里 `dotnet` 全废

在 WorkBuddy 的 bash 里跑 `dotnet build` 一律报：

```
error : Value cannot be null. (Parameter 'path1')
```

**原因**：WorkBuddy 的 bash 启动子进程时不带 Windows 系统环境变量
（`SystemRoot` / `ProgramData` / `APPDATA` 全缺）→ .NET 的
`Environment.GetFolderPath(CommonApplicationData)` 返回空 → NuGet 拼不出
`%ProgramData%\NuGet` → 抛异常。**连已能跑的 frost-spire 在这个 shell 里也构建不了。**

**绕过**：补齐 `SystemRoot`/`windir`/`ComSpec`/`ProgramData`/`ALLUSERSPROFILE`/`APPDATA`/
`LOCALAPPDATA`/`TEMP`/`TMP`/`ProgramFiles`/`CommonProgramFiles`，并加
`-p:MSBuildEnableWorkloadResolver=false -p:RestoreProjectStyle=`。

- **零依赖工程**（`dou-spire-rules`）：这样就能构建，`run.sh` 里已封好。
- **带 NuGet 依赖的工程**（quest-spire / frost-spire 要 RitsuLib / Godot.NET.Sdk）：
  **✅ 2026-10-06 已解决**。关键是在补系统变量的基础上**再指定 `NUGET_PACKAGES`**，
  让 NuGet 别去猜全局包目录：

  ```bash
  export NUGET_PACKAGES="$USER_HOME\\.nuget\\packages"
  ```

  已经封成脚本 **`projects/dou-spire-rules/tools/build-mod.sh`**，用法：

  ```bash
  cd "projects/dou-spire-rules"
  bash tools/build-mod.sh ../frost-spire      # 或 ../quest-spire / ../dou-spire
  ```

  实测 frost-spire + dou-spire 都是 0 错误 0 警告，并在沙箱里直接把 dll 拷进
  `<游戏目录>\mods\<ModName>\`。细节见技能 `dotnet-build-in-sandbox`。

  > ⚠️ 上面那句"沙箱里过不去、得用普通终端"是**过时的**了，已更正。
