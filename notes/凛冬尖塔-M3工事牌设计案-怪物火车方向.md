# 凛冬尖塔 · M3 工事牌设计案（怪物火车 2 方向）

> 2026-10-06 17:25 起稿，**18:xx 用 Monster Train 2 真实数值校准**（见第八节）。
> **毛烨两个关键决策**：
>   1. 「凛冬前线 = 各种效果建筑堆在一起去打伤害，感觉和能力牌很像，**只是建筑能放在场上挡伤害**」
>   2. 「不做很多条线，**往怪物火车 2 靠，只做一条线**」
>
> 本设计案按这两个决策重排 M3。**核心结论：全部 API 已验证可行，且比自己想的更顺。**

---

## 一、先纠正一个概念（重要，不然会走偏）

**怪物火车 2 的乐趣不在"线多"，在"位置有限被迫取舍"。**
一节车厢就几个格子，你必须在"谁扛 / 谁输出 / 谁辅助"之间做选择。**多线只是载体，取舍才是乐趣。**

所以我们真正要抄的是 **「有限部署位 + 单位分层」**，不是"多线"。而"只做一条线"这个决定**完全正确**：

| 好处 | 说明 |
|---|---|
| 裂隙地图**本来就是一条线** | `FrostRiftActMap` 已特意每层只连自己那一列（不是 Natsuki 的 3×3 全连） |
| **阶段 2（地图 UI）可以缓做** | 一条线不需要复杂的地图屏改造 |
| 精力全砸在"战斗里的部署" | 这才是好玩的地方 |

**结论：裂隙（一条线）+ 工事牌（部署）= 已经很接近怪物火车的骨架了。**

## 二、★ 但有一条硬边界（必须先说清）

> **怪物火车的"前排/后排"靠位置实现**（怪打最前面的单位）。
> **《杀戮尖塔》战斗里没有位置概念** —— 怪打谁由 AI 决定，**没有站位、没有路径**。

**所以"分层扛伤"不能靠站位，得靠机制实现。好消息：官方的机制正好够用，而且是现成的。**

### 2.1 `DieForYouPower` = 现成的「替伤」（1:1 可抄）

反编译源码（`MegaCrit.Sts2.Core.Models.Powers.DieForYouPower`）：

```csharp
public sealed class DieForYouPower : PowerModel
{
    // ★ 核心：把打到"主人"身上的伤害，转到宠物身上
    public override Creature ModifyUnblockedDamageTarget(Creature target, decimal _, ValueProp props, Creature? __)
    {
        if (target != base.Owner.PetOwner?.Creature) return target;   // 只挡主人
        if (base.Owner.IsDead) return target;
        if (!props.IsPoweredAttack()) return target;                  // 只挡"攻击"，不挡毒/能力伤害
        return base.Owner;                                            // 转移！
    }

    // ★ 宠物死了不从战斗移除（"尸体留下"）
    public override bool ShouldCreatureBeRemovedFromCombatAfterDeath(Creature creature)
        => creature != base.Owner;

    public override bool ShouldPowerBeRemovedAfterOwnerDeath() => false;
}
```

**这就是我们的"前排"。** 而且 `ZCode` 已经在 `SummonMilitiaCard` 里用了它 —— **已经在跑了**。

**关键细节（会影响设计）**：
- `IsPoweredAttack()` 判断意味着**只挡普通攻击**，不挡毒/能力伤害 → 天然有"穿甲"概念，是好设计。
- 宠物死后**留在场上** → 可以做"建筑被摧毁后变成废墟"的视觉。

### 2.2 全部可用的伤害钩子（都在 `AbstractModel` 上，已验证）

| 钩子 | 签名 | 拿它做什么 |
|---|---|---|
| `ModifyUnblockedDamageTarget` | `(target, amount, props, dealer)` → `Creature` | **伤害转向**（替伤） |
| `ModifyDamageMultiplicative` | `(target, amount, props, dealer, src, play)` → `decimal` | **减伤**（`GuardedPower` = 0.5） |
| `ModifyDamageAdditive` | 同上 | **固定减伤**（-2 / 击） |
| `ModifyDamageCap` | `(target, props, dealer, src, play)` → `decimal` | **"硬壳"：每击最多吃 N 点** |
| `ModifyBlockAdditive` / `Multiplicative` | `(target, block, props, src, play)` | **建筑给盾** |
| `ModifyHpLostBeforeOsty` | `(target, amount, props, dealer, src)` → `decimal` | 更精细的 HP 重定向 |
| `ShouldAllowHitting` | `(creature)` → `bool` | **"无敌"**（`DieForYouPower` 用它让死宠物不可打） |

**→ 建筑能做什么，技术上完全没有悬念了。全都有现成钩子。**

### 2.3 `GuardedPower` 是"减伤建筑"的 1:1 样板

```csharp
public sealed class GuardedPower : PowerModel
{
    protected override IEnumerable<DynamicVar> CanonicalVars => new[]
    {
        new StringVar("Applier"),
        new DynamicVar("DamageDecrease", 0.5m)      // 减伤 50%
    };

    public override decimal ModifyDamageMultiplicative(Creature? target, decimal amount, ...)
    {
        if (target != base.Owner) return amount;    // 只管自己
        ...                                          // 返回 amount * 0.5
    }

    // 施加者死了 → 能力消失
    public override async Task AfterDeath(PlayerChoiceContext ctx, Creature creature, bool wasRemovalPrevented, float len)
    {
        if (!wasRemovalPrevented && creature == base.Applier)
            await PowerCmd.Remove(this);
    }
}
```

**注意最后那个 `AfterDeath`**：能力**绑定在施加者身上**，施加者死了能力就没了 ——
这正是"建筑被拆了，效果就没了"的语义。**直接抄。**

### ★ 2.4 补充：`ThornsPower` = "被攻击就反击"的 1:1 样板（18:xx 新增）

```csharp
public sealed class ThornsPower : PowerModel
{
    public override PowerType Type => PowerType.Buff;
    public override PowerStackType StackType => PowerStackType.Counter;

    public override async Task BeforeDamageReceived(PlayerChoiceContext choiceContext,
        Creature target, decimal amount, ValueProp props, Creature? dealer, CardModel? cardSource)
    {
        if (target == base.Owner                                  // ★ 只管自己
            && dealer != null
            && (props.IsPoweredAttack() || cardSource is Omnislice))  // ★ 只反"攻击"
        {
            Flash();
            await CreatureCmd.Damage(choiceContext, dealer, base.Amount,
                ValueProp.Unpowered | ValueProp.SkipHurtAnim, base.Owner, null, null);
        }
    }
}
```

**这给"冰垒"提供了一个比 `DieForYouPower` 更轻量的变体**：被攻击时反弹伤害（尖刺塔）。
`props.IsPoweredAttack()` 再次出现 —— **"只挡/只反普通攻击"是官方一致惯例**，我们跟着做即可。

### ★ 2.5 补充：`BlackHolePower` 全源码（18:xx 新增，箭塔的正式样板）

```csharp
public sealed class BlackHolePower : PowerModel
{
    public override PowerType Type => PowerType.Buff;
    public override PowerStackType StackType => PowerStackType.Counter;

    public async Task DealDamageToAllEnemies()
    {
        Flash();
        await CreatureCmd.Damage(new BlockingPlayerChoiceContext(),
            base.CombatState.HittableEnemies,   // ★ AOE 目标池（现成）
            base.Amount,                        // ★ 能力层数 = 伤害值
            ValueProp.Unpowered, base.Owner);
    }
}
```

**两个关键收获**：
- **AOE 伤害一行搞定**：`CreatureCmd.Damage(ctx, 目标集合, 伤害, prop, 来源)`
- **`base.Amount` = 能力层数 = 伤害** → 箭塔"每次造成 N 伤害"直接用层数表达，**升级 = 加层数**，零额外状态

### ★ 2.6 回合钩子选择规则（18:xx 从 `AbstractModel` 官方注释抄下来的，直接照做）

| 想要的时机 | 用哪个钩子 | 依据 |
|---|---|---|
| 战斗开始**前**（挂能力、上状态） | `AfterRoomEntered(room)` + 判断 `room is CombatRoom` | 官方注释原话 |
| 战斗开始**后**（造成伤害、获得格挡） | `AfterSideTurnStart(side, participants, combatState)` + **RoundNumber 检查** | 官方注释原话 |
| 需要玩家做选择的效果 | `AfterPlayerTurnStart(ctx, player)` | 官方注释警告：否则与抽牌效果冲突 |
| 回合结束 | `BeforeSideTurnEnd(ctx, side, participants)` | — |

**→ 箭塔/熔炉的"每回合开始"：用 `AfterSideTurnStart` + `RoundNumber` 判断，不要用 Others。**
**→ 注意官方明确警告 `AfterSideTurnStartLate` / `AfterPlayerTurnStartEarly` 都"通常不该用"。**

## 三、M3 工事牌清单（按"一条线 + 部署取舍"重排）

### 设计原则

1. **一条线上的有限部署位** → **场上单位容量上限**（而不是靠地图线数）。
   **v1 建议：容量 5 点（抄 Monster Train 2 的真实数值，见第七节）**，建筑/单位各占 Size 权重，不按"个数"算。
2. **单位分层用"功能"而非"站位"**：
   - **前排（扛）**：带 `DieForYouPower` → 替玩家挡攻击
   - **后排（打）**：每回合自动对敌人造成伤害（`BlackHolePower` 是 1:1 样板，见 2.5）
   - **辅助**：给玩家/单位加盾、加力量
3. **建筑不占用手牌位，只占部署位** —— 通过"召唤"实现（`PlayerCmd.AddPet`）。

### v1 八张（4 建筑 + 4 单位）

| # | 名称 | 类型 | 费用 | Size | 效果 | 机制依据 |
|---|---|---|---|---|---|---|
| 1 | **冰垒** | 建筑 | 1 | 2 | 部署一个 6 血建筑，**替玩家挡普通攻击** | `DieForYouPower`（已验证） |
| 2 | **箭塔** | 建筑 | 2 | 2 | 部署一个 4 血建筑，**每回合对全部敌人造成 3 点伤害** | `BlackHolePower` 1:1 样板（2.5） |
| 3 | **符文壁** | 建筑 | 2 | 1 | 部署一个 8 血建筑，**受击伤害减半** | `ModifyDamageMultiplicative`（`GuardedPower` 样板） |
| 4 | **熔炉** | 建筑 | 3 | 3 | 部署一个 10 血建筑，**每回合给玩家 +2 格挡** | `ModifyBlockAdditive` + `AfterSideTurnStart`（2.6） |
| 5 | **民兵** | 单位 | 1 | 2 | 部署 6/6 民兵（**会按自己的 AI 自动攻击**） | `PlayerCmd.AddPet<LeafSlimeM>`（ZCode 已实现） |
| 6 | **猎手** | 单位 | 2 | 2 | 部署 5/5 猎手，**每回合自动打最弱的敌人** | `AddPet` + `AfterSideTurnStart` |
| 7 | **冰法师** | 单位 | 2 | 1 | 部署 4/4 法师，**每回合给随机敌人挂 1 层虚弱** | `AddPet` + `PowerCmd.Apply<WeakPower>` |
| 8 | **重装兵** | 单位 | 3 | 3 | 部署 12/12 重装兵，**带替伤**（相当于第二个前排） | `AddPet` + `DieForYouPower` |

> **Size 列是 18:xx 校准后新增的**。规则抄 Monster Train 2：**容量 5 点，单位 Size 1~6**。
> → 一回合最多摆 **2 个大件**（2+2 或 1+3）或 **3 个小件**（1+1+1，还剩 2 点）。**取舍自然就出来了。**
> → 想加"巨兽"就做 Size 4~5 的牌（对应 MT2 的融合怪/大恶魔），一张占完大半容量。

### 为什么这个清单是对的

- **1~8 全部踩在已验证的 API 上**（`AddPet` / `DieForYouPower` / `BlackHolePower` / 伤害钩子）。
- **"建筑挡伤害"这个你最在意的点，是第 1、3、8 号** —— 三种不同的挡法（替伤 / 减伤 / 第二前排）。
- **部署位上限 = 取舍**，这是怪物火车的核心乐趣，不需要多线就能有。

## 四、明确的**不做**清单（避免走偏）

| 想法 | 判定 | 理由 |
|---|---|---|
| 塔防格子 / 摆位拦怪 | ❌ 不做 | 《杀戮尖塔》战斗**没有位置概念**，怪不走路径 |
| 多线地图（怪物火车的多条车道） | ❌ 不做（本次决定） | 一条线足够，且地图 UI 成本低 |
| 单位被"阻挡"在某格 | ❌ 不做 | 同上，无格子 |
| 单位永久成长 / 跨战斗升级 | ⚠️ 待定 | 单位是战斗内实体，跨战斗要重新部署（v1 不做） |

## 五、和裂隙（传送门）怎么配合

**这两件事叠起来，体验就是"进关卡 → 部署 → 打 → 结算"：**

```
地图上打出「开启凛冬裂隙」
  └─ 进入裂隙小地图（一条线，3 列 × 2 层遭遇）
       └─ 每层遭遇 = 一场战斗
            └─ 在战斗里：部署工事牌（建筑挡伤害 + 单位输出）
                 └─ 打完 → 走下一层
                      └─ 走到终点 → 结算 → 回原地图
```

**裂隙 = 关卡容器；工事牌 = 关卡里的部署系统。** 这就是怪物火车的骨架。

**排期建议**：
1. **先实测阶段 1.5**（裂隙能不能进、能不能出）—— 这是地基。
2. 地基稳了 → **上 M3 的 1/2/5 号牌**（冰垒 + 箭塔 + 民兵，三张最小可玩集）。
3. 再补剩下的 5 张。
4. 最后才考虑阶段 2 的地图 UI。

## 七、★ 附：Monster Train 2 真实数值对照表（18:xx 反编译 `Assembly-CSharp.dll` 拿到）

> 来源：`D:/BaiduNetdiskDownload/game/Monster Train 2/MonsterTrain2_Data/Managed/Assembly-CSharp.dll`（**Mono 版，可反编译**）

### 7.1 核心数值（`BalanceData` / `SpawnPointGroup` / `CharacterData`）

| 参数 | 真实值 | 定义处 |
|---|---|---|
| **每层容量 `characterCapacityPerFloor`** | **5** | `BalanceData:815` |
| **每层物理点位 `numSpawnPointsPerFloor`** | **7** | `BalanceData:812` |
| **单位默认 Size** | **2** | `CharacterData:49`（`[Range(1,6)]`） |
| **单位 Size 范围** | **1 ~ 6** | `CharacterState.GetSize() => Mathf.Clamp(Size, 1, 6)` |
| **容量下限 / 上限** | **1 / 30** | `SpawnPointGroup.MinCapacity / MaxCapacity` |
| **隐藏容量 UI 的阈值** | **6** | `SpawnPointGroup.HideUIAtCapacity` |

### 7.2 ★ 最值得抄的一点：**容量是"权重和"，不是"格位数"**

```csharp
// SpawnPointGroup（反编译）
public int GetRoomCapacity()   // 当前占用 = Σ 存活单位.Size
{
    int num = 0;
    foreach (var c in GetCharacters(includeOuterTrain: false))
        if (c.IsAlive) num += c.GetSize();
    return num;
}

public int GetMaxCapacity() => baseCapacity + capacityAdjustment;   // 上限 = 基础5 + 修正

public bool WillBeAtCapacity(int characterSize = 0)
    => GetRoomCapacity() + characterSize > baseCapacity + capacityAdjustment;   // ★ 一句话判定能不能放
```

**关键差异**：MT2 的 `numSpawnPoints(7) ≠ capacity(5)`。
**7 个位置但只有 5 点容量** → 你永远填不满 7 个格子，但可以放 2 个 Size2 的单位（占 4 点）留 1 点。
**取舍感来自"容量贵"，不是"位置少"。**

**凛冬尖塔直接抄这个模型**：不问"场上有几个单位"，问"**场上单位 Size 加起来够不够 5**"。

### 7.3 次要但有意思的设计

| 机制 | MT2 实现 | 凛冬可借鉴 |
|---|---|---|
| **容量可被战局改变** | `RoomStateCapacityModifier`（`IRoomStateCapacityModifier`，`AdjustCapacity(team, ±n)`） | 做"冰封大地：本场容量 +1"的遗物/牌 |
| **容量变化有正负分支** | 进入战斗 `AdjustCapacity(+n)`，离开战斗 `AdjustCapacity(-n)`（`RoomState:2333/2353`） | 临时扩容要成对处理 |
| **阵型随规模自动拉开** | `SpawnPoint.GetRange()` 读 `ExtendedUnitTrigger1/2/3` + `ExtendedCapacityTrigger1/2/3` | 单位多了自动变阵（视觉手感，v1 可跳） |
| **默认从前排开始填** | `CardEffectSpawnMonster`：`SpawnMode.FrontSlot` | 部署顺序可视化 |
| **单位尺寸可被升级改** | `CharacterState.PrimaryStateInformation.Size += sizeDelta`，带 `CardStateModifiers` | 对应"升级卡"改 Size |

### 7.4 ⚠️ 必须说清的边界：**MT2 的代码不能移植**

Monster Train 2 是 **Unity + MonoBehaviour**（`RoomState : MonoBehaviour`），《杀戮尖塔 2》是 **Godot + C#**。
- **能拿的**：**设计数值、机制模型、手感规则**（就是上面这些）
- **不能拿的**：代码。`RoomState` 那种 Unity 组件写法在 STS2 里一行都用不上
- **正确姿势**：把 MT2 当"**数值设计师**"，把 STS2 的 `AddPet` / `PowerModel` / 钩子当"**实现工具**"
