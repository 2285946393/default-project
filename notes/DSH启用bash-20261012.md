# DSH 启用 bash（Windows）— 2026-10-12

## 一句话

给 DSH 挂上 **Git 自带的 bash 5.3.15**，让 AI 不再和 PowerShell 5.1 的编码坑打架。
**没有升级 DSH，没有装新插件，只改了两处配置。**

---

## 为什么要做这件事

起点是用户在 B 站看到「一键节省大肥鱼 40% token 花费的 dsh 插件」
（[BV1nFp46qECm](https://www.bilibili.com/video/BV1nFp46qECm)，项目
[T-Auto/dsh-ops](https://github.com/T-Auto/dsh-ops)）。

查证后发现问题：**dsh-ops 要求宿主 DSH `0.2.0-rc.2`，本机是 `0.1.5-rc.2`。**

用新版本干跑 `--dump-config` 验证，**7 个插件会被拒绝加载**：

| 插件 | 后果 |
| --- | --- |
| `@yuxianglin/dsh-bridge-browser` | **浏览器桥没了**（开 B 站靠它） |
| `dsh-better-sidebar` | 侧边栏没了 |
| `dsh-appearance-gallery` | 外观画廊没了 |
| `dsh-undo` | 撤销没了 |
| `dsh-chat-manager` | 聊天管理没了 |
| `dsh-connect-trae` | Trae 连接没了 |
| `@deepseek-ai/dsh-subagent-codex` | codex 子代理没了 |

原因：这些插件声明 `peerDependencies: ^0.1.5-rc.2`，主版本对不上，**直接被拒**。
插件作者也还没发 0.2.0 版本，升级插件解决不了。

**结论：不升级。** 但 dsh-ops 的核心价值（绕开 PowerShell）可以本地自己实现。

---

## 根因：DSH 在 Windows 上默认禁用了 bash

`dsh --profile web --dump-config` 原始状态：

```yaml
- id: bash-sandbox
  name: '@deepseek-ai/dsh-bash-sandbox'
  disabled: !!js process.platform === 'win32'   # ← Windows 直接关
- id: tool-bash
  name: '@deepseek-ai/dsh-tool-bash'
  disabled: true                                 # ← 无条件关
```

而且**整个 profile 里根本没挂 `dsh-bash-local`**（不受限的 bash 执行器）。

- `bash-sandbox` 要 `bwrap` / `Landlock` / `Seatbelt`，**三个都是 Linux/macOS 的**，
  Windows 上确实没法用 —— 官方禁用它是对的。
- 但 Windows 该用的是 **`dsh-bash-local`**（不受限版本），只是默认没挂。

## 改了什么（两处）

### 1. 把 Git bash 加进用户 PATH

```powershell
$bashDir = "D:\software\git\Git\bin"
$cur = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$bashDir;$cur", "User")
```

**为什么必须做**：`dsh-bash-local` 的 argv 是硬编码的 `["bash", "-c", command]`
（`lib/index.js` L216），**靠 PATH 解析，没有 `bashPath` 配置项**。
Git 的 `cmd` 目录本来就在 PATH（git 命令能用），但 `bin` 目录（`bash.exe` 所在）不在。

副作用：**终端里现在也能直接敲 `bash` 了**，算是白赚。

### 2. 改 `D:\software\dsh-home\profiles\web\cordis.patch.yml`

在文件末尾追加：

```yaml
- insert:
    - id: bash
      name: '@deepseek-ai/dsh-bash-local'
      config:
        timeoutMs: 120000
        maxTimeoutMs: 600000
        maxOutputBytes: 64000

- id: tool-bash
  disabled: false
```

**只新增，没动现有的 pwsh 配置。**

## 生效方式

**要重启 DSH**：关掉那个 `DeepSeek Harness (dsh)` 控制台窗口，再双击桌面 `dsh` 图标。

⚠️ **新开的进程才读得到新的 PATH** —— 这是踩过的坑（见 `踩坑笔记.md` 字体那条同理）。
所以必须**完全关掉再重开**，不能只刷新页面。

## 回滚办法

### 改配置的改动

`cordis.patch.yml` 里删掉末尾那两段（`# --- 启用 bash（2026-10-12）---` 往下），重启即可。

### 万一界面打不开

DSH 有官方逃生命令：

```console
dsh rescue --from-default-profile web
```

它会用一个干净的 web 模板建一个 rescue profile 再启动，绕开坏掉的配置。

## 相关事实（下次别再重新查）

**本机 DSH 结构**：`D:\software\dsh\node_modules` 顶层**只有一个包** `@deepseek-ai/dsh`，
它自带全套依赖（213 MB 全在它自己的 `node_modules` 里）。
**升级只要替换这一个目录**，回滚同理。没有 `package.json`、没有 lock 文件，
所以 `npm update` 走不通，得手动 `npm install @deepseek-ai/dsh@<版本>`。

**两个 DSH 版本不一致**（2026-10-12 时）：

- `D:\software\dsh`（桌面图标用的）= **0.1.5-rc.2**
- 全局 npm（终端敲 `dsh`）= **0.1.7-rc.2**

**npm 11 的 install-scripts 坑**（与 `踩坑笔记.md` 第 1 条一致）：
`--allow-scripts=<包名>` 在**项目级安装里不被允许**，会报
`EALLOWSCRIPTS: --allow-scripts is not allowed in project-scoped installs`。
正确做法是写进 `package.json` 的 `allowScripts` 字段，或 `.npmrc`。

**但这次实测**：`koffi` 装出来没有 `.node` 二进制，**是正常的**——
现役的 0.1.5 环境里也一样没有，DSH 跑得好好的。
`node-pty` 用的是 `prebuilds/win32-x64/pty.node` 预编译产物，不需要现场编译。
**所以 install-scripts 的警告在这个项目上不影响可用性**，别被吓到。
