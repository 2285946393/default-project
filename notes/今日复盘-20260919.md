## 三、踩的坑（重点）

### 1. 重启 dsh 不能从 dsh 内部做

dsh 用 Windows **Job Object**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）管子进程。
**凡是 dsh 自己派生的进程，都会跟着它一起被杀** —— 我杀我自己，重启就没了下文。

**解法**：交给**任务计划程序**（归系统服务管，杀不到）：

```powershell
$tr = 'powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\software\dsh\restart-dsh-once.ps1 -TaskName dsh-restart-N'
schtasks.exe /create /tn "dsh-restart-N" /tr $tr /sc once /st <HH:mm> /it /f
```

脚本 `D:\software\dsh\restart-dsh-once.ps1` 干四件事：等 20 秒（让当前这轮答完）→
杀掉 `dsh web` 进程树 → 重新拉起 → 删掉自己的任务注册。
日志在 `D:\software\dsh\restart-dsh.log`。

⚠️ **任务名每次要换**（-1、-2、-3…）。旧任务实例还在前台跑着（它就是 dsh 的宿主），
同名 `/create /f` 会先把旧实例干掉，等于**提前把当前 dsh 掐死**。

### 2. pnpm 拦截原生模块构建

装 `dsh-better-sidebar` 时报 `ERR_PNPM_IGNORED_BUILDS`，卡在 `node-pty`（侧边栏终端要用）。
pnpm 已经在 `profiles\web\pnpm-workspace.yaml` 写好占位行，改成 `true` 即可：

```yaml
allowBuilds:
  node-pty: true
```

（备份在同目录 `.bak-before-allowbuilds`）

### 3. `dsh-browser` 在 npm 上是**同名假货**

- npm 上的 `dsh-browser`（`ben7am1n/dsh-browser`）是 **Playwright 工具**，官方 README 明确说
  「不属于本项目、无关联」
- 真正要的是 **Chrome 扩展版**（`Lum1104/dsh-browser`，691★），**只能用它自己的安装脚本装**：

```powershell
$s="$env:TEMP\dsh-install.ps1"; irm https://raw.githubusercontent.com/Lum1104/dsh-browser/refs/heads/main/scripts/install.ps1 -OutFile $s; powershell -NoProfile -ExecutionPolicy Bypass -File $s
```

装完**必须手动**在 `chrome://extensions` 点「开发者模式」→「加载已解压的扩展程序」→
选 `D:\software\dsh-home\browser-extension`（Chrome 禁止脚本装扩展）。

**特性**：纯文字操作（页面转结构化文本 + 编号控件），**带着登录态**，所以 B站 这类登录后才能看的也能读。
令牌自动生成在 `D:\software\dsh-home\ext-bridge-token`，本地使用**不用填任何东西**。
（`DSH_EXT_TOKEN` / `DSH_BROWSER_SESSION_WORKSPACE` 空着是正常的，那是给远程部署钉死令牌用的。）

### 4. 插件市场的两个坑

- 市场数据源是 `https://www.dsh-plugin.shop/registry/all.json`（6350 条），但**水分极大**：
  大量是通用项目蹭 `dsh` 标签（如 `reactive-resume` 4.3 万星却是简历生成器）
- **市场显示的版本号会骗人**：它显示 `dsh-whale-widget` 最新 `v1.0.0`，实际 npm 上是 `0.3.7`。
  **以 npm registry 为准。**

### 5. `dsh plugin update` 不一定会真的升级

`dsh-whale-widget` 写的是 `^0.3.5`，`update` 跑完还是 0.3.5。**强制指定版本**才升上去：

```powershell
dsh plugin --profile web add dsh-whale-widget@0.3.7
```

## 四、和 opencode 的分工（实测结论）

| | dsh（我） | opencode |
|---|---|---|
| 看图 | ✅ 模型带视觉 | ❌ 默认模型不带（**但它配置里有能看的**：`gemini-2.5-pro`、`claude-5-opus`、`gpt-5.6-sol`） |
| 开网页 | ✅ 现在有 Chrome 扩展了 | ✅ Playwright |
| 读它的历史 | ✅ 会读（`opencode.db`，SQLite，5.9 GB） | — |
| 调它干活 | ✅ `opencode run --model <源>/<模型> "<任务>"` | — |
| 它的可用模型 | — | `qiniu12/deepseek-v4-pro-0813` 实测可用；`blameupstream-grok/gemini-2.5-pro` 报 `Invalid token` |

**dsh 读 opencode 历史的办法**：数据库在 `C:\Users\有花无实\.local\share\opencode\opencode.db`，
只读方式打开（`file:...?mode=ro`），表 `session` / `message` / `part`，
`part.data` 是 JSON，`type == "text"` 的 `text` 字段就是正文。
