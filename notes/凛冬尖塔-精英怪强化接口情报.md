# 凛冬尖塔 · 精英/Boss 怪强化接口情报（wb → ZCode）

> 起因：wb 在《M2 代码审查》里承诺「M2.5 的第一个具体任务：反编译怪属性强化接口」。
> 本文件是交作业。**结论：官方不改怪的血量/伤害属性，而是提供「乘算/加算钩子」让你改。**
> 全部结论经 `ilspycmd` 反编译实证。

---

## 一、先说结论（三句话）

1. **怪的血量上限 `MinInitialHp` / `MaxInitialHp` 是 `abstract` 只读，且怪类全是 `sealed`** —— **不能改模型属性、也不能继承**。
   ⚠️ **但这只堵死"改模型"**；**对已经存在的具体 `Creature`，可以用 `CreatureCmd.GainMaxHp(creature, amount)` 加血上限**
   （见《M3 未核项增补》§二）。**别把这条读成"血量完全不能动"。**
2. **官方给了一套「数值修改钩子」** —— 伤害/格挡/掉血都能乘算或加算，**这才是强化精英怪的正路**。
3. **官方自己就是这么干的**：`MultiplayerScalingModel` 用 `ModifyBlockMultiplicative` 按「幕数 + 房间类型」给敌人加格挡。
   **它的 `GetMultiplayerScaling` 就是「按 ActFloor 递增强化」的现成范式，可照抄。**

## 二、官方强化范式：`MultiplayerScalingModel`（照抄级别）

```csharp
// MegaCrit.Sts2.Core.Models.Singleton.MultiplayerScalingModel

public override decimal ModifyBlockMultiplicative(Creature target, decimal block,
    ValueProp props, CardModel? cardSource, CardPlay? cardPlay)
{
    if (target != null && !target.IsPrimaryEnemy && !target.IsSecondaryEnemy) return 1m;  // 只强化敌人
    if (!props.IsPoweredCardOrMonsterMoveBlock()) return 1m;
    int count = _runState.Players.Count;
    if (count <= 2) return count;
    return (decimal)count * GetMultiplayerScaling(_combatState.Encounter, _runState.CurrentActIndex);
}

public static decimal GetMultiplayerScaling(EncounterModel? encounter, int actIndex)
{
    switch (actIndex)
    {
        case 0: return 1.1m;
        case 1: return 1.2m;
        case 2: return (encounter?.RoomType == RoomType.Boss) ? 1.3m : 1.2m;
        default: throw new ArgumentOutOfRangeException("actIndex", actIndex, "Invalid act index for HP scaling");
    }
}
```

**三个可抄的点**：
1. **钩子签名**：`(Creature target, decimal 原值, ValueProp props, ...)` → 返回**乘数**（`1m` = 不变）。
2. **先判对象**：`target.IsPrimaryEnemy / IsSecondaryEnemy` 过滤，**只对敌人生效**。
3. **按幕数递增**：`GetMultiplayerScaling(encounter, actIndex)` —— **这正是凛冬尖塔「越往后越强」要的写法**。

## 三、★ 完整的「数值修改钩子」地图（`AbstractModel`）

所有钩子都在 `MegaCrit.Sts2.Core.Models.AbstractModel` 上，override 即可。

| 想干什么 | 钩子 | 默认返回 | 语义（官方注释原话） |
|---|---|---|---|
| **怪打人更疼（乘）** | `ModifyDamageMultiplicative(Creature? target, decimal amount, ValueProp props, Creature? dealer, CardModel? cardSource, CardPlay? cardPlay)` | `1m` | "Multiply the amount of damage... like **VulnerablePower** and **WeakPower**" |
| **怪打人更疼（加）** | `ModifyDamageAdditive(Creature? target, decimal amount, ValueProp props, Creature? dealer, CardModel? cardSource, CardPlay? cardPlay)` | `0m` | "Add to the amount of damage... like **StrengthPower** and **VigorPower**" |
| **怪更硬（减伤）** | `ModifyHpLostBeforeOsty(Creature target, decimal amount, ValueProp props, Creature? dealer, CardModel? cardSource)` | `amount` | "Modify the amount of HP that will be lost by the target" |
| **限制单次伤害上限** | `ModifyDamageCap(Creature? target, ValueProp props, Creature? dealer, CardModel? cardSource, CardPlay? cardPlay)` | `decimal.MaxValue` | "Set the maximum amount of damage that will be dealt in a single hit" |
| **怪格挡更多** | `ModifyBlockMultiplicative(...)` / `ModifyBlockAdditive(...)` | `1m` / `0m` | 同 MultiplayerScalingModel 的用法 |
| **攻击段数** | `ModifyAttackHitCount(AttackCommand attack, int hitCount)` | `hitCount` | 改"打几下" |

**注意 `ModifyHpLostBeforeOsty` 有个 `Late` 版本**（`...BeforeOstyLate`），官方注释说
「**CAREFUL! You should usually use BeforeOsty instead of this**」——**用非 Late 那个**。

## 四、★ 凛冬尖塔具体怎么用（推荐的落点）

### 场景：精英波（第 4/8/12 波）和 BOSS 波（第 14 波）的怪要比普通波强

**推荐做法：在 `FrostPactRelic` 上 override 两个钩子，按"这只怪属于哪个波"决定倍率。**

```csharp
// 在 FrostPactRelic 里加：

/// <summary>记录每只怪属于第几波（刷的时候填，Boss/精英波标记强化倍率）。</summary>
private readonly Dictionary<Creature, int> _waveOfCreature = new();   // ★ 注意：要不要进存档？

// 刷怪时记一笔（SpawnMonster 里）
// _waveOfCreature[creature] = (SubWavesSpawned + 1);

public override decimal ModifyDamageMultiplicative(Creature? target, decimal amount, ValueProp props,
    Creature? dealer, CardModel? cardSource, CardPlay? cardPlay)
{
    if (dealer == null || dealer.Side != CombatSide.Enemy) return 1m;   // 只强化"敌人出手"
    var mult = WavePowerMultiplier(dealer);
    return mult;
}

public override decimal ModifyHpLostBeforeOsty(Creature target, decimal amount, ValueProp props,
    Creature? dealer, CardModel? cardSource)
{
    if (target.Side != CombatSide.Enemy) return amount;
    var mult = WavePowerMultiplier(target);
    return mult <= 1m ? amount : amount / mult;     // 硬 → 少掉血（等效加血）
}

/// <summary>按波号给倍率——照抄 GetMultiplayerScaling 的"按幕递增"思路。</summary>
private decimal WavePowerMultiplier(Creature c)
{
    if (!_waveOfCreature.TryGetValue(c, out int wave)) return 1m;
    if (wave >= WaveTable.All.Length) return 1.5m;   // BOSS 波（第14）
    if (wave % 4 == 0) return 1.3m;                  // 精英波（4/8/12）
    return 1m;                                       // 普通波
}
```

**⚠️ 三个坑（务必注意）**：
1. **`_waveOfCreature` 是运行时字典，用 `Creature` 做 key。读档后 `Creature` 对象会重建，字典丢失** ——
   要么也走 `[SavedProperty]`（但存对象引用不行，只能存 `CombatId` → 波号的映射），
   要么**改判据**：不记"哪只怪属于哪波"，而是**用 `SubWavesSpawned` 这个已持久化的数字反推**
   （例如"当前场上所有的怪，都是第 `SubWavesSpawned` 波刷的"）。
   → **推荐后者**：钩子里读 `SubWavesSpawned`，不需要新状态。**（又一次踩「读档后状态丢」这个坑，见 API 备忘坑1）**
2. **别改 `dealer` 时判断错方向**：`ModifyDamageMultiplicative` 是"谁在打"，强化敌人要判 `dealer.Side == Enemy`。
3. **`ModifyHpLostBeforeOsty` 会作用于所有掉血**（包括反伤、AOE），要注意 `props` 过滤，避免误伤。

### 备选路径：继承 `MonsterModel` 做强化子类 —— ❌ **此路不通（已核实）**

```csharp
// ❌ 全部 sealed，无法继承
public sealed class LeafSlimeM : MonsterModel   // sealed!
public sealed class Inklet : MonsterModel        // sealed!
public sealed class CorpseSlug : MonsterModel    // sealed!
public sealed class GlobeHead : MonsterModel     // sealed!
```

**核实结果：凛冬尖塔用到的怪类全部是 `sealed`**，**继承强化这条路彻底堵死**。

而且血量全是算出来的（不是字面量）：

```csharp
public override int MinInitialHp => AscensionHelper.GetValueIfAscension(AscensionLevel.ToughEnemies, 33, 32);
public override int MaxInitialHp => AscensionHelper.GetValueIfAscension(AscensionLevel.ToughEnemies, 36, 35);
```

**这反而揭示了第三条路（见 §四·补）。**

## 四·补、★ 第三条路：飞升系统（Ascension）—— 官方的难度牙印

### 发现

`AscensionLevel` 枚举（`MegaCrit.Sts2.Core.Entities.Ascension`）里，**官方早就做好了难度分级**：

```csharp
public enum AscensionLevel
{
    None,
    SwarmingElites,     // ★ 更多精英
    WearyTraveler,
    Poverty,            // 金币变少（0.75x）
    TightBelt,
    AscendersBane,
    Inflation,
    Scarcity,
    ToughEnemies,       // ★ 更硬的敌人（血更多）
    DeadlyEnemies,      // ★ 更致命的敌人
    DoubleBoss,         // ★ 双 Boss
}
```

**「精英更多 / 怪更硬 / 怪更疼 / 双 Boss」——这几乎是凛冬尖塔「难度递增」的逐条对应。**

### 机制链路（已反编译核实）

```
AscensionHelper.GetValueIfAscension(level, ascensionValue, fallbackValue)
  → RunManager.Instance.HasAscension(level)
      → if (!IsInProgress) return false;
      → RunManager.AscensionManager.HasLevel(level)
          → AscensionManager 构造于 RunManager:498  new AscensionManager(State.AscensionLevel)
```

**关键**：`RunManager.AscensionManager` 是 **`{ get; set; }`（有 public setter）** —— **可以替换！**

### 两条用法

**A. 轻量（推荐先试）**：不改飞升，**用 §四的钩子自己算倍率**。
钩子只对"伤害/掉血/格挡"这类**运算**生效，飞升是对**属性**生效。**两者不冲突，可叠加。**

**B. 重量（如果 A 不够）**：把 `RunManager.Instance.AscensionManager` 换成自定义实现，
让凛冬模式下 `ToughEnemies` / `DeadlyEnemies` **恒为 true** →
**所有怪的血量、伤害自动按官方那套逻辑强化，一行数值都不用自己配**。

**B 的注意点**：
- 要确认 `AscensionManager` 是否**可继承 / 构造函数签名**（**未核实**）。
- 换了它对**整局**生效（包括非凛冬战斗）——凛冬是"前身局"，全程都是凛冬战斗，**正好合适**。
- ⚠️ `AscensionManager` 可能还管着"玩家侧"的惩罚（金币减少等），**换之前要看清楚它副作用**。

### 建议

**先走 A（钩子倍率），实测后如果觉得"数值调起来太碎"，再评估 B。**
B 的诱人之处：**官方已经算好了"多硬才算硬"，我们不用自己拍数字。**

## 五、给 ZCode 的行动清单

1. **优先走钩子路线**（四、推荐做法），**别先动血量上限**——钩子够用，且不涉及新类。
2. **倍率用 `SubWavesSpawned` 反推**，不要新建"怪→波号"字典（读档会丢）。
3. **先做"伤害强化"一个钩子**，实测有效再加"减伤"——一次改一个，好定位。
4. 数值建议（先粗调，等实测）：普通波 `1.0` / 精英波 `1.3` / BOSS 波 `1.5`。
   **别看数字，看玩家感受**：目标是"精英波要让玩家多耗 2~3 个回合"。
5. **不要试"继承怪类"** —— 已核实**全部 `sealed`**，此路不通（少走弯路）。
6. 如果以后觉得数值不够劲 → 评估**第三条路（飞升系统）**，见 §四·补。

## 六、wb 自记

这轮情报的挖法：

`MonsterModel` 的 `MinInitialHp` 是 `abstract`（**不能改**）
→ 那官方怎么强化怪？搜 `scaling` → 找到 `MultiplayerScalingModel`
→ 它 override 了 `ModifyBlockMultiplicative` → **原来官方是"改数值运算"而不是"改数值属性"**
→ 顺着 `AbstractModel` 列所有 `Modify*` → **拿到完整钩子地图**
→ 再追 `MonsterMaxHpBeforeModification`（看着像改血的入口）→ 读 `NCombatRoom:970` →
**发现它只是视觉缩放用的，不是强化机制**（排除掉一个假线索）。

**方法论**：**"官方怎么实现某功能"永远优于"猜官方留了什么口子"。**
先找到**功能相同的官方实现**（这里是 MultiplayerScalingModel），照抄它的姿势。
