## 0. 一句话

**它是生态里唯一一个"把游戏战斗完整克隆到旁边跑一遍"的样本。**
做法是：**克隆随机数 + 克隆牌堆/生物状态（影子状态）+ 逐个镜像卡牌行为**，
在**完全不推进真实随机数**的前提下，提前算出"这一手打下去会抽到什么、打多少、谁死"。

→ 这正是**斗地主 AI / 战斗求解器**需要的能力。CombatSolver 的模拟核心就是从它来的。

⚠️ 和 Intent Graph 的区别：Intent Graph 是**读**（反射 + 扫 IL 把怪物 AI 画出来）；
这个 mod 是**算**（自己维护一套影子世界，把结果推演出来）。后者难一个量级。

## 1. 它预测什么

### 局外（OutOfCombat，29 个预测器）
- 变牌结果、下一幕先古之民与 Boss、事件选项结果、水晶球透视
- 遗物拾起效果、送货员补货、浮木重掷、佩尔之翼献祭、休息处结果

### 局内（InCombat）
- 战斗随机变牌（熵）、回合结束效果总计、**冻结之眼**（按实际抽牌顺序显示牌堆）
- 随机印牌、抽牌预测（含洗牌后预览）、随机选牌、充能球效果
- 药水抽牌 / 随机生成 / 印牌、抽牌堆自动出牌、随机目标攻击

**公平模式（FairMode，默认开）**：只预测"可以通过存档读档获取的信息"。
**漂移警告（ShowDriftWarnings）**：预测不确定时显示警告。
**兼容模式**：`PredictBaseGameCardsOnly` / `InvokeBaseGameHookListenersOnly`（只预测本体卡 / 只调本体监听器）。

## 2. ★★★ 游戏本体的 RNG 机制（本次最大的收获）

### 2.1 `Rng`（`MegaCrit.Sts2.Core.Random.Rng`）

```csharp
public class Rng {
    private int _counter;
    private readonly MegaRandom _random;          // Xoshiro256**（4×ulong 状态）
    public static Rng Chaotic { get; }            // 非确定性，不入存档（UI 用）
    public Rng(ulong seed = 0);
    public Rng(SerializableRng serializable);      // ★ 从状态重建
    public Rng(Player player, ModelId id, ulong mixin = 0);   // ★ 按「玩家槽位 + 内容 id」定种
    public Rng(ulong seed, string name);           // seed + 名称哈希
    public void LoadFromSerializable(SerializableRng);         // 保留旧实例引用
    public SerializableRng ToSerializable();       // ★ 导出完整状态
    public void Shuffle<T>(IList<T> list);         // Fisher-Yates
    public T? WeightedNextItem<T>(...);            // 加权抽取
    public double NextGaussianDouble(...);         // 高斯（用于地图布点）
    // 取值方法：NextBool / NextInt / NextUnsignedInt / NextUnsignedLong /
    //          NextFloat / NextDouble / NextItem …
}
```

**★ `SerializableRng` = `{ int counter; ulong state0..state3 }`（4×ulong = Xoshiro256**）**
而且它实现了 **`IPacketSerializable`**（`Serialize`/`Deserialize`）→ **能直接走网络包传输**。
`ToString()` → `"Counter: N State: s0 s1 s2 s3"`。

**★ 克隆 RNG 的正规做法（两行）**：
```csharp
public static Rng Clone(this Rng rng) => new Rng(rng.ToSerializable());
```

**⚠️ v0.109.0 破坏性变更**：`Rng` 从「seed + counter 重建」改成「序列化完整 Xoshiro 状态」。
- 旧：`Seed` / `Counter` / `FastForwardCounter`（**已移除**）。
- 新：`ToSerializable()` / `new Rng(SerializableRng)`。
- 固定步进不再用 `FastForwardCounter`，改成**丢弃克隆流的 raw draw**：
  ```csharp
  public static void Advance(this Rng rng, int count) {
      for (var i = 0; i < count; i++) _ = rng.NextUnsignedLong();
  }
  ```
- **每次取值 `_counter++`** → counter 就是"这条流被取过多少次"，可用于断言。

### 2.2 `RunRngSet` —— 12 条 run 级流（`MegaCrit.Sts2.Core.Runs`）

每条的种子 = `new Rng(Seed, StringHelper.SnakeCase(RunRngType.ToString()))`，
其中 `Seed = StringHelper.GetDeterministicHashCode(字符串种子)`。
→ **同一个 run seed + 同一个流名，一定给同一串结果。**

| 属性 | `RunRngType` | 管什么 |
|---|---|---|
| `UpFront` | UpFront | **开局就生成的一切**：打什么怪、遇什么事件、给什么遗物 |
| `Shuffle` | Shuffle | 抽牌堆洗牌（开局 + 抽空重洗） |
| `UnknownMapPoint` | UnknownMapPoint | 未知地图点掷出什么房间 |
| `CombatCardGeneration` | CombatCardGeneration | 战斗内生成卡（攻击药水）—— **与卡牌奖励分开** |
| `CombatPotionGeneration` | CombatPotionGeneration | 战斗内生成药水（炼金）—— 与药水奖励分开，**不能出治疗药水** |
| `CombatCardSelection` | CombatCardSelection | 战斗内随机选牌（True Grit） |
| `CombatEnergyCosts` | CombatEnergyCosts | 战斗内随机费用（混乱 / 蛇眼） |
| `CombatTargets` | CombatTargets | 战斗内随机目标（弹跳药瓶 / 回旋镖） |
| `MonsterAi` | MonsterAi | 怪物随机出招 |
| `Niche` | Niche | 杂项一次性（诅咒之run 等） |
| `CombatOrbs` | CombatOrbs | 战斗内随机充能球（混沌） |
| `TreasureRoomRelics` | TreasureRoomRelics | 多人同选遗物时谁拿到 |

另有 `PlayerRngSet` —— **3 条每玩家流**：
`Rewards`（卡牌奖励 / 药水奖励 / 是否有药水奖励）、`Shops`（商店卖什么）、
`Transformations`（变牌结果）。

**⚠️ run 内种子不允许变**：`RunRngSet.LoadFromSerializable` 里
`if (StringSeed != save.Seed) throw new NotImplementedException("RngSet seed should not change during the run!")`。
**✅ 但 `MockRng(RunRngType, ulong)` 可以按流替换种子 —— 标注"ONLY USE THIS FOR TESTING"**（测试友好）。

### 2.3 其他可克隆的状态对象
- **`RelicGrabBag`**（遗物抽奖袋）：`ToSerializable()` / `FromSerializable()` → 同样两行克隆。
- `SerializableRunRngSet` / `SerializablePlayerRngSet` —— 整组流的存档形态。

## 3. ★★★ 核心机制：克隆 + 影子 + 镜像 + 记账

四块拼起来才是完整的"预测"：

```
真实游戏状态 ──(只读快照)──► 克隆 RNG（7 条战斗流）
                              + 影子状态（牌堆/生物/充能球/能量）
                              + 影子卡（PredictedCard）
                                    │
                                    ▼
                        CombatPredictionSimulator（2,438 行，13 个 partial）
                        自己跑一遍：出牌 / 抽牌 / 伤害 / 格挡 / 上状态 / 充能球 …
                                    │
                                    ▼
                        PredictionTrace（谁造成的）+ PredictionHistory（语义事件）
                                    │
                                    ▼
                        PredictionRisk（哪里不准 → UI 上弹警告）
```

### 3.1 `CombatPredictionSimulator`

- 13 个 partial 文件：`Attack` / `Block` / `Damage` / `Heal` / `Power` / `Orb` / `Potion` /
  `Energy` / `Card` / `CardPile` / `EndTurn` / `AutoPlay`。
- **`Rng = CombatPredictionRngSet.From(combatState.RunState.Rng)`** —— 构造时就克隆好 7 条流。
- `State` = 影子世界；`StateStore` = 按模型挂的预测态；`History` = 事件时间线。
- **镜像本体的战斗终局语义**：`IsInProgress` / `IsAboutToLose` / `IsEnding` / `IsOverOrEnding` /
  `CheckWinCondition()` / `LoseCombat()`。
- `Snapshot()` → 当前风险。

### 3.2 影子状态（改影子，不改真的）

| 类 | 作用 |
|---|---|
| `CombatPredictionState` | `Dictionary<Creature, SimCreatureState>` + `HashSet<Creature> _removedCreatures`。**"影子死亡"用集合记，不动真实 `CombatState`。** |
| `SimCardPile` | 影子牌堆（`List<PredictedCard>`），`Clone()` 深拷 |
| `SimPlayerCombatState` / `SimOrbQueue` / `SimCreatureState` | 玩家战斗态 / 充能球队列 / 生物态 |
| `PredictionStateStore` | `Dictionary<(AbstractModel, Type), object>` —— **把"预测态"挂在模型实例上，不改模型字段** |
| `PredictedCard` | `{ Original, Preview, MutablePreview }` —— 原卡 + 脱离的预览卡；`MutablePreview` 懒创建 |
| `PredictionCloner` | 底层克隆：`MemberwiseClone` + 清事件订阅 + 重建 `DynamicVars` / 附魔 / 苦痛 |

**★ 三条关键约束（写在文档里的设计原则）**：
1. **绝不调真 virtual 方法** —— 因为真方法会推进真 RNG、改真牌堆。
2. **`PredictedCard.Preview` 是"脱离的"（detached）** —— 它没有 `CombatState`，
   所以任何读"活牌堆/活生物"的 getter 都会读错 → 必须走镜像。
3. **`PredictionCloner.CloneModel`**：canonical（不可变）模型**原样返回**，可变模型才拷贝；
   拷贝时**丢掉事件订阅**（避免 UI 副作用漏出来）。

### 3.3 ★★★ 镜像方法（`MethodMirrorRegistry`）—— 最值得抄的设计

```csharp
internal enum MirrorDispatchKind {
    NotOverridden,   // 继承基类实现，不需要镜像
    Handled,         // 有精确注册的预测处理器
    Inferred,        // 未注册，但用 IL 推断出了尽力而为的处理器（→ 必记「不完整」风险）
    Ignored,         // 已审核：是非玩法 mod 的 override，无预测影响
    Unsupported      // 玩法相关但无安全处理器（→ 记「未镜像」风险）
}
```

**分发优先级（`Lookup`）**：
1. 精确运行时类型注册 → `Handled`
2. 未 override（`DeclaringType == 基类`）→ `NotOverridden`
3. override 来自 **`affects_gameplay: false` 的 mod** → `Ignored`（不记风险）
4. `AllowInference` 且推断器能处理 → `Inferred`（**先记 `MethodMirrorIncomplete` 再执行**）
5. 其他 → `Unsupported`（**记 `MethodNotMirrored`**）

**★ 三个设计要点**：
- **按"精确运行时类型"匹配，不做继承链匹配** —— 派生模型必须单独审核（防静默串味）。
- **查找结果缓存**（`_lookupCache`），但 `AllowInference` 变更时清缓存。
- **注册必须在首次查询前完成**（静态初始化期建表，不支持运行期注册）。
- 还有**返回值版** `MethodMirrorRegistry<TBase, TContext, TResult>`：
  只做 `Handled` / `Unsupported`，**不推断**（返回值不能瞎猜）。
- **`TryInvokeRegistered`**：只查精确注册、不记风险 —— 用于"大多数监听器直接调原方法、只替换少数几个"的场景。

**★ `MirrorMethodSpec`**：用 `AbstractModel.GetMethod(name, flags | DeclaredOnly)` 拿基类方法，
再 `TryGetOverride(runtimeType)` 判断是否真被 override：
```csharp
if (overrideMethod is null || overrideMethod.DeclaringType == BaseMethod.DeclaringType) return false;
```

**★ `IMethodMirrorContext<TBase>`**（只给分发器用的契约）：
`PushDispatchSource(receiver, method)` → `IDisposable`（开一帧轨迹）
/ `RecordMethodNotMirroredRisk()` / `RecordMethodMirrorIncompleteRisk()`。

### 3.4 ★★★ 风险记账（`PredictionRisk`）

```csharp
internal enum PredictionRiskReason {
    MethodNotMirrored,        // 有玩法 override 但没镜像 → 结果可能错
    MethodMirrorIncomplete,   // 镜像了但不完整（推断的 / 部分状态没模拟）
    UnresolvedPlayerChoice,   // 需要玩家选（如三选一），没法预知
    CardDrawLimitExceeded,    // 抽牌超出安全上限
    OrbChannelLimitExceeded,  // 充能球超上限
}
```
→ 转成 `IHoverTip` 显示在 UI（受 `ShowDriftWarnings` 开关控制）。

> **★ 这是最该抄的工程姿态：不确定就明说，而不是给一个看起来对的错答案。**
> 任何"推断"出来的结果都**强制**带上 `MethodMirrorIncomplete`。

### 3.5 `PredictionTrace` / `CombatPredictionHistory`

- 每次预测开一帧：`_trace.Push(model, PredictionInvocation.ForAction(kind))`
  / `ForMethod(methodInfo)` → `IDisposable`。
- `PredictionTraceFrame` 记录"这个结果是谁造成的、父帧是谁" →
  支撑 UI 上的"逐条伤害来源详情"。
- `CombatPredictionHistory` 把**语义事件 / 已解析事件 / 风险事件**放在同一条有序时间线里；
  条目抓取当时的不可变帧。用**引用同一性**的完成索引拒绝重复/跨历史完成。

## 4. ★★ IL 推断器（`CardOnPlayInferrer`，357 行）

未注册的卡牌怎么预测？**扫原始 IL，只认几条"一眼能看懂"的模板**：

```csharp
HarmonyIlMethodBody body = overrideMethod.GetOriginalIl();   // ★ RitsuLib 的工具，拿 patch 前的 IL
foreach (var ins in body.Instructions) {
    if (!HarmonyIl.TryGetCalledMethod(ins, out var called)) continue;
    if (IsAttackExecution(called))  { if (effects.Add(EffectKind.Attack)) actions.Add(GeneralAttackOnPlay); }
    else if (IsBlockGain(called))   { … GeneralBlockOnPlay }
    // 还有「抽牌」模板：认 1 参 / 4 参（count 为常量 1 或 DynamicVars.Cards.BaseValue/IntValue）
}
```
- **`STS2RitsuLib.Utils.HarmonyIl`** —— **RitsuLib 自带 IL 工具**（`HarmonyIlMethodBody` / `TryGetCalledMethod`）。
  **比自己写 IL 扫描干净得多**（Intent Graph 是自己写的）。
- **`GetOriginalIl()`** 拿的是 **Harmony patch 之前的原始 IL** —— 所以别人的 prefix/postfix/transpiler 不会污染推断。
- 明确写下的**边界**（文档 §"Deliberate limits"）：
  只看 `OnPlay`/`MoveNext` 函数体里**直接出现**的调用；
  **不跟**同卡 helper、虚/接口分发、委托、反射、任意传递调用；
  **不重建**任意控制流；不还原 Harmony 引入的行为。
  → **"扩大推断应该是加窄的、可离线验证的模板，而不是演化成通用 IL 解释器。"**

## 5. 钩子镜像（23 份文档）

`docs/hooks/` 每份文档 = 一个钩子家族的覆盖说明。总览 `overview.md` 里的**设计原则**：

- **优先用原版只读 value hook**（原版预览已经在用）；只有当影子状态会让原方法读错时，才替换成精确监听器。
- **只镜像能改变预测输出的副作用**：抽牌顺序、牌堆、预览卡的费用/动态变量、格挡、伤害、死亡/存活、
  充能球数量、当回合资源、**RNG 消耗**。
- **预测范围 = 能影响"当前玩家回合"的结果**。后续回合 / 房间结束 / 奖励变化**不需要**镜像（除非回流）。
  **敌人攻击在范围外。**
- 不模拟 VFX / SFX / 等待 / 成就 / 不可达效果。
- **"没有模拟到的状态变更一律按不支持处理"**，保留风险标记，而不是静默忽略。
- 用 `PredictionStateStore` 存模型局部计数/标志，**不要改活模型字段**。
- **保持原版监听器顺序 / 阶段 / 守卫 / 短路 / 结果链。**
- `CompatibilityUtils.FilterHookListeners` 是共享兼容过滤器（可按设置排除非本体监听器，**保序**）。

钩子文档清单：`after-card-changed-piles` / `after-card-discarded` / `after-card-drawn` /
`after-card-entered-combat` / `after-card-exhausted` / `after-card-generated-for-combat` /
`attack-hooks` / `block-hooks` / `card-play-count-hooks` / `card-play-hooks` /
`card-play-result-location-hooks` / `card-reward-hooks` / `damage-hooks` / `damage-modifier-hooks` /
`death-hooks` / `end-turn-hooks` / `energy-hooks` / `merchant-card-creation-results` / `orb-hooks` /
`power-amount-hooks` / `should-draw` / `shuffle-hooks`。

**镜像文档**（`docs/mirrors/`）：`card-on-play`（15.7KB，最详）/ `card-is-playable` /
`card-on-turn-end-in-hand` / `enchantment-on-play` / `affliction-on-play` / `potion-on-use` / `power-apply`。

## 6. ★★★ 多变体分发器（第 5 个样本，也是最标准化的一个）

`THIRD_PARTY_NOTICES.md` 明确写：**加载器设计抄自 STS2-RitsuLib**。

### 6.1 包结构

```
RandomForeseer.json          ← 工坊根清单（has_pck:false，依赖取「最低变体」的）
RandomForeseer.dll           ← 壳（assembly 身份 = RandomForeseer.Loader）
mod-variants.manifest        ← ★ 变体清单（故意用 .manifest 扩展名）
lib/0.8.4/RandomForeseer.{dll,pck}      ← min_game_version 0.107.1
lib/0.13.18/RandomForeseer.{dll,pck}    ← min_game_version 0.111.0
```

```json
{ "schema": 1, "variants": [
  { "modVersion": "0.8.4",   "minGameVersion": "0.107.1", "directory": "lib/0.8.4",
    "dependencies": [{ "id": "STS2-RitsuLib", "min_version": "0.4.9" }] },
  { "modVersion": "0.13.18", "minGameVersion": "0.111.0", "directory": "lib/0.13.18",
    "dependencies": [{ "id": "STS2-RitsuLib", "min_version": "0.5.14" }] }
] }
```

### 6.2 ★★ 递归 manifest 约束（会踩的坑）

> **游戏会把 mod 目录下每一个 `.json` 都当成 mod 清单递归解释。**
> 所以历史 `RandomForeseer.json` 只能留在 `artifacts/packages/`，**绝不复制进工坊的 `content/lib/`**。
> 变体元数据**故意用 `.manifest` 扩展名**（内容是 JSON）。

→ **我们做多版本包时，子目录里不能放 `.json` 清单。**

### 6.3 壳的实现要点（`workshop/loader/Bootstrap.cs`）

- `[ModInitializer(nameof(Initialize))]` 入口。
- **`ReleaseInfoManager.Instance.SemVer`** → 直接拿 `SemanticVersion` 对象（比 Intent Graph 用的 `.ReleaseInfo.Version` 字符串更好）。
- **选变体**：`MinGameVersion <= 宿主版本` 里取 **Mod 版本最高**的；宿主未知/太老 → 警告 + 取最高版兜底。
- **★ 同步 `Mod` 的版本**：选中后**同时改** `detectedMod.manifest.version`（字符串）
  和 `detectedMod.version`（SemanticVersion 缓存）→ 让依赖校验 / Mod UI / 遥测 / 联机 mod 列表
  **看到的是"实际选中的版本"而不是包版本**。
- **加载用当前 ALC**：`AssemblyLoadContext.GetLoadContext(typeof(Bootstrap).Assembly).LoadFromAssemblyPath(...)`
  （**和 LoadOrderManager 的结论一致，再次修正"默认 ALC 不探兄弟 dll"**）。
- **挂 PCK**：反射调 `Godot.ProjectSettings.LoadResourcePack(path)`（兼容参数变化）。
- **转发 initializer**：扫 `ModInitializerAttribute` 类型 → 反射调 `attribute.initializerMethod`；
  兜 `ReflectionTypeLoadException.Types.OfType<Type>()`。
- **★ 依赖失败的上报姿势**：不能直接写（`Mod.errors` 还没建），
  改成 `ModManager.OnModDetected += handler`，等游戏检测到本 mod 时再
  `mod.state = ModLoadState.Failed; mod.errors.AddRange(errors)`，
  并**在回调里 try/catch**（0.107 是直接调订阅者的，抛出去会炸 ModManager）。
  错误文本用 `new LocString("main_menu_ui", "MOD_ERROR.MISSING_DEPENDENCY").Add("id", …)` 拼。
- **壳编译对最老 API**（`Sts2ApiSignatureRoot`），保证所有分支都能加载壳。
- 目录越界校验：`IsUnderDirectory(variantDirectory, libRoot)` —— **防 manifest 指到包外面**。

### 6.4 发布流程（`scripts/` + `workshop/active-game-versions.txt`）

`active-game-versions.txt` 只列**当前 Steam 公开分支在用的游戏版本**（本机是 `0.107.1` / `0.111.0`）。
对每个活跃游戏版本选 `package.min_game_version <= 活跃版本` 的**最高 Mod SemVer**，
取并集上传 → **自动丢掉没人用的历史包**。

## 7. ★★ 逐版本适配方法论（4 个版本，最完整的样本）

`docs/version-adaptations/v0.108.0|109|110|111.md` —— 每份的结构：

1. **对比范围**：`从 vX <commit> 到 vY <commit>`。
2. **已适配内容**：逐条列出游戏改了什么 + 预测侧怎么跟。
3. **修改文件**：精确到文件名。
4. **验证**：`dotnet build /p:CopyModOnBuild=false /p:RunPckExport=false /p:SyncManifestDependenciesOnBuild=false`
   → **0 warning / 0 error**，加 `git diff --check`。
5. **待实机复核项** → `plans/vX-adaptation/review-items.md`。

**★ 判断标准（写得很清楚）**：数值 / 稀有度 / 关键词变化 → **canonical model 和 dynamic var 自动继承**，不用改；
只有 **RNG 消耗顺序 / 状态域 / 钩子签名 / 阶段顺序** 变了才需要动。
**主动排除**：generated subtype/serializer、动画/VFX、输入、多人握手、纯平衡数值噪声。

> **→ 这套"逐版本 diff → 分诊 → 只改 RNG/状态/钩子 → 附复核清单"的流程，我们做多版本支持直接照抄。**

## 9. ★★ 对我们 4 个 mod 的可用结论

| # | 结论 | 用在哪 |
|---|---|---|
| 1 | **`RunRngSet` 12 条流 + `PlayerRngSet` 3 条流，全部可 `ToSerializable()` 克隆** | **斗地主 AI 预演**：克隆 7 条战斗流，在影子世界里试打，不影响真局 |
| 2 | **`new Rng(SerializableRng)` + `ToSerializable()` 是唯一正确的克隆方式**（v0.109 起） | 任何需要"试算"的功能；**别再找 `Seed`/`Counter`，已移除** |
| 3 | **`SerializableRng` 实现 `IPacketSerializable`** | **联机同步 RNG 状态**（斗地主发牌可验证性 / 重放） |
| 4 | **镜像注册表 = 按精确运行时类型分发 + 5 种状态 + 风险记账** | 我们做"兼容未知 mod 内容"的通用姿态：**不确定就记风险，不要猜** |
| 5 | **`affects_gameplay: false` 的 mod 的 override 可安全 `Ignored`** | 生态里一半 mod 不改玩法 → 这条能挡掉大量误报 |
| 6 | **`STS2RitsuLib.Utils.HarmonyIl` 是现成的 IL 工具**（`GetOriginalIl()` 拿 patch 前的） | 以后要读别人 IL，**别自己写**（Intent Graph 自己写了一套，没必要） |
| 7 | **`ReleaseInfoManager.Instance.SemVer` 直接给 `SemanticVersion`** | 版本判断 |
| 8 | **`ModManager.OnModDetected` + `mod.state = Failed` + `mod.errors`（List\<LocString\>）** | **mod 加载失败的官方上报方式**（比弹错误框好） |
| 9 | **游戏递归解释 mod 目录下每个 `.json` 为清单** | 多版本包的子目录**不能放 .json**；元数据用 `.manifest` |
| 10 | **`Godot.ProjectSettings.LoadResourcePack(path)` 可反射挂 pck** | 壳 + 多变体（PCK 跟着变体走） |
| 11 | **`RitsuLibFramework.EnsureGodotScriptsRegistered(asm, logger)`** | pck 里放 C# 脚本的**必要条件**（和 Intent Graph 的 `ScriptManagerBridge.LookupScriptsInAssembly` 是同一件事的两个入口） |
| 12 | **设置带 schema 版本 + 迁移链 + `WithEntryEnabledWhen`** | 我们的 mod 设置页 |
| 13 | **逐版本 diff → 分诊 → 只改 RNG/状态/钩子 → 附复核清单** | 我们做多版本支持的标准流程 |
| 14 | **"影子死亡用 HashSet 记，不动真 CombatState"** | 任何"试算"都别改真状态 |
| 15 | **公平模式思想**：只预测"读档也能拿到"的信息 | 斗地主如果做"预知"，同样需要这条边界 |

⚠️ **提醒**：它用了 `CombatManager.DebugOnlyGetState()` 级别的内部反射（`_turnState?.State`、
私有字段 `_onPerform` 之类）、IL 读取、私有字段直写（`enchantment._status`）——
**属于"能用但官方随时可能改"的灰色地带**。要用就**收口到一个类型里**（沿用 Spine API 变更的教训）。

## 11. 一句话总结

**这个 mod 的价值不在"预测随机数"，而在于它证明了一件事：
只要能把 RNG 状态和战斗状态克隆出来，就能在旁边把整场战斗重跑一遍。**
它把这件事做到了 2,438 行模拟器 + 100 多个镜像 + 30 份设计文档 + 完整测试，
而且**每一条"没做到的地方"都老老实实记成了风险**。

→ 我们要做斗地主 AI 的"预演"，**结构照抄这个，但可以省掉 IL 推断和镜像那一大层**
（因为斗地主是我们自己的玩法，不需要去猜别人的卡牌行为）。
