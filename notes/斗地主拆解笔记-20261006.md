## 三、完整流程（拆 `round.py` / `game.py`）

```
洗牌 54 张
  ↓
发牌：每人 17 张，留 3 张底牌
  ↓
定地主（rlcard 里直接指定 0 号；注释里留了一套"按手牌评分抢地主"的逻辑）
  ↓
地主拿走 3 张底牌 → 地主 20 张、农民各 17 张
  ↓
地主先出牌
  ↓
循环：当前玩家 → 出牌 / 要不起 → 轮到下一家（+1 取模）
  ↓
若某玩家手牌空了 → 他是赢家，游戏结束
```

### 三个关键机制（我原来没写全的）

**① "两家都不要 → 我自由出"**
rlcard 用一个 `greater_player`（当前最大牌的持有者）来实现：
- 轮到谁时，如果 `greater_player` 是空 **或就是他自己** → 他可以**随便出**
- 否则 → 只能出"压得住当前最大牌"的

**② 要不起就 pass**，pass 不改 `greater_player`。转一圈回到 `greater_player` 本人时，他就自动获得自由出牌权。

**③ 结算**
- 赢家是地主 → 地主得 1，两个农民 0
- 赢家是农民 → 两个农民各得 1，地主 0

## 四、几条细节规则（拆 `judger.py` 的 `solo_attachments` / `pair_attachments`）

这三条是这次**被双向对车逮出来**的 —— 我原来凭印象写的版本有一条是错的，已更正。

1. **飞机 / 四带二 的每个点数"最多能拿出几张当带牌"是有上限的：**
   - 任何点数**最多 3 张**（第 4 张是炸弹本体，不拿出来当带牌）→ 也就是**不许拆炸弹凑飞机**。
   - 跟飞机**贴边**的点数（飞机首-1、尾+1）**最多 2 张**（第 3 张会被拉进飞机、产生歧义）；`2` 例外。
2. **四带二的那两张，不能是双王**（`attachment[-1]==14 and attachment[-2]==13 → 跳过`）。
   飞机带单的带牌同理，也不能同时含两张王。
3. ~~三带一时，带的那张不能跟三张连成顺子（比如 `333` 不能带 `4`）~~
   ⚠️ **这条我写错了。** 实测 `3334` 是**合法**的（`三带一`），rlcard 也认。
   真正被拦的是"**带牌里出现跟三张/飞机相邻点数的第 3 张**"，跟"三带一带什么单张"无关。
4. **顺子/连对/飞机一律不含 2 和王**（下标 ≥ 12 直接截断）。这条我原来是对的。
5. 顺子最长 12 张（3~A）、连对最长 10 对、飞机最长 6 组 —— 超过其实手牌也放不下。

> ### 我是怎么逮出来的（反例驱动）
> 光比对"合法出牌表"验不出这些（表里只有合法项，我多认的它不列）。
> 所以做了**双向对车**：拿 rlcard **真实的** `playable_cards_from_hand` 在 74 副手牌上生成合法集，
> 再把同一手牌的**每一个子集都穷举一遍**（共 **9,699,254** 种），两边对答案：
>
> ```
> 我判为合法 4263 手 ／ rlcard 判为合法 4263 手   → 完全一致
> ```
>
> 修之前是 16 条分歧，归成 3 类，全是上面第 1、2 条造成的：
> `QQQQKKK`(拆炸弹凑飞机) / `QQQQKKKK`(两炸弹冒充飞机) / `AAAABR`(四带二带双王)。

## 五、电脑怎么出牌（拆 `doudizhu_rule_models.py`，共 180 行）

rlcard 自带的规则型 AI，逻辑很朴素，但够用：

**自由出牌时**（该我领出）：
1. 先把整手牌拆成"最优组合"（`combine_cards`）：顺序是
   火箭 → 炸弹 → 三张/飞机 → 顺子 → 连对 → 对子 → 单张
2. 然后**出包含"手里最小那张牌"的那一组**（随手把最小的甩出去）

**跟牌时**（有人出过牌）：
1. 在"能压住"的牌里挑 **最弱的那一手**（能压就压最小的，别浪费大牌）
2. 压不住时：
   - 如果上家是**地主**、自己不是 → 随机出（该拼就拼）
   - 如果上家和自己是**一队**（都是农民）→ **pass**

⚠️ **更正（我第一版笔记写反了）**：上面第 2 条那个"队友不误伤"**只在压不住时才生效**。
`doudizhu_rule_models.py` 第 45~51 行是先找"同牌型里最省的能压住的牌"，
**找到了就直接出，根本不看是不是队友**。也就是说 rlcard 的规则 AI **会抢队友的牌**。
这是它的毛病，我在我们这版里改掉了（两个农民之间默认不互相压，能一把走完除外）。

还有一处：rlcard 只比对"同牌型族"，所以它**永远不会用王炸去压炸弹**（`bomb` 和 `rocket` 族名不同）。
我们这版允许。

**给我们的启发**：单机打 AI 不用一上来就搞神经网络。这套"甩最小 + 能压压最小 + 队友不误伤"
就能做出一个"打起来像个人"的电脑，一两百行搞定。想更强再换 DouZero。

# 五、搬进游戏（P1-mod）：`projects/dou-spire/`

用户拍板：「**不用非得往联机的那个模式赛。就是我们出一个自己模式。**」
→ 放弃 P2（联机同步）/ P3（四人 2v2），改做**独立自定义模式**。

## 5.1 游戏到底给我们留了什么入口（反编译实测）

| 想做的事 | 官方/RitsuLib 给的东西 | 结论 |
|---|---|---|
| 出一个"自己的模式" | `GameMode` 枚举 = `None / Standard / Daily / Custom`；自定义模式挑的是 **`ModifierModel`**（官方注释："Run-lifetime model which alters the run for daily and custom runs"） | ✅ 这就是正规入口，不用动角色、不用动联机 |
| 把修正器塞进自定义模式的勾选列表 | RitsuLib 的 `[RegisterGoodModifier]` / `[RegisterBadModifier]` / `[RegisterMutuallyExclusiveModifierGroup]`（会给 `ModelDb.GoodModifiers` / `BadModifiers` 打补丁合并） | ✅ 一个特性搞定，**不用自己写 Harmony** |
| 独立牌堆 / 额外手牌区 / 出牌协调器 | RitsuLib `STS2RitsuLib.CardPiles`：`ModCardPile` / `ModCardPileRegistry` / `ModExtraHand` / `ModExtraHandHandView` / `ModExtraHandPlayCoordinator` / `ModCardPileExtraHandSpec` | 🅿️ 现成的，但**这一版没用**（见下） |
| 内容脚手架 | `STS2RitsuLib.Scaffolding`（Cards / Characters / Ancients / Modifier）、`STS2RitsuLib.Timeline.Scaffolding`（Epoch / Story） | 🅿️ 备用 |

## 5.2 这一版怎么做（最小可玩）

**决定：不动原版战斗手牌，做一层自己的浮层桌面。**

理由：`ModCardPile` 那套要把斗地主的牌做成**游戏里的 CardModel 实体**（卡片场景、牌堆、
播放动画、和尖塔战斗的回合制耦合）。那是"最正统但最重"的路。
而斗地主是**独立牌局**，跟尖塔那一局的战斗其实没有关系——
用一层自己的 UI + 我们自己的 `GameState`，**几小时就能看到牌在桌上**，
而且改玩法完全不受尖塔框架牵制。

```
DouSpireModifier (ModifierModel, [RegisterGoodModifier])
        │  AfterRunCreated / AfterRunLoaded → 只记一个旗子
        ▼
Entry.OnRoomEntered()  ──►  DouSpireTable.Open()
                                │
                                ▼
                     DouSpireTable : Control（纯 C# 搭的 Godot 控制树）
                                │ 规则调用
                                ▼
                     DouSpireRules.*（★源码链接，不是复制）
```

## 5.3 关键决定：规则内核用**源码链接**

`DouSpire.csproj` 里 `Compile Include="..\dou-spire-rules\X.cs" Link="Rules\X.cs"`，
只链 6 个纯逻辑文件，**不链** `Program.cs` / `TextTable.cs` / `Simulation.cs` /
`RlcardCrossCheck.cs`（控制台专用，带 `Main`）。

好处：改一处两边同时生效，永远不会出现"原型修好了、mod 里还是旧的"。
代价：mod 工程必须开 `ImplicitUsings`（那几个文件里没写 using）。

## 5.5 踩到的坑（都在 README 里详写了）

1. **Godot 默认字体不含中文** → 必须从游戏已有的 `Label` 上"借"字体，借不到退回 `SystemFont`。
2. **`_Input` 早于 `_GuiInput`** → F9 用 `_Input` 才能穿透铺满屏幕的桌面。
3. **`Initialize()` 太早，场景树可能还没建** → 热键在 `GameReadyEvent` / `MainMenuReadyEvent` /
   `RunStarted` / `RunLoaded` 上补装（幂等）。**补上之后主菜单按 F9 就能开桌**，
   不用先开一局 —— 这是最快的验证路径。
4. **纯 dll 的 mod 没有正规本地化** → 写 `user://localization_override/<语言>/modifiers.json`。
   修正器的表名是 **`modifiers`**（不是 relics），key = `<Entry>.title` / `.description`；
   `<Entry>` 在初始化时查不到最终值，所以把几种候选形态全写一遍。
5. **桌面渲染出错绝不能抛进 Godot 的信号派发** → 各处 try/catch + `_broken` 停摆，
   只记日志。mod 的 UI 出问题不该把玩家整局拖下水。
6. **游戏的「确认加载 mod」弹窗**（`NConfirmModLoadingPopup`）没确认过的话，
   日志会写 `Skipping loading mod X, user has not yet seen the mods warning`，
   **所有本地 mod 全被跳过**。排查 mod 不生效时先看这条。

## 5.7 ⚠️ 方向纠正：5.2 那条路是错的（用户当场否掉）

用户看了第一版之后原话：

> 「**你这个是吧斗地主嵌套进了游戏啊，感觉跟游戏没关系啊。正确来说是不应该出现怪物，
> 就一个桌子然后你选的角色，和ai选的角色出现，说到底只是在游戏里面开了个斗地主的窗口**」

拆开看，用户否掉的是三层东西：

| 我做的 | 用户要的 |
|---|---|
| 走 `ModifierModel` 修正器 | 走**主菜单按钮**（压根不起 run） |
| 开局进第一个房间才开桌 → 有地图/怪物/房间 | **没有 run**，点进来就是一张桌子 |
| 桌上是"上家/下家/我"这种通用标签 | 桌上坐**游戏本体的角色**（有立绘、有名字、有配色） |

**根因**：我把"入口"和"玩法"混在一起想了。
「出一个自己的模式」的正规入口确实是修正器，**但修正器天生依附于一次 run** ——
只要走它，地图/怪物/房间就必然存在。用户要的其实是**旁路**，不是**寄生**。

### 改成了什么

```
主菜单按钮（DouSpireMenuButton，复制游戏原生按钮）
        │  或任意界面按 F9
        ▼
DouSpireTable.Open()  ──►  SceneTree.Root.AddChild(...)
        │                        │
        │  先「选角色」：三家各挑一个游戏本体角色（◀ ▶ 拨，不撞脸）
        │                        ▼
        └──────────►  DouSpireTable : Control（一张桌子，没有任何尖塔东西）
                                 │
                                 ▼
                      DouSpireRules.*（★源码链接不变）
```

删掉的：`DouSpireModifier.cs`（修正器）、`DouSpireLoc.cs`（修正器的本地化注入）。
新增的：`DouSpireMenuButton.cs`、`DouSpireCharacters.cs`。
订阅的钩子从「`RoomEntered` 开桌」换成「`RunStarted` **收桌**」。

### 5.7.1 主菜单按钮怎么挂（反编译 RitsuLib 实测，**不用 Harmony**）

`STS2RitsuLib.Ui.MainMenu.NMainMenuScroller`（`internal sealed : Control`）：

```csharp
internal static NMainMenuScroller? Find(NMainMenu menu)
    => menu.GetNodeOrNull<NMainMenuScroller>("MainMenuTextButtons");

internal static void Install(NMainMenu menu)
{
    ...
    var old = menu.GetNodeOrNull<Control>("MainMenuTextButtons");   // 原 VBoxContainer
    if (old is NMainMenuScroller) return;
    var scroller = new NMainMenuScroller();
    scroller.Name = old.Name;                     // ★ 沿用同一个节点名
    ...
    menu.RemoveChild(old); menu.AddChild(scroller); menu.MoveChild(scroller, index);
    foreach (var child in old.GetChildren())      // ★ 原按钮全搬过去
    { old.RemoveChild(child); scroller.AddChild(child); }
}
```

三个结论：

1. **节点名不变** → 无论 RitsuLib 装没装、我们先后顺序如何，
   `menu.GetNodeOrNull<Control>("MainMenuTextButtons")` 都拿得到，`AddChild` 就行。
2. **加子节点会自动排版**：容器的 `ChildOrderChanged += RequestLayout`，
   而 `SynchronizeItems()` 收的是 `GetChildren().OfType<Control>()` —— 不挑类型。
3. **原按钮被搬走不丢** → 我们比它先塞也不会被清掉。

### 5.7.2 按钮要**复制**游戏自己的，不能 `new`（这条最坑）

`MegaCrit.Sts2.Core.Nodes.Screens.MainMenu.NMainMenuTextButton`（**public**）：

```csharp
public override void _Ready() => ConnectSignals();
protected override void ConnectSignals()
{
    base.ConnectSignals();
    label = GetChild<MegaLabel>(0);      // ← new 出来的对象没有子节点，直接抛
    ...
}
```

所以正确姿势是复制容器里现成的一个：

```csharp
var clone = (NMainMenuTextButton)template.Duplicate(
    (int)(Node.DuplicateFlags.UseInstantiation | Node.DuplicateFlags.Scripts));
clone.Released += _ => DouSpireTable.Toggle(Entry.Logger);
container.AddChild(clone);              // _Ready 在这儿跑，label 这时才非空
clone.label.Text = "斗地主尖塔";
```

三个细节，每个都是坑：

- **刻意不带 `Signals` flag**。`Duplicate()` 默认会把**信号连接一起复制**，
  于是模板按钮原本接的动作（"继续游戏"…）也会被抄到我们按钮上，点一下莫名进别人的流程。
  `Groups` 同理。只要 `UseInstantiation | Scripts`，子节点（那个文字）照样会复制。
- **直接改 `label.Text`，别调 `SetLocalization`**。后者是
  `_locString = new LocString("main_menu_ui", locKey)`，要游戏本地化表里的 key ——
  我们没有也不该去加。复制体的 `_locString` 是 **null**（C# 字段不受 `Duplicate()` 影响），
  所以 `RefreshLabel()` 是空转，不会覆盖我们写的字。
  （`_Notification(2010)`＝翻译变更，也会走 `RefreshLabel`，同样空转。）
- **中文字体白送**。`Duplicate()` 会复制 theme override，模板那个 label 早就做过
  `ApplyLocaleFontSubstitution` 的中文替换 —— 复制体天然带对的字体。

**额外红利**：复制体就是 `NMainMenuTextButton`，会被排进 scroller 的 `_buttons`，
所以**键盘/手柄焦点导航 + 两侧光标动画全都免费拿到**，跟旁边几个按钮完全一体。

点击链路也确认过了（`NClickableControl`）：
`_GuiInput` → `MousePressed` → `HandleMousePress`（要求 `IsFocused`，靠 hover 时 `RefreshFocus` 置位）
→ `MouseReleased` → `HandleMouseRelease` → `OnReleaseHandler()` → `OnRelease()` + **`EmitSignal(Released)`**。
注意 `NMainMenuTextButton.OnRelease()` **没有**调 `base.OnRelease()`，
但 `Released` 是在外层 `OnReleaseHandler` 里发的，所以照样会触发 —— 直接 `clone.Released += ...` 就行。
另外 `_isEnabled` 字段默认 `= true`（`protected bool _isEnabled = true;`），不用手动 `Enable()`。

### 5.7.4 ⚠️ `--headless` 验证不了 mod（重要教训）

`--headless --log-file` 能跑起来、能写日志，**但所有 mod 都会被跳过**：

```
[INFO] Skipping loading mod DouSpire, user has not yet seen the mods warning
```

实测 **85 个 mod，85 个全 skip，加载数 = 0**。所以这不是 DouSpire 的问题。

**追下去发现了一个反直觉的事实** —— 这条日志的门控在
`MegaCrit.Sts2.Core.Modding.ModManager`：

```csharp
public static bool PlayerAgreedToModLoading => _settings?.PlayerAgreedToModLoading ?? false;
...
else if (!PlayerAgreedToModLoading) { Log.Info($"Skipping loading mod {modId}, ..."); }
```

而那个字段的 JSON 名（`ModSettings.cs`）**极具误导性**：

```csharp
[JsonPropertyName("mods_enabled")]
public bool PlayerAgreedToModLoading { get; set; }
```

> ⭐ **`settings.save` 里的 `mods_enabled` 就是"用户已确认加载 mod"这个旗子**，
> 不是"mod 功能总开关"。以后排查 mod 不加载，先看这个值。
> （会被 `NConfirmModLoadingPopup` 点确认时置 true；`NModMenuRow` 也会动它。）

**无头为什么还是 skip**：无头那次跑游戏落在了 `default/1` 这个 profile 上
（日志在很后面才写 `Profile-scoped data path initialized: user://steam/<id>/profile3`），
而 `AppData\Roaming\SlayTheSpire2\default\1\settings.save` 里 `mod_settings` 是 **null**
→ 旗子读出 false → 全 skip。

**真实 profile 是好的**，两层证据：

1. `user://steam/76561199532681033/settings.save` 里 `mods_enabled: true` + 87 条 `mod_list`。
2. 能反推它被真正写过：`ModManager` 只在旗子为 true 时才重建 `ModList`；
   false 时走 `_settings.ModList = new List<SettingsSaveMod>()`，而空表带
   `SaveIfNotCollectionEmptyOrNull`，**根本不会落盘**。文件里有 87 条 → 旗子当时就是 true。

**结论**：`--headless` 只能验证「游戏起不起得来」，**验证不了「我们的 mod 加载了没」**。
要验证只能有界面的会话里进主菜单看按钮在不在。
（另外：无头跑对 `settings.save` 是**只读**的 —— 实测跑完 md5 没变。）
