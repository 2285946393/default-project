# 凛冬尖塔 · 「传送门 → 独立地图 → 打完结算」实现情报

> 来源：反编译 `集成战略事件`（工坊 **3747637213**，作者 Natsuki，v0.5.6，`lib/0.111.0/IntegratedStrategyEvents.dll`）
> 该 mod 内部把机制叫 **「树洞 TreeHole」** —— 和毛烨描述的「地图上一个点，走进去到另一张地图，打完结算」**完全一致**。
> 情报时间：2026-10-06 夜。工具：`ilspycmd 8.2.0`。

---

## 0. 一句话结论

**这不是"换个房间"，而是"整套换掉 ActMap"**。

`RunState.Map` 被直接替换成一张新建的 `ActMap` 子类实例，同时把 **原地图 / 原访问记录 / 原历史 / 原 ActFloor / 原 Act 存档** 全部打包进一个 `TreeHoleSession` record 存起来；走完临时地图的终点节点后，再从 session 里**逐项还原**。存档则靠**往 `SerializableRun` 里塞一个自定义持久化对象**。

**关键点：官方允许这么干。** `RunState.Map` / `VisitedMapCoords` / `ActFloor` / `Act` 都是可写属性或提供 debug 写入方法，`ActMap` 是可以自己继承的（`ActModel` 才是 sealed 的重灾区）。这条路线**不依赖反射改私有字段**（反射只用在调 `RunManager` 的私有方法上）。

## 1. 完整调用链路（入口 → 进入）

```
事件里给一个选项
   └─ IntegratedStrategyTreeHoleController.EnterFromEvent(owner, destActName, stageLabel)
        └─ TreeHoleEntryCoordinator.EnterFromEvent(...)
             ├─ 单人(NetGameType==1) → 直接 TaskHelper.RunSafely(EnterFromEventDeferred)
             └─ 联机 → IntegratedStrategyTemporaryMapAction.EnqueueTreeHoleEntry(...)   // 同步动作队列
                  └─ EnterFromEventDeferred(owner, destinationActName, stageLabel)
```

### `EnterFromEventDeferred` 的 11 步（照抄这个顺序）

```csharp
// 1. 守卫：能力可用性（它自己有 IntegratedStrategyPatcher.IsAvailable("temporary-map")）
// 2. 取 RunManager.Instance / RunState / RunState(具体类)
// 3. 守卫：不能同时开两个树洞（TreeHoleSessionManager.IsActive）
// 4. 登记 pending 入口（防重复）
if (!TreeHoleSessionManager.AddPendingTreeHoleEntry(state)) return;

await TreeHoleSessionManager.AwaitNextProcessFrame();          // 5. 等一帧，让事件选项结算完
if (runManager.DebugOnlyGetState() != state) return;           //    期间 run 可能被换掉

if (await WaitForEventOptionSettlement(state, destinationActName))   // 6. 等事件选项全部结算
{
    // 7. ★ 快照原地图
    var originalActSave = state.Act.ToSave();
    MapCoord? entryMapCoord = state.CurrentMapCoord;

    // 8. 清场
    await TreeHoleRunAccessor.ExitCurrentRooms(runManager);
    TreeHoleRunAccessor.ClearScreens(runManager);

    // 9. ★ 造临时地图（种子 = 由原状态派生，保证可复现）
    uint seed = TreeHoleSeedFactory.CreateTreeHoleMapSeed(state, destActName, stageLabel);
    var rng = new Rng(seed, "integrated_strategy_tree_hole_map");
    var treeHoleMap = IntegratedStrategyTreeHoleActMap.Create(rng);

    // 10. ★ 打包 session + 换地图
    var session = new TreeHoleSession(
        state.Map,                                    // OriginalMap
        state.VisitedMapCoords.ToList(),               // OriginalVisitedMapCoords
        state.MapPointHistory.Select(h => h.ToList()).ToList(),  // OriginalMapPointHistory
        state.ActFloor,                                // OriginalActFloor
        originalActSave,                               // OriginalActSave
        seed,
        entryMapCoord,                                 // ← 返回时的落点
        stageLabel, destActName,
        treeHoleMap, treeHoleMap.TerminalCoord);       // 新地图 + 终点坐标
    TreeHoleSessionManager.SetTreeHoleSession(state, session);

    state.Map = treeHoleMap;                           // ★ 换掉
    state.ClearVisitedMapCoordsDebug();                // ★ debug 写入口
    state.AddVisitedMapCoord(treeHoleMap.StartingMapPoint.coord);
    TreeHoleSessionManager.RefreshLocationSynchronizers(state);

    // 11. 过场 + 进房
    await TreeHoleRunAccessor.FadeOut();
    TreeHoleSessionManager.SetMapScreen(treeHoleMap, state, initMarker: false);
    await TreeHoleRunAccessor.EnterRoomInternal(runManager, new MapRoom());
    await TreeHoleRunAccessor.PersistCurrentRunTransition(runManager, destActName + " tree-hole entry");
    await TreeHoleRunAccessor.FadeIn(runManager, showTransition: true);
}
```

**要点的工程含义**：
- `state.Map` 的 setter 是 public → 换地图不需要反射。
- `state.ClearVisitedMapCoordsDebug()` / `state.AddVisitedMapCoord(coord)` 是官方给的**"我就要手动改访问记录"** 的后门。名字带 Debug，但它是给这种情况用的。
- `state.ActFloor` 在这里**没改**（临时地图沿用原 ActFloor），只有快照存着，返回时才还原。
- `state.Act` **也没换** —— Act 还是原来那幕，只换了 Map。所以**临时地图是"挂在原 Act 上的临时层"**，不是新一幕。这点对凛冬尖塔很重要：**你不需要造新 Act**。

## 2. 临时地图怎么造 —— `IntegratedStrategyTreeHoleActMap : ActMap`

这是**整个方案里最核心、也最容易复刻的一步**：自己继承 `ActMap`，自己填 `Grid`。

```csharp
internal sealed class IntegratedStrategyTreeHoleActMap : ActMap, IIntegratedStrategyTemporaryActMap
{
    private const int GridWidth = 7, MapLength = 5, RouteCount = 3;
    private const int CenterColumn = 3, StartRow = 0, FirstRow = 1,
                      BranchStartRow = 2, BranchEndRow = 4, TerminalRow = 5, BossRow = 6;
    private static readonly int[] RouteColumns = new[] { 1, 3, 5 };

    private readonly MapCoord _terminalCoord;

    protected override MapPoint?[,] Grid { get; }        // ★ 必须 override
    public override MapPoint BossMapPoint { get; }       // ★ 必须 override
    public override MapPoint StartingMapPoint { get; }   // ★ 必须 override
    public MapCoord TerminalCoord => _terminalCoord;

    public static IntegratedStrategyTreeHoleActMap Create(Rng rng) => new(rng);

    private IntegratedStrategyTreeHoleActMap(Rng rng)
    {
        Grid = new MapPoint[7, 6];                                    // 7 列 × 6 行
        StartingMapPoint = CreateSpecialPoint(3, 0, (MapPointType)8); // 起点
        BossMapPoint     = CreateSpecialPoint(3, 6, (MapPointType)7); // BOSS

        bool hasShop = false;
        int eliteFreeLane = rng.NextInt(3);                            // 保证 3 条路里至少 1 条没有精英

        // 第 1 行：只有一个点
        var first = CreatePathPoint(3, 1, RollPointType(rng, isFirstNode:true, allowElite:false, ref hasShop));
        StartingMapPoint.AddChildPoint(first);
        startMapPoints.Add(first);

        // 第 2~4 行：每行 3 个分支点（列 1/3/5）
        var branch = CreateBranchRow(rng, 2, eliteFreeLane, ref hasShop);
        foreach (var p in branch) first.AddChildPoint(p);
        for (int row = 3; row <= 4; row++)
        {
            var next = CreateBranchRow(rng, row, eliteFreeLane, ref hasShop);
            for (int k = 0; k < 3; k++) branch[k].AddChildPoint(next[k]);
            branch = next;
        }

        // 第 5 行：终点（三路汇聚）
        var terminal = CreatePathPoint(3, 5, RollTerminalPointType(rng));
        foreach (var p in branch) p.AddChildPoint(terminal);
        terminal.AddChildPoint(BossMapPoint);
        _terminalCoord = terminal.coord;
    }

    private MapPoint CreatePathPoint(int col, int row, MapPointType type) {
        var p = new MapPoint(col, row) { PointType = type, CanBeModified = false };
        this.Grid[col, row] = p;
        return p;
    }
    private static MapPoint CreateSpecialPoint(int col, int row, MapPointType type)
        => new MapPoint(col, row) { PointType = type, CanBeModified = false };
}
```

### 附带的点类型随机规则（可复用）

```csharp
// 普通点池：5×MapPointType(5)，再各 1 个 (1)(3)(4)
// 首节点池：(1)(3)(4)
// 再有条件加 (2)=商店（全局最多 1 个）、(6)=精英（首节点不加、eliteFreeLane 那条路不加）
private static MapPointType RollPointType(Rng rng, bool isFirstNode, bool allowElite, ref bool hasShop)
{
    var pool = isFirstNode
        ? new List<MapPointType> { (MapPointType)1, (MapPointType)3, (MapPointType)4 }
        : new List<MapPointType> { (MapPointType)5, (MapPointType)5, (MapPointType)1, (MapPointType)3, (MapPointType)4 };
    if (!hasShop) pool.Add((MapPointType)2);
    if (!isFirstNode && allowElite) pool.Add((MapPointType)6);
    var t = pool[rng.NextInt(pool.Count)];
    hasShop |= (int)t == 2;
    return t;
}

private static MapPointType RollTerminalPointType(Rng rng)
    => rng.NextInt(2) == 0 ? (MapPointType)3 : (MapPointType)6;   // 终点 = 随机 宝箱/精英
```

### ▲ 待实测的 `MapPointType` 枚举值
反编译里是裸 int 强转，**数值→名字的映射没拿到**。已知相对关系：`7 = BOSS`、`8 = 起点`。
其余 `1/2/3/4/5/6` 是 战斗/商店/宝箱/休整/事件/精英 的某种排列 —— **【待实测】**，用 `ilspycmd -t MegaCrit.Sts2.Core.Map.MapPointType <publicized sts2.dll>` 一读就有。
> ⚠️ 凛冬尖塔不要硬编码这些数字；先把枚举名字查出来再用。

## 3. 打完怎么回原地图 —— 还原链路

```
玩家走完终点节点 → 宝箱/发奖 → ProceedFromTerminalRewardsScreen
   └─ [Patch] IntegratedStrategyTreeHoleTerminalRewardsProceedPatch (Postfix)
        await 原 task
        IntegratedStrategyTreeHoleController.MarkTerminalRewardsProceededCurrentRun()
        IntegratedStrategyTreeHoleController.TryRestoreCompletedCurrentRunAfterTerminalProceed()
             └─ TreeHoleSessionManager.RequestRestoreOriginalMap(state, session)
                  └─ IntegratedStrategyTemporaryMapAction.EnqueueTreeHoleReturn(player)  // 联机同步
                       └─ RestoreOriginalMapFromSyncedAction
                            └─ RestoreOriginalMapAndPersist(state, session)
                                 ├─ RestoreOriginalMap(state, session)   ★ 还原十件事
                                 ├─ if (CurrentRoom is not MapRoom) await runManager.EnterRoom(new MapRoom())
                                 └─ await TreeHoleRunAccessor.PersistCurrentRunTransition(runManager, "return from ...")
```

### `RestoreOriginalMap` 严格逐项还原（顺序不能乱）

```csharp
SessionStore.RemoveTreeHoleSession(state);
SessionStore.RemovePendingTreeHoleReturn(state);
state.Map = session.OriginalMap;                      // ① 换回原地图
state.ClearVisitedMapCoordsDebug();                   // ② 清访问记录
foreach (var c in session.OriginalVisitedMapCoords)   // ③ 逐条写回
    state.AddVisitedMapCoord(c);
RestoreMapPointHistory(state, session.OriginalMapPointHistory);  // ④ 还原历史
state.ActFloor = session.OriginalActFloor;            // ⑤ 还原楼层
TreeHoleRunAccessor.RestoreActRooms(state, session.OriginalActSave);  // ⑥ 还原 Act 的 RoomSet
RefreshLocationSynchronizers(state);                  // ⑦ 通知联机
SetMapScreen(session.OriginalMap, state, state.CurrentMapCoord.HasValue);  // ⑧ 刷新地图屏
```

> ⑦⑧ 里的 `RefreshLocationSynchronizers` / `SetMapScreen` 是 Natsuki 自己封装的（内部还是会碰 `NMapScreen`/同步器）。凛冬尖塔若只做**单人**，这两步可以先跳过或简化。

### 三条触发还原的路径（都要考虑）

1. **主动**：走完终点 → `ProceedFromTerminalRewardsScreen` patch → 还原
2. **被动兜底**：`RunManager.RoomEntered` 事件 → `OnRoomEntered()`，若 `CurrentRoom is MapRoom` **且** 已访问过终点 → 还原
   （**关键**：这条是防"玩家在临时地图里手动回地图屏"之类的漏网情况）
3. **读档**：见第 5 节

### `RestoreActRooms` —— 这个坑值得单独抄

临时地图期间 `state.Act` 的 `_rooms`（`RoomSet`）可能被战斗/事件污染。还原时**不是直接覆盖**，而是取 max：

```csharp
var restored = RoomSet.FromSave(originalActSave.SerializableRooms);
var current  = (RoomSet)ActRoomsField.GetValue(state.Act);
restored.normalEncountersVisited = Math.Max(restored.normalEncountersVisited, current.normalEncountersVisited);
restored.eliteEncountersVisited  = Math.Max(restored.eliteEncountersVisited,  current.eliteEncountersVisited);
ActRoomsField.SetValue(state.Act, restored);
```

**原因**：如果不用 max，临时地图里打过的怪会被"忘记"，出去后可能重复遇到同一组。这是一个真实的边界坑。

### 隐藏私有节点的通用手法（值得抄）

```csharp
// 反射拿私有字段（NMapScreen 的私有 Node 字段）
var node = (CanvasItem)typeof(NMapScreen).GetField(fieldName, BindingFlags.Instance|BindingFlags.NonPublic)!
                                         .GetValue(screen)!;
node.Hide();

// 隐藏路径：_paths 是 IDictionary，key = (MapCoord, MapCoord) 元组，value = IEnumerable<TextureRect>
```

## 5. 存档 —— 最硬核的一节

### 5.1 存

`[HarmonyPatch(typeof(RunManager), "ToSave")]` Postfix，把当前状态**重写进 `SerializableRun`**：

```csharp
var snapshot = IntegratedStrategyTreeHoleController.GetSaveSnapshot(state);   // 当前（临时地图）状态
int i = __result.CurrentActIndex;
if (i >= 0 && i < __result.Acts.Count)
    __result.Acts[i].SavedMap = SerializableActMap.FromActMap(snapshot.CurrentMap);   // ★ 存的是"临时地图"
__result.VisitedMapCoords = snapshot.CurrentVisitedMapCoords.ToList();
__result.MapPointHistory  = snapshot.CurrentMapPointHistory.Select(h => h.ToList()).ToList();
__result.MapDrawings = null;
IntegratedStrategyTreeHoleSaveStateStore.Save(state, __result, snapshot, resumeRoom);  // ★ 原地图等存进自定义字段
```

**设计精髓**：官方存档字段里存的是**"当前所在的地图"**（临时地图），而**"原地图"等还原所需的一切**存进 mod 自己的持久化对象。这样**原版读档逻辑不需要任何修改**就能正常把玩家放回临时地图。

### 5.2 自定义持久化对象挂在哪 —— `IntegratedStrategyTreeHoleSaveStateStore`

反编译这一层是 `IntegratedStrategyPrivateMembers` + 一堆反射，没直出源码。**但 `TreeHolePersistedState` 的字段清单是完整的**（这就是你要存的东西）：

```csharp
internal sealed class TreeHolePersistedState
{
    public int Version { get; set; }
    public long StartTime { get; set; }
    public bool PendingArchitectCompletion { get; set; }
    public string? ResumeRoom { get; set; }        // "Architect" / "Map" / null
    public string Kind { get; set; }               // TreeHole / EndlessFinale / ...
    public int CurrentActIndex { get; set; }
    public string? ParentActId { get; set; }
    public int CurrentActFloor { get; set; }
    public MapCoord? CurrentMapCoord { get; set; }
    public List<int>? CurrentMapPointHistoryCounts { get; set; }
    public SerializableActMap? TemporaryMap { get; set; }
    public List<MapCoord>? TemporaryUnmodifiableCoords { get; set; }
    public SerializableActMap? OriginalMap { get; set; }
    public List<MapCoord>? OriginalUnmodifiableCoords { get; set; }
    public List<MapCoord>? OriginalVisitedMapCoords { get; set; }
    public List<int>? OriginalMapPointHistoryCounts { get; set; }
    public int OriginalActFloor { get; set; }
    public SerializableActModel? OriginalActSave { get; set; }
    public uint TreeHoleMapSeed { get; set; }      // ★ 只存种子，地图可重建
    public string? StageLabel { get; set; }
    public string? DestinationActName { get; set; }
    public MapCoord TerminalCoord { get; set; }
}
```

> **重要观察**：`OriginalMap` **同时**存了完整 `SerializableActMap` **和** `TreeHoleMapSeed`。
> 正常情况用存下来的 map；**如果 map 对不上（版本/结构变了），就用 seed 重建**（见 `RestoreMapForGeneration`）。
> 这就是"**版本兼容兜底**"。凛冬尖塔第一版可以不搞，但要知道留了这条路。

### 5.3 怎么把对象塞进 `SerializableRun` —— 【★ 头号待查】

这是**唯一没有直接看到源码**的地方。三种可能：
1. `SerializableRun` 上有一个可写扩展字段（RitsuLib 可能提供）
2. 反射往 `SerializableRun` 里塞一个 `[SavedProperty]`
3. 它自己劫持了 `RunManager.ToSave` 的序列化流程

**dll 里有 `InjectSavedPropertyCaches()`（在 `ModEntry.Initialize` 里调）** —— 名字高度暗示是**给类型"注入一个可被保存的属性"**，很可能是 RitsuLib 的能力。
**下一步动作**：`ilspycmd -t IntegratedStrategyEvents.IntegratedStrategyPrivateMembers <dll>` + 搜 RitsuLib 的 `SavedProperty` 相关 API。

### 5.4 `ResumeRoom` —— 一个容易漏的状态

存档时要额外记"**读完档该把玩家放在哪**"：
- `Architect` → 读档后走「建筑师完成」流程
- `Map` → 读档后直接进地图房
- `None` → 不特殊处理

`TreeHoleRunAccessor.ResumeRoomForSave` 是个 `AsyncLocal<TreeHoleResumeRoom>`，在 `PersistCurrentRunTransition` 期间才有效 —— **因为 `ToSave` 可能在别的时刻被调，需要一个"这次保存属于哪种语境"的旁路标记**。
> 凛冬尖塔如果只做单人 + 不做建筑师联动，这一层可以先砍掉（存 `None`）。

## 6. 读档

`[HarmonyPatch(typeof(RunState), "FromSerializable")]` Postfix → `QueueRestoreFromSave(save, state)`：

```
QueueRestoreFromSave
  ├─ 若 resumeRoom==Architect → AddPendingArchitectCompletion
  ├─ 若 resumeRoom==Map       → AddPendingMapRoomResume
  ├─ Load(save, state) 取出 TreeHoleRestoreSnapshot
  ├─ SessionStore.QueueRestore(state, snapshot)
  └─ 必要时 SuppressCompletionUntilTerminalProceed
```

真正重建在 `TryRestoreSavedSession`：先做**新鲜度校验**（act 是否对得上、map 里有没有 TerminalCoord），过期快照直接丢弃并 log warn；然后重建 `TreeHoleSession`，把 `state.Map` 设成临时地图。

**顺序注意**：`Save` 用 `[HarmonyBefore("com.ritsukage.sts2-RitsuLib.framework-core")]`，`Load` 用 `[HarmonyAfter(...)]` —— 和 RitsuLib 的存档流程有明确顺序依赖。

## 7. 和凛冬尖塔的对接方案（我的建议）

### 7.1 你要的东西，最小可用版本 = 5 个文件

| 文件 | 职责 | 参考源 |
|---|---|---|
| `PortalMap.cs` | `: ActMap`，就是**一张 3×4 的小地图**（甚至可以是单点直通 BOSS） | `IntegratedStrategyTreeHoleActMap` |
| `PortalSession.cs` | `record`，存原地图快照（照抄 `TreeHoleSession` 的字段） | `TreeHoleSession` |
| `PortalEntry.cs` | 进传送门：快照 → 换 `state.Map` → `EnterRoomInternal(MapRoom)` | `TreeHoleEntryCoordinator.EnterFromEventDeferred` |
| `PortalExit.cs` | 出传送门：逐项还原（第 3 节那 8 步） | `TreeHoleSessionManager.RestoreOriginalMap` |
| `PortalHooks.cs` | 4 个 Harmony patch：`NMapScreen.SetMap` / `RunManager.ToSave` / `RunState.FromSerializable` / `RoomEntered` | 第 4、5、6 节 |

### 7.2 但 ★ 我建议凛冬尖塔**先不要做完整版**

理由（说难听但有用）：
- 上面的存档部分是**这个 mod 最复杂、最脏的一层**（反射 + 与 RitsuLib 顺序耦合 + 版本兼容）。Natsuki 用了 `TreeHolePersistedState` **18 个字段**才把它做稳。
- 而你真正想要的**玩法体验**其实只需要前 3 个文件 + **最简单的地图 UI 侧处理**。

### 7.3 阶段性落地（推荐）

**阶段 1（低风险，先拿到体验）**
- 用一个**遗物/卡牌**作为"传送门"入口（不需要在地图上放点）
- 进入时：快照 → `state.Map = PortalMap` → 进 MapRoom
- 出来时：还原 `Map` + `VisitedMapCoords`（其余先不动）
- **不做存档兼容** —— 临时地图期间**禁止存档**（或者干脆约定：临时地图里退出 = 本局作废，做提示）
- 目标：**先让你能进去打、打完能出来**

**阶段 2（补地图上的"点"）**
- 在 `ActMap` 生成后往 `Grid` 里塞一个自定义 `MapPoint`，给个特殊 `MapPointType` 或自定义图标
- 抄 `NMapScreen.SetMap` Postfix + `RollRoomTypeFor` Prefix，让这个点解析成"传送门房"
- 目标：**地图上真的有个点，走进去触发**

**阶段 3（补存档）**
- 再上 `TreeHolePersistedState` 那一套
- 目标：**中途退出游戏不丢进度**

### 7.4 三条要提前知道的硬约束

1. **`ActModel` 是 sealed 的**（重灾区）——所以**绝不能造新 Act**。只能换 `Map`。Natsuki 的方案正是这个思路，可以放心跟。
2. **`MapPointType` 是枚举，可能无法直接扩展** —— 要塞自定义节点类型时，要么用现有类型 + 自己的判断分支，要么查清枚举能否扩展。
3. **联机同步是额外一层** —— Natsuki 用了 `IntegratedStrategyTemporaryMapAction`（`NetGameAction` 子类）来同步"进入/返回"。凛冬尖塔**如果只做单人，整层可以砍掉**（`NetGameType==1` 那条直通路径就是为单人准备的）。

## 9. 附：`ModEntry.Initialize` 的注册顺序（凛冬尖塔可照抄骨架）

```csharp
IntegratedStrategyTreeHoleSaveStateStore.Initialize();   // 先初始化存档存储
InjectSavedPropertyCaches();                              // ★ 注入可保存属性
RegisterRelics();                                          // ModHelper.AddModelToPool(EventRelicPool, type)
RegisterCards();                                           // ModHelper.AddModelToPool(TokenCardPool, type)
RegisterActEvents();                                       // ModContentRegistry.For(id)
                                                           //   .RegisterActEvent(type, actType)
                                                           //   .RegisterSharedEvent(type)
EnsureModelsRegisteredIfModelDbAlreadyInitialized();       // ModelDb.Inject(type) + InitId(id)
HarmonyInstance = new Harmony("Natsuki.IntegratedStrategyEvents");
IntegratedStrategyPrivateMembers.Validate();               // ★ 先校验反射目标存在，再打补丁
IntegratedStrategyPatcher.ApplyAll(HarmonyInstance, Assembly.GetExecutingAssembly());
IntegratedStrategyEventRuntimeCompatibility.Install();
IntegratedStrategyTreeHoleController.Install();            // 挂 RunManager.RunStarted / RoomEntered
```

**两个值得学的手法**：
- `IntegratedStrategyPrivateMembers.Validate()` —— **打补丁前先校验所有反射目标（类型/字段/方法）存在**，不存在就明确报错而不是静默失败。这是版本升级时的救命稻草。
- `IntegratedStrategyPatcher` + `[IntegratedStrategyPatch(id, feature, desc)]` —— **自定义补丁特性**，把每个 patch 归类到 feature 上，可以按 feature 开关。凛冬尖塔做大了会需要这个。

## 10. 其他树的树洞（同 mod 里的变体，供参考规模）

同 mod 还实现了 8 种「终局地图」（`EternalDust`/`RadiantApex`/`CarefreeVihara`/`AbyssalJungle`/`DesireHall`/`EndlessFinale`/...），每个都是**一张独立的 ActMap 子类**（`IntegratedStrategyEternalDustFinaleActMap` 等），共用同一套 session/还原机制。

**这说明这套 scheme 是可复用、可规模化的** —— 你以后想给凛冬尖塔加"第二个传送门目的地"，就是再加一个 `ActMap` 子类的事。
