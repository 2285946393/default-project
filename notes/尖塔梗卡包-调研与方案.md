## 一、技术结论（已反编译核实，不是猜的）

### 1. 加一张卡 = 写一个 `CardModel` 子类
真实例子（PengoTarot，44 张塔罗牌的 mod）：

```csharp
public abstract class TarCard : CardModel      // 自己起一个基类
{
    protected TarCard(CardType type) : base(1, type, CardRarity.Rare, TargetType.Self) { }
    // 效果写 OnPlay(...)
}

public sealed class TarChariotReversed : TarCard
{
    protected override IEnumerable<IHoverTip> ExtraHoverTips => ...;
}
```

**和游戏本体自己的卡一模一样**（本体 `DefendIronclad : CardModel` 也是这个形状）：
构造里给 `(费用, 类型, 稀有度, 目标)`，效果重写 `OnPlay(...)`，升级重写 `OnUpgrade()`。

### 2. 卡要进"卡池"才会出现在奖励里
- **PengoTarot 的做法**（老 mod）：自己写 `CardPoolModel` 子类，再 Harmony 补 `ModelDb.AllCardPools` 把它塞进去。
- **RitsuLib 的做法**（我们已经在用 RitsuLib 注册遗物）：`STS2RitsuLib.Content.ModContentRegistry`
  + 一堆 `AllSharedCardPoolsPatch` / `AllCardsPatch` 之类的补丁 —— 应该比手写 Harmony 干净。
  ⚠️ **要读一下 RitsuLib 的注册方式再动手**（我们只注册过遗物，没注册过卡）。

### 3. 我们现成能复用的东西（这是选这个方向的原因）
| 已有能力 | 用在哪 |
|---|---|
| `ModRelicTemplate` + `[RegisterRelic]` | 加遗物的路子（加卡同一套思路） |
| Harmony 补丁（2 个，已跑通） | 卡池注入 / 特殊判定 |
| pck 打包（`tools/build_pck.ps1`） | **卡图**放进 pck |
| 本地化注入（`LocInjector`）+ `QuestTextEn` 生成器 | 卡名 / 卡面文案的多语言 |
| `tools/check_i18n_coverage.py` | 文案查漏 |
| 上架流程（`prepare_workshop.py` + ModUploader） | 发布 |

### 4. 唯一的硬成本：**卡图**
每张卡都要一张图。三条路（下面方案里选）：
- **AI 生成**（有 imagegen；也有本地 SD）—— 风格统一最省事。
- **官方素材改色/拼接**（遗物就是这么做的，致谢里注明来源）—— 快，但创意度低。
- **极简文字卡面**（纯色 + 大字）—— 最省事，但不好看。

## 二、素材（已经有了）

- `notes/杀戮尖塔2-梗清单.md`：B 站《尖塔梗百科》全 14 期 + 社区梗，**每条都查过可行性**。
  其中"做任务"用掉了很多，但**做卡不受限制**——卡只要"名字 + 机制贴合梗"即可，不需要可统计的行为。
- 可用素材举例：基米精神、战个未来、东尼意思、还在启动、删内切（152 金币）、火焰屏障输出特别高、
  我说〇〇〇有没有懂的、严父在上、劣人手速、鸡煲、战士鸽、小蓝人、宇宙冷漠（本体已有这张牌）、
  蛇花圣经、复制防御、掉集中、蛇咬、假货、数值轮椅、太牢了……

### 设计原则（重要）
**每张卡的"机制"要对应梗的"含义"，不能只是名字搞笑。** 例：
| 梗 | 机制应该是什么 |
|---|---|
| 基米精神（不打过渡、死赌未来） | 现在亏（弃牌/掉血），后面大赚 |
| 战个未来（先忍着，后面会变强） | 先受伤，之后变强 |
| 东尼意思（"xxx 很强→增强别的"） | 不强化自己，**强化你其他牌** |
| 还在启动（鸡煲启动慢） | 前几回合很弱，之后爆发 |
| 删内切（花 152 金币删牌） | 花钱 / 消耗一张牌换收益 |
| 严父在上（一层精英敲废鸡煲） | 对**精英**特攻 |
| 我说〇〇有没有懂的 | 围绕"过牌/别带/有费"做效果 |

## 三、三个方案（差别明显，挑一个）

### 方案 A：一批梗卡（12~15 张，无色池）——**推荐先做这个**
- 只加卡，进"无色/共享"卡池，谁都能抽到。
- 工作量：中。上线最快，能先验证"这方向有人玩"。
- 之后想扩再扩。

### 方案 B：梗卡 + 梗遗物 + 梗事件（小合集）
- 卡 12 张 + 遗物 6 件 + 事件 3 个，凑成一个像样的"内容包"。
- 工作量：中大。更像"一个 mod"，但周期翻倍。

### 方案 C：一个完整的梗角色
- 新角色 + 30 张专属牌 + 起始遗物 + 立绘/动画。
- 工作量：大（要画角色、做动画资源）。最出圈，但周期最长。

## 四、风险 / 待确认

1. **RitsuLib 注册卡牌的正确姿势**要再读一遍（我们只注册过遗物）。
2. **卡图**是唯一会卡住的地方 —— 定方案时一起定"图从哪来"。
3. **平衡**：梗卡容易做太强/太弱，先按"能玩"做，之后按玩家反馈调。
4. 别碰本体的版权素材做商业用途；沿用现在"致谢里注明来源"的做法。
