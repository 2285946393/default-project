# 找项目 · 搜索手册

> 建这份手册的原因：以前每次找灵感都去翻 B 站收藏夹，翻多了没意思。
> 这里是一套**自己找素材**的固定流程——B 站找教程/灵感，GitHub 找能直接改的成品。
> 最后附 2026-10-04 实测挖到的"惊艳项目"清单。

## 一、B 站：一条命令搜，不用翻收藏夹

工具就是上次做的那个收藏夹工具，加了个搜索。按播放量搜（最稳，能看出什么内容真的火）：

```powershell
node tools/bili-fav.mjs --search "webgl 从零" --order click --pages 2
```

只看播放过万的：

```powershell
node tools/bili-fav.mjs --search "开源 物理引擎" --order click --min-play 10000
```

存成 json 方便再筛：

```powershell
node tools/bili-fav.mjs --search "着色器 教程" --order click --json "%TEMP%\bili.json"
```

排序参数 `--order`：

| 值 | 意思 | 什么时候用 |
|---|---|---|
| `totalrank` | 综合（默认） | 想找"公认好"的 |
| `click` | 播放最多 | 想找爆款/成熟讲解 |
| `pubdate` | 最新发布 | 想看新玩法、新工具 |
| `dm` | 弹幕最多 | 找有梗、有讨论的 |
| `stow` | 收藏最多 | 找"干货型"教程 |

**关键词模板**（比一个个试快）：

- `<技术> + 从零/保姆级/源码` → 教程类
- `我做了一个 + <东西>` → 能抄的成品
- `开源 + <类型>` → 直接给仓库
- `从夯到拉 / 盘点 + <主题>` → 现成的榜单，抄选题
- **中文搜完用英文再搜一轮**（技术内容英文标题更多）

登录态过期会提示，浏览器登录一下 bilibili.com 后跑 `--refresh` 即可。

## 二、GitHub：找"惊艳"

### 语法速查（拼进 `q=` 就能用）

| 想找什么 | 写法 |
|---|---|
| 够火的 | `stars:>1000` |
| 还在维护的 | `pushed:>2026-01-01` |
| 某个领域 | `topic:webgl`、`topic:raymarching`、`topic:procedural-generation`、`topic:creative-coding` |
| 某个语言 | `language:JavaScript` |
| 最近爆的新项目 | `created:>2026-09-27` |
| 有网页 demo 的 | `homepage:*` |

### 三个常用命令行

领域里最火的（把 `topic:raymarching` 换成你要的领域）：

```powershell
curl.exe -s "https://api.github.com/search/repositories?q=topic:raymarching+stars:>300&sort=stars&per_page=10"
```

最近一周的新星榜（最能发现惊艳的新东西）：

```powershell
curl.exe -s "https://api.github.com/search/repositories?q=created:>2026-09-27+stars:>200&sort=stars&per_page=12"
```

查许可证和最后更新时间（决定能不能抄、值不值得抄）：

```powershell
curl.exe -s "https://api.github.com/repos/OWNER/REPO"
```

### 固定入口

- `github.com/trending?since=daily` —— 趋势榜（HTML 页，抓的时候正则要跟着改）
- `terkelg/awesome-creative-coding` ★15k —— 创意编程资源总表
- `blob42/awesome-explorables` ★1k —— **交互式讲解**清单（这一类特别适合做作品集）
- `github.com/topics/<任意词>` —— 网页版主题页，比搜索好用

### 怎么判断值不值得花时间

1. **star + 最近提交**：star 高但两年没动 → 抄思路别抄代码。
2. **许可证**：
   - `MIT` / `Apache-2.0` / `CC0` → 随便改，署名即可
   - `AGPL-3.0` → 改了必须开源（自己玩没事，别商用）
   - `NOASSERTION` → GitHub 认不出来，**先去读它的 LICENSE 文件**
3. **有没有在线 demo** → 有 demo 说明能跑起来，改造成本低。
4. **能不能纯前端跑**（不用后端、不用大模型）→ 对你最省事。

## 四、下次找项目的标准动作

1. 先 `--search` 两轮 B 站（中文一轮 + 英文一轮），确认**这个话题有人看**。
2. 再 GitHub 搜 `topic:` + `stars:>`，找**能直接改的成品**（第一原则：先找轮子）。
3. 查许可证 + 最后更新时间，写进结论。
4. 给 2~3 个"做完长什么样"的选项，别只给一个。
