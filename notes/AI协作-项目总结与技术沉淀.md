## 一、用户画像与核心偏好

### 已确认的硬约束
1. **不造轮子**：做创意/交互/可视化类项目时，优先去 GitHub 寻找成熟开源项目作为基础，在其基础上修改定制。用户明确说过"不要自己造轮子"，且已保存为全局偏好。
2. **高互动优先**：用户要的是"操作即内容"——用户的每个操作都能创造新内容、引发连锁反应。**反感**"只切预设看模型"的静态展品，反感"全一个颜色"，反感"太眼花缭乱"。
3. **视觉要惊艳**：沉浸式、发光、有机、有生命感。用户原话"非常喜欢这张视觉效果交互的东西"。
4. **单文件离线**：最终交付必须是单个 HTML 文件，零外部依赖（CDN/字体/图片都不行），双击即可在浏览器离线运行。
5. **自主完成，不追问**：用户要求"找点乐子""不要问我的意见"，给出方向后应自主推进到交付，不要反复确认。

### 用户的工作模式
- 用户会同时使用多个 AI（"我是多ai协用"），可能让别的 AI 做类似项目，需注意**避重**（见第六节已有项目清单）。
- 用户会在浏览器里实时玩项目，边玩边反馈。反馈通常很短："可以可以""一般吧""不好玩""这个也可以"。
- 用户满意的项目会说"有点圆满了""非常喜欢"，然后要求"再找点有意思的"。

## 三、统一技术架构（可直接复用）

所有项目共享同一套前端架构模式，新 AI 接手时建议沿用以保持一致性。

### 3.1 单文件内联
- 所有 CSS `<style>` 内联在 `<head>`，所有 JS `<script>` 内联在 `<body>` 末尾。
- **零外部引用**：交付前必须 grep 检查 `src=|href=|http://|https://|cdn|googleapis|jsdelivr|unpkg`，只允许 `canvas.toDataURL()` 这种本地生成。
- 中文字体用系统字体栈：`-apple-system, "Segoe UI", "Microsoft YaHei", "PingFang SC", system-ui, sans-serif`。

### 3.2 玻璃拟态 UI（统一风格）
```css
.glass{
  background:rgba(11,15,24,.62);
  backdrop-filter:blur(22px) saturate(1.4);
  -webkit-backdrop-filter:blur(22px) saturate(1.4);
  border:1px solid rgba(150,175,220,.14);
  border-radius:16px;
  box-shadow:0 18px 60px rgba(0,0,0,.5);
}
```
- 右上面板（268px 宽，可滚动）、底部工具栏、左下状态读数、左上品牌标题。
- 滑块、分段按钮、矩阵格子、配色色块都有统一样式。
- 主题色每个项目换一个强调色（粒子生命=青绿色、引力沙盒=青蓝色、反应扩散=粉紫色）。

### 3.3 开场遮罩（必须有）
```css
.veil{position:fixed;inset:0;z-index:30;display:grid;place-items:center;
  background:radial-gradient(ellipse at center,rgba(4,6,11,.25),rgba(4,6,11,.82));
  transition:opacity .8s ease;cursor:pointer;}
.veil.gone{opacity:0;pointer-events:none;}
```
```js
veil.addEventListener("click",()=>{
  veil.classList.add("gone");
  setTimeout(()=>{veil.style.display="none";},900); // 兜底，兼容动画被节流环境
});
```
- 遮罩内容：大标题（渐变文字）+ 一句话说明 + 操作提示。
- **必须加 setTimeout display:none 兜底**：无头/节流环境下 opacity 过渡可能不推进，纯靠 class 会残留半透明遮罩挡画面。

### 3.4 键盘快捷键（统一）
- `空格`：暂停/继续
- `G`：隐藏/显示面板
- `P`：保存 PNG（`canvas.toDataURL` + a.click）
- `C`：清空/重置
- `R`：随机参数/随机世界

### 3.5 状态读数（左下）
```
粒子 3,000 · 物种 5
帧率 14 fps · 活跃度 2.5
```
用 `requestAnimationFrame` 的时间差算 fps，做指数平滑（`fps=fps*0.92+(1/dt)*0.08`）避免跳动。

## 四、各项目技术要点与踩坑记录

### 4.1 粒子生命（Particle Life）
**核心算法**：
- 多物种吸引矩阵 `matrix[speciesA][speciesB]` ∈ [-1,1]，正值吸引负值排斥。
- 分段力曲线：距离 < r1 时强排斥（防重叠），r1~r2 时按矩阵值吸引/排斥，> r2 时无作用。
- **空间哈希网格优化**：O(n²) 暴力在 3000 粒子时会卡，按作用半径分网格，只查相邻 9 格。

**踩坑**：
- 上游 hunar4321/particle-life 是 O(n²) + CDN 英文面板 + 无分段力（结构不好看），需重写核心。
- 矩阵格子点击要在 -1/0/+1 间循环，红绿配色（绿=吸引、红=排斥、灰=中立）。

### 4.2 引力沙盒（N-body）
**核心算法**：
- 子步半隐式欧拉积分：每帧分 4 个子步，先更新速度再用新速度更新位置（比显式欧拉稳定）。
- 软化引力：`d2 = dx²+dy²+soft²`，soft=6 避免 d→0 时引力爆炸。
- 碰撞合并：距离 < r1+r2 时合并，**动量守恒** `v=(m1v1+m2v2)/(m1+m2)`，质量相加，半径按 `cbrt(M)*0.9` 增长，产生爆炸粒子。
- 拖拽放置：按下定世界坐标，松开时初速度 = (松开点-起点)*0.012，虚线箭头实时预览。

**踩坑**：
- 上游 Genicleito gist 是葡萄牙语 + 显式欧拉 + 点击只给固定 y 方向速度 + 视觉朴素，需重写交互和物理。
- 天体类型体系（小行星/卫星/行星/巨行星/恒星/红巨星/黑洞）可直接沿用上游设计，质量差 30 万倍。
- 黑洞渲染：黑圆 + 旋转吸积盘（椭圆 radial gradient，`ctx.rotate(t)`）。

### 4.3 反应扩散（Gray-Scott）—— 踩坑最多
**核心算法**：
```
dU = Du*lapU - U*V² + f*(1-U)
dV = Dv*lapV + U*V² - (k+f)*V
```
- 9 点拉普拉斯：中心 -1，四邻 0.2，四角 0.05（和为0）。
- 环形边界 wrap。
- dt=0.6，每帧迭代 18 次（总演化速度 10.8/帧）。
- Du=0.16, Dv=0.08（标准值）。

**成熟参数组（f, k）**：
| 形态 | f | k |
|---|---|---|
| 斑点 | 0.0367 | 0.0649 |
| 条纹 | 0.022 | 0.051 |
| 迷宫 | 0.029 | 0.057 |
| 珊瑚 | 0.0545 | 0.062 |
| 波浪 | 0.014 | 0.045 |
| 分裂 | 0.03 | 0.063 |
| 孔洞 | 0.039 | 0.058 |

**重大踩坑（其他 AI 务必注意）**：
1. **初始化不能用全屏随机噪声**：全屏 30% 格子 V=1 会导致全局 U 被大量消耗，U 降到极低后 V 失去来源，最终 V 衰减到 ~1e-7（图案消失）。**正确做法：中心区域（半径 min(W,H)*0.2）随机噪声，概率 0.5**，周围 U=1 可补充。受控实验证明中心种子 400 步后达到稳态（Vmax≈0.384，之后完全不变）。
2. **dt 不能用 1.0**：dt=1.0 时 U 在 V=1 区域一步内从 1 降到 0（`nu=1-1*1=0`），导致反应项 U*V²=0，V 衰减。dt=0.6 更稳定（U 降到 0.4 不会到 0）。
3. **渲染要拉伸对比度**：稳态 Vmax≈0.384，直接映射颜色只有 0.384*255≈98 索引（偏暗）。用 `v=min(1, v*2.4)` 拉伸后再 smoothstep，中等浓度更亮。
4. **无头截图有合成缓存假象**：bu.screenshot 可能截到旧的合成层（显示有图案但实际 canvas 是纯黑）。验证真实渲染必须用 `ctx.getImageData(x,y,1,1).data` 读像素，或用 `for` 循环读 V max（`reduce` 和 `Math.max(...V)` 在 bu.js 序列化时可能返回 None）。
5. **预设同步滑块时 output 位置**：slider 结构是 `div.row > div.lab > span+output, input`，output 不是 input 的 nextElementSibling。要用 `input.parentElement.querySelector("output")`。

### 4.4 菌丝世界（Physarum）
- 粒子释放信息素 → 信息素扩散衰减 → 粒子感知前方信息素浓度并转向。
- 多物种、多参数（感知距离、转向角、扩散率）。
- 连续痕迹场（Canvas2D 或 WebGL ping-pong）。
- 详见项目文件，此项目较早，技术细节可直接读 `菌丝世界.html` 源码。

## 五、浏览器自动化与测试经验

### 5.1 无头环境特性
- `computer_use_tool(plane="bu")` + `seed_browser_use as bu` 是唯一浏览器控制路径。
- **无头环境 rAF 被严重节流**（实测 2-17fps，真机 60fps），**不要以无头帧率判断性能**。
- CSS transition / animation 在无头环境可能不推进（页面被冻结），需要兜底（如遮罩的 setTimeout display:none）。
- Canvas/WebGL 页面操作后要留足够等待时间（`time.sleep`）让渲染和物理推进。

### 5.2 事件派发
- `bu.click(ref)` 在遮罩/遮挡时可能失效，改用 `bu.js("document.querySelector(selector).click()")`。
- 键盘事件用 `bu.js` 派发 `new KeyboardEvent(...)`，`bu.hotkey` 常因焦点被拒。
- 模拟鼠标绘画：用 `bu.js` 派发 `PointerEvent`（pointerdown/pointermove/pointerup），比 `bu.drag` 更可控。

### 5.3 验证清单（交付前必跑）
1. `grep` 零外部引用
2. 浏览器打开，读 `console_messages()` 确认无报错
3. 读 canvas 像素确认非纯黑（`ctx.getImageData`）
4. 核心交互各测一次（粒子生命=改矩阵、引力沙盒=拖拽放天体、反应扩散=画一笔）
5. 预设场景切换测试
6. file:// 协议下可运行（不依赖 localhost）

## 七、未来方向与点子（可继续探索）

按与已有项目的差异化程度排序：

### 高优先级（差异化大、对味用户偏好）
1. **Lenia 连续细胞自动机**：真正的数字人工生命，glider 生物会蠕动、生长、分裂。视觉偏学术但可美化，互动是绘制初始图案。注意：互动偏弱，需加强绘画交互。
2. **音频驱动生成艺术**：麦克风/音频输入驱动粒子/流体/反应扩散，声音即画笔。互动极强，视觉惊艳。需处理音频权限。
3. **WebGL Metaball 发光果冻球**：液态发光球融合分开，鼠标推/加球。和流体气质接近但机制不同（离散球标量场 vs 连续流体场）。pr0xy.dev 有成熟 raw WebGL 单文件实现。
4. **地形生成 + 流水侵蚀**：鼠标抬高地形，雨水侵蚀形成山脉河流。互动强，视觉惊艳。可参考 terrain-generation 开源项目。

### 中优先级（有重叠但可做差异化）
5. **Boids 大规模鸟群/鱼群**：群体智能，鼠标引导。和粒子生命有重叠（都是粒子群体），但机制不同（对齐/分离/聚合三规则 vs 吸引矩阵）。可做 3D 或加捕食者。
6. **DLA 晶体/闪电/分形树生长**：点击放种子，随机游走粒子粘住生长。视觉惊艳但偏静态（粘住后不动），互动中等。可加多种子竞争生长。
7. **多项目组合/杂交**：反应扩散 + 粒子生命（粒子在反应扩散场中运动）、引力沙盒 + 流体（天体在流体中）。差异化大，技术挑战高。

### 低优先级（重叠多或互动弱）
8. **3D 版本**：Three.js 做 3D 粒子生命/引力/反应扩散。但 Three.js 需内联（体积大），且用户偏好 2D 沉浸式。
9. **Wireworld / 电路元胞自动机**：画电路看信号传播。互动强（绘画式）但视觉不够惊艳。
10. **MIDI 控制器支持**：给已有项目加 MIDI 输入。属于增强而非新项目。

### 通用增强点子（可加到任何现有项目）
- 保存/加载自定义场景（localStorage 或导出 JSON）
- 自动演化模式（定时随机参数，坐着看文明漂移）
- 录屏/GIF 导出
- 双场景同屏对比/对战
- 笔刷压力/速度感应
-  undo/redo

## 八、工作流程建议（给接手的 AI）

1. **先读本文档**，理解用户偏好和已有项目，避重。
2. **找成熟开源**：GitHub / gist / personal site 找单文件实现，优先 MIT/无许可的公开 gist。下载到项目子目录（如 `project-name/upstream.html`），评估后改造。
3. **不要从零写算法**：物理/化学/生物模型都是公知的，直接用成熟实现的核心，重写交互和视觉。
4. **沿用统一架构**：玻璃 UI、开场遮罩、快捷键、状态读数、单文件内联——见第三节。
5. **充分测试**：无头环境实测，用 `ctx.getImageData` 验证真实渲染，测核心交互和预设切换，确认零 console 报错。
6. **写玩法说明**：每个项目配一个 `项目名-玩法说明.md`，包含操作、技巧、参数说明。
7. **交付**：`present_files` 交付 HTML + 玩法说明，最终回复简洁有感染力，给出上手建议。
