# 杀戮尖塔 2 · 特效坑清单（按症状查）

> 整理日期：2026-10-08
> **用法：出问题时按"症状"找，不要按 mod 找。**
> 来源：三个社区 mod 的拆解 + 我们自己踩的坑，全部有出处。
>
> 出处标记：
> `①` = 万象辉星 RegentFX · `②` = 动作与特效 MeleeAttack · `③` = More Ironclad Animations
> `斗` = 我们自己的斗地主尖塔 · `书` = 从游戏反编译/官方教程核实的

## 一、特效看不见 / 不显示

| # | 可能原因 | 怎么确认 | 修法 | 出处 |
|---|---|---|---|---|
| 1.1 | **位置口径搞错**（把"缩放比"当"屏幕宽"用） | 打印实际坐标，看是不是个位数 | 算出 `(0.5, 0.25)` 这种像素值就是错。见下方【详细案例】 | `斗` |
| 1.2 | **`VfxCmd` 传了完整 `res://` 路径** | 无报错、无特效、卡牌结算卡住 | 只传**内部路径**（`"vfx/vfx_attack_slash"`）。传全路径会变成 `res://scenes/res://…tscn.tscn`，**加载为空且不报错** | `书` |
| 1.3 | **挂到了错误的容器** | — | 世界层挂 `CombatVfxContainer`（ZIndex 0）；想垫在角色后面挂 `BackCombatVfxContainer`；**UI 层和世界层不能混** | `①` `书` |
| 1.4 | **场景里没有 `StartPos`** | 看日志有没有 `No StartPos found in VFX scene` | 指向性特效的场景必须放一个名为 `StartPos` 的空 `Node2D` | `①` |
| 1.5 | **翻转之后粒子飞反了** | 只有角色往左时异常 | 翻转前先把所有粒子的 `LocalCoords` 设成 `true`，翻转后 `Restart()` 重播 | `②` |
| 1.6 | **层级被角色挡住** | — | `BgContainer -20 < CombatVfxContainer 0 < NCreature 10`。想压住角色就调大 | `①` `②` |
| 1.7 | **本地缓存被本体的清理干掉** | 第一次有、第二次没了 → 见第二节 | — | `①` |

### 【详细案例】1.1 位置口径搞错（我们自己踩的）

```csharp
// ❌ 错：DouSpireUi.Screen 是「视口宽 ÷ 1920」的缩放倍率（≈1.0），不是屏幕宽
SpawnGameVfx(..., new Vector2(DouSpireUi.Screen * 0.5f, DouSpireUi.Screen * 0.25f), 2.2f);
// → 算出 (0.5, 0.25) 像素，特效被扔到牌桌左上角，看着就像"粒子没显示"

// ✅ 对：用真实视口尺寸
var vs = Size;
if (vs.X < 8f || vs.Y < 8f) vs = new Vector2(DouSpireUi.Px(1920f), DouSpireUi.Px(1080f));
SpawnGameVfx(..., new Vector2(vs.X * 0.5f, vs.Y * 0.44f), 2.2f);
```

**通用教训**：项目里凡是名字里带 `Screen` / `Scale` / `Factor` 的变量，
用之前**先打印一次它的实际值**。名字骗人。

## 二、第一次有特效，第二次就没了

| # | 原因 | 修法 |
|---|---|---|
| 2.1 | **`PreloadManager.Cache` 在换房间时 `UnloadAssets()`，把 mod 自己的资源一起清掉了** | 必须自建缓存：`ConcurrentDictionary<string, PackedScene>`，启动时填满，`GenVfx` 先查自己的 |
| 2.2 | 缓存键用了不同写法（有时 `res://`，有时内部路径） | 缓存键统一。注意 `SceneHelper.GetScenePath` = `"res://scenes/" + innerPath + ".tscn"` |
| 2.3 | 读盘失败被缓存成了 `null` | 只在成功时进缓存，失败每次重试（开发期补上文件就不用手动重启） |

出处：`①`（文档化的 `VFXUtil` 模式）、`③`（`LooseAsset.GetTexture` 的写法）

## 三、游戏卡住 / 卡牌结算卡死

**这是最严重的一类** —— 玩家看到的不是"特效没播"，是"游戏坏了"。

| # | 原因 | 修法 | 出处 |
|---|---|---|---|
| 3.1 | **特效代码抛异常，没人吞** | 所有表现层的 `await` 链条都包 `try/catch`。用 `PresentationFlow.SafelyAsync(visual)` | `③` |
| 3.2 | 特效逻辑和原逻辑**串行**跑，特效慢就拖着游戏 | `PresentationFlow.AlongsideAsync(visual, original, release)` —— 表现层并行起步、最后收尾 | `③` |
| 3.3 | 放行动作没写在 `finally` | 一定要 `finally { release(); }`，否则异常路径会把游戏锁死 | `③` |
| 3.4 | `VfxCmd` 路径错 → 加载空场景（**不报错**） | 见 1.2 | 书 |
| 3.5 | 用了 `Timer` 等"时间被冻住"的状态 | `Engine.TimeScale = 0` 时 Timer **也停**。hitstop 这类要用挂钟 `Time.GetTicksMsec()` + `ProcessFrame` 信号轮询 | `②` |

**通用做法**（`③` 的 `PresentationFlow`）：

```csharp
static async Task SafelyAsync(Func<Task> visual, Action<Exception>? failed = null)
{
    try { await visual(); }
    catch (Exception e) { failed?.Invoke(e); /* 只记日志，不往上抛 */ }
}
```

## 四、联机时串味

| # | 症状 | 原因 | 修法 | 出处 |
|---|---|---|---|---|
| 4.1 | **队友出牌，在我屏幕上播了我的特效** | 本体会把出牌动作**广播给所有机器**，每台都跑一遍 | 每个本地演出钩子先判 `LocalContext.IsMe(owner)`，不满足就 `return true`（走原逻辑） | `①` `②` 斗 |
| 4.2 | 队友出牌把我的本地状态改了 | 同上 | 用 `AsyncLocal<T>` 存"当前正在处理的攻击"，别用普通静态字段（联机是并发的） | `①` |
| 4.3 | 我的特效被同步机制判为不同步 | — | 纯表现 mod 在清单里写 `"affects_gameplay": false`，并**不新增网络消息** | `③` |

> ⚠️ **三个独立来源都踩到这个坑**（万象辉星、动作与特效、斗地主尖塔的 `RestSiteSynchronizer.ChooseLocalOption`）。
> 凡是"本地表现层"的钩子，**第一行就该是 `IsMe` 判断**。

## 五、角色/特效永久歪了、回不到原位

| # | 原因 | 修法 |
|---|---|---|
| 5.1 | 改了 `Position`/`Scale`/`Modulate`/`ZIndex` 但**没记原值** | 改动前备份。参考 `②` 的一组表：`_initialScales` / `_visualInitialScales` / `_originalColors` / `_originalZIndices` / `_blockIconInitialPositions` |
| 5.2 | 异常路径导致"还原"没执行 | 还原写 `finally`；并且加**兜底的强制还原**（战斗结束 / 回合结束 / 换房间） |
| 5.3 | 和本体的摆位**同时改位置**，互相打架（抖动） | 拿一个"位置锁"（`CancellationTokenSource`）先把控制权抢过来，`finally` 放掉 |
| 5.4 | 多段攻击时"回家"的位置越走越偏 | 锁定 `LockedHomePos` 一次，之后每段都回**同一个原点** |
| 5.5 | 异步流程累积超时，卡住不返回 | 加延时上限（如 `MaxTotalDelay = 3f`） |
| 5.6 | 异步返回流程没被取消，第二次攻击来了还在跑 | 每个 creature 一张 `CancellationTokenSource` 表，新流程来了先 `Cancel()` + `Dispose()` 旧的 |

出处：`②`（`AttackSequenceState` / `SimpleTeleportPatch`）

## 六、打包成 pck 之后加载不出来

| # | 原因 | 修法 | 出处 |
|---|---|---|---|
| 6.1 | **只把 `.png` 塞进了 pck** | 贴图在 pck 里是**两份**：`xxx.png.import`（~200B 文本，里面 `path=` 指向）+ `.godot/imported/xxx.png-<md5>.ctex`（真数据）。要么让 Godot 导出，要么手工造两份 | `①` |
| 6.2 | **场景被转成二进制 `.scn`，改不动** | Godot 导出设置里的 **"Convert Text Resources To Binary"** —— **自己打包时关掉** | `②` |
| 6.3 | **着色器 `#include` 了本体的 `_util`，编译失败** | 本体 `shaders/vfx/_util/*.gdshaderinc` 共 7 个。抄的时候**必须内联**（万象星辉就是这么干的，它的 pck 里一个 `gdshaderinc` 都没有） | `①` |
| 6.4 | 抽别人的 pck 看不到 C# 源码 | `Scripts/*.cs` 全是 **1 字节占位**（一个 `\n`），Godot 不导出 C# 源码。**必须反编译 dll** | `①` |
| 6.5 | 手动组包后启动崩 / 找不到文件 | 干脆**不用 pck**：散装文件 + `Assembly.Location` + `Image.LoadFromFile` | `③` |

### 免 pck 的完整做法（`③`）

```csharp
// 1) dll 就躺在 mod 目录里 → 定位自己
var dir = Path.GetDirectoryName(typeof(LooseAsset).Assembly.Location);

// 2) 直接从磁盘读，绕过 res:// 导入系统
Image img = Image.LoadFromFile(Path.Combine(dir, "vfx", "laser.png"));
var tex = ImageTexture.CreateFromImage(img);
img.Dispose();          // ★ Image 是 IDisposable
```

**取舍**：免 pck ⟹ 改一张 PNG 直接生效、不用装 Godot 编辑器；
代价是要自己写加载/缓存/优雅失败。

## 七、解包/分析别人 mod 时读到错数据

| # | 坑 | 正确做法 | 出处 |
|---|---|---|---|
| 7.1 | pck 条目 offset 直接用 → 读到上一个文件的尾巴 | 条目里的 offset 是**相对 `file_base`** 的。`file_base` = 头部**偏移 24** 处的 u32（本机 = 112）；真实位置 = `file_base + offset`。**目录偏移** = 头部**偏移 32** 处的 u64 | 书 + 实战 |
| 7.2 | 解析 `[ext_resource]` 时 id 全被认成 uid | `id="([^"]*)"` 会**先匹配到 `uid="uid://…"` 里的 `id=`**。必须写 `(?:^\|\s)id="…"` | 实战 |
| 7.3 | `strings` 命令不在 PATH | 用 `tools/scan-game-strings.py`（ASCII + UTF-16LE） | 书 |
| 7.4 | 抽出来的 `.cs` 全是 1 字节，以为解包器坏了 | 不是 bug，见 6.4 | ① |
| 7.5 | 二进制 `.scn` / `.gdc` / `.spatlas` 读不了 | `.scn` 能捞字符串表；`.spatlas`/`.atlas` 是**文本**；`.gdc` 是 GDScript 字节码 | ② |

## 八、观感"乏力"（不报错，但就是不好看）

**这一类才是"特效做得不够好"的真正原因**，而且都没有报错。

| # | 症状 | 原因 | 修法 | 出处 |
|---|---|---|---|---|
| 8.1 | 冲刺像"瞬移"，不像"冲" | **只有位移，没有形变** | 加 squash & stretch：X 轴按 `StretchFactor()` 拉峰值再回落（**只拉 X，Y 不变**）；位移用 `EasedProgress()` 分段缓动 | `②` |
| 8.2 | 打击"轻飘飘" | 没有打击停顿 | 命中瞬间 `Engine.TimeScale = 0` 冻 0.1~0.2s。⚠️ 加"一次攻击只顿一下"的闸，否则多段攻击连冻三下 | `②` |
| 8.3 | 特效"没打在身上" | 瞄的是 `GlobalPosition`（**脚底**） | 用 `Hitbox.GlobalPosition + Hitbox.Size * 0.5` —— 判定框中心 | `②` |
| 8.4 | 直线冲刺像"贴地滑行" | 走的直线 | 走抛物线弧：弧高 = 距离 × 0.3 | `②` |
| 8.5 | 特效"贴"在角色上、不跟场景 | 场景按"目标在原点、起点在 StartPos"画，靠 `FitVfx` 拉伸对准 | 见手册 §八 的 `StartPos` 约定 + 数学验算 | `①` |
| 8.6 | 辉光叠了一堆还是不亮 | alpha 直接用高斯权重 | 用 **`1 - exp(-strength × w)`** 让中心饱和到 1，边缘快速衰减 | `③` |
| 8.7 | 颜色/参数全靠改代码 | 效果写死在 `if/else` 里 | 做成**声明式 JSON 方案**（几滴血、走哪条线、什么时候出发都是数据）。3 条血流 vs 2 条 = 数据差异，不是代码分支 | `③` |

## 九、卡顿 / 掉帧

| # | 原因 | 修法 | 出处 |
|---|---|---|---|
| 9.1 | 辉光每层副本建一个 `Sprite2D` | 用 **`MultiMeshInstance2D`** 一次 draw call 画完所有副本 | `③` |
| 9.2 | 每帧重建顶点/索引缓冲 | 复用缓冲，只更新变化的区域（`SurfaceUpdateVertexRegion`） | `③` |
| 9.3 | 相邻、同贴图同变换的图形各画一次 | 合并成一个提交 | `③` |
| 9.4 | 每次播特效都读盘 | 加缓存（但**失败不要缓存**） | `③` |
| 9.5 | 每次都用 `ResourceLoader.Load` 而不是用缓存 | `①` 的 `ModSceneCache` 模式 | `①` |
| 9.6 | 预热不按需，白白占内存 | 只在"该角色/单机"时才预热，用**代际号 + CancellationToken** 支持中途取消 | `③` |

## 十、着色器相关

| # | 坑 | 说明 |
|---|---|---|
| 10.1 | 本体着色器抄过来编译失败 | 见 6.3：`#include "res://shaders/vfx/_util/*.gdshaderinc"`，必须内联 |
| 10.2 | 为了做屏幕扭曲去动 `WorldEnvironment` | 更轻的做法：着色器里用 `uniform sampler2D screen_texture : hint_screen_texture`，**直接读屏幕** |
| 10.3 | 着色器要落成 `.gdshader` 文件 | 可以**写成 C# 字符串**：`new Shader { Code = "shader_type canvas_item; …" }`，改 GLSL 直接生效 |
| 10.4 | 全屏闪白用完了不弹回来 | 用 `try/finally` 保证弹回 `1f`；并且**要给玩家关掉的开关**（光敏感） |
| 10.5 | 材质 `.tres` 指向另一个 `.tres` 看晕 | 本体确实有这种"再套一层材质"的情况，看 `材质 → 材质 → shader` 三层 | `书` |

## 十一、十条最容易记住的（如果只记十条）

1. **本地表现层钩子第一行判 `LocalContext.IsMe(owner)`** —— 三个来源都踩过。
2. **表现层的异常全部吞掉**，否则卡死卡牌结算。
3. **`VfxCmd` 只吃内部路径**，传 `res://` 会静默加载空场景。
4. **`PreloadManager.Cache` 换房间会清 mod 资源** → 自己缓存。
5. **改了属性就要备份 + `finally` 还原 + 兜底强制还原。**
6. **`Engine.TimeScale = 0` 时 Timer 也停** → 用挂钟计时。
7. **翻转特效前先给粒子设 `LocalCoords = true`**，否则粒子飞反。
8. **只有位移没有形变 = 瞬移**；打击没有停顿 = 轻飘飘。
9. **瞄目标用 `Hitbox` 中心，不是 `GlobalPosition`（脚底）。**
10. **抄本体着色器必须把 `_util` 的 `#include` 内联。**

## 十二、出问题时的诊断顺序

```
1. 看日志有没有报错                    → 有 → 按报错查（多为资源路径 / 可选依赖）
2. 没有报错但什么都看不到              → 查 1.2 (VfxCmd 路径) / 1.1 (位置口径)
3. 第一次有第二次没有                  → 第二节（缓存被清）
4. 游戏卡住/结算卡死                    → 第三节（异常没吞 / Timer 停 / 空场景）
5. 能播但"不好看"                      → 第八节（打击感六件套）
6. 联机才出问题                        → 第四节（IsMe）
7. 打包后才出问题                      → 第六节（.import/.ctex / .scn / gdshaderinc）
8. 一放就掉帧                          → 第九节（MultiMesh / 缓冲复用 / 缓存）
```
