## 二、核心方法论收获

### 1. 开源项目改造工作流（已固化为全局偏好）
> **做创意/交互/可视化类项目时，优先去 GitHub 寻找成熟的开源项目作为基础，在其基础上修改定制，不要从零开始造轮子。**

```
选定方向 → GitHub 搜索 → jsDelivr CDN 下载（直连常被墙）
→ 分析源码结构（定位入口、DOM 依赖、外部资源）
→ 最小化测试页面验证核心功能
→ 深度美化（UI、氛围、交互增强）
→ 浏览器验证 + bug 修复
```

### 2. WebGL/混淆代码调试方法论
- **最小化排除法**：先创建只含必要 DOM 的最小页面，排除 CSS/JS 干扰
- **全局错误捕获**：`window.onerror` 写 document.title，即使 console 被缓冲也能看到错误
- **关键定位点**：在混淆 JS 中，`getElementById`、着色器源码字符串、`getContext("webgl2")` 是定位入口的锚点
- **静默失败排查**：画布全透明 + 无报错 = 大概率是外部资源（纹理/图片）加载失败，检查 `new Image().src` 引用的文件

### 3. 3D 场景常见 bug 清单
- 相机 lookAt 平滑逻辑可能导致正反馈发散 → 直接 lookAt，不做复杂平滑
- 天空/背景球体必须跟随相机/主体移动 → 每帧更新位置
- 地形顶点位移幅度要控制，轨道附近必须平坦
- 相机高度要足够低才能看到脚下的轨道/地面

### 用户喜欢的调性（从极光流体参考中提炼）
- **沉浸式**：全屏、无多余 UI、主体即内容

## 四、工具与环境收获

| 问题 | 解决方案 |
|------|----------|
| GitHub 直连 Connection reset | jsDelivr CDN：`https://cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/` |
| PowerShell 不支持 `&&` | 用 `;` 分隔，或 `Set-Location` 后单独执行 |
| PowerShell 中 curl 是别名 | 用 `curl.exe` 强制使用真正的 curl |
| file:// 下 ES module CORS | 启动本地 HTTP 服务器：`python -m http.server` |
| canvas 被背景层遮挡 | 检查 z-index，canvas 必须高于背景层 |
| Haxe 编译 JS 无法直接修改逻辑 | 保留 main.js 原样，通过自定义 HTML/CSS/JS 包裹和增强 |
