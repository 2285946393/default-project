## 三点八、文件放哪：**一个主题 = 一个主目录**（2026-10-16 用户要求）

> 用户原话：「**可以加个全局告诉放文件的地方。嗯。。work 和现在的工作区也有点散乱，
> 说实话我不知道该去哪里找文件**」

### 病根

同一个主题的文件被散在**多个地方**（会话工作区、`notes`、`D:\work\AI产出`、下载目录），
**用户自己找不到东西**。

**2026-10-16 的 NAI 画图就是活例子**：同一个主题的文件散在
`dsh_orb`（47 个）、`notes`（41 个）、`D:\work\AI产出` 三处。

### 规矩

**新产出先问自己"这属于哪个主题"，然后放进那个主题的主目录 —— 不要随手丢在会话工作区。**

### 已建立的主目录（照这个模式扩）

| 主题 | 主目录 | 入口文件 |
|---|---|---|
| **NAI 画图**（出图 / 提示词 / 反推 / 配方） | **`D:\work\AI产出\NAI画图\`** | **先看里面的 `00-README-先看这个.md`** |
| 其他 AI 产出 | `D:\work\AI产出\<主题>\` | 沿用同样的编号结构 |

**NAI画图 的子结构**（可复用）：
```
01-反推/     资料、数据、工具
02-配方手册/  主力文档
03-参考图/    素材图
04-脚本/      可执行脚本
99-归档/      已合并 / 重复 / 临时（可整个删）
00-README-先看这个.md   ← 文件地图
```

### 三条硬规矩

1. **会话工作区（如 `dsh_orb`）不是仓库** —— 它是 agent 临时干活的地方，
   **产出必须落到主目录**，别让用户去工作区翻。
2. **`notes` 只放"给用户读的笔记 + 索引"**，不放大量产出（否则又会散）。
   某个主题搬走后，`notes` 里留**一份索引**指向主目录。
3. **搬家 / 归档之前先写 README**（文件地图），让用户一眼知道去哪找。
   搬完在原位置留索引。

### 各常见位置的定位（判断"这东西该放哪"）

| 位置 | 该放什么 |
|---|---|
| **`D:\work\AI产出\<主题>\`** | ✅ **agent 的产出物（默认放这）** |
| `C:\Users\有花无实\Documents\Default Project\` | 用户的**作品仓库**（pages / assets / notes / projects） |
| `D:\software\<软件名>\` | **软件本体**（不是产出） |
| `D:\BaiduNetdiskDownload\` | **网页下载的临时文件**（出图下载落这） |
| 会话工作区（`dsh_orb` 等） | ⚠️ **临时**，不要长期堆产出 |

### ⚠️ 会话工作区可能不是用户想要的（2026-10-16 发现）

**DSH 按工作区分目录存会话**（`D:\software\dsh-home\sessions\--<转义后路径>--/`），
新建会话时**归属"侧边栏当前选中的工作区"**。

**用户的习惯工作区是 `C:\Users\有花无实\Documents\Default Project`（他叫它 dp）** ——
那里有 **58 个**会话。但 2026-10-16 发现有 **13 个会话开在了
`D:\software\dsh-home\dsh_orb`**（一个 orb 项目的遗留工作区），包括当时正在进行的会话。

**⇒ 两个后果：**

1. **agent 的产出容易堆在会话工作区**（而不是主目录）—— 这正是当年文件散乱的原因。
   **解法见上面的三条硬规矩：产出一律落到 `D:\work\AI产出\<主题>\`。**
2. **用户会困惑**「为什么我的对话不在这里 / 为什么文件散得到处都是」。

**⇒ 用户的操作**：在侧边栏**点一下 `Default Project` 分组**（选中它）→ 再点「新建会话」，
新会话才会落在 dp 里。**新建后可以看它在哪个分组下面验证。**

**⇒ agent 的判断**：如果发现当前工作区不是 dp、而任务产出需要长期保存，
**直接落到主目录**（`D:\work\AI产出\<主题>\`），必要时提醒用户一句。
