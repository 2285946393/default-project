# 接下来任务清单 · 2026-09-22

> 目标：30 天内，把“我做过很多作品但不知道核心竞争力是什么”变成一套清晰、可展示、可验证的求职能力。
>
> 暂定定位：AI 辅助的开源项目改造与产品化开发。

---

## 一、当前阶段的三个结论

- [ ] 我最强的能力不是从零造底层轮子，而是理解已有项目、修复问题、改造交互、完成视觉和产品化。
- [ ] 我现在要补的不是再学一个框架，而是独立发现问题、判断项目潜力、提出改造方向。
- [ ] 未来 30 天不以新增项目数量为成功标准，而以能否证明判断和改造价值为标准。

## 二、第 1—3 天：收拢定位

### 1. 确定求职方向

- [ ] 主方向定为：AI 应用开发 / 创意前端 / 全栈前端。
- [ ] 不再把自己包装成“从零实现各种底层算法的人”。
- [ ] 统一表述：我擅长借助 AI 快速理解成熟开源项目，并将其改造成完整、可用、有风格的产品。
- [ ] 准备三版一句话介绍：AI 应用版、创意前端版、全栈前端版。

### 2. 选三个旗舰项目

- [ ] 旗舰一：ai-interviewer。
- [ ] 旗舰二：creator-studio 或 ai-gateway，只选一个做主展示。
- [ ] 旗舰三：从极光流体、粒子生命、深渊塔中选一个。
- [ ] 其他项目统一归入实验作品库，不再平均占用首页注意力。
- [ ] 每个旗舰项目确认源码、演示、README、截图、许可证、面试追问卡都齐全。

### 3. 做一次删减

- [ ] 删除或隐藏重复、弱、只有换皮、没有玩法的项目。
- [ ] 分成旗舰项目、实验作品、历史练习三类。
- [ ] 作品集首页重点展示不超过 6—8 个项目。
- [ ] 检查在线链接、手机宽度、控制台报错和加载失败。

## 三、第 4—7 天：说清楚“我做了什么”

为三个旗舰项目各写一页说明，每个项目回答：

- [ ] 原项目或基础来源是什么？许可证是什么？
- [ ] 为什么选它，而不是自己从零写？
- [ ] 原项目能做什么？最大问题是什么？
- [ ] 我删掉了什么？新增或重写了什么？
- [ ] 最难定位的 Bug 是什么？怎么定位？
- [ ] 哪个性能、兼容性或工程问题被解决了？
- [ ] AI 帮了什么？我自己做了哪些判断？
- [ ] 改造前后，用户体验有什么具体变化？
- [ ] 这个项目还有什么真实局限？
- [ ] 面试官最可能追问的三个点是什么？

写作规则：

- [ ] 不写“完全从零开发”。
- [ ] 不把 API 调用写成训练模型。
- [ ] 不把模板改色写成原创设计系统。
- [ ] 统一使用“问题 → 判断 → 改造 → 结果”。
- [ ] 明确标出开源基础和个人贡献边界。

## 四、第 8—21 天：训练独立发现力

### 每周评估 5 个候选项目

- [ ] 第一轮不让 AI 直接推荐项目。
- [ ] 自己从 GitHub Trending、作者主页、技术关键词和社区找候选。
- [ ] 每个候选回答：它解决了什么问题、用户为什么会再次打开、最明显的缺点是什么。
- [ ] 判断两天内能改出什么明显差异。
- [ ] 判断它适合做工具、游戏、视觉作品还是 AI 产品。
- [ ] 检查许可证是否允许改造和展示。
- [ ] 写下我预测用户会喜欢还是无聊，以及理由。
- [ ] 每周只选 1 个做最小改造。
- [ ] 改造前写预测，改造后记录真实反馈。
- [ ] 每周统计预测正确和错误的地方。

### 候选项目打分

每项 1—5 分，低于 18 分不做：

- [ ] 交互潜力：用户操作能否改变结果？
- [ ] 产品潜力：能否形成明确用途或玩法？
- [ ] 改造空间：两天内能否做出明显差异？
- [ ] 视觉潜力：是否有清晰的氛围和展示价值？
- [ ] 工程价值：能否体现调试、性能、数据或架构能力？
- [ ] 复玩或复用价值：用户是否有理由再次打开？

### 明确禁止

- [ ] 不做只是换颜色的项目。
- [ ] 不做已有作品的重复版本。
- [ ] 不做只能截图、不能互动的展示页。
- [ ] 不因为技术名词高级就立项。
- [ ] 不在没有用户反馈前连续扩展功能。

## 五、第 15—24 天：加入真正属于你的产品层

从已有项目中选一个，加入原项目没有的完整产品体验：

- [ ] 粒子生命：世界种子、保存、分享、关系变化记录、作品导出。
- [ ] 反应扩散：绘画创作、参数实验、作品保存、随机挑战、PNG 导出。
- [ ] AI 面试官：岗位知识库、面试历史、复盘报告、针对性训练建议。
- [ ] 创作中台：作品扫描、标签生成、技术栈统计、发布流程。
- [ ] AI 网关：模型对比、成本估算、故障切换、调用日志分析。

交付标准：

- [ ] 有明确目标用户。
- [ ] 有从进入到完成的完整流程。
- [ ] 有加载、空状态和错误状态。
- [ ] 有保存、分享或复用结果。
- [ ] 有移动端基本适配。
- [ ] 有“原项目 vs 我的产品层”对比说明。
- [ ] 有真实测试记录，而不是只确认页面能打开。

## 六、第 22—30 天：开始求职执行

### 材料

- [ ] AI 应用版简历只放最相关的 3—4 个项目。
- [ ] 创意前端版简历突出交互、视觉、性能和完成度。
- [ ] 每个旗舰 README 第一屏能在 30 秒内看懂。
- [ ] GitHub 置顶顺序明确：AI 应用 → 产品工程 → 创意交互。
- [ ] 所有项目来源和许可证信息可追溯。
- [ ] 所有项目准备 AI 参与边界说明。

### 投递

- [ ] 每天投递 3—5 个匹配岗位。
- [ ] 记录公司、职位、方向、截止时间、简历版本、投递日期、状态。
- [ ] 优先投 AI 应用开发、AI 前端、创意前端、全栈前端、互动体验开发。
- [ ] 暂时不把大量时间花在纯底层算法岗或纯视觉设计岗。

### 面试反馈

- [ ] 每次面试后记录面试官问得最多的三个问题。
- [ ] 标记问题属于真实性、技术深度、工程能力、产品判断还是职业方向。
- [ ] 每周只修复排名最高的两个薄弱点。
- [ ] 连续三次被问同一个问题，就补 README、面试卡或项目实现。

## 七、每周复盘模板

每周日回答：

- [ ] 这周我独立发现了什么？
- [ ] 哪个判断被事实证明是错的？
- [ ] 哪个项目看起来很酷，但实际没有用户价值？
- [ ] 哪个普通项目通过改造变得有价值？
- [ ] 我新增的能力是什么？
- [ ] 哪个项目可以停止继续打磨？
- [ ] 下周唯一最重要的任务是什么？

把“我没天赋”“我什么都会一点”“我是不是该学新技术”改写成可验证的问题：

- [ ] 我这周有几次独立选题？
- [ ] 用户喜好预测命中了几次？
- [ ] 面试官在哪个项目上愿意继续追问？
- [ ] 哪项能力在三个项目中重复出现？

## 八、30 天后的验收标准

- [ ] 我能在 3 分钟内说清自己的定位。
- [ ] 我能诚实说明每个项目的开源基础和个人贡献。
- [ ] 我能独立筛选项目，而不是完全依赖 AI 推荐。
- [ ] 我能解释为什么一个项目值得改、另一个不值得改。
- [ ] 我完成了至少一个有明确产品层的新改造。
- [ ] 我获得了真实投递或面试反馈。
- [ ] 我知道下一阶段要补的具体能力。

最终要形成的证据链：

发现问题 → 判断潜力 → 选择基础 → 借助 AI 加速 → 完成改造 → 验证体验 → 交付产品

## 九、今天只做三件事

- [ ] 勾选已经完成的项目。
- [ ] 确定三个旗舰项目和一个主要求职方向。
- [ ] 不做新项目，先完成第一个旗舰项目的“原项目 vs 我的改造”说明。

> 你现在不需要立刻找到终身方向，只需要连续 30 天用行动验证：自己究竟擅长发现、改造、产品化，还是其中某一个更具体的环节。
