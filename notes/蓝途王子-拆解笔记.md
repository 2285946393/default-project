# 蓝途王子（Blue Prince）拆解笔记 — 2026-10-10

> 拆完即删游戏本体（4GB）。本文只记录**观察到的架构与设计**，不含任何游戏文件。
> 拆解对象：`D:\BaiduNetdiskDownload\game\Blue Prince`（游侠网绿色版，Build 25386781）
> 拆解方式：只读本地文件 + IL2CPP 元数据字符串提取，**没有分发任何内容**。

---

## 一、先说结论：这游戏是怎么搭的

**一句话**：Unity + **PlayMaker 可视化状态机** + 数据驱动的"房间牌堆"系统。

最反直觉的一点：**它的核心逻辑大部分不在 C# 里，而在 PlayMaker 的 FSM（有限状态机）里**。
所以就算你把 C# 全反编译出来，也看不到多少游戏逻辑——逻辑是状态机图 + 数据配的。
这是一个很聪明的做法：**把内容层（谜题、房间效果）从代码层剥离**。

## 三、房间系统（核心）

这是整个游戏最值得学的地方。扒出来的类/字段：

```
RoomDatabase        _roomDictionary      ← 房间全库
RoomCard            RoomType            ← 房间卡片 / 类型
RoomRarities                            ← 稀有度分级
RoomDeck  RoomDeckEntry  RoomDeckEntryCollection
RoomDeckMixer                           ← 牌堆混合器
RoomDraftContext                        ← 抽选上下文
PickRoomFromCurrentSlot / PickRoomFromSlot
RefreshRooms
RoomEngine / RoomEngine1 / RoomEngine2
"Room rarity"  "Room filter"  "Room ID: {0}"
```

**读出来的设计**：

1. 房间被做成**卡牌**（`RoomCard`），有**稀有度**（`RoomRarities`）
2. 进的不是"随机生成地图"，而是**抽牌堆**（`RoomDeck` + `RoomDeckMixer`）——标准的 roguelike 牌堆机制
3. `PickRoomFromSlot`：某个格子（槽位）给你几张牌，**你从里面选一张**——这就是核心玩法
4. `RoomDeckMixer` 说明牌堆是会**按条件重新混合**的（受永久升级、道具、日期影响）
5. 有 `Room filter` → 可以对牌堆做过滤（比如"只要某种类型的房间"）

**为什么这是好设计**：把"地图生成"换成"抽卡选牌"，玩家每一步都有决策感，同时作者能通过调稀有度和过滤器精确控制难度曲线。

## 五、永久升级系统（局外成长）

扒出来的 `Upgrade_Disk_*_found` 标记（至少 **11 个**）：

```
MasterBedroom   MorningRoom   Foundation   Cloister
Mechanarium     Freezer       TorchRoom    TradingPost
LostFound       GreatHall     Garage
```

→ **"升级磁盘"分散在各个房间里**，找到就是永久解锁。这是典型的 meta  progression：
每天庄园重置（除永久升级外一切消失），但磁盘是跨局保留的。

**设计要点**：永久升级不是数值加成，而是**"往牌池里加新房间 / 加新机制"**（配合上面的 `RoomDeckMixer`）。所以越玩后面抽到的牌越丰富——这是它"越玩越爽"的原因。

## 七、统计与反馈

```
"Rooms: Best draft rate"    "Rooms: Worst draft rate"
"Rooms: Most drafts"        "Rooms: Most time spent"
"Average rooms drafted:"    "Average rank:"
"Selected Day: {0}"         "STEPS: {0}"
```

它在**统计玩家自己的表现**（抽牌成功率、平均每天抽多少房间），并用这些数据做结算反馈。
roguelike 的标准做法，但值得记：**给玩家看自己的数据，会显著提升留存**。

## 八、对我有什么用（可迁移的点）

1. **内容层与代码层分离** — 用可视化状态机 / 数据配置承载游戏内容，C# 只写通用系统。改内容不用改代码。
   → 和我在尖塔 2 mod 里"把玩法定在配置里"的思路一致，它做得更彻底。
2. **牌堆 + 稀有度 + 过滤器** — 比"纯随机生成"可控得多，且玩家有决策感。
3. **局外成长 = 扩充牌池，而非加数值** — 让后续局数"内容更多"而不是"数字更大"，体验曲线更好。
4. **给玩家看自己的统计** — 低成本高回报的留存设计。
5. **后处理当玩法用** — 夜视/热成像不是特效，是解谜工具。

## 九、拆解方法（可复现）

游戏是 **IL2CPP**（`GameAssembly.dll` 是原生 `MZ` 头，不是托管 dll），所以 dnSpy 那套直接反编译 C# **行不通**。

能做的低成本操作：

```
1. 定位元数据：BLUE PRINCE_Data/il2cpp_data/Metadata/global-metadata.dat（13.7MB）
2. 直接正则提取明文 ASCII 串（长度≥6），零依赖：
     re.findall(rb'[ -~]{6,}', open(path,'rb').read())
   → 得到 132,351 条，去重 118,370 条。类名、方法名、游戏内文本全在里面。
3. 想要完整方法签名/类结构 → 上 Il2CppDumper（需下载）配合 IDA/Ghidra
```

⚠️ **IL2CPP 只能拿到"骨架"（名字和字符串），拿不到可读的逻辑代码**。
想看算法得啃汇编——性价比很低。对这款游戏来说，**字符串 + 类名已经能把设计意图看明白 80%**。

# 十一、深度拆解：Il2CppDumper 类结构（第二层）

> 第一节那个"提取字符串"只是零成本的开胃菜。用 **Il2CppDumper v6.7.46** 能拿到
> **完整类结构**——本次共导出 **9673 个类**，26MB 的 `dump.cs`。

## 能拿到什么 / 拿不到什么

| | 有没有 |
|---|---|
| 类名、字段、属性、**方法签名** | ✅ 全有 |
| 类之间的引用关系、字段偏移量 | ✅ 有 |
| 用 dnSpy 打开 `DummyDll/` 浏览结构 | ✅ 可以 |
| **方法体（真正的算法代码）** | ❌ 空的 |

IL2CPP 把方法实现编译成了原生机器码（`GameAssembly.dll`），所以 dump 出来只有签名。
想看实现得再往下走一层（见本节末尾）。

## RoomDatabase：房间全库

```csharp
public class RoomDatabase {
    public List<RoomTemplate> Rooms;
    private Dictionary<GameObject, RoomTemplate> _roomDictionary;
    public Dictionary<int, List<RoomTemplate>> RoomRarities;   // 稀有度 → 房间列表

    public void AddRoom(RoomTemplate template);
    public RoomTemplate GetRoom(GameObject o);
    public RoomTemplate GetRoomByName(string name);
}
```

`RoomRarities` 是 `int → List<RoomTemplate>`：**稀有度是整数分级，每个等级挂着一批房间**。

## RoomDeck：教科书级牌堆实现 ⭐

```csharp
public class RoomDeck {
    public List<RoomCard> Cards;        // 全部牌
    private List<RoomCard> _usedCards;  // 已用过的
    private List<RoomCard> FilteredDeck;// 过滤后的
    private List<RoomCard> _tempUnfiltered;
    public int CurrentPick;

    // 三层"空"的判断——设计得很细
    public bool IsEmpty { get; }        // 全空
    public bool IsFilterEmpty { get; }  // 过滤后没牌了
    public bool IsDepleted { get; }     // 抽干了

    public void Shuffle();
    public void FilterDeck(List<RoomTemplate>[] avoid);
    public void AddFilter(List<RoomTemplate> avoid, bool currentStage = False);
    public void AddCustomFilter(CardFilterDelegate filter);   // 可插拔过滤器
    public void ResetFilters();
    public RoomCard PickTop();
    public RoomCard PickTop(bool reshuffle);                  // 抽完可重洗
    public RoomCard PickFirst();
    public void RemoveAndAddOnTop(RoomCard card);             // 抽走再放回顶
    public void RemoveAndAddOnIndex(RoomCard card, int index);// 插回指定位置
}
```

**值得抄的细节**：

1. **`IsEmpty / IsFilterEmpty / IsDepleted` 三个状态分开** —— 说明"过滤后没牌"和"牌堆抽干"是**不同事件**，要分别处理（前者放宽过滤，后者重洗）。很多人写牌堆只写一个 `IsEmpty`，这里处理得更细。
2. **`AddCustomFilter(CardFilterDelegate)` 用委托** —— 过滤器是可插拔的。游戏里"图书馆"房间能改牌堆，就是往里塞了个自定义过滤器。
3. **`RemoveAndAddOnTop / RemoveAndAddOnIndex`** —— 抽走的牌能**精确插回指定位置**。这是控制节奏的利器：想让玩家再遇到某张牌，直接插到下一次会抽到的位置。

## RoomDeckMixer：三种洗牌策略

```csharp
public class RoomDeckMixer {
    public static void ShuffleDecksByWeightPrefilter(RoomDeck startDeck, RoomDeckEntryCollection filterDecks);
    public static void ShuffleDecksByWeight(RoomDeck startDeck, RoomDeckEntryCollection filterDecks);
    public static void ShuffleDeckByRarity(RoomDeck deck, float[] probs);
}
```

三种策略：**按权重预过滤洗 / 按权重洗 / 按稀有度洗（传概率表）**。
不是一招 `Shuffle()` 走天下，而是分场景调不同的混合算法。

## RoomDraftContext：抽选的总控（信息量最大）⭐⭐

```csharp

    // 8 套预置分布序列
    private static int[] Distribution_CommonSequence;
    private static int[] Distribution_CommonGemSequence;
    private static int[] Distribution_RareSequence;
    private static int[] Distribution_RareGemSequence;
    private static int[] Distribution_Even;
    private static int[] Distribution_Two_Three;
    private static int[] Distribution_Free;
    private static int[] Distribution_Gem;

    // 四个牌堆
    public RoomDatabase Database;
    public RoomDeck Commons;
    public RoomDeck CommonsGems;
    public RoomDeck Rare;
    public RoomDeck RareGems;

    private Dictionary<RoomTemplate, int> _maxCounts;    // 每种房间上限

    public List<RoomDeck> Rooms_NoGems;
    public List<RoomDeck> Rooms_Gems;
    public List<DraftSlot> Slots;
    private DraftSlotSettings _currentSlotProbs;
    private int _currentRank;
    private DraftRankRarity _runbackTable;

    // 三个可插拔过滤器 + 一个检查器
    private CardFilterDelegate _boolsFilter;
    private CardFilterDelegate _libraryFilter;   // ← 图书馆的过滤器
    private CardFilterDelegate _ignoreFilter;
    private CheckFilterDelegate _libraryCheck;
    private DraftRankRarity _libraryRarityOverride;

    private int[][] _rarityPriority;             // 稀有度优先级表（二维）
    private int[][] _rarityPriority_Library;
    private int[] _cardsLeftByRarity_free;       // 各稀有度剩余牌数

```

**读出来的设计**：

1. **四个牌堆分治**：普通 / 普通宝石 / 稀有 / 稀有宝石。不是一锅乱炖。
2. **8 套分布序列**：均匀、2-3、免费、宝石……按场景切换"出牌节奏"。
3. **`_maxCounts` 上限控制** —— 防止某房间刷屏，这是 roguelike 体验的关键。
4. **`_roomCounts` 计数** —— 配合上限做"见过几次"的控制。
5. **`RedraftCount`** —— 重抽是**一等公民**，游戏里明确有"重抽"这个动作。
6. **`PulledPlans`（List<RoomDraftRound>）** —— 抽牌历史完整保存，可以回溯/复盘。
7. **`_libraryFilter` + `_libraryRarityOverride`** —— 图书馆房间能**覆盖稀有度规则**，这就是那张房间的特殊能力。
8. **`_rarityPriority` 是二维数组** —— 不同情境下稀有度优先级不同，不是固定权重表。

## 统计系统（RoomStats）实锤

```csharp
public class RoomStats {
    public List<RoomStatsEntry> Rooms;
    public List<RoomStatsEntry> Rank_MostDrafted;      // 抽得最多
    public List<RoomStatsEntry> Rank_BestDraftRate;    // 最佳抽取率
    public List<RoomStatsEntry> Rank_WorstDraftRate;   // 最差抽取率
    public List<RoomStatsEntry> Rank_MostGemsSpent;    // 花宝石最多
    public List<RoomStatsEntry> Rank_MostTimeSpent;    // 待得最久

    public void RoomDrafted(int id, int gems = 0);
    public void RoomDiscarded(int id);
    public void AddTime(int id, int time);
    public void GenerateRankings();
}

public class RoomStatsEntry {
    private RoomID id;
    private int built;      // 建造次数
    private int discarded;  // 丢弃次数
    private int gems;       // 花的宝石
    private int time;       // 停留时间
}
```

**每个房间单独记 4 项数据，生成 5 个排行榜**。
这是第八节猜的"给玩家看统计"的完整实现——**按房间维度**，不是笼统的总数。
玩家能看到"我最爱抽哪个房间""哪个房间我最亏"，代入感极强。

# 十三、Cpp2IL 走不通（记录，别再踩）

想看**方法体**（真正的算法代码）试了 Cpp2IL，结论：**这条路对 2025 年后的 Unity 游戏不通**。

```
[Info] Determined game's unity version to be 2021.3.45
[Fail] LibCpp2ILInitializationException:
       Unsupported metadata version found! We support 24-29, got 31
```

- Cpp2IL 最后一个 release 是 **2022.0.7**（2022-09），支持 metadata **v24–29**
- 本游戏是 **v31**（2025 年出的 Unity 版本）
- 新版只在 GitHub Actions 的 nightly 里，要登录才能下，且同样未必支持 v31

**另外记两个参数坑**（2022.0.7 版）：
- 没有 `--output-to` 参数（输出目录不可指定）
- `--force-binary-path` + `--force-metadata-path` 单独用会报 `Invalid force option configuration`，
  必须配合 `--force-unity-version` 一起给

**结论**：对 IL2CPP 游戏，**Il2CppDumper 那一层（类结构）就是性价比天花板**。
再往下的算法代码要啃 IDA/Ghidra 汇编，投入产出比很低。
