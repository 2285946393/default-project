## 一、用户原话

> 「那本来的卡是不是没什么用？要不要直接把自己卡组全部删掉换成我们凛冬前线的卡组？
>   但是难度也得和凛冬前线对齐。」

拆成三问：
1. 原版卡是不是没用？
2. 要不要把整副卡组换成凛冬卡组？
3. 难度要跟着对齐。

---

## 二、先回答问题 1：原版卡**不是没用，是作用不同**

| | 原版 Strike | 我们的牌 |
|---|---|---|
| 时间尺度 | **即时**：1 费 6 伤，当场打死一只怪 | **投资**：箭塔 4 伤/回合、篝火 2 回血/回合，要 2~3 回合才回本 |
| 16 波连打 | 每轮就 6 点，不会变强 | **复利**：建筑每回合自动输出，越铺越强 |

⇒ 结论：**短期原版更强，长期我们更强。** 原版卡是"起手不崩"的保险。

★ 但更关键的是**当时的卡池根本支撑不起纯凛冬卡组**：
在 M3.8 之前，我们 14 张卡里**只有 1 张攻击牌**（暴风雪，2 费 AOE 8），
其余全是"部署建筑 / 控制 / 回血"——**没有任何一张便宜的即时直伤**。
⇒ 那时候把卡组换成纯凛冬牌，**第 1 波都过不去**。

**所以答案不是"换不换"，而是"先补课再换"。** 本轮补了《凛冬前线》五大类里缺的
**「攻击」与「防御」**两类，卡组才成立。

## 三、★ 顺手挖出一个真 bug：民兵的「每回合自动攻击」是假的

`MilitiaM` 原来覆写了 `GenerateMoveStateMachine()`：
```csharp
var attack = new MoveState("FROST_MILITIA_ATTACK", AttackMove, new SingleAttackIntent(5));
attack.FollowUpState = attack;
...
private static Task AttackMove(IReadOnlyList<Creature> targets) => Task.CompletedTask;   // ← 空的
```
`SingleAttackIntent(5)` **只负责在怪头上画一个"5 点伤害"的意图图标**，
真正的伤害要 `AttackMove` 自己打 —— 而它是 `Task.CompletedTask`。
⇒ **卡面写着"每回合自动攻击"，实际每回合打 0 点。** 玩家看不出来（图标在闪）。

### ★★ 为什么不能简单补上 `FromMonster`（这是坑，千万别写）

反编译 `AttackCommand.GetTargets()`：
```csharp
if (_sourceType == SourceType.Monster)
    return _combatState.PlayerCreatures;      // ← 硬编码：怪物打「玩家侧」
if (Attacker == null) throw ...;
return _combatState.GetOpponentsOf(Attacker);
```
**第一个分支不看攻击者在哪一侧。** 民兵是**玩家侧**的随从，
用 `DamageCmd.Attack(...).FromMonster(militia)` 会让它**打自己人**
（玩家本体 + 自己所有建筑）。

### ★ 官方自己怎么做的

本体缚灵师的随从 `Osty` 的 move 状态机是：
```csharp
new MoveState("NOTHING_MOVE", (IReadOnlyList<Creature> _) => Task.CompletedTask)
```
—— **官方随从根本不靠状态机攻击**，它靠卡牌触发
（`AttackCommand.FromOsty(osty, card, cardPlay)`，走 `_sourceType = SourceType.Card` 分支 → 目标解析才正确）。

### 我们的修法

**不覆写 move 状态机**（继承 `MinionModel` 的待机循环），自动攻击改由
**`MilitiaAttackPower`（`BeforeSideTurnStart` 触发）** 实现 ——
和箭塔 `ArrowTowerPower` / 冰墙 `IceWallPower` / 篝火 `CampfirePower` **同一套已验证机制**（M3.1 起跑通）。
顺带白拿好处：**光环按层数叠加** ⇒ 「重复部署 = 强化」时民兵每回合多打 5 点。

数值：每回合对**最前方的敌人**造成 `5 × 层数`。
（不用随机是为了免掉 `Rng` 的联机一致性处理；打"最前"而不是全体，是为了和箭塔的 AOE 区分定位。）

## 四、问题 2 的实现：凛冬起始卡组

**新文件 `FrostDeck.cs`**，13 张：

| 类别 | 卡 | 张数 |
|---|---|---|
| 攻击 | 凛冬打击（1 费 6 伤，**新增**） | 5 |
| 防御 | 凛冬壁垒（1 费 5 格挡，**新增**） | 3 |
| 攻击/技能 | 暴风雪（2 费 AOE 8 + 虚弱） | 1 |
| 防御/建筑 | 冰垒（前排 6 血替伤） | 1 |
| 建筑 | 箭塔（4 AOE/回合） | 1 |
| 建筑 | 篝火（0 费，2 回血/回合） | 1 |
| 技能 | 冰封术（打断） | 1 |

剩下 7 张（民兵 / 后排冰垒 / 符文壁 / 瞭望台 / 法师 / 霜爆塔 / 王座）走**间隙补给**进牌库。

**换装机制**：
- `CardPileCmd.RemoveFromDeck(整副)` + `CardPileCmd.Add(13 张, PileType.Deck)`
- **只对新开局生效**（读档局在 `GetRelic != null` 那里就 continue 掉了）
- **兜底重试**：`RunStarted` 时牌库不一定已铺好 → 若 `Deck.Cards.Count == 0` 就留着，
  之后每次进房间（`RoomEntered` → `EnsurePanel`）再试，装上为止（`_deckInstallState` 防重复）
- 设置项 `FrostDeck`（bool，**默认开**）：关掉就保留角色原卡组（M3.7 及以前的行为）

**补给比例也跟着改**：开了凛冬卡组 → **2 凛冬 + 1 角色牌**（牌库真的往凛冬长）；
没开 → 1 凛冬 + 2 角色牌（原比例）。

## 五、问题 3：难度对齐

**对齐口径：起始卡组的输出/防御量与本体起始卡组对齐 ⇒ 波次表不用重调。**

| | 本体 Ironclad | 凛冬 |
|---|---|---|
| 攻击牌 | 5×Strike（1 费 6 伤） | 5×凛冬打击（**同费同数值**） |
| 防御牌 | 4×Defend（1 费 5 格挡） | 3×凛冬壁垒（**同费同数值**） |
| 特殊 | 1×Bash | 暴风雪 / 冰垒 / 箭塔 / 篝火 / 冰封术 |
| 攻击密度 | 5/10 = **50%** | 5/13 = **38%** |

★ 第一版只放了 4 张打击（4/12 = 33%）—— **开局会明显比本体弱**，已加到 5 张。
多出来的功能牌短期不产生伤害（是投资），所以**开局不会更强**、中期才开始滚雪球。

**⇒ 结论：换装后开局难度与本体相当，M3.7 重调的波次表无需再改。**
（M3.7 的波次表本来就是按"起始卡组 ≈70 血 / 每回合 12~18 输出"算的，这个前提没变。）

⚠️ 但要注意：**凛冬牌没有任何"易伤"（Vulnerable）来源**，本体 Bash 的 2 层易伤是个不小的伤害放大器。
如果实测感觉"打不动"，第一优先是给凛冬补一张带易伤的牌，而不是再削波次。

## 八、遗留

- **凛冬牌池仍偏小**（16 张）⇒ 补给三选一里 2 张凛冬牌会很快重复。要真正像《凛冬前线》
  那样"各种有意思卡"，卡池得继续扩（目前只有 1 张带易伤、0 张带力量、0 张带"消耗/固守"这类词条）。
- **`WaveTable.All` 用固定种子 0**（M3.7 遗留）—— 「每局波次不同」仍未生效。
- 换卡组**对多人都生效**吗？当前只换**本地玩家**的卡组。多人局里其他人仍是原卡组 —— 未适配。
