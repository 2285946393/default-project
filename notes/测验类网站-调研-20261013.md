## 一、标杆站拆解：Loveage「你的戀愛年齡感是幾歲？」

### 它是什么

- 繁体中文为主，另有 **简体 / English / 日本語** 三个完整版本（i18n 做全了）
- **24 道情境题，3–5 分钟**，测"你在恋爱里看起来比对方大几岁"
- 结果 = **−8 到 +8 岁的年龄差** + **12 种类型**里的一种

### 页面流程

1. 首页（标题 + 类型预览 + 常见问题 + 语言切换）
2. `/quiz` → 输入暱称（可跳过）
3. → 选"你想着谁"：**现任 / 暧昧对象 / 喜欢的人 / 前任 / 理想中的另一半 / 单纯测自己**
4. → 四段式答题：

| 段落 | 标题 | 副标题 |
|---|---|---|
| Part 1 | 聊天模擬 | 先從你們的對話開始。 |
| Part 2 | 戀愛日常 | 如果你們已經在一起了。 |
| Part 3 | 突發事件 | 事情開始不照計畫走。 |
| Part 4 | 真正喜歡上之後 | **這一段最準，慢慢選。** |

5. → 结果页（免费）：年龄差 / 类型 / 副型 / 反差类型 / 四个恋爱指数 / 六维图

### 计分机制（从 JS 里扒出来的真实结构）

题目数据结构：

```js
{ id:"Q01", part:1, type:"conversation", weight:1, scenario:"…", prompt:"…",
  options:[ { text:"…", scores:{ holding:3, care:2 } }, … ] }
```

- **题库其实是 42 道**（不是 24），每次抽 24 道给用户。Part 分布：P1=8、P2=12、P3=11、P4=11
- 题型三种：`conversation`（聊天模拟，8 道）/ `instinct`（直觉，19 道）/ `event`（事件，15 道）
- **每题带权重 `weight`**：1.0 / 1.1 / 1.2 / 1.3 / 1.4 / 1.5 / 1.6（关键的 Part 4 题权重更高，如 Q34 是 1.5）
- **六个维度**（每个选项给 1–3 分）：

| 键名 | 中文 | 含义 |
|---|---|---|
| `care` | 照顧感 | 多自然地进入照顾者位置 |
| `lead` | 主導感 | 关系需要推进时是不是你 |
| `holding` | 情緒承接 | 接得住对方情绪的程度 |
| `responsibility` | 责任 | 把事情扛下来的倾向 |
| `dependency` | 依賴 | 自在被照顾、直接说出想要 |
| `playfulness` | 玩心 | 跟对方闹、耍赖 |

- 每个维度**标准化成 0–100**

### ★ 它最聪明的一招：反差类型

**Part 1–3（别人看到的你）和 Part 4（真正喜欢上一个人之后的你）分开算**，
两个数字的落差 = **"反差类型"**。

这是整个站最勾人的设计 —— 人对"原来我在喜欢的人面前是另一个样子"几乎没有抵抗力。

### 商业化（怎么赚钱）

| 免费 | 付费 |
|---|---|
| 作答本身 | 「完整戀愛人格報告」 |
| 结果页：年龄差 / 类型 / 副型 / 反差类型 / 四个指数 / 六维图 | 「雙人相處詳細報告」 |

**付费钩子**：同一个浏览器**前 2 份结果免费看，第 3 份起必须购买那一份的完整报告**才能看结果。
→ 等于逼复购：测完自己 → 测前任/暧昧对象 → 第 3 份就要付钱。

**传播设计**：
- **没有账号系统**，答案直接编码在结果页网址里 → 发链接别人就能看 → 分享零门槛
- 官网 FAQ 明说"任何拿到这个网址的人都看得到同一份结果"
- 有 `/share`（分享卡）、`/compare`（双人对比）、`/couple`（双人版）路由
- OG 图 `https://loveage.lazybearlife.com/og.png`（1200×…），Twitter card 齐全

### 合规护身符（重要）

- 首页和每页页脚都写：「**心理娛樂測驗，結果僅供參考**」
- 12 个类型名**全是夸人的**：「把你養得很好的年上型」「超會討抱的年下型」「一起耍笨的同齡型」……
- 它**不诊断你，它夸你**，还让你想把夸奖发出去 —— 这是它和低端货的根本区别

### 技术栈（实测响应头 / 源码）

- **Next.js**（App Router，`x-nextjs-prerender`、`vary: rsc`）
- **部署在 Zeabur**（`x-zeabur-request-id`、`x-zeabur-ip-country`）
- **Cloudflare 在前面**（`Server: cloudflare`、`cf-ray`、`cf-cache-status`）
- 有**数据库**（`GET /api/health` → `{"ok":true,"web":"ok","database":"ok"}`）
- 有**登录后台**（`/admin` → 200，标题「後台｜你的戀愛年齡感是幾歲？」，内容是登录表单）
- 前端分析：**Google Analytics**（`gtag` / `googletagmanager`）
- 安全头齐全：CSP `frame-ancestors 'none'`、`X-Frame-Options: DENY`、HSTS preload、
  `permissions-policy: camera=(), microphone=(), geolocation=()`
- 多语言：middleware `x-middleware-rewrite: /zh-TW`；`Cache-Control: s-maxage=31536000`
- **SEO 做满**：`sitemap.xml`（含 `xhtml:link hreflang` 四语言 + `x-default`）、
  `robots.txt` 屏蔽 `/result /compare /share /api /admin /report /couple /premium`，
  并**单独给 AI 爬虫放行**：`OAI-SearchBot`、`ChatGPT-User`、`PerplexityBot`、
  `Claude-SearchBot`、`Claude-User`、`Applebot`、`meta-webindexer`

## 三、⚠️ 合规红线（2026-02-10 央视点名过，必须守住）

来源：[央视揭露网络"心理测试"套路：免费填表、付费看报告](https://moment.rednet.cn/pc/content/646046/54/15690828.html)

### 被点名批评的具体做法

1. **"免费填表、付费看报告"** —— 等填完才告诉你要花钱才能看结果
2. **结果病理化 / 扩大化** —— 尤其抑郁、焦虑、NPD、BPD、ADHD 这类**看着像诊断**的测试
3. **引流** —— 测完推荐你买更多相关服务
4. 专家（广东省人民医院 贾福军、上海精神卫生中心 乔颖、回龙观医院 霍平欣）反复强调：
   **线上测试不能替代专业诊断**，可能给人错误的消极暗示、加重焦虑
5. 隐私风险：测试前若要求填个人信息，可能被收集

### 我们自己的规矩（照这个做）

| ✅ 可以做 | ⛔ 绝对别做 |
|---|---|
| 恋爱、性格、游戏、摸鱼、学习习惯等**明摆着娱乐**的题材 | 抑郁 / 焦虑 / ADHD / NPD / BPD 等**像在诊断**的题材 |
| 每页写明「娱乐测验，仅供参考」 | 出现"诊断""秒出报告""你是不是有病"这类表述 |
| 结果让人开心、想截图分享 | 结果让人焦虑、给人贴负面标签 |
| 不收集个人信息、不要注册 | 强制填手机号/邮箱才能看结果 |
| 要收费就**提前说清楚**哪部分收费 | "免费"填完才弹出要付费 |

## 四、可复用的机制清单（做自己的站时照抄这些）

### 必抄（决定成败）

1. **反差设计** —— 测两遍：别人眼中的你 vs 动心/深入之后的你，用落差造出"副型/反差类型"
2. **结果是个数字 + 一个名字** —— "−3 岁 · 外冷內黏的年上型" 比一堆形容词好传播得多
3. **结果卡能直接截图** —— 数字、类型名、六维图，竖版，适配手机截图
4. **没有账号，结果编码进网址** —— 分享零门槛（Loveage 的核心增长机制）
5. **开头问"你想着谁"** —— 一份题能测很多次，天然的复购来源
6. **全部类型名都是夸人的** —— 这是合规护身符，也是分享动力

### 值得抄（提质感）

7. **分段式流程**（Part 1/2/3/4 + 每段一句引导语），比一口气 24 题不累
8. **题库大于展示题数**（42 抽 24），用户二刷不会全重样
9. **题目分权重**，关键的几题加成，结果更"像那么回事"
10. **每题三个选项就够**，A/B/C/D 四个已偏多
11. **六维雷达图**，图比文字有说服力
12. **多语言**（繁/简/英/日）—— 如果只做中文，至少繁简都留

### 收费标准参考

- Loveage 的免费/付费切法：**结果页免费看，深度报告收费**，且**前 2 份免费、第 3 份起收费**
- 别学 0.99 元那种一次性倒卖

## 四之二、★ 现成开源引擎：XBTI（**首选，不要从零手搓**）

> 用户定的总规矩是"先找现成的改，不从头手搓"。**这就是那个"现成的"。**

仓库：**https://github.com/lovstudio/XBTI**（`lovstudio/XBTI`）

- 描述：**「一个开源的人格测试引擎 — 5 分钟创建你自己的 BTI」**，基于 SBTI 泛化
- 语言 **JavaScript**｜License **Apache-2.0**｜约 57 MB｜9 star / 2 fork
- 在线 demo：**https://xbti.lovstudio.ai**（`/c/sbti`、`/c/cbti`）
- 主题标签：`chinese` `mbti` `open-source` `personality-test` `quiz` `react` `sbti` `vite` `xbti`
- 技术栈：**React 19 + Vite 8 + pnpm**，部署 Vercel + Cloudflare DNS
- 原创内容版权归 **B站 @蛆肉儿串儿**（SBTI 原作者），代码由 lovstudio.ai 维护

### 引擎架构（关键：算法不用动，只填数据）

```
cases/                    # 各 BTI 变体数据
├── registry.js           # 注册所有变体（CASES 数组）
├── sbti/                 # 恶搞人格（27 种）
├── cbti/                 # 猫猫人格
└── nombti/
src/
├── components/
│   ├── HomePage.jsx      # 首页（选择 BTI 变体）
│   ├── TestFlow.jsx      # 测试流程控制
│   ├── CaseIntro.jsx     # 变体介绍页
│   ├── TestScreen.jsx    # 答题页
│   └── ResultScreen.jsx  # 结果页
├── logic/scoring.js      # ★ 通用匹配算法（无需修改）
└── useHashRoute.js       # 路由
```

**添加新 BTI 的做法**：在 `cases/` 下新建目录，填入数据文件，在 `registry.js` 里加一行注册。

### 每个 case 要填的文件（cbti 实测体积）

| 文件 | 体积 | 内容 |
|---|---|---|
| `dimensions.js` | 3.7 KB | 15 维度定义（5 模型 × 3 子维度） |
| `questions.js` | 10.9 KB | 30 道题（每维度 2 题、每题 3 选项） |
| `types.js` | 14.8 KB | 人格类型（代号、模式、描述） |
| `index.js` | 447 B | 导出 meta + 上面三样 |
| `case.json` | 26.7 KB | 完整打包设定 |

### 匹配算法（照抄即可）

1. 每道题对应一个维度，同维度得分求和
2. 映射为三级：**L（≤3）/ M（4）/ H（≥5）**
3. 构建 15 维用户向量，与所有人格模式做**曼哈顿距离**匹配
4. 最近距离为匹配结果，相似度 = `(1 - distance/30) × 100%`
5. 兜底：相似度 < 60% 时强制分配到 fallback 人格

### 两个白送的好东西

- **`html-version` 分支**：只有一个 `index.html`（**68 KB**），是**最初的单文件 HTML 版**
  → 正好对应本仓库 `pages/` 的单文件路子（双击就能开，不依赖构建）
- **彩蛋题机制**：`cases/cbti/questions.js` 导出 `CATNIP_TRIGGER_QUESTION_ID`（猫薄荷触发题）
  → 引擎支持**特殊触发题**，对应媒体夸 PRTI 的"突发事件和小彩蛋"
- **配套 skill**：`npx skills add lovstudio/skills --skill lovstudio:xbti-creator`
  → 输入主题名即可生成整套 BTI（Claude Code skill）

**关键结论（推翻"小黑盒已占赛道"的判断）：**

1. 这一波拼的是 **UI 好看 + 题目好玩 + 有彩蛋**，**不是**"能不能读到 Steam 库"

3. 这批几乎全是**个人开发者**作品（SBTI 原作者是 B站 UP 主，为劝朋友戒酒而做，不盈利）
4. 受众与求职作品集**完全重合**

**理论底座可白嫖**：[巴特尔玩家分类 Bartle taxonomy](https://zh.wikipedia.org/zh-cn/%E5%B7%B4%E7%89%B9%E5%B0%94%E7%8E%A9%E5%AE%B6%E5%88%86%E7%B1%BB)

## 六、载体与合规决策（建议，待用户拍板）

### 载体三选一

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 单文件 `pages/` 页面** | 用 XBTI 的 `html-version`（68 KB 单 `index.html`）改造，落 `pages/` | 双击就能开、能塞博客 `public/lab/`、不依赖构建、面试官打开即见 | 榜单/统计弱 |
| **B. Vite + React 独立工程** | 直接 fork XBTI 主分支，放 `projects/` | 有引擎、有彩蛋机制、可扩展 | 要 `npm install`，面试官未必装环境 |
| **C. 两个都要** | 先 A 出成品，再搬 B | 兼得 | 工作量翻倍 |

> 结合本仓库惯例（`pages/` 是"给人看的、双击就能开"），**A 最稳**；B 更像是"技术深度展示"。

### 收费：建议**先不做**

理由：
1. 涉及收款通道、退款、税务、合规，成本高
2. 央视点名的正是"**免费填表、付费看报告**"这套路，做不好会被打上同类标签
3. SBTI 原作者就是**完全不商业化**，照样刷屏——**流量和作品集价值不来自收费**

**如果将来要做**：必须**提前明码标价**哪部分收费，绝不能"填完才弹出要付费"。
