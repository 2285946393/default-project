# 开源改造说明（面试用）

> **这份文档回答一个问题**：面试官问「这些项目有多少是你自己做的」，你怎么答。
>
> **核心立场**：大方承认用了开源底座，然后**把重点放在"你改了什么、为什么这么改"**。
> 2026 年，「从零写一个粒子引擎」没有价值了——AI 十分钟就能生成。
> **真正稀缺的是：从几百个项目里挑出对的那个，判断它值不值得做成产品，然后真的把它做出来。**
>
> 用法：面试前过一遍。被问到任何作品，能立刻说出「原项目是什么 / 我改了什么 / 为什么」。

---

## 一、先把定位讲清楚（开场就说这段）

被问到"你的作品是原创的吗"，**不要绕**，直接说：

> "我的项目分两类。
>
> 一类是**完全自己做的**，比如 AI 面试官、鲸云 API、创作中台，从零到上线都是我自己写的。
>
> 另一类，我更愿意叫**开源改造**——我会先在 GitHub 上找成熟的技术底座，然后自己负责判断、改造、玩法设计和视觉包装。比如菌丝世界，它的黏菌模拟内核来自一个开源项目，但**"输入一个词长出一只专属生物"这个玩法是我加的**，整套中文界面、8 套配色、参数面板也都是我重做的。
>
> 我不太倾向于重复造轮子。**因为把时间花在'重新实现一个已有的粒子系统'上，产出的东西不会比现成的好，但会耗掉我做玩法设计的时间。**"

**为什么这么说**：
- 先亮出"我也能完全自己做"（第二类），堵住"他只会拿别人的东西"的质疑
- 再说改造（第一类），并且强调**你加的东西**
- 最后给出理由——这是**工程判断**，不是偷懒

## 二、逐个作品：原项目 / 我改了什么 / 为什么

### 1. 菌丝世界（Mycelia）⭐ 改造类里最强的一个

| | |
|---|---|
| **原项目** | **MattKulka/mycelia** —— WebGL2 GPU 黏菌（Physarum）模拟 |
| **技术底座** | WebGL2 + `EXT_color_buffer_float` 浮点纹理，多 Pass 迭代，粒子状态存在纹理里 |

**我改了什么（这些是能讲的）**：

1. **「文字 → 基因组」——这是我加的原创玩法**
   原版只能手动调参数。我的做法是：把用户输入的任意文字（中文、英文、整条链接都行）**哈希成一个种子**，再用这个种子**确定性地推导出全部 14 个参数**（感知角度、感知距离、转向速度、痕迹衰减、配色、萌发形态……）。
   效果是：**同一个词永远长出同一只生物**，链接发给别人能一字不差复刻。
   > 代码里就是个字符串哈希 + 确定性伪随机，不难，但**想法是我的**。

2. **整套中文界面与交互层重做**：8 套氛围配色（深渊/余烬/孢子/星云/象牙/青腐/岩浆/霜雪）、7 项参数实时滑块、鼠标"喂养 / 驱散"。

3. **打包成零依赖单文件**，双击即运行。

**为什么这么改**：
> "原项目是个很棒的模拟，但它是个'参数面板'——普通人打开不知道该干嘛。
> 我想让它变成一个'**能玩**'的东西：不用懂什么叫感知角度，输入自己的名字就能长出一只独一无二的生物。**降低上手门槛，才有分享的欲望。**"

**如果被追问**：
- **Q：为什么要做"同词同生物"？**
  A：为了**可复现**。如果每次都不一样，用户就没法跟别人说"这是属于我的生物"。确定性哈希让一个词变成一个身份。
- **Q：哈希冲突怎么办？** A：会有，但哈希空间很大，日常用词基本不会撞；就算撞了也只是两只生物长得像，不影响体验。

### 2. 粒子生命（Particle Life）

| | |
|---|---|
| **原项目** | **hunar4321/particle-life**（MIT License, Copyright (c) 2022 Hunar Ahmad） |
| **我改了什么** | **重写了空间哈希网格**（`buildGrid`）+ 换成经典分段力曲线（Clusters / Tom Mohr 模型），自建中文界面与可视化吸引矩阵 |

**技术细节（这段是真功夫，可以讲深）**：

重写的网格用的是**紧凑数组 + 计数排序**结构，不是简单的嵌套数组：

```
cellStart  / cellFill / cellCount   ← 三个 Int32Array
cellSize = max(8, 感知半径)
```

先在整数数组里统计每格粒子数，再前缀和算出每格起始下标，最后把粒子按格号填进 `sorted` 数组。这样遍历邻居时**内存连续**，对缓存友好。

同时用 `srand` + 自实现的 `rng()` 做**可复现的种子随机**，所以"同一个种子永远是同一个世界"，还支持把种子写进 URL 分享。

**为什么这么改**：
> "原版在粒子数上去之后会掉帧，因为邻居查询是暴力两两比较。我换成空间网格之后，每个粒子只查附近格子，复杂度从 O(n²) 降到接近 O(n)。"

**这里能主动说的话**：
> "这部分我不是照抄的——**网格结构是我按缓存友好的方式自己设计的**，因为我想跑更多粒子。"

### 3. 元素秘境（落沙沙盒）

| | |
|---|---|
| **原项目** | **sandspiel**（MIT）—— Rust/WASM 落沙内核 + `sand.glsl` 渲染 |
| **我改了什么** | 移植 + **手写 wasm-bindgen 胶水层** + 原生 WebGL 渲染 + 中文 UI |

**诚实边界（务必守住）**：
- **内核是 sandspiel 的，不是我写的。绝对不要说"我用 Rust 从零写了内核"。**
- 说：「**移植改造 + 手写胶水层和渲染**」

**但你不用心虚，因为**：
1. **零拷贝数据通路**：把 WASM 内存里的 `cells` 数组直接用 `Uint8Array` 视图喂给 `texSubImage2D`，中间不复制
2. **手写胶水层**：按 wasm-bindgen 约定自己提供 `imports`（`random` / `throw` / `externref` 初始化表）
3. **软笔刷优化（这是我自己发现的）**：一开始用实心圆撒沙，结果**一整块沙同时出现、整体下坠，很假**。我改成**圆内按密度逐格随机撒点**，每粒沙独立取随机数，下落抖动彼此独立，才形成自然的沙流。
4. **图形层移植**：把 `sand.glsl` 里的 `hsv2rgb`、2D/3D simplex noise 手写内联

**能读懂 Rust↔JS 的 ABI、手写 glue、把 GLSL 移植过来、做性能适配——这本身就是硬功夫。**

## 三、通用应答：三个问题怎么答

### Q1：「你用 AI 写代码吗？」（2026 必问）

> "大量用，当加速器。但我把它用在**该用的地方**：
> 让它帮我**检索和筛选**开源项目、解释我看不懂的代码、处理样板逻辑。
> 而**选题、判断这个项目值不值得做、玩法怎么设计、交互怎么调、最后验收——这些是我自己来**。
>
> 举个例子：菌丝世界的软笔刷，实心圆版本看着很假，是我自己发现'颗粒之间缺少独立性'，然后改成逐格随机撒点才自然的。**这种问题 AI 给不了答案，得自己看、自己判断。**"

### Q2：「那你到底自己写了多少？」

> "分项目。像 AI 面试官、鲸云、创作中台，**全部是我写的**。
> 改造类的话，**内核可能来自开源，但玩法设计、交互、视觉、中文化和工程适配都是我做的**。
> 比如粒子生命，空间网格是我重写的；菌丝世界的'文字变生物'是我加的玩法。
> 我判断一个项目的标准是：**我能不能让用户打开之后觉得'这个有意思'**——如果只是把别人的 demo 改个颜色，那没有意义。"

### Q3：「为什么不自己从零写？」

> "**因为不值得。**
> 一个成熟的黏菌模拟、流体求解，人家迭代了好几年。我从零写，最好的结果是达到人家的水平，但要花掉几周——**这几周我本来可以用来设计玩法、调交互、做包装**。
>
> 我更愿意把时间花在**有差异化的部分**：这个东西怎么玩、怎么让人一眼看懂、怎么让人愿意分享。
>
> 当然，**前提是我得真的读懂它**——知道入口在哪、依赖怎么接、为什么会卡、改哪里会坏。这个我从来不含糊。"

## 四、你必须守住的三条底线

1. **绝不说"从零原创"** —— 被追问细节会露馅。说"改造"，一点都不丢人。
2. **绝不说"我写了内核"** —— 尤其元素秘境，内核是 sandspiel 的。
3. **许可证要能说清** —— 我逐个核查了原项目的许可证：

| 作品 | 原项目 | 许可证 | 你的声明 | 是否合规 |
|---|---|---|---|---|
| 粒子生命 | hunar4321/particle-life | MIT | ✅ 完整（含版权行）| **合规** |
| 流体花园 | WebGL Fluid Simulation | MIT | ✅ 完整 | **合规** |
| 元素秘境 | MaxBittker/sandspiel | MIT (c) 2018 Max Bittker | ✅ 已补全版权行 | **合规** |
| 菌丝世界 | MattKulka/mycelia | **该仓库没有 LICENSE 文件** | ✅ **只标来源，未声称任何许可证** | **合规** ✅ |

**核查结论：四个改造类作品现在都站得住，不用再改代码。**

之前我一度以为「菌丝世界写了 MIT」——**那是我判断错了**。实际核查后：
- 菌丝世界的 HTML 和玩法说明里**从来没有出现过 "MIT" 字样**
- 只写了「技术底座来自 MattKulka/mycelia」
- **这恰恰是最准确、最安全的写法** ✅

**只有元素秘境需要补**（已补）：它原本写「(MIT, Max Bittker）」，格式简略，现在补成了标准版权行：

```
sandspiel: MIT License, Copyright (c) 2018 Max Bittker
https://github.com/MaxBittker/sandspiel
```

**「没声明许可证」这件事本身，面试时是个加分点**——说明你查过：

> "这个底座的作者**没有声明许可证**，所以我只在作品里如实标注了来源，**没有声称它适用某个协议**。我觉得用别人的代码，把来路搞清楚是基本的。"

> 主动说"**我用了 XX 开源项目并保留了它的 MIT 声明**"是加分项，但**前提是声明准确**。你现在四个项目都准确。

## 五、一句话总结你的定位

面试时如果只能说一句：

> **"我擅长把成熟的开源技术，快速判断、改造、包装成一个有主题、有交互、有完成度的作品。"**

这比「我擅长从零开发图形系统」**更真实，也更能打**——因为后者一堆人会吹，而前者需要真的做出东西来证明。
