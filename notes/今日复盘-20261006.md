## 二、方法论收获（今天最重要的沉淀）

1. **多 AI 协作可行形态**：任务书落盘 → 实现 → 回执写回同一文档 → 互审。互纠 4 次零事故
   （wb 修 ZCode 读档 bug / ZCode 纠 wb 斗地主过时情报 / wb 自纠 MapPointType 误判 / ZCode 撤件让位）。
2. **实测喂 bug 碾压闭门造车**：用户一张截图（邦布 16/16 站场 + `cards.FROST` key）直接定位两个真因。
3. **"自己能构建 + 自己能反编译"是 AI 干活的分水岭**（wb 总结）：它的高价值产出全建立在这上面。
4. **用户的碎碎念全是设计**："不是新角色是搬玩法" / "只做一条线" / "建筑像能力牌但能挡伤害" /
   "选了传送点才给牌" / "像邦布那样能点" —— 每条都被直接采纳为架构。
5. **发现"代码没被运行"比堆功能重要**：wb 19:5x 的自检转向是对的——
   未运行代码的风险不随"写完"清零。

## 三、踩坑（新增，均已写进对应文档）

| 坑 | 细节 |
|---|---|
| `PowerModel`/`CardModel` 基类在 `MegaCrit.Sts2.Core.Models` | 不在 Entities.*；quest-spire 旧笔记§3 写漏了 |
| `PowerModel.Owner` 是生物不是玩家 | 抽牌要 `Owner.Player`；遗物的 Owner 才是 Player |
| `[RegisterPower]` 无参可用 | Power 上可直接 override 战斗钩子，side 守卫用 `Owner.Side != side` |
| 卡池抽象成员 ≠ 遗物池 | Title/IsColorless/DeckEntryCardColor/CardFrameMaterialPath 必须实现 |
| `BeforeCombatStart` 读档不重跑 | 只在 `CombatManager.StartCombatInternal` 触发——战斗内状态别指望它重建 |
| `MapCoord` 字段小写 | `col` / `row` |
| **mod 禁用是无症状的** | 日志仅一句 `Skipping loading mod`——实测前先确认开着 |
| 并行 AI 写同一文件 | Write/Edit 会报"file modified"——一律先回读再改；撞车当场让位 |
| `ActModel.ToSave().SavedMap` 恒为 null | 运行时取原图只有内存引用一条真路（wb 逐行取证） |
