## 零、大白话结论

**结论：能做，而且比一开始想的干净。**

用户这次更正掉了一件大事：**不需要"互相攻击"**。  
所以这个 mod **不需要血条、不需要伤害、不需要"把别人打死"**。  
它要的全部就是——**谁先把手里的牌打完，谁赢。** 到此结束。

于是整个东西可以这样理解：

> **不是做一个新战斗，是在杀戮尖塔的战斗房间里，摆一桌斗地主。**

游戏本体只负责提供：房间、卡牌能拿能打、动画、拖拽、联机管道。  
**斗地主的规则（发牌、轮到谁、牌型对不对、谁先打完）全部自己写。**

另外三条证据（从游戏本体里挖的，不是猜的）：

1. **官方支持 4 人联机**，而且开发者**主动给 mod 作者留了扩展口子**。
2. **mod 可以注册自己的网络消息**——这是"联机三人/四人"能不能成的钥匙。
3. **改战斗循环有现成先例**：你硬盘上那个类幸存者 mod 已经把整个战斗从回合制改成了实时动作游戏，  
   连原版胜负判定都 patch 掉了。同类操作是可复制的。

**建议起手顺序**：① 单机 + 打 AI → ② 3 人联机 → ③ 4 人 2v2。

## 二、三条证据（证据链）

### 证据 1 · 官方支持 4 人，且留了扩展口

`data_sts2_windows_x86_64/sts2.xml` 第 25499 行，开发者注释原文：

> Technically we only support four players, but I figured I'd make it easy for modders to expand the number of players!

（我们其实只支持四个人，但我特意让 mod 作者扩展人数变得容易。）

→ **4 人 2v2 在人数上没有硬墙。**

### 证据 2 · mod 能注册自己的网络消息（★ 最关键）

`MegaCrit.Sts2.Core.Multiplayer.Serialization.MessageTypes`：

```csharp
public static void Initialize()
{
    List<Type> list = new List<Type>();
    list.AddRange(INetMessageSubtypes.All);
    list.AddRange(ReflectionHelper.GetSubtypesInMods<INetMessage>()); // ★ 会主动扫 mod 里的消息类型
    _cache = new NetTypeCache<INetMessage>(list);
}
```

→ 游戏**主动扫描 mod 程序集里的 `INetMessage` 实现**并分配类型 ID。  
意味着："现在轮到谁出牌""谁打了什么牌""桌面上的牌是什么"这些**都能自己定义消息同步**。  
**联机斗地主的最大拦路石在这里被搬开了。**

### 证据 3 · 改战斗循环有先例（幸存者 mod）

`workshop/content/2868840/3804485262/local.action_game.dll`（229 KB，`dependencies: []`）里的类型：  
`ModEntry` / `CombatPatches` / `PlayerWasdMoveSystem` / `EnemyChaseSystem` / `AutoSpawnSystem` /  
`EncounterTimerSystem` / `AutoCardSelectSystem` / `AutoSortHandSystem` / `CreatureYSortSystem` /  
**`DelayedWinCheckPatch` / `IsOverOrEndingHoldPatch` / `IsEndingHoldPatch`**。

它做的事：把回合制战斗改成实时动作游戏，**并且把原版的胜利判定"按住不动"**，改用自己那套倒计时胜负。  
→ **"改掉回合结构 + 换掉胜负判定"已经被实盘验证过，不是理论。**

## 三、真正的难点（只有两个，加一个小麻烦）

### 难点 1 · 回合是"集体制"，不是"轮流"

`CombatManager` 的流程是：所有玩家出牌并点结束 → 切到敌方回合 → 敌人行动 → 回到玩家。  
内部状态是 `CombatTurnState` + `_turnLoopTask`（一个长跑任务）。

**斗地主需要**：只有"当前这个人"能出牌，其他人只能看；他出牌或要不起 → 轮到下一个。

**要做的**：把回合循环掐掉，换成自己的"轮次指针"。  
参考 `CombatManager` 里的 `SetReadyToEndTurn` / `SetPhaseForAllPlayers` / `PlayerTurnPhase`  
（有现成的"锁住某些玩家操作"能力可借用）。

### 难点 2 · 出牌要"一次选多张"

斗地主的对子/三张/顺子/连对/飞机，都是**一次打出一组牌**。  
原版选牌界面（`NCardGridSelectionScreen` / `NSimpleCardSelectScreen` / `NCombatPileCardSelectScreen`…）  
是为"卡牌效果选目标"做的，不是为"组牌型"做的。

**要做的**：手牌区改成可多选 + 实时显示"当前选的是不是合法牌型"。  
好消息：手牌排序（`AutoSortHandSystem` 先例）、手牌上限（`baseHandDrawCount = 5` 可调）都是可改的。

### 小麻烦 · 胜负怎么落地（已定：直接用原版那套，不用打架）

**用户给的做法（更省事，已定）**：
> 「如果说牌出完了。对其他两个角色一次性操作所有生命值伤害。其他两个角色会显示失败。
> 然后你这边单独显示一个胜利就行了。」
> 「**不用考虑怎么对玩家造成伤害，杀戮尖塔有现成的攻击 mod。**」

即：**直接用原版的血量/失败/胜利流程**——谁出完牌，就把另外两家一次性打死，
他们自然走原版的失败显示，出完牌的人走胜利。**不需要 patch 掉原版判定。**

手段已确认现成（反编译核过）：`CreatureCmd.Damage(...)` / `CreatureCmd.Kill(Creature)` /
`CreatureCmd.SetCurrentHp(Creature, 0)` 都能对玩家生效；另有现成攻击类 mod 可用。

> 已排除的伪难点：一开始以为要"玩家打玩家"，担心游戏只有 `Player`/`Enemy` 两个阵营
> （`enum CombatSide { None, Player, Enemy }`）。
> 用户更正后**这条不成立了**——不需要任何攻击目标选择与阵营改造。

## 四、技术路线（怎么装进去）

整体思路学幸存者 mod：**不重写游戏，而是把斗地主拆成一堆独立小系统，各自挂到原版流程上。**

| 系统            | 职责                                       | 挂钩点                               |
| ------------- | ---------------------------------------- | --------------------------------- |
| `TableSystem` | 座位、队伍、轮次指针                               | `CombatBegan` 建桌；`TurnStarted` 驱动 |
| `DeckSystem`  | 造 54/108 张扑克、洗牌、发牌、留底牌                   | 自建牌堆，用 `CardPileCmd` 摆到手上         |
| `PlaySystem`  | 收集玩家选中的多张牌 → 判牌型 → 比大小 → 合法才放行           | 拦截出牌动作（Harmony patch 出牌入口）        |
| `ComboJudge`  | 牌型识别与比较（单/对/三/三带一/三带二/顺/连对/飞机/四带二/炸弹/王炸） | 纯逻辑，无依赖，最先能写完也能最先自测               |
| `PassSystem`  | "要不起"→ 轮下家；连续两家不要 → 桌面清空、上家自由出           | 跟随 `TableSystem`                  |
| `SeatView`    | 其他玩家的手牌数、桌面牌、轮到谁的提示                      | 参考幸存者 mod 的 HUD patch             |
| `WinSystem`   | 手牌空 → 立刻判胜、放行结算                          | 学 `DelayedWinCheckPatch`（接管原版判定）  |
| `AiSeat`      | 电脑座位出牌（单机用）                              | 只依赖 `ComboJudge`，可单独开发            |
| `NetSync`     | 自定义 `INetMessage`：回合、出牌、要不起、桌面状态         | `MessageTypes` 自动扫描 mod 消息        |

构建链直接**复刻 `projects/quest-spire/` 与 `projects/frost-spire/`**  
（`Godot.NET.Sdk 4.5.1` / `net9.0` / Publicizer / RitsuLib / BaseLib，`dotnet build` 自动部署到 `mods\`）。

### 规则归属（谁判输赢）

- **3 人**：标准斗地主是 **1 地主 vs 2 农民**。地主先出完 → 地主赢；任一农民先出完 → 农民赢。  
  （如果只想认"谁先打完谁赢"、不分队，也可以——见 §七的规则待定项。）
- **4 人 2v2**：A 队任意一人先出完 → A 队赢；同理 B 队。

## 七、规则（已拍板）

**用户决定：一切按标准斗地主的法则。** 落地下来就是：

| 项    | 定下的规则                                                    |
| ---- | -------------------------------------------------------- |
| 3 人局 | 标准斗地主：1 个地主 vs 2 个农民。地主先出完 → 地主赢；任一农民先出完 → 农民赢。（**要分队**） |
| 4 人局 | 标准四人斗地主：**两副牌 108 张**，每人 25 张 + 8 张底牌，2v2，任一人先出完即该队赢     |
| 单人   | 没朋友就是单人打 AI（电脑座位按同一套规则出牌）                                |
| 牌    | 3~10 / J / Q / K / A / 2 / 大小王                           |

**仍可边做边定的细节**（先按标准来，不服再改）：

- 地主是"抢"还是"翻牌定"？v1 建议简单点：翻一张牌定点数，谁拿到谁是地主。
- 加倍 / 春天 / 明牌这类花活：v1 全不要，先把牌打起来。
- 手牌上限：原版战斗手牌 5 张，斗地主 17 张，界面怎么摆（扇形铺开 / 分两行 / 可滚动）  
  —— 到 P1 时给你 2~3 个成品级方案挑。
