## 一、五个词，逐个拆

### 1. LLM（大语言模型）

| | |
|---|---|
| **行业说法** | Large Language Model，大语言模型 |
| **大白话** | 就是 ChatGPT / DeepSeek / Claude 背后那个"会说话的大脑"。你的程序不自己造它，而是**通过 API 调用它**。 |
| **你在哪做过** | `projects/ai-interviewer/lib/ai.ts` —— 你用 `createOpenAICompatible()` 接了 DeepSeek 的接口，模型是 `deepseek-chat`。**这就是"接入 LLM"。** |
| **面试怎么说** | "我通过 OpenAI 兼容协议接入大模型，把它封装成一个 provider，换模型只改环境变量。" |

> ⚠️ 常见坑：别说"我训练了模型"。**接入 ≠ 训练。** 你是调用方，这是完全正常的——绝大多数岗位也是调用方。

### 2. Prompt / Prompt Engineering（提示词 / 提示词工程）

| | |
|---|---|
| **行业说法** | Prompt Engineering，提示词工程 |
| **大白话** | 你跟模型"下指令"的那段话。**写得越具体，模型干得越准。**"工程"指的是把它当代码一样设计和版本管理，而不是随口一说。 |
| **你在哪做过** | `app/api/interview/chat/route.ts` 里的 `system:` 那一段——你写了 **6 条硬性规则**："每次回复不超过 130 个字"、"先点出具体的亮点，不要'很好很棒'这种空话"、"**绝对不要使用 markdown 符号**（因为这段文字会被语音朗读）"。<br>**这就是标准的 Prompt Engineering，而且做得相当细。** |
| **面试怎么说** | "我的 prompt 是有约束设计的：限定字数、限定口吻、禁止 markdown——最后一条是因为输出要喂给语音朗读。**提示词要服务于下游消费者。**" |

> 最后那条"禁用 markdown"是你自己想到的，**这是个能加分的高级细节**，一定讲出来。

### 3. 流式（Streaming）

| | |
|---|---|
| **行业说法** | Streaming / 流式输出 / SSE |
| **大白话** | 模型一个字一个字往外吐，而不是等它全想完再一次性显示。**你看到 ChatGPT 打字机的效果，就是流式。** |
| **你在哪做过** | `app/api/interview/chat/route.ts` —— 你用的是 `streamText({...})`，最后 `return result.toTextStreamResponse()`。**这一行就是流式。** |
| **面试怎么说** | "面试官的点评用流式返回——用户不用等整段生成完，首字延迟低，体验上像真人在说话。" |

> 关键词：**首字延迟**。说出这个词，面试官会知道你懂体验。

---

### 4. RAG（检索增强生成）

| | |
|---|---|
| **行业说法** | Retrieval-Augmented Generation，检索增强生成 |
| **大白话** | 模型本身不知道你的简历和 JD。**RAG = 先从你自己的资料里"查"出相关的几段，塞进 prompt 一起发给模型**，让它的回答贴着你的真实经历走。 |
| **你在哪做过** | `projects/ai-interviewer/lib/rag.ts` —— 你写了 **`tokenize`（中文 bigram 分词）、`chunkText`（420 字一块 / 80 字重叠）、`class BM25Index`（BM25 打分）**，检索出 topK 片段后拼成带来源标注的上下文注入出题 prompt。**这是一套完整的、零依赖的、手写的 RAG。** |
| **面试怎么说** | 见 `面试复盘卡.md` 卡 4 的「为什么用 BM25 不用向量检索」——**那段要能一口气说完。** |

> 很多人只会"调个 LangChain 的 RAG 模板"。**你是自己实现的检索算法**，这在面试里是实打实的加分项。

## 二、一句话把它们串起来

**你的 AI 面试官，就是这五个词的一次完整实战：**

```
用户输入岗位
   ↓
【RAG】从知识库检索相关片段（rag.ts 的 BM25）
   ↓
【Prompt】把片段 + 规则拼成提示词（chat/route.ts 的 system）
   ↓
【LLM】发给大模型（ai.ts 的 DeepSeek）
   ↓
【流式】一个字一个字返回给前端（streamText）
   ↓
【React】界面实时渲染出来（app/ 下的页面）
```

**这条链路上的每一环，都是你写的。**

## 三、JD 里还会出现的词（一句话版）

| 词 | 一句话 |
|---|---|
| **Token** | 模型处理文字的最小单位，约等于"字/词块"。**计费和上下文长度都按 Token 算。** |
| **API Key** | 调用模型服务的钥匙。你已经处理过"没配 Key 就降级"的逻辑。 |
| **Embedding / 向量** | 把文字变成一串数字，用来算"两句话像不像"。**你没用——你用了 BM25**，这有正当理由（见复盘卡）。 |
| **向量数据库** | 专门存向量的数据库。**你没用，别硬说用了。** |
| **微调 / Fine-tune** | 拿自己的数据继续训练模型。**你没做过，别说做过。** |
| **Agent** | 让模型自己决定"先做什么、再做什么、用哪个工具"。**这是当前最缺人的方向。** |
| **LangChain** | 一个把 LLM 应用各环节串起来的框架。**你没用——你手写了，这是优势不是劣势。** |
| **SSR / CSR** | 服务端渲染 / 客户端渲染。Next.js 默认是 SSR，你已经在用了。 |
| **SDK** | 官方提供的"调用工具包"。你用的 `ai` 包（Vercel AI SDK）就是。 |
| **部署 / CI** | 把代码发布到线上。你用 Vercel 部署，这就是。 |
