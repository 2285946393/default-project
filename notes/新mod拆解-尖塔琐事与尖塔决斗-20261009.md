## 1. 尖塔：琐事（STS2_Things 1.25.10，作者 Adnermo）

### 1.1 包结构 —— 这是本次最大的收获

```
STS2_Things.dll            2.0 MB   ← 壳（Bootstrap），内嵌下面两个实现
STS2_Things.BaseLibBridge.dll  22 KB ← BaseLib 配置桥（可选）
STS2_Things.pck          209 MB   ← 全部美术/音频
STS2_Things.json                   ← manifest：dependencies 是空的
```

`STS2_Things.dll` 反编译只有 416 行 —— 它是个**壳**。把 PE 里的 `MZ` 切出来（脚本见下），
里面**内嵌了两个完整实现**：

- `@15924` → 993,792 B → `STS2_Things.Implementations.v107.1.dll`
- `@1009724` → 1,023,488 B → `STS2_Things.Implementations.v111.dll`

切包脚本（一行 python，直接扫 PE 头）：

```python
import struct
b = open(dll, 'rb').read()
for o in [i for i in range(len(b)) if b[i:i+2] == b'MZ']:   # 简化写法，实际用 find 循环
    e = struct.unpack_from('<I', b, o + 0x3C)[0]
    if b[o+e:o+e+4] != b'PE\x00\x00': continue
    nsec  = struct.unpack_from('<H', b, o+e+6)[0]
    sizeopt = struct.unpack_from('<H', b, o+e+20)[0]
    base = o + e + 24 + sizeopt
    end = max(struct.unpack_from('<I', b, base+s*40+20)[0]
              + struct.unpack_from('<I', b, base+s*40+16)[0] for s in range(nsec))
    open(f'impl-{o}.dll','wb').write(b[o:o+end])
```

### 1.2 技巧 A：**一个包同时吃两个游戏版本**

壳在运行时**反射探测**游戏版本，再从自己的嵌入资源里挑实现加载：

```csharp
// STS2_Things.Bootstrap/UnifiedBootstrap.cs（反编译还原）
private static string DetectTarget(Assembly gameAssembly)
{
    int[] arity = gameAssembly
        .GetType("MegaCrit.Sts2.Core.Models.AbstractModel", throwOnError: true)
        .GetMethods(BindingFlags.Instance | BindingFlags.Public)
        .Where(m => m.Name == "ModifyDamageMultiplicative")
        .Select(m => m.GetParameters().Length)
        .Distinct().Order().ToArray();

    if (arity.SequenceEqual(new[]{5})) return "v107.1";          // 5 个参数 = 0.107.1
    if (arity.SequenceEqual(new[]{6})                            // 6 个参数 = 0.111.x
        && gameAssembly.GetType("MegaCrit.Sts2.Core.Combat.CombatId") != null)
    {
        if (gameAssembly.GetType("MegaCrit.Sts2.Core.Multiplayer.Connection.HandshakeManager") != null)
            return "v111";
        throw new NotSupportedException("…detected a v0.110.x assembly…");
    }
    throw new NotSupportedException("…");
}
```

加载 + 注册：

```csharp
// 1) 从嵌入资源里把对应实现 LoadFromStream
var ctx = AssemblyLoadContext.GetLoadContext(typeof(UnifiedBootstrap).Assembly)
          ?? AssemblyLoadContext.Default;
var impl = ctx.LoadFromStream(asm.GetManifestResourceStream("STS2_Things.Implementations.v111.dll"));

// 2) 告诉游戏「这个程序集属于 STS2_Things 这个 mod」★
ModManager.AssociateAssemblyWithMod("STS2_Things", impl);

// 3) 手动调实现自己的初始化入口

```

**老版本（v107.1）走 Harmony 桥**：补 `ReflectionHelper.ModTypes` 的 getter（把实现的类型追加进去）
+ `ModelIdSerializationCache.Init`（把 `ModManager.Mods` 里那条记录的私有 `assembly` 字段替换成实现程序集）。

> **对我们（斗地主）的意义**：我们现在是「一个 dll + `min_game_version` + RitsuLib compat 分支」。
> 这套「壳 + 内嵌多实现」是**另一种**做法，好处是 manifest 里 `min_game_version` 可以写到最低的那个版本，
> 玩家装哪个版本都能跑，不用依赖 RitsuLib 的 compat 目录。
> **不是要马上换**，但要知道这条路存在。

### 1.3 技巧 B：`AssociateAssemblyWithMod` 与联机的关系 ★★★

**这条最重要，直接解释「联机下 mod 内容错乱/报错」**。

`ModManager.cs:1194`：

```csharp
public static void AssociateAssemblyWithMod(string modId, Assembly assembly)
```

为什么必须调？看 `ContentSorter.cs:57`（游戏原话）：

> ```
> Attempting to register type {type} in assembly {type.Assembly}, but it is not associated
> with any mod! You may need to call ModManager.AssociateAssemblyWithMod to manually register
> the assembly. Type sorting may break because of this, causing errors in multiplayer.
> ```

也就是说：**游戏的联机内容排序（ContentSorter）要求每个 mod 类型都能追溯到它属于哪个 mod**。
追溯不到 → 排序不稳定 → **联机时 ID 对不上 → 报错/失步**。

相关的另外两个入口：

- `ReflectionHelper.ModTypes`（`ReflectionHelper.cs:38`）—— 游戏枚举 mod 类型的那份总表；
  在 ModManager 初始化完成前调用会抛 `"ModManager is not finished initializing!"`。
- `ModelIdSerializationCache.Init` —— 联机序列化用的 ModelId 缓存，就在这里建。
- `AssemblyInfo.BaseGame` / `AssemblyInfo.ModMap` / `AssemblyInfo.ModForType(type, out isBaseGame)`
  —— 游戏判断「这个类型是本体还是哪个 mod 的」。

> **排查建议**：我们联机出问题时，先 grep 游戏日志里有没有上面那句
> `not associated with any mod`。有的话，就是某个程序集没注册。

### 1.4 技巧 C：**同时接 BaseLib 和 RitsuLib 的配置页**

`LibraryIntegration` 在 `AppDomain.CurrentDomain.GetAssemblies()` 里找 `BaseLib` /

RitsuLib 那边的入口（**反射调用，不需要编译期引用**）：

BaseLib 那边更简单 —— 单独编一个 `*.BaseLibBridge.dll`（编译期引用 BaseLib），
在桥里 `ModConfigRegistry.Register("STS2_Things", new ThingsBaseLibConfig())`。

它 Harmony 补了 `ModManager.State` 的 setter，等状态变成 `"Initialized"` 时再试一次：

```csharp

    .GetMethod("OnModManagerStateChanged", BindingFlags.Static | BindingFlags.NonPublic)));
```

> **对我们**：我们的设置页是 RitsuLib 那套。这个「反射注册 + 等 Initialized 再重试」

> `ModSettingsRuntimeReflectionInteropMirror.RegisterProviderTypeAndTryRegister(string, string)`** 这个公开口子。

### 1.6 技巧 E：往本体内容池里加东西，要**确定性排序**

它自己写了个 `DeterministicContentOrder`（注意：`ModHelper.ConcatModelsFromMods` 游戏里也有类似的，
但 Things 选择了自己按 `ModelId` 排）：

```csharp
internal static class DeterministicContentOrder
{
    public static IEnumerable<TModel> SortBaseThenMods<TModel>(IEnumerable<TModel> source)
        where TModel : AbstractModel
    {
        if (AssemblyInfo.BaseGame == null || AssemblyInfo.ModMap == null) return source;
        var all = source.ToList();
        var modItems = all.Where(m => m.GetType().Assembly != AssemblyInfo.BaseGame).ToList();
        if (modItems.Count <= 1) return all;

        var queues = modItems.GroupBy(m => m.GetType())
                             .ToDictionary(g => g.Key, g => new Queue<TModel>(g));
        // ★ 用游戏自己的 ContentSorter 排出稳定顺序（和联机那套一致）
        var sorted = ContentSorter<ModelId>.Sort(
            modItems.Select(m => m.GetType()), (Func<Type, ModelId>)ModelDb.GetId, true);

        var result = all.Where(m => m.GetType().Assembly == AssemblyInfo.BaseGame).ToList();
        foreach (var item in sorted) result.Add(queues[item.type].Dequeue());
        return result;
    }
}
```

补丁写法 —— **追加型 postfix 一律 `[HarmonyPriority(0)]`**，保证自己的东西排在最后：

### 2.4 ★★★ 技巧 D：**让每个玩家都看到「自己在左边」**

这条对我们三人牌桌直接可用。

```csharp
public readonly record struct DuelPlacement(float X, float Y, bool Mirror);

public static class DuelLayout
{
    public static DuelPlacement Place(ulong viewer, ulong owner, int petIndex = -1)
    {
        bool isMe = viewer == owner;
        float x = isMe ? 0.25f : 0.75f;              // 自己左、对手右
        if (petIndex < 0) return new DuelPlacement(x, 0.55f, !isMe);
        float dir = isMe ? 1f : -1f;                 // 宠物往哪边铺开
        int col = petIndex % 2, row = petIndex / 2;
        return new DuelPlacement(x + dir * (0.085f + col * 0.065f),
                                 0.57f - row * 0.065f, !isMe);
    }
}
```

落位 + 镜像：

```csharp
var p = DuelLayout.Place(LocalContext.NetId.Value, owner.NetId, petIndex);
creatureNode.GlobalPosition = room.GetGlobalTransform()
    * new Vector2(room.Size.X * p.X, room.Size.Y * p.Y);
FaceInward(creatureNode, p.Mirror);

private static void FaceInward(NCreature node, bool mirror)
{
    var body = node.Body;
    if (body == null) return;
    var pose = BodyPoses.GetValue(body, b => new BodyPose(b));
    body.Scale = new Vector2(Math.Abs(body.Scale.X) * pose.Sign * (mirror ? -1 : 1), body.Scale.Y);
    var b = node.Visuals.Bounds;
    float mid = b.Position.X + b.Size.X * 0.5f;
    body.Position = new Vector2(mirror ? 2f * mid - pose.Position.X : pose.Position.X, pose.Position.Y);
}
// 位置改完必须通知导航系统重算
AccessTools.Method(typeof(NCombatRoom), "UpdateCreatureNavigation").Invoke(room, null);
```

**注意它的判据是 `LocalContext.NetId`（本机玩家 id）**，不是「我是不是房主」——
所以同一份逻辑在双方机器上跑，各自算出各自的布局。**这是纯本地的呈现层，不走网络。**

### 2.5 ★★★ 技巧 E：官方给的**联机同步原语** `PlayerChoiceSynchronizer`

这是本次第二个大发现。游戏里就有：

```csharp
public class PlayerChoiceSynchronizer : IDisposable
{
    public uint ReserveChoiceId(Player player);
    public void SyncLocalChoice(Player player, uint choiceId, PlayerChoiceResult result);
    public async Task<PlayerChoiceResult> WaitForRemoteChoice(Player player, uint choiceId);
    public event Action<Player, uint, NetPlayerChoiceResult>? PlayerChoiceReceived;
    // PlayerChoiceResult.FromIndex(int?)  /  result.AsIndex()
}
```

SpirePvp 拿它当「通用的双方投票/回合栅栏」用：

```csharp
public static async Task<bool[]> Exchange(PlayerChoiceSynchronizer sync,
                                          IReadOnlyList<Player> players, Player local,
                                          Func<Task<bool>> choose, CancellationToken ct)
{
    var slots = players.Select(p => (Player: p, Id: sync.ReserveChoiceId(p))).ToArray();
    return await Task.WhenAll(slots.Select(async slot => {
        int v;
        if (slot.Player == local) { v = await choose() ? 1 : 0; sync.SyncLocalChoice(local, slot.Id, PlayerChoiceResult.FromIndex(v)); }
        else                      { v = (await sync.WaitForRemoteChoice(slot.Player, slot.Id)).AsIndex(); }
        return v == 1;
    }));
}
```

房主权威判定：

```csharp
bool isHost = (int)manager.NetService.Type != 3;      // 3 = 单机/客机
// Things 那边写的是 (int)service.Type == 2  → Host
```

> **对我们**：我们的斗地主联机是自研 netcode。**游戏本来就有**
> `RunManager.Instance.PlayerChoiceSynchronizer` 这个现成的「选一个整数并全网同步」口子。
> 出牌、抢地主、要不起、回合推进 —— 全都能编码成 `int` 走这条路，
> 比自己搓 RPC 少一大堆失步风险。**强烈建议国内台评估。**
