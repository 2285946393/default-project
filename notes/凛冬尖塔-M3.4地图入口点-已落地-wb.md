## 二、地图入口点 —— ★ 全部反编译取证

### 关键结论（6 条，缺一条整个方案就不成立）

1. **地图屏只画 `Grid` 里的点。**
   `NMapScreen.SetMap()` 用 `map.GetAllMapPoints()` 遍历；
   `ActMap.GetAllMapPoints()` 就是**双层循环走 `Grid[col, row]`**（`<GetAllMapPoints>d__11`）。
   ⇒ 我们的点**必须写进 `Grid`**，否则屏幕上根本不显示。

2. **`Grid` 尺寸定死，不能扩容。**
   `protected abstract MapPoint?[,] Grid { get; }`，标准图构造时 `new MapPoint[7, _mapLength]`。
   ⇒ 只能找**本来就空着的格子**放。

3. **标准图 `row 0` 只有起点一个点。**
   `StandardActMap.GenerateMap()`：真实路径点全在 `row == 1`（`GetOrCreatePoint(rng.NextInt(0,7), 1)`），
   起点 `StartingMapPoint` 单独在 `new MapPoint(GetColumnCount()/2, 0)` 即 `(3, 0)`。
   ⇒ `row 0` 除起点列外的格子天然为空 —— **放我们点的最佳位置**。

4. **可达性 = `Children`。**
   `MapTravel.GetTravelablePointsFrom()` 直接 `return currentPoint.Children;`
   地图屏 `RecalculateTravelability()` 也按 `Children` 判"能不能走"。
   ⇒ `StartingMapPoint.AddChildPoint(ourPoint)` = 开局即可直接点。

5. **`RunManager.EnterMapCoord(MapCoord)` 是"点地图 → 进房间"的唯一入口**（`public Task`）。
   链路：`NMapPoint.OnRelease()` → `_screen.OnMapPointSelectedLocally(node)` → …… → `EnterMapCoord(coord)`。
   ⇒ Harmony **Prefix** 拦它：坐标是我们的点 → `EnterRiftAsync` + `return false`（不进普通房间）。

6. **时机：`MapGeneratedEvent` 正好在刷屏之前。**
   `RunManager.GenerateMap()` 顺序：
   ```
   Hook.ModifyGeneratedMap(...)
     → Hook.AfterMapGenerated(...)        ← RitsuLib 在这里发 MapGeneratedEvent
     → State.Map = map
     → State.RemoveStaleVisitedMapCoords(map)
     → NMapScreen.Instance?.SetMap(map, ...)   ← 刷屏，此时已带上我们的点
   ```
   ⇒ 在事件里改 map 就够了，**不用自己刷 UI**。
   ⚠️ `MapPostProcessing.CenterGrid` 会**重写 `coord.col`**，但它在 `StandardActMap` 构造里就跑完了，
     事件触发时早就结束 —— 不过代码仍**以当前 `StartingMapPoint.coord.row` 为基准**算，
     不写死数字，才能适配任意居中偏移。

### 实现（`Portal/FrostRiftMapNode.cs`）

```
OnMapGenerated(MapGeneratedEvent evt)
  ├─ evt.Map is StandardActMap ？（裂隙自己的图不走这条）
  ├─ OnlyFirstAct && evt.ActIndex != 0 → 跳过（只在第 1 幕放）
  ├─ 在起点所在行找第一个空列（从最右往左扫）
  ├─ map.GetOrCreatePoint(col, row)   ← ★ public，会**同时写进 Grid**
  ├─ node.PointType = MapPointType.Treasure   （借用本体已有类型；枚举不可扩展）
  ├─ node.CanBeModified = false
  └─ start.AddChildPoint(node)        ← 开局可达
```

拦截：

```csharp
[HarmonyPatch(typeof(RunManager), nameof(RunManager.EnterMapCoord))]
internal static class EnterMapCoordPatch
{
    [HarmonyPrefix]
    private static bool Prefix(RunManager __instance, MapCoord coord)
    {
        if (_riftCoord is not { } rift || !coord.Equals(rift)) return true;  // 不是我们的点 → 原逻辑
        if (state.Map is FrostRiftActMap) return true;                        // 已在裂隙里 → 防套娃
        if (!state.AddVisitedMapCoord(coord)) return true;                    // 已走过 → 原逻辑
        _ = FrostRiftSession.EnterRiftAsync(state);
        return false;                                                         // 拦下
    }
}
```

★ 为什么 Prefix 里要**自己补 `AddVisitedMapCoord`**：
原方法第一件事就是它（`if (!State.AddVisitedMapCoord(coord)) return Task.CompletedTask;`），
我们 `return false` 跳过了原方法 → 得自己补，否则"当前位置"不更新，出口回不来、地图屏也不会标已走。

### 设计取舍

- **`PointType` 用 `MapPointType.Treasure`**：枚举不可扩展（`Unassigned/Unknown/Shop/Treasure/RestSite/Monster/Elite/Boss/Ancient`），
  借用 `Treasure` 只是因为图标/配色现成。**不影响玩法** —— 因为我们 Prefix 拦住了，它永远不会被掷成真房间。
- **只放第 1 幕**：`OnlyFirstAct = true`。想每幕都放改 false。
- **原版零改动**：不点这个点 → 地图、路径、牌库全和原版一模一样。
